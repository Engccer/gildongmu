# 장소 상세 주소 복사 버튼 위치 감사

## 감사 범위

- 흐름: 검색 → 검색 결과에서 장소 선택 → 장소 상세 상단 정보 확인
- 화면: 프로덕션 영문 UI, 데스크톱 기본 뷰포트와 모바일 390×844
- 사용자 목표: 주소를 확인한 직후 주소를 빠르고 명확하게 복사하기
- 접근성 목표: 주소와 복사 동작의 관계가 명확하고, 키보드·터치·스크린 리더에서 동작이 독립된 컨트롤로 인식되기

## 단계별 기록

1. **검색 결과에서 장소 선택 — 양호**
   - `경복궁 관훈점` 결과를 선택하면 상세 화면으로 전환되고 장소명 `h2`로 포커스가 이동한다.

2. **상세 상단에서 주소와 복사 동작 확인 — 조정 권장**
   - 근거: [01-current-detail.png](./01-current-detail.png), [02-current-detail-mobile.png](./02-current-detail-mobile.png)
   - 주소 두 줄 바로 뒤에 복사 버튼이 있어 의미상 연관은 가깝다.
   - 그러나 버튼이 독립 행을 차지하면서 주소 정보와 전화번호 사이의 읽기 흐름을 끊는다.
   - 모바일에서 버튼의 실제 터치 높이는 44px로 적절하지만, 보이는 라벨은 작은 텍스트라 빈 행처럼 느껴지고 주소에 딸린 동작이라는 시각적 묶음이 약하다.
   - DOM 읽기 순서는 주소 → 복사 → 전화로 논리적이며, 아이콘은 보조기술에서 숨겨지고 버튼 이름도 있다.

## 판정

현재 위치는 기능·접근성 면에서 틀리지는 않지만 시각적 위계와 정보 흐름은 다듬는 편이 낫다. 복사 버튼을 주소 블록의 오른쪽 끝에 붙여 주소의 보조 동작으로 묶는 안을 권장한다. 버튼은 44×44px 최소 터치 영역과 독립된 접근 가능한 이름을 유지하고, 긴 주소가 버튼 때문에 과도하게 좁아지지 않도록 주소 블록 전체를 반응형으로 배치한다.

## 조정 후 확인

- 근거: [03-adjusted-detail.png](./03-adjusted-detail.png), [04-adjusted-detail-mobile.png](./04-adjusted-detail-mobile.png)
- 주소 블록을 콘텐츠 너비에 맞추고 최대 너비를 화면으로 제한해, 데스크톱에서도 복사 버튼이 주소에서 멀리 밀리지 않는다.
- 모바일 390×844에서 복사 버튼은 47.9×44px이고 가로 오버플로는 0px이다.
- DOM 순서는 주소 → 복사 버튼 → 전화번호이고, 버튼의 접근 가능한 이름은 `Copy`로 확인했다.
- 로컬 브라우저 자동화 세션은 페이지의 Clipboard API 쓰기를 허용하지 않아 실제 클립보드 값은 읽지 못했다. 대신 jsdom 컴포넌트 테스트에서 `navigator.clipboard.writeText` 호출 값과 성공 상태 통지를 검증했다.
- 최종 판정: **조정 완료 — 배치 양호**.

### 사용자 실사용 후 기준선 보정

- 사용자 Chrome+VoiceOver 화면에서 버튼의 44px 터치 상자는 주소와 같은 행이었지만, 버튼 내부 라벨이 수직 중앙 정렬되어 주소 글자보다 12px 아래에 보였다.
- 수정 전 글자 상단: 주소 209.75px, 복사 221.75px.
- 44px 터치 영역을 유지하고 버튼 내부만 `flex-start`+상단 2px로 정렬했다.
- 수정 후 글자 상단: 주소 119.75px, 복사 119.75px로 일치했다.
- 근거: [05-aligned-copy-label-local.png](./05-aligned-copy-label-local.png)

### 스크린 리더의 빈 탐색 지점 제거

- 원인은 주소와 복사 버튼 사이에 항상 렌더되던 빈 `role="status"` 요소였다. 시각적으로는 숨겨져도 접근성 트리에는 별도 상태 객체로 남았다.
- 주소 행 자체를 `aria-live="polite"`·`aria-atomic="false"`인 기존 live region으로 사용하고, 복사 성공 문구는 성공 순간에만 숨김 텍스트로 추가한 뒤 2초 후 제거하도록 바꿨다.
- 대기 상태의 실제 브라우저 접근성 트리는 `도로명 주소` → `복사` → `전화` 순서이며, 주소와 버튼 사이의 빈 `status` 객체가 없음을 확인했다.
- 로컬 브라우저는 Clipboard API 쓰기를 허용하지 않아 성공 알림의 실브라우저 발화는 재현하지 못했다. 컴포넌트 테스트에서 성공 시 `주소 복사됨` 문구가 live region에 추가되고, 평상시에는 문구와 `role="status"`가 모두 없음을 검증했다.

## 대안

1. **권장: 주소 블록 오른쪽 상단에 복사 버튼 배치**
   - 주소 두 줄과 복사 동작이 하나의 시각적 그룹이 된다.
   - 전화번호가 주소 블록 바로 다음 정보로 이어져 읽기 흐름이 좋아진다.
   - 모바일에서는 버튼을 오른쪽에 고정하고 주소 텍스트만 자연스럽게 줄바꿈한다.

2. **현 위치 유지 + 버튼 외형만 강화**
   - 변경 폭이 가장 작고 긴 주소 폭을 보존한다.
   - 독립 행 문제는 남는다.

3. **주소 행 전체를 복사 버튼으로 만들기**
   - 클릭 영역은 커지지만 주소 텍스트가 버튼 역할까지 가져 과도한 상호작용이 되고, 텍스트 선택과 스크린 리더 탐색이 불편해질 수 있어 비권장이다.

## 증거 한계

- 화면 캡처와 DOM 구조로 시각적 위계·읽기 순서·터치 영역을 확인했다.
- 실제 VoiceOver 발화와 물리 키보드 조작은 구현 후 브라우저 검증에서 별도로 확인해야 한다.
