# Play 데이터 안전성 섹션 초안 (Data safety)

> **초안** — Play Console 입력 전 위원장 판정 3건(§5)이 남아 있다. 근거는 ① `play-policy-insights` 스킬 정적 감사(2026-09-17, `compliance-report-2026-09-17.md`) ② iOS `PrivacyInfo.xcprivacy`·ASC 영양 라벨(`docs/appstore/1.0-submission-draft.md` §7) ③ 웹 개인정보 처리방침(`messages/*.json` `privacy.*`) ④ 안드로이드 소스(매니페스트·`location/`·`chat/`·`speech/`·`guide/`). **4자 일치 불변식**(CLAUDE.md): 수집·전송 항목을 바꾸면 이 넷을 함께 고친다.

## 1. 요약

- 계정·로그인 없음. 자체 서버(DB)에 개인정보 저장 없음. 광고·추적 SDK·분석 SDK 없음(웹의 Vercel Analytics는 앱과 무관).
- 기기를 떠나는 데이터는 셋뿐이고 전부 **사용자 조작으로 촉발되는 실시간 요청**이다: 정확한 위치(내 주변·길찾기·채팅 맥락), 검색어, AI 채팅 질문·대화.
- 기기에 머무는 것: 받아쓰기 음성(온디바이스 인식기만, 서버 폴백 없음), 걸음 수(실험판 도보 안내, 메모리), 체중(설정, 기기 저장), 최근 검색어·수동 위치·설정(기기 `SharedPreferences`).
- 전송 경로는 전부 HTTPS, 대상은 길동무 서버 `gildongmu.dodoplanet.space` 하나이며 서버가 제공자(카카오·네이버·ODsay·Tmap·공공데이터·Google Gemini·Perplexity)에 중계한다.

## 4. 감사 결과 요지 (`play-policy-insights`, 14건 — IMPORTANT 1·SUGGESTION 13, 위반 0)

- IMPORTANT #8 정확한 위치: 수집·전송 사실을 위 표대로 선언하면 충족. 모든 전송이 사용자 조작 뒤라 별도 눈에 띄는 고지(prominent disclosure)는 면제 판정(시스템 권한 다이얼로그로 충분).
- #13 위치 권한 정책: 백그라운드 위치 미요청(D11)·연속 추적은 전경 서비스(location 타입)로 — 정책 부합. 권장: 첫 권한 요청 직전 "무엇을 위해" 설명이 있는지 확인 → 앱은 내 주변 진입·길찾기 조회·채팅 첫 전송의 **기능 맥락 안에서만** 요청한다(spec §4 세 자리). 별도 사전 고지 화면은 두지 않는다(목적이 맥락으로 자명 — 미니멀리즘).
- #14 전경 서비스: 도보 실시간 안내가 정식 기능이 되어(2026-09-23, BACKLOG E43 우선순위 4) 전경 서비스(`location`)·`FOREGROUND_SERVICE(_LOCATION)`·`WAKE_LOCK`·`ACTIVITY_RECOGNITION`이 **정식 매니페스트**(`app/src/main/AndroidManifest.xml`)에 있다(`AppSourceGuardTest` + `android/scripts/check-release-manifest.mjs`가 정식·실험 APK 모두에 있음과 백그라운드 위치 0을 잠근다). 따라서 **정식판 첫 제출에 Play 전경 서비스 선언(기능 설명·동영상 데모)이 필요하다** — 선언 근거: 사용자가 [도보 안내 시작]을 누른 뒤 세션 동안만 위치 스트림을 열고, 화면을 꺼도 방향 톤·음성 안내가 이어져야 하는 사용자 인지 작업이며 사용자가 알림의 [안내 종료]로 언제든 멈춘다.
- 나머지 11건은 오탐 정리(계정·오디오 파일·파일 공유·음악·신용 등)와 로컬 전용 확인.

## 5. 판정 (코디네이터 2026-09-17, 위원장 판정 재료)

1. **승인** — 서버 중계 제공자는 Play 정의상 "서비스 제공자"라 공유 아님(iOS 논리 유지). (원문) **"공유(shared)" 표기**: 서버가 카카오·네이버·ODsay·Tmap·Gemini·Perplexity에 중계하는 것을 Play 정의의 "제3자 공유"로 볼 것인가, "개발자를 대신해 처리하는 서비스 제공자"(공유 아님)로 볼 것인가. 초안은 후자(iOS 라벨과 같은 논리) — 보수적으로 "공유"를 택하면 위치·검색어·채팅 셋 다 공유 예 + 대상 명시.
2. **결정** — Play 값은 iOS ASC 라벨과 같게(수집함, 일시적 처리 아님); Vercel 런타임 로그에 요청 경로가 남는 사실을 §2에 명시했다. ASC 라벨은 "수집함/미연결/비추적"이라 어긋남 없음. (원문) **"일시적 처리"**: 서버 인프라 요청 기록에 일시적으로 남는 것(처리방침 문장)을 Play의 ephemeral 정의("요청 처리에 필요한 시간만 메모리에")로 볼 수 있는가. 아니면 "수집(저장 없음)"으로만 표기.
3. **결정** — 정식판 빌드 구성에서 뺀다(§4 #14). → **2026-09-23 대체**: 도보 안내 정식판 이동(BACKLOG E43 우선순위 4)으로 정식 매니페스트에 승격, 첫 제출에 선언한다. (원문) **전경 서비스(location) 선언문**: 정식판에 봉인된 실험 기능을 근거로 선언할지, 정식판 첫 제출 때는 매니페스트에서 서비스·`FOREGROUND_SERVICE_LOCATION`을 빌드 구성으로 빼서 선언 자체를 미룰지(빌드 구성 분기는 iOS `Info-Experimental.plist` 관례와 같다).

## 6. 갱신 규칙

수집·전송 항목이 바뀌면(새 데이터 유형·새 제3자) 이 문서 §2 + `ios/Gildongmu/PrivacyInfo.xcprivacy` + ASC 라벨 + 웹 `privacy.*` 6로케일을 **같은 커밋**에서 고친다. 안드로이드에 서버 STT 폴백·분석 SDK·계정이 들어오면 각각 오디오·진단·개인 정보 행이 새로 선다(감사 #3·#7·#1의 조건문).
