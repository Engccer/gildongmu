# 베르길리우스 말로 묻기: Claude 두 모델 실호출 표

측정일 2026-11-14. Claude 선택지(`claude-opus`·`claude-sonnet`)를 끝점에 더한 날의 머지 게이트 기록이다. 같은 날의 OpenAI·Google 표 `docs/evals/2026-11-14-e82-vergilius-ask.md`와 같은 재료·질문·판정 스크립트를 썼다. 시점 고정 기록이다.

## 1. 한 줄 결론

일곱 질문 모두 두 모델의 답에 재료 밖 이름, 좌우 불일치, 지나온 가게를 앞이라 말한 답이 0건이었고 오류·거절·잘림도 0건이었다. 목록에 있는 가게로 가자는 질문은 네 번 모두 그 가게를 제안했다. 첫 글까지의 시간은 조회 없는 질문에서 Sonnet 1.0~1.6초, Opus 1.2~2.8초(중앙값)로 OpenAI(1.0~1.1초)·Google(0.6~0.9초)보다 느리다. **조회가 끼는 질문은 첫 글과 끝이 같은 순간이다**(Opus 5.1~7.1초, Sonnet 4.7~6.2초): 도구 결과 뒤 회차의 글이 조각으로 흐르지 않고 끝에 한꺼번에 온다(§4). Opus는 15번 중 1번 지침이 금한 마크다운 굵게(`**식당은**`)를 썼다.

## 2. 무엇을 어떻게 쟀는가

- **자리**: Mac 로컬 개발 서버(`next dev`)의 `POST /api/vergilius/ask`. 휴대전화 회선, Vercel 구간, 기기 받아쓰기 시간은 들어 있지 않다.
- **모델**: `claude-opus-5-5`(생각 설정 생략, effort `low`), `claude-sonnet-5-5`(`thinking: {type: "between_tools"}`, effort `low`). SDK `@anthropic-ai/sdk` 1.6.0 `messages.stream`.
- **재료·질문·판정**: OpenAI·Google 표 §2와 같다(종각역 부근 30곳, 위원장 일곱 질문 원문, 보조 질문 x1). 방향 모름 보조 질문(x2)은 이번에 돌리지 않았다.
- **반복**: q1~q5는 모델마다 3회, 조회가 끼는 q6·q7과 x1은 2회.
- **시간**: 「첫 글」은 `final`이 참인 첫 글 조각까지, 「전체」는 `done`까지. 초, 중앙값(최소~최대).
- **지출**: 회차 기록의 토큰으로 계산하면 약 $0.65(Opus $0.45, Sonnet $0.21). §4의 확인 호출 약 $0.05를 더해 $0.7 남짓이다.

- q6·q7의 수치는 도구 결과와 따로 대조하지 않았다(OpenAI·Google 표 §4와 같은 도구·같은 실행부다).

## 4. 도구 결과 뒤 글은 끝에 한꺼번에 온다

회차 기록(`[vergilius]` 줄)에서 도구 결과를 받은 두 번째 회차는 첫 글 조각과 회차 끝의 차이가 2~19ms였다(169~273토큰). 첫 회차는 같은 길이의 글이 수백 ms에 걸쳐 흐른다. 끝점 밖의 짧은 스크립트로 같은 모양(도구 한 번 → 결과 → 답)을 다시 쟀더니 두 모델, 도구 선택 `auto`·`none`, 생각 설정 넷(Opus 생략, Sonnet `between_tools`·`adaptive`·설정 없음), effort `low`·기본에서 모두 같았다. 우리 설정이 아니라 API 쪽 동작이다. 그래서 조회가 끼는 질문은 「첫 글」이 곧 「전체」이고, 줄이려면 두 번째 회차의 입력(q6은 도구 결과 때문에 캐시 밖 입력이 1만 1천 토큰)과 모델 생각 시간을 줄이는 수밖에 없다.

같은 스크립트에서 두 모델 모두 회차 하나에 4~12초가 걸린 때가 있었다(측정 중 API 지연이 출렁였다). 표의 수치는 그보다 앞선 시간대의 것이다.

## 5. 캐시

도구 선언과 지침 앞부분 약 4,470토큰이 첫 요청에서 캐시에 쓰였고, 이후 52회차 중 50회차가 그만큼을 캐시에서 읽었다(`cache_read_input_tokens`). 캐시 밖 입력은 회차마다 약 1,930토큰(재료와 질문)이다. 회차당 출력 중앙값은 Opus 160토큰, Sonnet 98토큰이고, 질문 하나의 지출은 Opus 약 2.2센트, Sonnet 약 1센트였다.
