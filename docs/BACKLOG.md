1. **정합** — 이미 있는 기능이 틀린 답을 내는가

**B1 상태 정정(2026-08-01 코드 대조)**: 종전 "웹조차 부재" 서술은 사실이 아니었다. `src/components/DistanceBeacon.tsx` · `src/hooks/useDistanceBeacon.ts` · `src/lib/beacon.ts` · `beacon-tones.ts`가 실재하고 `PlaceDetail.tsx:208`에 **조건 없이 마운트**되어 prod에 나가 있다(2026-07-04 훅 생명주기 결함 2건 수정 후 재마운트, 경위는 `PROGRESS.md`). 미지원 브라우저는 컴포넌트 자체 게이트로 null을 반환한다.

따라서 이 항목은 신규 개발이 아니라 **진짜 플랫폼 갭**이고, 막고 있는 것은 구현이 아니라 실보행 스모크다. 게이트 내용은 그대로다: 자동 테스트로 검증 불가한 기능이라 "폰에서 장소 상세 → 거리 추적 펼침 → 시작 → 걸으며 톤·거리 확인"이 유일한 판정이며, 그 전에 iOS로 옮기면 안 쓰이는 기능을 두 플랫폼에 들고 가는 셈이 된다.

이식 비용은 표면보다 싸다: iOS `Localizable.xcstrings`에 `beacon.*` 11키가 **이미 미러돼 있고 Swift 소비자가 0**이라, 남은 일은 CoreLocation 상시 업데이트 + 뷰 조립이다(반대로 스모크에서 가치가 부정되면 이 11키가 죽은 키로 확정되어 제거 대상이 된다).

**신규 기능의 갭 예방 규칙**: 아래 E의 신규 도메인은 착수 시점에 웹·iOS를 같은 마일스톤에 넣는다. B 축이 존재하는 이유가 "웹 먼저 내고 iOS는 나중에"의 누적이었고, 공유 계층(`useNearbyFetch`/`NearbyPanelShell` · `NearbyLoadCore`/`RevealWindow`)은 정확히 그 동시 착수를 싸게 만들려고 뽑아 둔 것이다.

## D. 내부 품질 (사용자 비가시: 기본은 편승, 편승할 작업이 없으면 별도 정리)

⚠ **편승은 얹힐 작업이 실제로 올 때만 유효한 정책이다.** D1·D4는 다음 도보 작업·다음 릴리스가 반드시 그 코드를 지나가므로 성립하지만, D2·D3은 그런 작업이 예정에 없어 무기한 보류로 굳는다(판정과 처리안은 아래 "다음 마일스톤").

- **D1. 카카오 도보 잔여**: 2026-08-01 spec §테스트 계획 대 실제 테스트 대조로 두 건으로 좁혔다.
  - **미커버 1건**: ACCESSIBLE 요청 → 무계단 경로 부재 → **기본 모드 재호출이 throw**하는 경로. `walk-route.ts`의 마지막 `fetchPrimaryOrFallback`이 던지면 502로 전파되는데 테스트가 없다(재호출의 *null* 케이스만 `walk-route.test.ts:210`에 있다).
  - **문구 부정확 1건**: ACCESSIBLE 응답이 왔는데 계단 문구가 남아 `no_stepfree_route`로 강등될 때(fail-closed), 안내 문장은 "계단 없는 경로를 찾지 못해 **일반 경로를 안내합니다**"라고 말하지만 실제로 반환하는 것은 ACCESSIBLE 경로다. 안전 방향의 오차라 급하지 않으나 사실과 다르다.
  - 다음에 도보를 손댈 때 편승.
- **D2. 서울 열린데이터 무효키가 원인 불명 SyntaxError로 나타난다**: 인증키가 무효하면 `/json/` 경로여도 **HTTP 200 + XML 본문**이 온다(실측 2026-08-01: `<RESULT><CODE>INFO-100</CODE><MESSAGE>인증키가 유효하지 않습니다`). `res.json()`을 그냥 부르면 `Unexpected token '<'`가 되어 502의 원인이 키라는 사실이 가려진다. **혼잡도 provider는 막았고**(`seoul-congestion.ts`의 `readSeoulOpenJson`), 같은 키·같은 호스트를 쓰는 **따릉이(`seoul-bike.ts`)·문화행사(`seoul-culture-events.ts`)에는 그대로 남아 있다.** 키가 죽으면 셋이 동시에 같은 방식으로 오진된다. 셋을 손댈 때 공용 fetch 헬퍼로 뽑는다(`fetchDataGoKrJson` 선례 — **모양은 공용, 봉투 정책은 provider**).
- **D3. 좌표 파라미터 누락이 "서비스 지역 밖"으로 위장된다**: 라우트 **14곳**(2026-08-01 재확인: `places`·`places/kids`·`places/around`·`places/barrier-free`·`places/barrier-free/match`·`bike/nearby`·`bus/nearby`·`walk/nearby`·`air-quality/nearby`·`weather/nearby`·`clinic/nearby`·`where-am-i`·`station/subway-arrival/nearby`·`geocode/reverse`)이 `searchParams.get("lat") ?? ""`를 `z.coerce.number()`에 직접 태운다. `Number("")===0`이라 (0,0)이 되고 `isInKorea(0,0)`이 false여서 **400이어야 할 요청이 `200 {"outOfCoverage":true}`로 응답**한다. 공용 헬퍼는 **이미 있다**(`src/lib/coord-param.ts`의 `latParam`/`lngParam`, 2026-08-01 혼잡도 마일스톤에서 두 번째 소비자가 생기며 추출). 남은 것은 14곳 백포트뿐이다. 정상 클라이언트는 항상 좌표를 보내 사용자 발현은 없고 CLI/MCP 소비자에게만 보이는 정합 결함이라 D축. 리뷰 검출(2026-08-01, 같은 날 재확인: 헬퍼 소비자는 여전히 `congestion`·`events` 2곳뿐).
- **D4. ASC 제출 스크립트의 쓰기 경로가 미검증**: `ios/scripts/asc-submit.mjs`는 읽기 경로(인증·앱 조회·버전/빌드 조회·로케일 매칭·드라이런)만 실호출로 확인됐다(2026-08-01). **PATCH·POST(버전 생성·What's New 입력·빌드 연결·심사 제출)는 한 번도 실행된 적이 없다**: 심사 중인 버전에 시험 삼아 쓸 수 없어 구조적으로 확인이 미뤄졌다. 다음 릴리스(1.3)에 편승해 `--apply`(제출 없이) → ASC 초안 육안 확인 → `--submit` 순으로 닫는다. ⚠ 미검증 상태에서 `--apply --submit`을 한 번에 부르지 말 것: 쓰기 실패가 절반만 적용된 초안을 남기면 브라우저로 되돌아가 수습해야 하고, 그게 이 스크립트를 만든 이유(세션 만료 시 사람 로그인 없이 멈추는 문제)를 되살린다.
