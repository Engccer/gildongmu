# 과금·쿼터 상태 리포트 설계 (2026-07-31)

## 1. 배경

길동무는 외부 API 13종 이상을 조합해 동작한다. 그중 실제로 돈이 나가는 곳과 무료지만 일일 쿼터가 있는 곳이 뒤섞여 있고, 각각의 현황은 벤더 콘솔 6곳에 흩어져 있다. 위원장은 스크린 리더 사용자라 콘솔을 하나씩 순회하는 비용이 특히 크다.

`PROGRESS.md` Phase 0 항목에 "위원장 콘솔 작업 잔여: 유료 3종(Google AI Studio·Perplexity·Deepgram)+Vercel 스펜드 알림 설정"으로 남아 있던 것이 출발점이다. 이 문서는 그 수동 작업을 **한 번의 명령으로 읽는 단일 리포트**로 대체하는 설계다.

## 2. 목표와 비-목표

### 목표
1. **콘솔 순회 대체**: 터미널 명령 한 줄로 과금·가용성·시한을 한 화면에서 읽는다.
2. **기능이 죽는 것 감지**: 쿼터 소진·키 만료로 길찾기·도착정보가 조용히 실패하는 상황을 사전에 잡는다. 시각장애인 사용자에게는 청구서보다 이쪽이 더 치명적이다.
3. **판단 근거 확보**: 2단계(자체 계측) 착수 여부를 결정할 실수치를 이 리포트가 산출한다.

### 비-목표 (이번 단계에서 하지 않는 것)
- **웹·앱 노출 없음.** 길동무는 인증 계층이 없는 공개 앱이다. 관리자 경로를 여는 순간 토큰 게이트·브루트포스 방어라는 새 공격면이 생긴다. 리포트는 로컬 전용이다.
- **자체 계측 없음.** provider 호출을 세어 저장하는 계층은 2단계이며, 착수 조건은 §10에서 정량으로 정의한다.
- **알림·크론 없음.** 이번 단계의 실행 주체는 사람이다.
- **CLI 패키지 편입 없음.** npm `gildongmu`는 제3자 공개 패키지라 운영자 전용 명령이 들어갈 자리가 아니다.

## 3. 실측으로 확정한 사실

문서 추정이 아니라 실호출로 판정했다. 이 절의 내용이 설계의 근거다.

### 3.1 Vercel은 Hobby 플랜이라 과금 축이 성립하지 않는다

```
GET /v2/teams/team_66LLUVeTidGmTUOdF9ESgxuf  →  plan: "hobby"
GET /v1/billing/charges?from&to             →  404 {"code":"costs_not_found"}
```

- **Spend Management(스펜드 알림)는 Pro 전용**이다. Hobby에는 설정 화면 자체가 없다.
- Hobby는 무료 한도 초과 시 **과금이 아니라 프로젝트 자동 일시정지**다. 즉 비용 위험은 구조적으로 0이며, 위험의 성격은 "돈"이 아니라 "정지"다.
- 따라서 `PROGRESS.md`의 "Vercel 스펜드 알림 설정" 잔여 항목은 **수행 불가이자 수행 불요**로 종결한다. 리포트는 이 사실을 §4 4번 섹션에 명시해 다시 찾아보지 않게 한다.
- 부수 확정: **Hobby 런타임 로그 보존은 1시간**이다. 로그를 긁어 일간 집계를 만드는 접근은 원천 봉쇄이며, 2단계에서 계측을 하려면 외부 저장소가 반드시 필요하다.

### 3.2 Deepgram 사용량·잔액 API는 현재 키로 접근 불가

같은 `DEEPGRAM_API_KEY`로 세 경로를 호출한 결과가 갈렸다.

```
GET /v1/projects                    →  200  (프로젝트 1개 확인)
GET /v1/projects/{id}/usage         →  403  "usage:read 스코프 필요"
GET /v1/projects/{id}/balances      →  403  "billing:read 스코프 필요"
```

문서만 읽었으면 "Deepgram은 API로 조회 가능"으로 적었을 대목이다. **스코프를 가진 별도 키 발급이 선행 조건**이다(§9).

### 3.3 유료 API의 무과금 프로브가 성립한다 (대조 실호출로 증명)

리포트를 돌릴 때마다 과금되면 목적에 반한다. 유료 3종 중 2종에서 **비용 0인 판정 경로**를 확정했다.

| 대상 | 프로브 | 유효 키 응답 | 무효 키 응답 | 과금 |
|---|---|---|---|---|
| Gemini | `GET /v1beta/models?key=&pageSize=1` | 200, `models[]` | (키 오류) | 없음 |
| Perplexity | `POST /chat/completions` body `{"model":"__invalid__","messages":[]}` | **400** `invalid_model` | **401** `invalid_api_key` | 없음 (모델 검증이 과금보다 앞) |
| Deepgram | `GET /v1/projects` | 200, 프로젝트 목록 | (키 오류) | 없음 |

Perplexity는 잔액 조회 API가 없다는 점을 문서에서 확인했고, 대신 **400과 401의 분리**로 키 유효성만 무과금으로 판정한다. 무효 키를 실제로 넣어 401을 받아 본 대조까지 마쳤다. ODsay Referer 검증 때와 같은 방식이다. 성공 하나만으로는 증명이 안 되고, 실패 대조가 있어야 판정이 성립한다.

### 3.4 나머지 벤더는 사용량 조회 API가 없다

| 벤더 | 조회 수단 |
|---|---|
| Gemini | 직접 API 없음. Cloud Monitoring 경유 또는 AI Studio 대시보드(5~60분 지연) |
| Perplexity | 콘솔 전용 |
| 카카오·Tmap·ODsay·data.go.kr·네이버·서울 열린데이터 | 콘솔 마이페이지 전용 |

**벤더 API로 채울 수 있는 칸은 사실상 Deepgram 하나**다. 이 사실이 "얼마나 남았나" 대신 "지금 살아 있나"를 묻는 §4.2 설계의 근거다.

## 4. 설계

### 4.0 산출물과 실행

```
scripts/usage-report.mjs          진입점. .env.local 로드, 프로브 실행, 렌더 호출
scripts/lib/usage-report-core.mjs 순수 함수. 응답 분류·D-day 계산·문장 렌더
scripts/lib/__tests__/usage-report-core.test.mjs
```

실행은 `node scripts/usage-report.mjs`. 외부 의존성 0(Node 내장 `fetch`만 사용). 앱 코드·서버 라우트·배포 설정은 건드리지 않는다.

`vitest.config.ts`의 `include`는 현재 `src/**`만 잡으므로 `scripts/**/*.test.mjs`를 추가한다. 판정 로직이 순수 함수라 검출력 있는 테스트가 가능하고, 이 계층을 `src/lib/`에 두지 않는 이유는 앱 런타임과 무관한 운영 도구이기 때문이다(`src/lib`의 dodo 이식성 계약을 오염시키지 않는다).

### 4.1 섹션 1: 돈

유료 4종의 현황. 가져올 수 있으면 수치, 없으면 정보 없음과 콘솔 URL.

| 항목 | 이번 단계 표시 |
|---|---|
| Gemini | 키 유효 여부 + 콘솔 URL. 사용량 수치는 정보 없음(§11 후속) |
| Perplexity | 키 유효 여부 + 콘솔 URL. 잔액은 정보 없음(API 부재 확정) |
| Deepgram | 스코프 키 있으면 잔액·최근 30일 사용량, 없으면 정보 없음 |
| Google Cloud TTS | 키 유효 여부. iOS는 온디바이스가 정본이라 실사용은 웹 PWA 폴백뿐 |

### 4.2 섹션 2: 가용성 (프로브)

각 API에 요청 1건을 보내 지금 동작하는지 실측한다. **3-state를 넘어 4-state로 분류**한다.

| 판정 | 근거 | 사용자에게 뜻하는 바 |
|---|---|---|
| `정상` | 2xx 또는 계약상 정상 envelope | 그 기능은 지금 동작한다 |
| `쿼터 초과` | 벤더별 초과 코드·메시지 | 그 기능이 오늘 죽었다. 즉시 조치 대상 |
| `인증 실패` | 401·403·키 오류 코드 | 키 만료·이관·오등록 |
| `조회 실패` | 네트워크 오류·타임아웃·미분류 응답 | 판정 불가. 원문을 함께 출력 |

**미분류 응답을 정상으로 뭉개지 않는다.** 길동무의 3-state 불변식과 같은 정신이며, 특히 `쿼터 초과`와 `조회 실패`를 합치면 "오늘 도보 경로가 왜 안 되는지"를 영원히 알 수 없게 된다.

무료 쿼터 API의 프로브 1건은 일 1,000건 중 1건이므로 소모를 수용한다. 유료 API는 §3.3의 무과금 경로만 쓴다.

### 4.3 섹션 3: 시한

만료·이관 예정일을 정적 목록으로 두고 D-day를 계산한다. 프로브가 잡지 못하는 위험(아직 유효하지만 곧 죽을 것)을 덮는다.

| 대상 | 기한 | 근거 |
|---|---|---|
| ODsay URI 앱 키 | 2027-01-04 | PROGRESS 등록 이력 |
| 네이버 지역검색 API Hub 이관 | 2027-06-30 | 2026-07-21 공지 메일 |
| Apple 배포 인증서(Cloud Managed) | 2027-07-18 | TestFlight 첫 업로드 시 발급 |

날짜에 요일을 병기할 때는 `python3`로 검증한다(글로벌 규칙). D-day 계산은 순수 함수이므로 테스트 대상이다.

### 4.4 섹션 4: 걱정 불필요

**"이건 안 봐도 된다"를 명시하는 것이 순회를 줄이는 핵심**이다. 목록에 없으면 확인해야 한다는 오해를 막는다.

- **카카오**: 유료 전환 미신청. 쿼터 초과는 과금이 아니라 오류이고, 오류는 Tmap 폴백으로 이어진다. 비용 상한이 구조적으로 0원이다.
- **Vercel**: Hobby. 초과 시 과금이 아니라 일시정지. 스펜드 알림은 Pro 전용이라 설정 대상이 아니다.
- **juso·서울 열린데이터·data.go.kr**: 무료. 쿼터는 §4.2 프로브가 담당한다.

각 항목에 "왜 안전한가"를 한 줄로 붙인다. 근거 없는 안심은 다음 세션에서 다시 의심받는다.

### 4.5 출력 형식

스크린 리더 낭독이 1급 요구다.

- **표·괘선·좌우 정렬 금지.** 한 줄에 한 사실을 담은 평문 문장으로 낸다. 시각적 정렬은 낭독에서 공백 잡음이 된다.
- **한 줄 = 한 접근성 객체 원칙의 터미널 판**: 항목명·상태·수치를 별도 열로 흩지 않고 한 문장으로 합친다. 예: `Deepgram 정상, 잔액 4.21달러, 최근 30일 요청 128건`
- **섹션 제목은 짧게** 두어 화면 낭독에서 건너뛰기 지점이 되게 한다.
- 색·기호에만 의존하지 않는다. 상태는 반드시 단어로 적는다.
- 이모지 금지(글로벌 규칙).

출력 예시:

```
길동무 과금·쿼터 리포트  2026-07-31 (금) 21:40 KST

[돈]
Gemini 키 정상. 사용량 수치는 조회 API가 없어 정보 없음. 콘솔 aistudio.google.com/usage
Perplexity 키 정상. 잔액은 조회 API가 없어 정보 없음. 콘솔 console.perplexity.ai
Deepgram 정상, 잔액 4.21달러, 최근 30일 요청 128건
Google Cloud TTS 키 정상. 웹 PWA 폴백 전용이라 사용량 미미

[가용성]
카카오 로컬 정상
카카오 도보 정상
Tmap 보행자 정상
ODsay 대중교통 정상
서울 실시간 지하철 정상
서울 버스 정상
공공데이터포털 정상
네이버 지역검색 정상
juso 주소 정상

[시한]
ODsay 키 만료까지 157일 (2027-01-04)
네이버 API Hub 이관까지 334일 (2027-06-30)

[걱정 불필요]
카카오는 유료 전환 미신청이라 초과가 과금이 아니라 오류이고 Tmap으로 폴백한다
Vercel은 Hobby라 초과 시 과금 대신 일시정지이며 스펜드 알림은 Pro 전용이라 설정 대상이 아니다
```

### 4.6 시크릿 취급

- 키는 `.env.local`에서만 읽는다. 리포트 출력·로그·오류 메시지에 키 값이 절대 실리지 않게 한다(오류 원문을 출력할 때 키 문자열 마스킹).
- `DEEPGRAM_MANAGE_KEY`는 **Vercel에 등록하지 않는다.** 서버 런타임이 쓸 일이 없고, 등록하면 공격면만 넓어진다. 로컬 전용 키다.
- 리포트 출력물을 파일로 남기지 않는다(기본은 표준출력). 남기고 싶으면 사용자가 리다이렉트한다.

## 5. 프로브 카탈로그

확정과 미확정을 구분한다. 미확정은 구현 착수 게이트에서 실호출로 확정하며, **추정으로 코드를 쓰지 않는다.**

| 대상 | 프로브 경로 | 상태 |
|---|---|---|
| Gemini | `GET /v1beta/models?pageSize=1` | 확정(200 실측) |
| Perplexity | `POST /chat/completions` 무효 모델 | 확정(400/401 대조 실측) |
| Deepgram 존재 | `GET /v1/projects` | 확정(200 실측) |
| Deepgram 사용량 | `GET /v1/projects/{id}/usage`·`/balances` | 확정(403, 스코프 키 필요) |
| Vercel | `GET /v2/teams/{id}` | 확정(200, plan 필드 실측) |
| 카카오 로컬·도보·Tmap·ODsay·서울지하철·서울버스·data.go.kr·네이버·juso·NCP·Google TTS | 각 도메인 최소 요청 1건 | **미확정.** 정상 응답 형태와 쿼터 초과 코드를 착수 게이트에서 실측 |

쿼터 초과 응답은 **초과 상황을 인위로 만들 수 없으므로** 벤더 문서의 코드를 후보로 두되, 관측되지 않은 코드는 `조회 실패`로 떨어뜨린다(fail-closed). 실제 초과를 만나면 그때 코드를 확정해 카탈로그에 기록한다. 카카오 도보의 미관측 status를 throw로 처리한 것과 같은 원칙이다.

## 6. 오류 처리

- **한 프로브의 실패가 리포트 전체를 죽이지 않는다.** 전 프로브를 `Promise.allSettled`로 병렬 실행하고, 실패한 칸만 `조회 실패`로 렌더한다.
- 타임아웃은 프로브당 10초. 전체가 느려지면 리포트를 안 돌리게 되고, 안 돌리는 리포트는 없는 것과 같다.
- 키가 없는 항목은 오류가 아니라 `키 미설정`으로 표기한다. 설정하지 않은 것과 설정했는데 실패한 것은 다른 상태다.

## 7. 테스트 전략

순수 함수만 테스트한다. 프로브 자체는 외부 상태라 실호출 수동 게이트다.

| 대상 | 방식 |
|---|---|
| 응답 → 판정 분류 | fixture 기반. 4-state 각각과 **미분류 응답이 정상으로 새지 않는지**를 못 박는다 |
| D-day 계산 | 기준일 주입. 경계(당일·하루 전·지난 날짜) 케이스 |
| 문장 렌더 | 키 미설정·정보 없음·수치 있음 세 갈래가 각각 다른 문장을 내는지 |
| 시크릿 마스킹 | 오류 원문에 키가 섞여 들어와도 출력에 남지 않는지 |

마지막 항목은 특히 중요하다. 벤더가 오류 응답에 요청 URL을 되돌려주면 쿼리스트링의 키가 그대로 실린다.

## 8. 구현 순서

1. `usage-report-core.mjs` 순수 함수와 테스트(판정·D-day·렌더·마스킹)
2. 확정 프로브 4종(Gemini·Perplexity·Deepgram·Vercel) 배선과 실행
3. 미확정 프로브 실호출 게이트: 정상 응답 형태를 하나씩 확인하며 카탈로그 확정
4. 출력 문장 다듬기와 실사용 1회

## 9. 선행 작업 (위원장 콘솔)

**Deepgram 스코프 키 발급**: Deepgram 콘솔에서 `usage:read`와 `billing:read` 스코프를 가진 API 키를 새로 만들어 `.env.local`에 `DEEPGRAM_MANAGE_KEY`로 저장한다. 기존 `DEEPGRAM_API_KEY`는 STT 전용으로 그대로 둔다.

이 키가 없어도 리포트는 동작하며 Deepgram 칸만 `키 미설정`으로 나온다. 즉 **차단 게이트가 아니다.** 구현을 먼저 진행하고 키는 나중에 채워도 된다.

## 10. 2단계(자체 계측) 승격 판정 기준

"변경은 측정 가능한 성과에 묶는다" 원칙에 따라, 다음 중 하나라도 참이면 2단계를 착수한다. 판정 데이터는 이 리포트가 만든다.

1. **월 실지출이 10달러를 넘는다.** 그 규모면 어느 기능이 돈을 쓰는지 모르는 상태가 위험하다.
2. **유료 축 4칸 중 2칸 이상이 계속 `정보 없음`이다.** 리포트가 목적(콘솔 순회 대체)을 절반도 달성하지 못한다는 뜻이다.
3. **쿼터 초과가 실제로 1회 이상 관측된다.** 그때는 "지금 죽었나"가 아니라 "언제 죽을까"를 알아야 한다.

2단계의 형태는 그 시점에 다시 설계한다. 다만 §3.1에서 확정했듯 Vercel Hobby 로그는 1시간만 남으므로 **외부 저장소가 필수**라는 제약은 이미 확정되어 있다.

## 11. 미해결

- **Gemini 사용량 수치**: Cloud Monitoring API로 `generativelanguage.googleapis.com` 메트릭을 조회하면 요청 수를 가져올 수 있을 가능성이 있다. 다만 `GEMINI_API_KEY`가 어느 GCP 프로젝트에 묶여 있는지 확인이 선행되어야 하고, 서비스 계정 자격증명이 추가로 필요하다. 최대 지출처이므로 가치는 크지만, 이번 단계의 차단 요소는 아니다. 구현 후 별건으로 시도한다.
- **쿼터 초과 응답 코드**: 실제 초과를 만나기 전까지 확정 불가. fail-closed로 두고 관측 시 기록한다.
- **Cloud TTS 무과금 프로브**: `voices.list`가 무과금인지 미확인. 착수 게이트에서 확인한다.
