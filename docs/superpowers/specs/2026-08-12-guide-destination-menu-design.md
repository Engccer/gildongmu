# 안내 시트 목적지 메뉴 — 장소 상세 보기·목적지 바꾸기 (2026-08-12)

> 위원장 실보행 리포트(2026-08-11, 자택 → 주택 A → 오아시스마켓)에서 출발.
> 이동 중 목적지를 바꾸려면 안내를 중지하고 시트를 닫고 도착지를 다시 검색해 재시작해야 했고,
> 이동 중 목적지 장소의 세부 정보를 확인할 방법이 없었다. 두 부담을 안내 시트 제목 메뉴로 푼다.
>
> **개정 이력**: 초판 4ba0049 → 적대적 설계 리뷰(§9) 반영판. 확정 단위·가드 결합·전환 중 발화
> 공백·세대 가드·stale 후보 문턱이 리뷰로 보강되었다.

## 0. 범위와 결정 요약

- **iOS 3수단**(도보·자동차 `BeaconTrackingSheet`, 대중교통 `TransitTrackingSheet`). 웹 실시간 안내는 범위 밖 — 마일스톤 닫을 때 PORTS.md에 이식 후보 등록.
- 대중교통 목적지 전환은 **후보 목록에서 선택**(위원장 확정 2026-08-12): 경로가 복수라 선택이 본질적 단계이고, 기존 "안내 시작 버튼은 경로에 귀속" 원칙과 일치한다. 자동 최상위 선택은 예상 밖 경로(더 먼 정류장 도보 등)를 임의로 태우는 위험으로 기각.
- 뒤 화면(길찾기 폼)은 **필드 갱신 + 무통지 자동 재조회**(위원장 확정 2026-08-12): 시트를 닫으면 새 목적지 기준 화면이 드러나야 일관되고, 최근 목록 기록도 기존 `setEndpoint` 경로를 그대로 탄다. 경로 API 1회 추가 호출은 수용.

## 1. 제목 메뉴 (두 시트 공통)

추적 섹션 헤더의 단순 텍스트(`joinText(수단 heading, destinationLabel)`)를 같은 라벨의 **네이티브 `Menu`**로 바꾼다(`GildongmuTitleMenu` 선례 — VoiceOver "…, 팝업 버튼" 낭독). 항목 2개:

1. **장소 상세 보기** (`guide.titleMenu.detail`)
2. **목적지 바꾸기** (`guide.titleMenu.changeDest`)

- 공용 뷰 `GuideTitleMenu(heading:label:onShowDetail:onChangeDestination:)` 하나를 두 시트가 쓴다(복붙 금지).
- **헤딩 시맨틱 유지 시도**: `Menu` 라벨에 `.isHeader` trait를 붙여 헤딩 로터 항행을 보존한다. 실기기에서 "헤딩+팝업 버튼" 조합 낭독이 어색하거나 로터에서 빠지면 **폴백**: 헤더는 기존 텍스트 유지 + 섹션 첫 행에 메뉴 버튼 1행("목적지 메뉴"). 판정은 실기기 VoiceOver(§8).
- **도착 종료 화면·대중교통 도보 핸드오프 화면의 헤더는 불변**: 세션이 끝난 화면이라 "목적지 바꾸기"가 성립하지 않고, 도착 화면에는 이미 주변 확인이 있다. 잉여 진입점을 만들지 않는다(미니멀리즘).

## 2. 장소 상세 보기

- 시트 위 시트(전 구간 조망 `RouteOverviewSheet` 동형 표준 중첩)로 `NavigationStack { PlaceDetailView(place:) }`를 띄운다. NavigationStack이 필요한 이유는 상세 안의 주변 정보 `NavigationLink` 4종.
- 목적지는 이름+좌표뿐이므로 **최소 `Place` 변환**으로 연다(`cultureEventToPlace` 등 기존 선례 — id는 `"guide-dest:{lat},{lng}"` 합성, 주소·카테고리 빈 문자열). 주소 목적지도 동일하게 열린다 — 상세의 주변 섹션(지하철·버스·따릉이·공기질)은 좌표만으로 성립한다.
- **"여기까지 길찾기" 버튼은 이 문맥에서 숨긴다**: 이미 그곳으로 안내 중이라 무의미하고, 누르면 시트 뒤 화면(길찾기 폼)을 조작해 보이지 않는 상태 변화를 만든다. `PlaceDetailView`에 표시 여부 파라미터 1개 추가(기본값 표시 — 기존 호출부 불변).
- 상세를 보는 동안 **안내 톤·음성 통지는 유지**한다: 사용자는 걷는 중이고 임박 회전 큐는 안전 계층이다. VoiceOver 낭독과 겹치는 순간이 있어도 안전 신호를 끄는 쪽이 더 나쁘다(통지 억제는 §5의 검색 시트 구간만).

## 3. 목적지 바꾸기 — 도보·자동차 (즉시 확정)

메뉴에서 누르면 기존 도착지 검색 시트 `DirectionsEndpointSearchView(target: .to)`(최근 장소 목록 포함)를 시트 위에 띄운다. 후보를 고르면 그 자리에서 확정.

### 3.1 `BeaconModel.changeDestination(dest:label:)` 계약

**모델은 "같은 세션의 경로 재획득"으로 다룬다** — 재조회(`performReroute`)가 아니라 세션 시작(`start`)의 경로 획득 국면을 세션 유지 채로 다시 도는 것에 가깝다.

- **세션은 끊지 않는다**: `isTracking`·톤 세션·위치 스트림·워치독 유지. `dest`·`destinationLabel` 교체.
- **진입 즉시 옛 경로를 내려놓는다**(리뷰 B2): 경로 종속 상태를 전부 초기화하고 `awaitingRoute=true`(기존 발화 보류 기계 재사용)로 전환 — 조회 왕복 동안 옛 경로의 회전·도착 신호가 나갈 창을 구조적으로 없앤다. 위치 종속 상태는 승계한다.
  - **초기화(경로 종속)**: `guideRoute`·`guideState`(스텝·임박 래치 포함)·`displayUnits`/`liveSteps`/`liveBaselineD`·`currentGuidanceText`·`statusText`·`offRoute`·`finalApproach` 래치 일체(`resetFinalApproach(nil)`)·car ETA(카운터·타이머)·`roadSpans`·`pendingStepFreeNotice`·`lastStepFree`.
  - **승계(위치·세션 종속)**: 톤 엔진 세션·모션 3-state·유도기 버퍼(`courseDerivation` — 재조회 §2.9 동형: 같은 세션의 새 경로)·`accessible`(계단 회피는 세션 시작 시점 값 유지).
- **즉시 확인 통지**(리뷰 B2·M7): 진입 시점에 `.high`로 "목적지를 {새 이름}(으)로 바꿨습니다"를 **억제 게이트를 우회해** 발화한다 — 검색 시트는 select에서 dismiss되지만 억제 해제 타이밍과 경합하므로, 이 1건은 사용자 활성화의 직접 응답이고 마이크는 이미 닫혔다(헌장 §6 활성화 응답 `.high` 계약의 적용). 경로 요약은 조회 완료 시 별도 `.high` 통지(재조회 성공 통지 동형). 빠른 응답에서 두 통지가 겹치면 앞 통지가 잘릴 수 있으나 뒤 통지(요약)가 더 최신 정보라 수용.
- **상세 재적격**: 데이터 로케일 ko면 현재 위치 → 새 목적지로 `fetchGuideRoute` 계열 조회(latest-wins 토큰 `routeFetchToken`++). 간략 세션에서 바꿔도 다시 상세를 시도한다(목적지 변경 = "이 세션에서 현재 목적지에 대해 조회"의 새 기회).
- **실패는 간략 폴백**: 조회 실패·부적격이면 새 목적지 기준 간략 안내로 정직 폴백(`fallbackToBrief` 기존 경로). 옛 목적지로 되돌리지 않는다(사용자 확정 우선).
- 도착 종료 상태(`arrivalDest`)에서는 불리지 않는다(§1 — 그 화면엔 메뉴가 없다).

### 3.2 확정 가드 (리뷰 B3)

- **선택 핸들러는 세션 생존을 확인한다**: `isTracking`이 아니면(검색 중 자동 도착·중지·외부 종료) 선택을 통째로 폐기한다 — 세션도 폼도 건드리지 않는다(죽은 안내를 되살리지 않고, 폼만 바뀌는 분리 상태도 만들지 않는다). SwiftUI 시트 스택이 세션 종료 시 검색 시트를 함께 닫으므로 이 창은 좁지만, UI 타이밍에 기대지 않고 모델 가드로 박는다.
- **같은 목적지 재선택은 무변화**: 새 endpoint가 현재 `.to`와 같으면 폼 갱신·플래그·재조회를 전부 생략하고 세션 쪽 확인 통지만 낸다(플래그 잔류 경로 원천 차단, §5.2).

### 3.3 포커스

- 검색 시트가 닫히면 **중지 버튼 착지**(`landStopFocus` 재사용). 시트 dismiss 후 "지연·검증·1회 재시도" 착지는 이 repo의 실증된 정본 패턴이다 — 리뷰의 "dismiss 전 선점 이동" 제안은 기각: 선점 대상(중지 버튼)이 다른 프레젠테이션 계층에 있어 dismiss 전 대입이 성립하지 않고, 기존 패턴이 같은 전이를 이미 커버한다(§9 M3 기각 근거).

## 4. 목적지 바꾸기 — 대중교통 (2단 확정)

대중교통은 경로가 복수라 **"새 목적지 선택"과 "새 경로 선택"까지가 한 확정 단위**다. 중간 상태(세션은 옛 목적지, 폼은 새 목적지)를 만들지 않는다.

### 4.1 흐름

1. 검색 시트에서 새 목적지 선택 → **아직 아무것도 확정하지 않는다**. `TransitGuideModel.prepareDestinationChange(dest:label:)`가 현재 위치 → 새 목적지 대중교통 경로를 **사이드 채널로 조회**(`RouteService.transit(includeStops: true)` — 폼과 무관, 안내용이라 includeStops 필수). 조회 완료 시각을 기록한다.
2. 시트 안에 **후보 목록 섹션**이 뜬다: 라벨은 기존 `transitRouteEntries` 조립(추천 고정 이름 + 대안 축 이름 + 요약) 재사용, 항목 정체성 = `routeKey`. 조회 중·0건·실패는 3-state(진행 문구 / "경로 없음" / 오류 문구). 0건·실패의 출구는 취소뿐(재시도는 메뉴 재진입 — 별도 버튼은 잉여).
3. **후보 선택 = 확정**: 세션이 새 경로·새 라벨로 이어지고(시트 유지), 그때 폼 동기화(§5) 실행.
4. **취소(후보 목록 닫기) = 전체 무효**: 세션·폼·최근 목록 모두 옛 목적지 그대로. 사이드 채널 조회의 늦은 응답은 폐기(latest-wins 토큰).

### 4.2 stale 후보 가드 (리뷰 B5)

후보는 조회 시점 위치의 스냅샷이다. **선택 시점에 조회 후 경과가 120초를 넘으면 그 후보로 확정하지 않고 자동 재조회**해 목록을 갱신한다(첫 후보 재착지 + polite 통지 "경로를 다시 조회했습니다"). 승차 이동 중 지나친 정류장을 첫 승차 지점으로 확정하는 경로를 차단한다. 120초는 잠정값(실사용 판정 대상, `GuideTuning` 계열 상수로).

### 4.3 세션 연속성·세대 가드 (리뷰 B3·B4)

- `TransitGuideModel.changeRoute(transitRoute:destinationLabel:)`: 내부 상태를 새 경로 기준으로 재시작하되 `state`가 nil을 스치지 않게 원자 교체한다 — 시트 presentation이 `isTracking(state != nil)`에 묶여 있어 nil 순간이 시트를 닫는다. `pendingWalkHandoff` 소거(옛 목적지의 제안).
- **세션 세대(generation) 도입**: `changeRoute`가 세대를 증가시키고, 옛 세션이 걸어 둔 모든 비동기 경로(도착 폴링·타이머·위치 콜백·통지 태스크)는 커밋 전 세대 일치를 확인한다. 구현 시 기존 토큰 기계가 이미 이 역할을 하는 콜백은 그대로 두고, 세대 검사가 없는 콜백만 보강한다(이중 가드 신설 금지 — 실측 후 최소 보강).
- **확정 가드**: 후보 선택 핸들러도 §3.2와 동일 — 세션 생존(`state != nil`)+준비 세대 일치가 아니면 폐기.
- 승차 중 전환 허용: 새 경로는 현재 위치 기준 첫 leg 대기 국면으로 시작한다. "타고 있던 차량에서 이어가기" 정합 추정은 하지 않는다(추정 오류가 더 위험 — 대기 국면의 기존 탈출구 "이미 탔습니다"가 그 역할).

### 4.4 후보 화면 포커스·통지 계약 (리뷰 M2)

- 검색 시트 dismiss 후: **후보 섹션의 상태 행(조회 중 문구)에 착지**(정본 착지 패턴 — 가시화→지연→대입→검증→1회 재시도).
- 후보 도착: **첫 후보 착지**(같은 정본 패턴, 항목 정체성 `routeKey`). 도착 통지는 별도로 내지 않는다(착지 낭독이 첫 후보를 읽는다 — 이중 낭독 금지).
- 0건·실패로 전환: 그 문구 행에 착지(조회 중 행이 사라지는 전이 — 헌장 §5).
- 취소: 후보 섹션이 사라지고 **중지 버튼 착지**(`landStopFocus`).

## 5. 폼 동기화·가드 통과 (도보·자동차 확정 시, 대중교통 후보 선택 시)

1. **출발지도 함께 갱신한다**(리뷰 M1): 안내 주도 변경은 "지금 여기서 새 목적지로"이므로 `.from`을 `.current`로, `.to`를 새 목적지로 갱신한다 — 세션(현재 위치 출발)과 폼(재조회 결과)의 출발점 의미를 일치시킨다. 최근 목록 기록은 `setEndpoint` 기존 경로가 담당(이중 기록 금지).
2. **가드 통과는 값 결합 1회 소비형**(리뷰 B1): Boolean이 아니라 **예상 endpoint 값**을 담는 `guidanceInitiatedEndpoint: DirectionsEndpoint?`를 둔다. `.onChange(of: .to)` 핸들러는 새 값이 이 플래그와 일치할 때만 중지를 생략하고 플래그를 소비한다. 불일치·nil이면 종전대로 양쪽 중지. 같은 목적지 재선택은 §3.2에서 setEndpoint 자체를 생략하므로 플래그가 남을 경로가 없다. 두 안내 모델 동시 생존은 `GuideSessionCoordinator` 단일 세션 불변식이 이미 차단한다.
3. **무통지 재조회**: 기존 진행 조회를 취소하고 결과를 비운 뒤 `performQuery`를 통지·포커스 이동 억제 모드로 실행(완료 합산 통지·수단 heading 이동 생략). stale 경합은 기존 latest-wins 기계(사용자 수동 조회와 같은 경로)를 그대로 탄다(리뷰 M6) — 재조회 중 사용자가 시트를 닫고 수동 조회하면 나중 조회가 이긴다. 재조회 실패는 조용히 결과 없음 상태(시트를 닫고 조회 버튼으로 복구 — 기존 화면 계약).
4. **검색 시트가 열린 동안만** 통지·톤을 억제한다(`beacon.outputSuppressed` 기존 계약 — 받아쓰기 전사 오염 방지). 대중교통도 동형 억제를 신설하되(리뷰 M4) **소유권은 DirectionsTabView가 아니라 각 추적 시트의 검색 시트 표시 상태**에 두고, 모델 `stop()`/`start()`가 무조건 해제한다(잔류 억제로 다음 세션이 무음이 되는 경로 차단). 후보 목록(마이크 없음)과 장소 상세 시트에는 걸지 않는다 — 안내 신호는 안전 계층이라 필요 최소 구간만 끈다(§2).

## 6. 불변식 정리

- **확정 단위**: 도보·자동차 = 목적지 선택 1탭. 대중교통 = 목적지 선택 + 경로 선택 2탭. 확정 전에는 세션·폼·최근 목록 어느 것도 변하지 않고, 확정 시 셋이 한 번에 바뀐다.
- **세션 무단절**: 확정 경로에서 `isTracking`(비콘)·`state != nil`(대중교통)이 false를 스치지 않는다.
- **전환 중 옛 경로 발화 0**: 도보·자동차는 진입 즉시 경로 종속 상태 초기화 + `awaitingRoute` 보류가 구조적으로 보장한다.
- **확정은 살아 있는 세션에만**: 선택·후보 확정 핸들러는 세션 생존(+세대 일치)을 확인하고, 죽었으면 아무것도 바꾸지 않는다.
- **가드 통과는 값 결합 1회 소비형**: 예상 값과 일치하는 변경 1회만 통과, 소비 후 원래 가드 복귀.
- **stale 응답 폐기**: 경로 조회·사이드 채널 후보 조회·폼 재조회 모두 latest-wins 토큰. stale **후보**는 120초 문턱 재조회(§4.2).
- **실패 시 정직**: 경로 실패 = 간략 폴백(도보·자동차) / 3-state 표시 + 취소 출구(대중교통). 옛 목적지로 몰래 되돌리지 않는다.

## 7. i18n

신규 키(전 로케일, 웹 messages → xcstrings 파이프라인): 메뉴 항목 2, 목적지 변경 확인 통지 1, 대중교통 후보 섹션 헤딩·진행·0건·오류·재조회 통지·취소 라벨. 통지 문장은 완성 문장 조립(슬롯 조립 금지 — `spoken-guidance-is-prose-not-slots`).

## 8. 검증

- **단위**: 확정 단위 불변식(값 결합 가드 1회 소비·불일치 시 중지 유지·취소 시 무변화), `changeDestination`의 경로 종속/위치 종속 상태 분리(§3.1 목록), 세션 생존 가드(죽은 세션 선택 폐기), stale 후보 문턱, 최소 Place 변환. **리뷰 M1 계열 경합 재현**(리뷰 MINOR 1): 같은 목적지 재선택, 조회 중 세션 종료, 억제 잔류 없는 stop.
- **빌드 게이트**: 시뮬레이터 빌드 + 기존 스위트 통과.
- **실기기 VoiceOver 판정 항목**:
  1. 헤딩+팝업 버튼 조합 낭독·헤딩 로터 포함 여부(어색하면 §1 폴백).
  2. 목적지 전환 즉시 확인 통지 + 완료 요약 통지 도달, 중지 버튼 착지.
  3. 대중교통 후보 상태 행 착지 → 첫 후보 착지 → 선택 후 시트 연속성.
  4. 어제 시나리오 재현: 도보 안내 중 오아시스마켓으로 전환 → 끊김 없는 재개(실보행).
