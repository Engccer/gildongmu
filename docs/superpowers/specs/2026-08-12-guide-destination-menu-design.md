# 안내 시트 목적지 메뉴 — 장소 상세 보기·목적지 바꾸기 (2026-08-12)

> 위원장 실보행 리포트(2026-08-11, 자택 → 주택 A → 오아시스마켓)에서 출발.
> 이동 중 목적지를 바꾸려면 안내를 중지하고 시트를 닫고 도착지를 다시 검색해 재시작해야 했고,
> 이동 중 목적지 장소의 세부 정보를 확인할 방법이 없었다. 두 부담을 안내 시트 제목 메뉴로 푼다.

## 0. 범위와 결정 요약

- **iOS 3수단**(도보·자동차 `BeaconTrackingSheet`, 대중교통 `TransitTrackingSheet`). 웹 실시간 안내는 범위 밖 — 마일스톤 닫을 때 PORTS.md에 이식 후보 등록.
- 대중교통 목적지 전환은 **후보 목록에서 선택**(위원장 확정 2026-08-12): 경로가 복수라 선택이 본질적 단계이고, 기존 "안내 시작 버튼은 경로에 귀속" 원칙과 일치한다. 자동 최상위 선택은 예상 밖 경로(더 먼 정류장 도보 등)를 임의로 태우는 위험으로 기각.
- 뒤 화면(길찾기 폼)은 **필드 갱신 + 무통지 자동 재조회**(위원장 확정 2026-08-12): 시트를 닫으면 새 목적지 기준 화면이 드러나야 일관되고, 최근 목록 기록도 기존 `setEndpoint` 경로를 그대로 탄다. 경로 API 1회 추가 호출은 수용.

## 1. 제목 메뉴 (두 시트 공통)

추적 섹션 헤더의 단순 텍스트(`joinText(수단 heading, destinationLabel)`)를 같은 라벨의 **네이티브 `Menu`**로 바꾼다(`GildongmuTitleMenu` 선례 — VoiceOver "…, 팝업 버튼" 낭독). 항목 2개:

1. **장소 상세 보기** (`guide.titleMenu.detail`)
2. **목적지 바꾸기** (`guide.titleMenu.changeDest`)

- 공용 뷰 `GuideTitleMenu(heading:label:onShowDetail:onChangeDestination:)` 하나를 두 시트가 쓴다(복붙 금지).
- **헤딩 시맨틱 유지 시도**: `Menu` 라벨에 `.isHeader` trait를 붙여 헤딩 로터 항행을 보존한다. 실기기에서 "헤딩+팝업 버튼" 조합 낭독이 어색하거나 로터에서 빠지면 **폴백**: 헤더는 기존 텍스트 유지 + 섹션 첫 행에 메뉴 버튼 1행("목적지 메뉴"). 판정은 실기기 VoiceOver(§8).
- **도착 종료 화면·대중교통 도보 핸드오프 화면의 헤더는 불변**: 세션이 끝난 화면이라 "목적지 바꾸기"가 성립하지 않고, 도착 화면에는 이미 주변 확인이 있다. 잉여 진입점을 만들지 않는다(미니멀리즘).

## 2. 장소 상세 보기

- 시트 위 시트(전 구간 조망 `RouteOverviewSheet` 동형 표준 중첩)로 `NavigationStack { PlaceDetailView(place:) }`를 띄운다. NavigationStack이 필요한 이유는 상세 안의 주변 정보 `NavigationLink` 4종.
- 목적지는 이름+좌표뿐이므로 **최소 `Place` 변환**으로 연다(`cultureEventToPlace` 등 기존 선례 — id는 `"guide-dest:\(lat),\(lng)"`류 합성, 주소·카테고리 빈 문자열). 주소 목적지도 동일하게 열린다 — 상세의 주변 섹션(지하철·버스·따릉이·공기질)은 좌표만으로 성립한다.
- **"여기까지 길찾기" 버튼은 이 문맥에서 숨긴다**: 이미 그곳으로 안내 중이라 무의미하고, 누르면 시트 뒤 화면(길찾기 폼)을 조작해 보이지 않는 상태 변화를 만든다. `PlaceDetailView`에 표시 여부 파라미터 1개 추가(기본값 표시 — 기존 호출부 불변).
- 상세를 보는 동안 **안내 톤·음성 통지는 유지**한다: 사용자는 걷는 중이고 임박 회전 큐는 안전 계층이다. VoiceOver 낭독과 겹치는 순간이 있어도 안전 신호를 끄는 쪽이 더 나쁘다(통지 억제는 §5의 검색 시트 구간만).

## 3. 목적지 바꾸기 — 도보·자동차 (즉시 확정)

메뉴에서 누르면 기존 도착지 검색 시트 `DirectionsEndpointSearchView(target: .to)`(최근 장소 목록 포함)를 시트 위에 띄운다. 후보를 고르면 그 자리에서 확정:

### 3.1 `BeaconModel.changeDestination(dest:label:)` 계약

- **세션은 끊지 않는다**: `isTracking` 유지, 위치 스트림·톤 세션·워치독 그대로. `dest`·`destinationLabel`만 교체 후 경로를 새로 조회한다.
- **상세 재적격**: 데이터 로케일 ko면 현재 위치 → 새 목적지 경로를 조회한다(`performReroute`와 같은 기계 — latest-wins 토큰, 원자 교체, `resetFinalApproach`, walk 표시 유닛 재구축, car ETA 초기화). 간략 세션에서 바꿔도 다시 상세를 시도한다(목적지 변경 = 스펙 §4.1 "이 세션에서 현재 목적지에 대해 조회"의 새 기회).
- **실패는 간략 폴백**: 경로 조회 실패·부적격이면 새 목적지 기준 간략 안내(직선거리·방향)로 정직 폴백. 안내는 끊기지 않는다. 옛 목적지로 되돌리지 않는다(사용자 확정이 우선).
- **이탈 상태 해소**: 새 목적지 확정은 새 경로 기준이므로 `offRoute` 등 이탈 래치는 재조회 성공 경로와 동일하게 초기화된다. 유도기 버퍼는 잇는다(재조회 §2.9 동형 — 같은 세션의 새 경로).
- 도착 종료 상태(`arrivalDest`)에서는 이 메서드가 불리지 않는다(§1 — 그 화면엔 메뉴가 없다).

### 3.2 통지·포커스

- 확정 통지는 **`.high` 1건**: "목적지를 {새 이름}(으)로 바꿨습니다." + 새 경로 시작 요약(재조회 성공 통지 `GuideText.reroute` 동형 조립, 간략 폴백이면 간략 시작 문형). 검색 시트 dismiss로 포커스가 이동하며 낭독되는 라벨에 기본 우선순위 통지가 잠식되는 실사고 계열(헌장 §6)이므로 `.high`가 필수다.
- 검색 시트가 닫히면 포커스는 **중지 버튼 착지**(`landStopFocus` 재사용 — 시트 열림과 같은 계약).

## 4. 목적지 바꾸기 — 대중교통 (2단 확정)

대중교통은 경로가 복수라 **"새 목적지 선택"과 "새 경로 선택"까지가 한 확정 단위**다. 중간 상태(세션은 옛 목적지, 폼은 새 목적지)를 만들지 않는다.

### 4.1 흐름

1. 검색 시트에서 새 목적지 선택 → **아직 아무것도 확정하지 않는다**. `TransitGuideModel.prepareDestinationChange(dest:label:)`가 현재 위치 → 새 목적지 대중교통 경로를 **사이드 채널로 조회**(`RouteService.transit(includeStops: true)` — 폼과 무관, 안내용이라 includeStops 필수).
2. 시트 안에 **후보 목록 섹션**이 뜬다: 라벨은 기존 `transitRouteEntries` 조립(추천 고정 이름 + 대안 축 이름 + 요약)을 재사용, 도착 시 첫 후보 착지(항목 정체성 = `routeKey`). 조회 중·0건·실패는 3-state로 가른다(진행 문구 / "경로 없음" / 오류 문구). 0건·실패의 출구는 취소뿐이다(재시도는 메뉴 재진입 — 별도 재시도 버튼은 잉여).
3. **후보 선택 = 확정**: 세션이 새 경로·새 라벨로 이어지고(시트 유지), 그때 폼 동기화(§5)가 실행된다.
4. **취소(후보 목록 닫기·"취소" 버튼) = 전체 무효**: 세션·폼·최근 목록 모두 옛 목적지 그대로. 사이드 채널 조회의 늦은 응답은 폐기(latest-wins 토큰).

### 4.2 세션 연속성

- `TransitGuideModel.changeRoute(transitRoute:destinationLabel:)`: 내부 상태를 새 경로 기준으로 재시작하되 `state`가 nil을 스치지 않게 원자 교체한다 — 시트 presentation이 `isTracking(state != nil)`에 묶여 있어 nil 순간이 시트를 닫는다. `pendingWalkHandoff`는 소거(옛 목적지의 제안).
- 승차 중 전환도 허용한다: 새 경로는 현재 위치 기준이라 첫 leg부터 대기 국면으로 시작한다. "타고 있던 차량에서 이어가기" 같은 정합 추정은 하지 않는다(추정 오류가 더 위험, 대기 국면의 기존 탈출구 "이미 탔습니다"가 그 역할).

## 5. 폼 동기화·가드 통과 (도보·자동차 확정 시, 대중교통 후보 선택 시)

1. `DirectionsModel.setEndpoint(newDest, for: .to)` — 최근 목록 기록은 이 경로가 담당(이중 기록 금지).
2. 기존 가드 `.onChange(of: model.endpoint(for: .to)) → stopBecauseDestinationChanged()`는 **안내 주도 변경 1회에 한해 통과**시킨다: `DirectionsModel`에 소비형 플래그(예: `consumeGuidanceInitiatedEndpointChange()`)를 두고 onChange 핸들러가 먼저 소비 시도 → 참이면 중지 생략. 플래그는 setEndpoint 직전에 세우고 onChange에서 반드시 소비된다(1회성 — 이후 사용자 수동 변경은 종전대로 중지).
3. **무통지 재조회**: `performQuery`를 통지 억제 모드로 실행(완료 합산 통지·포커스 이동 생략). 결과는 시트 뒤 화면을 최신화할 뿐이다. 재조회 실패는 조용히 결과 없음 상태로 남긴다(시트를 닫고 조회 버튼을 누르면 복구 — 기존 화면 계약).
4. **검색 시트가 열린 동안만** 통지·톤을 억제한다(`beacon.outputSuppressed` 기존 계약 — 받아쓰기 전사 오염 방지. 대중교통 세션에 동형 억제 수단이 없으면 신설한다). 후보 목록(마이크 없음)과 장소 상세 시트에는 걸지 않는다 — 안내 신호는 안전 계층이라 필요 최소 구간만 끈다(§2).

## 6. 불변식 정리

- **확정 단위**: 도보·자동차 = 목적지 선택 1탭. 대중교통 = 목적지 선택 + 경로 선택 2탭. 확정 전에는 세션·폼·최근 목록 어느 것도 변하지 않고, 확정 시 셋이 한 번에 바뀐다.
- **세션 무단절**: 확정 경로에서 `isTracking`(비콘)·`state != nil`(대중교통)이 false를 스치지 않는다 — 시트 presentation이 그 값에 묶여 있다.
- **가드 통과는 1회 소비형**: 안내 주도 변경만 통과하고, 소비 후엔 원래 가드로 복귀한다.
- **stale 응답 폐기**: 목적지 전환 조회·사이드 채널 후보 조회·기존 재조회 모두 latest-wins 토큰(기존 `rerouteToken`·`routeFetchToken` 기계 확장).
- **실패 시 정직**: 경로 실패 = 간략 폴백(도보·자동차) / 3-state 표시 + 취소 출구(대중교통). 옛 목적지로 몰래 되돌리지 않는다.

## 7. i18n

신규 키(전 로케일, 웹 messages → xcstrings 파이프라인): 메뉴 항목 2, 목적지 변경 통지 1, 대중교통 후보 섹션 헤딩·진행·0건·취소 라벨. 통지 문장은 완성 문장 조립(슬롯 조립 금지 — `spoken-guidance-is-prose-not-slots`).

## 8. 검증

- **단위**: 확정 단위 불변식(가드 1회 소비, 취소 시 무변화), `changeDestination`의 상태 교체(기존 reroute 테스트 계열 확장), 최소 Place 변환.
- **빌드 게이트**: 시뮬레이터 빌드 + 기존 스위트 통과.
- **실기기 VoiceOver 판정 항목**:
  1. 헤딩+팝업 버튼 조합 낭독·헤딩 로터 포함 여부(어색하면 §1 폴백).
  2. 목적지 전환 후 `.high` 통지 도달 + 중지 버튼 착지.
  3. 대중교통 후보 목록 첫 후보 착지·선택 후 시트 연속성.
  4. 어제 시나리오 재현: 도보 안내 중 오아시스마켓으로 전환 → 끊김 없는 재개(실보행).
