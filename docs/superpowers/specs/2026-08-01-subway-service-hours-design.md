# 지하철 구간 운행 시간 판정 설계 (2026-08-01)

> 백로그 A1. 선행 스펙 `2026-08-01-odsay-service-hours-design.md`(버스 판)의 나머지 절반이다. 그 스펙이 만든 계층(순수 판정 모듈·강등 정렬·낭독 문구·웹/iOS/CLI 표기)을 **무변경으로 재사용**하고 지하철 조인 소스만 더한다.

## 1. 문제

ODsay는 출발 시각 파라미터가 없어 심야에도 주간 노선을 추천한다(2026-08-01 03:58 실측, 6개 대안 전량 운행 밖). 이를 2026-08-01에 수정했으나 판정은 **버스 구간만** 커버한다.

남은 구멍: **지하철 구간은 판정 대상이 아니다.** `annotateServiceStatus`가 `leg.mode !== "bus"`를 그대로 통과시키고, 경로 rank 산출도 "판정된 leg가 없으면 rank 0"이라 **지하철만으로 구성된 경로는 심야에 최상단에 그대로 남는다.** 국내 도시철도는 대략 01시~05시 미운행이므로 그 시간대에 확실히 탈 수 없는 경로를 1순위로 추천하고 있다.

시각장애 사용자는 화면에서 "이건 첫차 시각이네"를 알아챌 수 없다. 3-state 불변식("운행 중" ≠ "정보 없음" ≠ "운행 밖")의 직접 위반이다.

## 2. 사전 실호출로 확정한 계약 (추측 0)

설계를 가르는 미확정 4건을 구현 착수 전에 실호출로 닫았다.

### 2-A. ODsay는 방향을 준다 — `wayCode`

지하철 `subPath`의 실제 키(길동→강남 15경로 수집): `trafficType, distance, sectionTime, stationCount, lane, intervalTime, startName, startX, startY, endName, endX, endY, way, wayCode, door, startID, endID, startExitNo, startExitX, startExitY, endExitNo, endExitX, endExitY, passStopList`.

`wayCode` ↔ TAGO `upDownTypeCode` 대응을 **양방향 실측 2건**으로 확정했다.

| 구간 | ODsay | TAGO 상행(U) 종착 | TAGO 하행(D) 종착 | 판정 |
|---|---|---|---|---|
| 길동→천호 (5호선, 서쪽) | `wayCode:1` | 강동·애오개·**방화**(서) | 하남검단산·상일동(동) | **1 = U** |
| 천호→잠실 (8호선, 남쪽) | `wayCode:2` | 구리(북) | **모란·가락시장**(남) | **2 = D** |

⚠ `way` 필드는 방면 종착역이 아니라 **그 구간의 하차역**과 같은 값이었다(`endName`과 동일). 방향 판별에 쓰면 안 된다.

### 2-B. 노선명 표기가 양쪽에서 다르고, 인천만 예외다

| ODsay `lane[0].name` | TAGO `subwayRouteName` |
|---|---|
| 수도권 1·2·4·5·7·8·9호선 | `1호선`…`9호선` |
| `수도권 수인.분당선` | `수인분당` |
| `수도권 신분당선` | `신분당` |
| `수도권 공항철도` | `공항` |
| `부산 1·2·3호선` / `대구 1·2호선` / `광주 1호선` | `1호선`·`2호선`·`3호선` |
| **`인천 1호선` / `인천 2호선`** | **`인천1호선` / `인천2호선`** |

즉 ODsay는 항상 `"<지역> <노선>"`인데, TAGO는 **인천만 노선명에 지역을 유지**하고 나머지 지역은 뗀다.

⚠ 그래서 "선행 지역 토큰을 무조건 제거"하면 **부평에서 깨진다**. 부평은 수도권 1호선과 인천1호선의 환승역이고 TAGO 검색은 둘 다 반환한다. 지역을 떼면 ODsay `인천 1호선`이 `1호선`이 되어 두 후보 모두에 걸린다.

**규칙(순서 있는 2단계)**: 지역을 **유지한** 변형으로 먼저 맞춰 보고, 0건일 때만 지역을 **제거한** 변형으로 재시도한다. "제거"는 **첫 공백 앞 토큰 하나만** 떼는 것이고 노선명 본체는 건드리지 않는다(`수도권 공항철도`→`공항철도`, `수도권 신분당선`→`신분당선`). 지역 목록을 매핑표로 고정하지 않으므로 표에 없는 지역도 그대로 동작한다(`대전 1호선`→1단계 `대전1` 0건→2단계 `1호선` 적중). 공백이 없는 이름은 2단계가 없어 1단계 결과가 곧 최종이다.

| 사례 | 1단계(지역 유지) | 2단계(지역 제거) | 결과 |
|---|---|---|---|
| `인천 1호선` @부평 | 코어 `인천1` → `인천1호선` 적중 | (미실행) | 인천1호선 ✓ |
| `수도권 1호선` @부평 | 코어 `수도권1` → 0건 | 코어 `1` → `1호선`만 적중 | 1호선 ✓ |
| `부산 2호선` @서면 | 코어 `부산2` → 0건 | 코어 `2` → `2호선` | ✓ |

2단계에서 `1`이 `인천1호선`에 오매칭되지 않는 것은 기존 `lineHintMatches`의 **숫자 코어 완전 일치** 규칙 덕이다(`"11".startsWith("1")` 오매칭 방지용으로 이미 있던 가드가 여기서 그대로 작동한다).

### 2-C. 동명이역 교차도시 충돌은 존재한다 — 판정하지 않는다

TAGO 역 검색 응답 필드는 `subwayStationId`·`subwayStationName`·`subwayRouteName` 셋뿐이라 도시 정보가 없다. 실측 충돌: **부산 `시청(연제)` 1호선**과 **대전 `시청` 1호선**은 괄호 제거 후 이름이 같고 노선명도 같다.

`subwayStationId` 접두어(`MTRS`=수도권, `MTRBS`=부산, `MTRDG`=대구, `MTRDJ`=대전, `MTRGJ`=광주, `MTRICI`=인천…)가 도시를 담고 있어 ODsay `subwayCityCode`와 매핑하면 가를 수 있으나, **수도권만 운영사별로 접두어가 여러 개**(`MTRS`·`MTRIC`·`MTRDX`·`MTREVE`·`MTRGMG`·`MTRGXA`·`MTRARA`·`MTRKRK`…)라 매핑표가 커지고 실측 없이 채우면 거짓 판정을 낳는다.

**결정: 후보가 2건 이상이면 판정하지 않고 `unknown`.** 틀린 답보다 "정보 없음"이 정직하고, `unknown`은 rank 1이라 `running`과 `outside` 사이 중립 위치에 놓인다. 지방 커버리지 요구가 생기면 그때 접두어 맵을 실측으로 추가한다(버스의 `TAGO_CITY_CODE`가 검증된 3개 지역만 담은 것과 같은 규율).

### 2-D. 호출 비용은 제한적이다

`normalizeOdsayRoute`가 `paths.slice(0, 3)`으로 경로를 3개까지만 취한다. 경로당 지하철 구간은 환승 포함 최대 3~4개이므로 (승차역·노선·방향) 중복 제거 후 보통 3~6건이다. 건당 TAGO 2회(키워드 검색 + 시간표)이고 **둘 다 `revalidate: 86400`** 이라 같은 역·방향 재조회는 하루 1회로 수렴한다. 공휴일 판정은 요청당 1회 공유(기존 캐시 재사용). TAGO 개발 쿼터 일 10,000건 대비 여유.

최악값은 요청당 24회(3경로 × 4구간 × 2호출)다. 도달하지 않을 값이지만 방어로 **ref 상한 12건**을 둔다. 상한을 넘긴 구간은 `unknown`으로 떨어지므로 조용한 절단이 아니라 정직한 미판정이다.

## 3. 설계

### 3-1. 데이터 흐름

```
ODsay subPath(trafficType=1)
  → TransitLeg{ mode:"subway", fromName, lineName, serviceWayCode }   ← wayCode 투영 추가
  → fetchSubwayServiceHoursMap(refs)                                   ← 신설
        키워드 검색(역명) → pickTimetableStation(2단계 노선 매칭·모호=null)
        → 시간표 조회(upDownTypeCode = wayCode 1?"U":"D")
        → deriveFirstLast → ServiceHours{firstMinutes,lastMinutes}
  → annotateServiceStatus(result, busHours, subwayHours, now)          ← 지하철 분기 추가
  → 기존 강등 정렬·낭독·표기 계층 (무변경)
```

### 3-2. 신설 모듈 `src/lib/providers/subway-service-hours.ts`

버스 판(`bus-service-hours.ts`)과 동형으로 만든다. **불변식: 이 모듈은 절대 throw하지 않는다.** 운행시간은 부가 정보이고, 조회 실패가 길찾기 응답을 죽이면 결함을 고치려다 더 큰 회귀가 된다. 실패한 구간은 Map에서 빠지고 호출부가 `unknown`으로 읽는다.

```ts
export interface SubwayLegRef {
  stationName: string;  // ODsay startName (승차역)
  lineName: string;     // ODsay lane[0].name ("수도권 5호선")
  wayCode: number;      // 1=상행(U), 2=하행(D)
}

/** Map 키. leg 쪽과 조회 쪽이 같은 함수를 써야 조인이 어긋나지 않는다. */
export function subwayHoursKey(ref: SubwayLegRef): string;

/** 순수: 키워드 검색 결과에서 이 구간의 역을 고른다. 0건·모호(2건 이상)는 null. */
export function pickTimetableStation(
  candidates: Array<{ id: string; name: string; routeName: string }>,
  stationName: string,
  odsayLineName: string,
): { id: string } | null;

export async function fetchSubwayServiceHoursMap(
  refs: SubwayLegRef[],
): Promise<Map<string, ServiceHours>>;
```

**역명 매칭은 정규화 후 완전 일치만 인정한다.** TAGO 키워드 검색은 포함 검색이라 `서울`이 `서울역`·`서울대입구`·`서울숲`을 모두 돌려준다. `normalizeStationName`(괄호 부가명·후행 노선 토큰·`역`/`station` 접미 제거 + 소문자)을 **양쪽에 적용**한 뒤 `===`로만 거른다 — 부분 일치를 쓰면 같은 노선의 다른 역 시간표를 조인한다. 노선 매칭은 이 필터를 통과한 후보에만 적용한다.

**승차역 기준이 정답이다.** 버스는 첫차·막차가 차고지 출발 시각이라 막차 직후 중간 정류장이 보수적으로 `outside`가 되는 비대칭 한계가 있었다(백로그 A2, 수용). 지하철 시간표는 **역별 발차 시각**이라 그 한계가 구조적으로 없다.

`deriveFirstLast`가 돌려주는 `time`은 `"HH:MM"`(콜론 포함)이고 `parseServiceTime`은 숫자만 받는다. 호출부에서 콜론을 떼어 넘긴다(공유 파서의 계약을 넓히지 않는다 — 넓히면 `"1a2b"` 같은 오염 문자열도 통과한다).

### 3-4. 판정 대상 leg는 반드시 상태를 갖는다 (선재 결함 동반 수정)

현행 배선은 조인 키가 없는 leg를 **상태 없이 통과**시킨다:

```ts
if (leg.mode !== "bus" || !leg.serviceRouteId) return leg;   // serviceStatus 미부여
```

`routeRank`는 `serviceStatus != null`인 leg만 세고 하나도 없으면 rank 0(최상단)을 준다. 따라서 **`serviceRouteId`가 없는 버스 구간 하나로만 이루어진 경로는 판정 불가인데도 `running` 경로와 같은 최상단에 놓인다.** 이미 존재하는 구멍이고, 지하철을 얹으면 `serviceWayCode`·`lineName` 결측으로 같은 경로가 하나 더 생긴다.

**규칙: `mode`가 `bus`·`subway`면 조인 키 유무와 무관하게 항상 `running | outside | unknown` 중 하나를 부여한다.** 조인 키가 없으면 `unknown`이다. rank 0 가드는 "판정 대상 leg가 0개", 즉 **도보 전용 경로에만** 남는다.

실측상 ODsay 지하철 구간 53건 전량이 `lane` 1개·`wayCode` 1 또는 2를 갖지만(2026-08-01, 5개 구간 수집), 결측을 관측하지 못한 것이 결측이 없다는 증명은 아니므로 결측 경로를 상태로 흡수한다.

### 3-4-1. rank 의미 변화 (의도적)

현행 주석: "버스 leg가 없는 경로(지하철·도보 전용)는 판정 대상이 아니라 rank 0을 준다." 이 규칙은 지하철이 판정 대상이 아니던 시절의 것이므로 갱신한다.

- 지하철 구간이 `outside`면 그 경로는 rank 2로 강등된다. **이것이 이 마일스톤의 목적이다.**
- 지하철 구간이 `unknown`(미커버·모호·조회 실패)이면 rank 1이 되어, 판정에 성공한 `running` 버스 경로보다 **한 단계 뒤로 밀린다**. 종전에는 rank 0이었으므로 행동 변화다. 수용 근거: ① `running > unknown` 서열은 이미 확립된 설계이고 버스도 동일 취급을 받는다 ② 강등이지 제외가 아니라 사용자는 여전히 그 경로를 본다 ③ 안정 정렬이라 같은 rank 안에서는 ODsay 추천순이 보존된다.
- 도보 전용 경로는 판정된 leg가 0이라 rank 0을 유지한다(기존 가드 그대로).

### 3-5. 3-state 대응표

| 상황 | serviceStatus | 낭독 |
|---|---|---|
| 시간표 조회 성공 + 현재 운행 구간 안 | `running` | 침묵 |
| 시간표 조회 성공 + 구간 밖 | `outside` | "첫차 HH:MM, 막차 HH:MM, 지금은 운행하지 않습니다" |
| 역 미커버 / 후보 모호 / 조회 실패 / 유효 행 0 | `unknown` | 침묵 |

`unknown`을 `outside`로 뭉개지 않는다 — 조회 실패를 결함으로 단정하면 멀쩡한 경로가 강등된다.

## 4. 테스트 계약

**순수(node-env, fixture)**
1. `pickTimetableStation`: 인천 1호선 @부평 → 인천1호선 선택(1단계 적중) / 수도권 1호선 @부평 → 1호선 선택(2단계 폴백) / 부산 2호선 @서면 / 수인.분당선 ↔ 수인분당 / 이름 불일치 0건 → null / 시청 충돌(2건) → null
2. `subwayHoursKey`: 같은 ref는 같은 키, 방향이 다르면 다른 키
3. `annotateServiceStatus`: 지하철 `outside` 경로 강등 / 지하철 `unknown`이 `running` 버스 뒤 / 도보 전용 rank 0 유지 / 버스·지하철 혼합 경로는 최댓값 채택 / 안정 정렬로 동순위 원순서 보존
4. `lineHintMatches`: 구분자 제거 후에도 기존 케이스(양평 5호선 vs 경의중앙, 1호선 vs 11호선) 불변

## 5. 스코프 밖

- **경전철·GTX·광역철도 전 노선 커버 보장**: TAGO SubwayInfo 수록 범위에 종속. 미수록은 `unknown`(침묵)으로 정직하게 떨어진다.
- **교차도시 동명이역 판정**: §2-C 결정대로 `unknown`. 접두어 맵은 요구가 생길 때 실측으로.
- **A2(버스 차고지 기준 오강등)**: 지하철엔 해당 없음. 버스 쪽은 백로그 동결 유지.
- **혼잡도(E2)**: 별건. 이 마일스톤에 끼우지 않는다.
- **분기 노선의 행선지별 막차**: 5호선처럼 하행이 상일동행·마천행으로 갈리면 "그 역 그 방향 막차"가 사용자가 가려는 지선의 막차보다 늦을 수 있다. 이 경우 판정은 낙관적으로 기운다(운행 밖인데 `running`). **오강등이 아니라 놓침**이라 기존 서열을 해치지 않고, 정확히 하려면 `passStopList`와 시간표 종착역 대조가 필요해 별도 스코프로 둔다. 버스 A2(차고지 기준 오강등)와 방향이 반대인 알려진 한계다.

## 7. 실호출 게이트가 잡은 선재 결함 — 토요일 다이어 부재

fixture 1,309건이 전부 green인 상태에서 실호출이 **조인 전멸**을 잡았다. 원인은 조인이 아니라 요일 코드였다.

| 역·노선 | `01`(평일) | `02`(토요일) | `03`(휴일) |
|---|---|---|---|
| 길동 5호선 | 103행 | **0행** | 81행 |
| 잠실 2호선 | 240행 | **0행** | 197행 |
| 서면 부산1호선 | 175행 | 164행 | 158행 |

수도권 운영사는 **토요일 다이어를 따로 제출하지 않는다**(`resultCode 00` + `totalCount 0`, 오류가 아니라 정상 응답의 빈 결과). 부산은 제출한다. 지역별로 갈리므로 일괄 폴백도, 일괄 포기도 옳지 않다.

**이 결함은 지하철 판정만의 문제가 아니었다.** 역 상세 첫차·막차(`fetchStationTimetable`, 2026-07-22 출시)가 같은 매핑을 써서 **매주 토요일 수도권에서 섹션이 통째로 사라지고 있었다**. 0행 → `deriveFirstLast` null → 방향 생략 → `lines: []` → 미노출이라 조용히 죽었다.

**조치**: `02` 빈 결과일 때만 `03`으로 한 번 재조회한다. 추측이 아니라 소거법이다 — 데이터셋이 갖는 다이어가 `01`·`03`뿐이고 토요일은 평일이 아니므로 남는 후보가 하나다.

**⚠ 폴백의 결정 단위가 소비자마다 다르다 (코드 리뷰 검출, 실측 확정)**

| 소비자 | 단위 | 근거 |
|---|---|---|
| 경로 운행시간 판정 (`fetchScheduleRows`) | **구간**(역·노선·방향 하나) | 한 판정에 다이어가 섞일 수 없다 |
| 역 상세 시간표 (`fetchStationTimetable`) | **역**(2패스) | 여러 노선을 기준 라벨 **하나로 묶어** 표기하므로, 노선마다 다른 다이어를 섞으면 그 라벨이 거짓이 된다 |

혼합 사업자 환승역이 실재한다 — **대저역은 부산3호선이 토요일 150행인데 부산김해경전철은 0행**이다(실호출 2026-08-01). 구간 단위로 폴백하면 "토요일 기준" 라벨 아래 김해경전철의 휴일 값이 섞인다. 그래서 역 상세는 **한 노선이라도 토요일에 답하면 폴백하지 않고**, 답하지 못한 노선은 휴일 값으로 메우지 않고 미노출로 빠진다(확정할 수 없으면 보여주지 않는다).

**정직성**: 역 단위 폴백이 발동하면 `dailyType`을 실제로 답한 다이어(`sunday`)로 보고한다. 토요일에 "일요일·공휴일 기준"이 표시되는 것은 어색하지만 참이고, "토요일 기준"이라 쓰는 것은 거짓이다. 평일 대비 휴일 다이어는 첫차가 같고 막차만 이르다(길동 5호선 상행 00:38→00:00).
