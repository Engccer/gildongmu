# 이탈 중 "경로 다시 조회" 버튼은 자동 판정이 손을 든 자리에서만 (E69)

- 판정 정본: `docs/BACKLOG.md` E69(위원장 판정 2026-10-07, 재논의 금지). 통지 문안은 2026-10-17 위원장 판정.
- 범위: 웹(`useRouteGuide`·`DistanceBeacon`) · iOS(`BeaconModel`·`BeaconTrackingSheet`) · 안드로이드(`WalkGuideModel`·`GuideSheet`). 리듀서(`route-guide.ts` ↔ `RouteGuide.swift` ↔ `RouteGuide.kt`)는 바꾸지 않는다.
- 설계 리뷰 판정: 생략. 새 판정 계층이 아니라 기존 판정(자동 조회 결말·예산·`GuideFix.stopped`)을 읽는 표시 상태 래치 하나이고, 서버·저장 포맷·개인정보에 닿지 않는다. 구현 리뷰(spec·quality·a11y)로 충분하다.

## 1. 노출 조건

버튼은 `offRoute` ∧ **이 회차의 래치**가 섰을 때만 보인다. 래치는 아래 셋 중 하나가 서면 켜지고, 이탈 회차가 새로 시작될 때(`offRoute(notice: confirm)`)와 세션 정리에서만 꺼진다. 복귀·채택으로 `offRoute`가 풀리면 버튼은 지금처럼 사라진다.

| | 조건 | 판정 자리 |
|---|---|---|
| ⓐ | 이 회차의 자동 조회가 **실패·경로 없음·신선도 미달**로 끝났다 | 자동 조회 함수의 세 결말(토큰·이탈 지속 가드를 통과한 뒤의 결말만. 폐기된 조회는 세지 않는다) |
| ⓑ | 자동 조회 요청을 **세션 예산 5회 소진**으로 무시했다 | 조회 트리거의 `budget` 사유(`RerouteProposalGate.mayFetch`) |
| ⓒ | 벗어난 채 **30초 이상 서 있다** | `GuideFix.stopped`의 연속 시간(`RerouteProposalGate.stillStep`, 웹·Kit·`:kit` 미러) |

- 돌아가는 중(다가감·멀어짐·나란히 계수 진행 중)에는 래치가 서지 않는다. ⓐⓑ는 자동 조회가 끝난 결말에서만 서고, ⓒ는 조회 진행과 무관하다(조회가 30초 넘게 걸리는 동안 서 있는 사람에게는 버튼이 서도 된다).
- ⓑ는 "예산이 0이다"가 아니라 "예산 때문에 요청을 무시했다"다. 예산이 바닥난 뒤 새 회차가 시작돼도 돌아가는 동안은 버튼이 없고, 리듀서가 새 경로가 필요하다고 판정하는 순간(`rerouteNeeded`) 선다. 그 순간이 "앱이 판정했는데 실행할 수 없다"는 자리다.
- **래치는 회차 안에서 내리지 않는다.** ⓒ로 선 버튼은 사용자가 다시 걷기 시작해도 남는다. 버튼이 사라지면 그 버튼에 커서를 둔 스크린 리더 사용자가 맥락을 잃는다(헌장 §5: 포커스를 쥔 요소를 제거하는 전이). 회차 안에서 버튼이 사라지는 전이는 복귀·채택(`offRoute` 해제) 하나뿐이다. 예외는 웹의 uncertain 구간이다(§3, 현행): 표시 상태가 리듀서 국면이라 숨었다가 다시 서고, 그 버튼에 포커스가 있었으면 종전대로 시작·중지 토글로 옮긴다(`DistanceBeacon` 레이아웃 이펙트).
- 수동 재조회가 실패해도 버튼은 남는다(래치가 이미 섰다).

### 1.1 ⓒ 정지 판정

새 정지 판정을 만들지 않는다. 리듀서에 넣는 `GuideFix.stopped`(iOS `motionStep` `.stopped`, E55 3-state)를 그대로 쓰고 **`speedUnknown`은 정지가 아니다**(연속을 끊는다). 연속 시작 시각은 정지 fix에서 비어 있으면 그 fix 시각으로 놓고, 정지가 아닌 fix에서 비운다. 연속 시간이 N초 이상인 fix에서 래치가 선다. **리듀서 국면이 돌아가기(`offRoute`)인 fix만 센다**: uncertain·reacquiring(정확도 악화·공백) fix에서는 연속을 비운다. 끊긴 시간이 정지로 산입되면 관측 없이 30초가 찬다(E63 §3.9의 "시간이 쌓이는 필드" 규칙과 같은 이유). 세 플랫폼이 같다.

### 1.2 N = 30초 (착수 기본값, 실보행 판정 항목)

실험판 `guide-diag` 로그(2026-08-09 ~ 10-11, 23개 파일)의 이탈 국면 fix에서 정지 연속 구간을 재려 했으나 **잴 수 없었다**.

- E55(도플러 3-state) 이전 로그의 `motion=`은 지금의 `stopped`와 뜻이 다르다(08-24 표본: 속도 0.00인데 `moving`·`speedUnknown`이 번갈아 찍힌다).
- E63(2026-10-03) 이전에는 이탈 확정 즉시 재조회가 채택돼 이탈 국면이 수 초로 끝났다. 정지 구간이 국면 끝에서 잘린다.
- E63 이후(10-04~10-07) 이탈 국면 fix의 `stopped`는 7개, 가장 긴 연속이 5초다.

그래서 기본값 30초다. E63 §3.5 자동 발동 중앙(52초)보다 짧고, 길 건너 신호 대기(대개 30초 안쪽에서 끝나거나 그보다 길면 손을 들 자리)보다 길게 둔다. 실보행 판정 항목: ① 30초가 "길을 잃어 멈춘 사람"에게 늦지 않은가 ② 신호 대기에서 버튼이 섰다가 걸어가도 남는 것(§1 래치)이 거슬리지 않는가 ③ 서 있을 때 `speedUnknown`이 섞여 연속이 자꾸 끊기지 않는가(10-05 표본은 `speedUnknown`이 `stopped`보다 많다 — 끊기면 ⓒ가 사실상 서지 않는다) ④ 말없이 선 버튼을 스크린 리더로 찾았는가(시트를 이미 훑은 사람은 다시 처음부터 넘기지 않으면 모른다 — 못 찾으면 후보: 문장 없는 톤 하나, 다음 재통지 문장에 얹기, 위원장 판정).

## 2. 버튼이 나타나는 순간의 통지

- **ⓐⓑ: 한 문장, "새 경로를 자동으로 찾지 못했습니다."**(키 `guide.rerouteAutoGaveUp`, 위원장 판정 2026-10-17). ⓐ나 ⓑ가 서는 순간 말한다. 지금까지 자동 조회 실패는 침묵이었고, 그 침묵은 정상 대기와 고장을 구분하지 못한다.
- **ⓒ: 침묵.** 멈춘 사람에게 말을 더하지 않는다.
- 문장은 회차에 한 번이다(재무장으로 실패가 되풀이돼도). "말했음" 표식은 버튼 래치와 따로 둔다: ⓒ로 버튼이 먼저 조용히 섰어도 뒤이은 ⓐⓑ는 한 번 말하고, iOS·안드로이드는 문장이 버려지면(받아쓰기 억제·백그라운드 음성 끔·뒤 통지에 밀림, `onDropped`) 표식을 되돌려 다음 ⓐⓑ에서 다시 말한다(1회성 통지는 전달된 시점에 래치). 웹은 버림 신호가 없어 게시 시점에 래치한다.
- 포커스는 옮기지 않는다(E57 착지 계약 밖). 통지는 각 플랫폼의 기존 단일 창구(웹 `announce` polite, iOS `announce` 기본 우선순위, 안드로이드 `announce`)를 지난다. 상태 행(`statusText`)은 바꾸지 않는다 — 윗줄은 리듀서가 소유하는 이탈 문장(벗어난 쪽)이 그대로다.
- 분류는 `.actionable`: 돌아갈지 다시 조회할지를 사용자가 정해야 하는 문장이라 백그라운드 음성 토글이 켜져 있으면 말한다(E53).
- **운전자 채널(iOS)**: 버튼 규칙은 같다(확정 즉시 조회가 실패·경로 없음·신선도 미달·예산으로 끝난 뒤에만). ⓒ는 적용하지 않고 통지도 하지 않는다 — 운전 중 화면을 누르라는 권유가 되고, 운전자 채널은 GPS 상태를 말하지 않는다(`BeaconModel`의 `uncertainEnter` 운전자 침묵과 같은 계열).

## 3. 플랫폼 자리

| | 표시 상태 | ⓐ | ⓑ | ⓒ |
|---|---|---|---|---|
| 웹 | `useRouteGuide`의 `rerouteGaveUp` 상태, API `showReroute = offRoute ∧ rerouteGaveUp` | `autoReroute`의 세 결말 | `autoReroute`의 `mayFetchReroute` 거짓 | `stepDetail`(이탈 국면 fix) |
| iOS | `BeaconModel.rerouteGaveUp`, `showsRerouteButton` | `fetchProposal`의 none·stale·실패 | `maybeFetchProposal` → `"budget"` | `handleDetail`(이탈 국면 fix) |
| 안드로이드 | `WalkGuideUiState.rerouteGaveUp`, 시트 행 조건 | `fetchProposal`의 none·stale·실패 | `maybeFetchProposal` → `"budget"` | 리듀서 호출 자리(이탈 국면 fix) |

- 웹은 이탈 국면 표시 상태가 리듀서 국면(`phase === "offRoute"`)이라 uncertain 동안 버튼이 숨는다(현행). 래치는 회차 상태라 uncertain을 넘어 잇는다.
- 시트 착지 판정의 행 존재 사본(iOS `rowExists(.reroute)`, 안드로이드 `SheetRow.reroute`)도 같은 조건으로 바꾼다.
- 진단 로그: 래치가 서는 순간 `rerouteButton cause=failed|none|stale|budget|still` 한 줄(iOS·안드로이드 `GuideDiag`).

## 4. 하위 호환

서버·경로 응답·저장 값이 그대로다. 문장 키 하나가 늘고 앱 번들에 빌드 시점에 굳는다. 스토어 2.1·안드로이드 설치본은 종전대로 이탈 내내 버튼을 보이고, 웹은 배포 즉시 새 규칙이다.
