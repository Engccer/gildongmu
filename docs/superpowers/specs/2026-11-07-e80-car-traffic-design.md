## §0 게이트 결과

- **실호출**(2026-11-07 토 06:45, Tmap 3·카카오 2회): 필드·코드표·채움률은 `gate-a-corpus.md`. 정체 옵션은 같은 호출에 덧붙어 호출 수가 늘지 않고, Tmap 옵션 유무 대조에서 안내 문장·좌표 수가 같았다.
- **약관**(원문 확인, `terms-research.md`): 두 회사 모두 **음성 낭독(TTS) 금지 조항 없음** — Google Places 선례 같은 조항이 없어 멈추지 않는다. 저장은 Tmap "저장 후 24시간 이상 사용 금지"·카카오 "목적 외 캐시 금지"로 no-store가 충족한다. **재제공이 가장 위험하다**: Tmap 회원약관 제15조⑧("제3자에게 이용하게 할 수 없습니다")·카카오 운영정책 13호("타인에게 제공하는 행위") — 그래서 CLI·MCP·채팅은 정체를 옵트인하지 않고, 응답에도 provider 원값(구간 index·속도)을 싣지 않고 우리가 요약한 구간만 싣는다. 카카오 "변경·방송" 문언의 회색지대는 통상 앱 이용 해석으로 진행하되 공식 문의는 외부 발신이라 하지 않았다(미결로 남김).

## §1 provider에서 무엇을 받는가

| | Tmap(ko 기본) | 카카오모빌리티(ko 폴백) | NCP(en) |
|---|---|---|---|
| 요청 | 본문에 `trafficInfo: "Y"` | `road_details=true` | 없음 |
| 원천 | LineString `geometry.traffic` = `[시작index, 끝index, 혼잡도, 속도]` | `sections[].roads[]`의 `traffic_state`·`distance`·`vertexes`·`name` | — |
| 정체로 읽는 코드 | **4 정체, 3 지체(문서상 폐기)** | **1 정체, 2 지체** | — |
| 읽지 않는 코드 | 1 원활, 2 서행, 0 정보없음 | 4 원활, 3 서행, 0 정보 없음, 6 교통사고(관측 0, 아래) | — |
| 추가 호출 | 0(같은 호출에 덧붙음, 대조 호출로 안내 문장·좌표 수 불변 확인) | 0 | — |

⚠ **두 provider의 숫자 방향이 반대다**(Tmap은 클수록, 카카오는 작을수록 막힘). 코드표는 provider 파일 안에서만 읽고, 밖으로는 등급 낱말만 나간다.

- **서행은 읽지 않는다**: 토요일 06:45 표본에서도 서행이 경로 절반을 덮었다(gate-a-corpus). 매번 나오는 말은 행동을 가르지 않는다.
- **카카오 6(교통사고·통행 불가)은 정체로 친다**(리뷰 반영): 관측 0건이지만 정보 없음으로 접으면 그 구간이 「막히는 곳 없음」의 근거가 된다. 통행 불가는 정체보다 나쁘다.
- `0 정보없음` 조각이 섞여도 나머지로 판정하되, **교통 정보가 있는 길이가 경로 총거리의 80%(`CONGESTION_MIN_COVERAGE`) 미만이면 "정보 없음"**이다(설계·접근성 리뷰 수렴: 짧은 한 조각만 원활이어도 「없습니다」로 단정하면 정보 없음과 정체 없음이 섞인다). 분모는 조각 합이 아니라 총거리다 — Tmap은 정보 없는 LineString에 조각을 만들지 않는다. 실호출 표본은 98.9~100%(06:45 corpus 4건을 `tmapCongestionPieces`·`kakaoCongestionPieces`로 재계산 — 카카오 강남→서울역 98.9%, 나머지 100%), 07:30 재실행에서 null로 접힌 응답 0.

## §2 응답 계약 (옵트인, additive)

`/api/route/car`에 옵트인 `traffic=1`(누락 또는 정확히 `"1"`만, 그 외 400 — `includeGeometry` 동형). 미지정 응답은 **byte 불변**(요청 본문에도 `trafficInfo`·`road_details=true`를 싣지 않는다). 옵트인일 때만 응답에 `congestion`이 붙는다:

```ts
congestion: { jams: CarJam[] } | null   // null = 정보 없음
interface CarJam {
  road: string | null;     // 구간 안 가장 긴 이름 있는 도로(Tmap "일반도로"·빈 이름은 null)
  startMeters: number;     // 경로 출발점에서 정체 시작까지(m, 정수)
  lengthMeters: number;    // 정체 길이(m, 정수)
  start: Coord; end: Coord;// 정체 시작·끝 좌표(주행 중 판정이 안내 경로에 투영)
}
```

3-state:
- **정체 없음** = `{ jams: [] }` (정보는 있는데 문턱을 넘는 정체가 없다)
- **정보 없음** = `null` (provider가 교통 정보를 주지 않았다 — 전부 0, 또는 en NCP 경로)
- **조회 실패** = 종전 502(경로 자체 실패). 정체 해석 실패는 경로를 깨지 않고 `null`로 접는다(경로 안내가 정체 부가정보 때문에 사라지면 안 된다).

en: NCP 경로(`lang=en` + NCP 키 + via·기하 없음)는 `traffic=1`이어도 `congestion: null`. 소비자는 null에 아무 줄도 내지 않는다(침묵). ko 폴백된 en 응답은 정체가 있으면 싣는다.

CLI·MCP·채팅은 옵트인하지 않는다(카탈로그 불변). 웹·iOS 길찾기 결과 화면, 자동차 안내 시작 조회, ETA 재조회만 싣는다.

## §3 정규화 (서버 `src/lib/car-traffic.ts`, 순수)

1. provider 파일이 자기 코드표로 경로를 따라 **연속 조각** `{fromM, toM, jam: boolean, road, from: Coord, to: Coord}`를 만든다(Tmap: LineString 좌표 누적 거리로 index 구간 환산 / 카카오: `roads[].distance` 누적, 좌표는 `vertexes` 첫·끝).
2. 정체 조각을 이어 붙인다: 사이 간격이 `JAM_MERGE_GAP_M`(200m) 이하면 하나로.
3. 길이가 `JAM_MIN_M` 이상인 것만 남긴다. **500m**(위원장 판정 2026-11-07 ③, 200m 병합과 함께 확정) — 6분 재조회 주기·차 속도로 볼 때 그보다 짧은 정체는 1분 안팎이라 행동을 가르지 않는다.
4. 출발 직후 정체(`startMeters` < 50m)도 남긴다 — 출발 전 브리핑엔 의미가 있다.

## §4 출발 전 브리핑 (웹 `CarRouteResult`, iOS `CarRouteRows`)

요약 줄 바로 다음 한 줄(한 접근성 객체, 항목은 쉼표 결합 — 항목이 빈 조각일 수 없어 `joinText` 대신 `join(", ")`). 최대 3곳(`BRIEFING_JAM_MAX`), 나머지는 개수만. 조립은 웹 `car-traffic-text.ts` ↔ iOS `RouteBriefing.swift` 같은 키(키가 문장 정본).

| 상태 | 줄 |
|---|---|
| 정체 1곳 | 「막히는 구간 1곳: 7.4km 앞 올림픽대로 1.1km 구간.」 |
| 정체 여럿 | 「막히는 구간 2곳: 7.4km 앞 올림픽대로 1.1km 구간, 10.5km 앞 청파로 600m 구간.」 |
| 출발 지점 100m(`JAM_FROM_START_M`) 안에서 시작 | 「출발 지점부터 통일로 900m 구간」(「0m 앞」을 피한다) |
| 정체 넷 이상 | 끝에 「, 그 밖에 2곳」 |

| 정보 없음·미요청 | 줄 없음 |

- 거리는 `formatDistance`만 지난다. 이름 없는 구간은 이름 자리를 뺀다(「7.4km 앞 1.1km 구간」).
- **문안은 위원장 확정본**(2026-11-07 TextEdit 왕복, `wording-final-202611070727.md`): 항목 틀 「{거리} 앞 {도로} {길이} 구간」, 「막히는 구간이 없습니다.」와 주행 중 두 문장은 초안 그대로. it `jamMore` 복수형(「un altro」)·ja 항목 안 「、」 제거는 접근성 감사 INFO 반영.
- 비-ko 화면은 도로 이름을 뺀다(영문 원천 없음, `carSpokenLandmark` 관례).

## §5 주행 중 재조회와 새 정체 통지

- 상수: 웹 `CAR_ETA_INTERVAL_MS` 600,000 → **360,000**, `CAR_ETA_CALL_CAP` 6 → **10**, `CAR_ETA_STALE_S` 660 → **420**(주기 + 1분, 같은 산식). iOS는 흩어져 있던 리터럴(타이머 600초·캡 6 두 자리·오래됨 660)을 `BeaconModel.carEtaIntervalSeconds`·`carEtaCallCap`·`carEtaStaleSeconds` 셋으로 모아 동조. 안드로이드는 자동차 실시간 안내 세션이 없어 해당 상수가 없다.
- iOS `RouteService.car`의 `traffic`은 기본값 없는 인자다(결과 화면·안내 조회는 켜고, 그 밖은 끈다를 호출부가 밝힌다).
- 자동차 안내 시작 조회(`includeGeometry=1`)도 `traffic=1`을 싣는다 — 그 응답의 정체가 **이미 아는 정체**의 기준선이다(없으면 첫 재조회가 기존 정체를 전부 "새"로 말한다).
- 재조회(`traffic=1`) 응답의 각 정체에 대해 순수 판정 `newJamsAhead`(웹 `src/lib/car-traffic-ahead.ts` ↔ Kit `CarTrafficAhead.swift`, 공유 fixture `src/lib/__tests__/fixtures/car-jams-ahead-cases.json`):
  1. 시작·끝 좌표를 **지금 안내 중인 경로**에 투영(`projectOnPolyline`, 창 = [현재 진행거리, 끝]). 둘 다 수직거리 ≤ `JAM_ON_ROUTE_M`(40m)이 아니면 버린다 — 재조회가 다른 길을 골랐을 때 그 길의 정체는 내가 지날 구간이 아니다.
  2. 투영 시작이 현재 진행거리보다 앞이 아니면 버린다(지나간 구간).
  3. 이미 아는 정체 구간(투영 구간)과 겹치면 새것이 아니다.
  4. 투영 구간 길이가 정체 길이와 `max(150m, 정체 길이의 25%)` 넘게 어긋나면 버린다(설계 리뷰 M3: 양 끝만 내 경로에 걸린 우회로 정체를 그 도로 이름과 함께 내 앞 정체로 말하지 않는다).
  5. 남은 것 중 **가장 가까운 하나**만 한 문장으로 알리고 **그 하나만** 아는 정체에 더한다 — 먼 새 정체는 다음 재조회(6분 뒤)가 말한다(설계 리뷰 m3: 전부 더하면 먼 것은 영영 말하지 않는다).
  - 아는 정체는 좌표로 보관하고 판정 때마다 지금 경로에 다시 투영한다(재경로 뒤에도 유효).
- **호출부 규칙 넷**(웹 `useRouteGuide.announceNewJam` ↔ iOS `BeaconModel.announceNewCarJam`, 소스 가드 `e80-traffic-wiring-guard.test.ts`):
  1. **정보는 Tmap만 센다**(설계 리뷰 M2): 카카오 폴백 응답은 코드표·경로가 달라 Tmap 기준선과 대조하면 서행을 새 정체로 말한다. 시작 조회가 카카오면 상세 안내 자체가 강등이고, 재조회가 카카오면 판정하지 않는다.
  2. **기준선이 없으면 이번 정보를 말없이 기준선으로**(설계 리뷰 m1): 시작 조회에 정보가 없었으면(아는 정체 = null) 정보가 처음 온 재조회는 말하지 않는다 — 원래 있던 정체를 「새로 생겼습니다」로 말하지 않으려고.
  3. **응답을 기다리는 사이 이탈했으면 말하지 않는다**(코드 리뷰 B5·설계 m2): 이탈 동결은 조회 전에만 걸려 있었다.
  4. **보류 중이거나 말하는 중인 통지가 있으면 밀어내지 않고 건너뛴다**(설계 리뷰 M4·재리뷰 MAJOR-1): 통지 창구는 latest-wins 한 칸이라, 톤 뒤 최대 3초 기다리는 「잠시 후 우회전하세요」·도착 문장을 비동기 정체 문장이 밀어낼 수 있다. iOS는 기기 음성(운전자 채널 `speakGuidance`는 진행 중 발화를 끊는다·백그라운드 대기 칸)도 `GuideSpeechOutput.speechBusy`로 본다. 건너뛴 정체는 아는 정체에 넣지 않아 다음 재조회가 다시 판정한다.
  - **말하지 못하면 되돌린다**(접근성 감사 W1, 「1회성 경고 latch는 발화 성공 시점」): 알린 정체는 통지가 버려지면(iOS `onDropped` — 억제·백그라운드 토글 끔·선점, 웹은 같은 모양으로 단 `announce(text, onDropped)` — 선점·늦은 폐기) 아는 정체에서 빠져 다음 재조회가 다시 말한다. 세션 경계에서는 아는 정체를 먼저 비우므로 되돌림이 불려도 무해하다(iOS는 `advanceGeneration`이 부르지 않고, 웹은 다음 통지 때 불릴 수 있으나 아는 정체가 null(기준선 없음)이라 `?.filter … ?? null`이 null을 그대로 둔다).
- **알려진 한계**(설계 리뷰 M1): 판정 재료가 "지금 위치에서 다시 찾은 경로"라, 길찾기가 새 정체를 피해 다른 길을 고르면 내 경로 위 정체가 응답에 없어 침묵한다. 실호출 게이트 ⓓ(경로 30% 지점 재조회의 정체가 원 경로 위인가, 07:30 1/1 위)와 iOS 로그 `carJams fresh= new= pending=`로 실주행 빈도를 잰 뒤 판정한다(원 경로 위 교통을 따로 묻는 Tmap 호출은 호출량이 늘어 지금은 하지 않는다).
  - 풀린 정체는 알리지 않는다(기본값, 판정 요청). 풀렸다가 다시 생긴 같은 자리는 "아는 정체"라 다시 말하지 않는다.
- 문장(확정): 「3km 앞 올림픽대로에 1.1km 정체가 새로 생겼습니다.」(이름 없으면 「3km 앞에 1.1km 정체가 새로 생겼습니다.」, 비-ko는 이름 없음). 거리는 현재 위치에서 정체 시작까지.
- 통지 창구: 웹 `announce`(톤 뒤 발화 `speechDeferStep` 슬롯), iOS `announce(_:speechClass:onDropped:)` — 분류 `.actionable`(1회성 경고·행동을 가를 수 있는 문장 — 백그라운드 음성 토글이 켜져 있으면 잠금 중에도 말한다). 이탈 국면(`offRoute`)엔 재조회 자체가 동결이고, 응답 뒤에도 다시 본다.
- 웹 재조회는 경유지를 싣지 않는다(설계 리뷰 m6) — 웹 자동차 안내는 경유지 조회에서 열리지 않아(PROGRESS) 해당 경로가 없다. iOS는 싣는다.
- iOS 디코딩은 정체만 관용적이다(설계 리뷰 m7): 정체 형식이 어긋나면 경로는 살리고 `congestion`만 nil(정보 없음).
- 운전자 모드(실험판, iOS만): **새 정체 문장을 싣는다**(위원장 판정 2026-11-07 ⑤ — 기본값과 다름). 스피커 발화는 `post`의 운전자 채널이 맡아 따로 갈래를 두지 않는다. 그 밖의 판정(「없습니다」 줄 둔다·정체 등급 500m·200m 병합·풀린 정체 미통지)은 기본값 그대로 확정.
- 언어: 시작 조회(기하 옵트인)는 모든 언어가 ko 서비스(Tmap)라 기준선이 늘 있다. 재조회는 웹이 `lang`을 싣지 않아(ko 서비스) en 화면도 새 정체를 이름 없이 듣고, iOS는 `lang=en`이면 NCP 경로라 `congestion: null` — iOS en은 주행 중 정체 통지가 없다(en NCP는 침묵이라는 계약 그대로, ETA 원천을 바꾸지 않기 위해 둔 차이).
- 소리 추가 없음(`BeaconTonePlayer` 불변).

## §6 호출량

- 정체 옵션은 같은 호출에 덧붙어 호출 수 0 증가.
- 재조회는 여정당 최대 6 → 10회(시작 조회 포함), 증가분 최대 4회. 주기 10 → 6분이라 1시간 주행 기준 6 → 10회(캡 도달). Tmap 일 1,000건(도보 폴백과 공유)에 대해 여정 하나가 최대 10건.
- `scripts/usage-report.mjs`는 Tmap을 가용성 프로브(보행자 1회)로만 보고 **일 사용량을 보여 주지 않는다**. 일 사용량은 SK open API 콘솔, 호출 분포는 Vercel Observability(`/api/route/car`)로 본다 — 보고서 확장은 별도 항목.

## §7 남은 보정·검증

- 실호출 게이트 `scripts/verify-car-traffic.mjs`는 언제나 실호출이다(Tmap 9·NCP 1회, 무료 쿼터 안 — 저장 응답 재생 모드는 두지 않았다. 결과는 보고 디렉터리 corpus에 남긴다). 2026-11-07 07:30 재실행 20/20.
- 약관 미결(설계 리뷰 m8·코드 리뷰 NIT): `/api/route/car`는 공개 라우트라 누구나 `traffic=1`을 붙일 수 있다. 우리 소비자(CLI·MCP·채팅)는 옵트인하지 않고 provider 원값도 싣지 않지만, 제3자 직접 호출까지 막지는 않는다 — 카카오 「변경·방송」 문언과 함께 공식 문의(외부 발신)가 필요하면 위원장 판정으로.
- 실주행 판정(FIELD-TEST): 새 정체 문장의 빈도·타이밍.
