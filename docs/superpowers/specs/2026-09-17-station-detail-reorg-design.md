# 역 장소 상세 개편 — 순서·시설 접기·역 전화번호·경유역 로터 (iOS)

> 2026-09-17. 계기는 2026-09-16 실승차(마들 → 길동, 실험판) 피드백과 그 로그(`docs/superpowers/specs/logs/README.md` 2026-09-17 행). 선행 수정 `453f3497`(시트로 띄운 장소 상세에 닫기 버튼, 공용 `PlaceDetailSheet`)은 범위 밖이고 끝났다. **iOS 앱 안에서 닫힌다** — 서버 코드 변경 0, 기존 라우트 `/api/places`를 새 자리에서 부를 뿐이다(push 동결 2026-09-22 09:00 KST 안에서 착수 가능).
>
> **설계 리뷰 판정**: 필요 — ②새 외부 계약 가정(카카오 키워드 검색의 지하철역 POI 이름·분류·전화번호 형식). 서브에이전트 적대적 리뷰 1회(실호출 18회) 뒤 개정. 반영 내역 §9.

## 1. 문제

위원장 실사용 피드백(2026-09-17, 요지):

1. 경유역 장소 상세가 **너무 길고 논리적 순서가 없다.** 역 정보 → 역 시설 → 역 주변 순이어야 한다.
2. 엘리베이터·장애인 화장실 등 시설이 **너무 길게 펼쳐진다.** 접어 두고 펼치게 한다.
3. 역 정보 **맨 위에 전화번호**가 와야 한다. 가장 많이 쓸 메뉴다.
4. 지나가는 역 목록에서도 **전화 걸기 등 주요 액션을 로터로** 바로 하고 싶다(검색 탭 장소 결과처럼).
5. 지하철 화면에서 들어간 역 상세에 "근처 지하철"이 있는 것은 논리적으로 모순이다.

현행 코드 사실(2026-09-17 확인):

- `PlaceDetailView` 순서는 장소 종류와 무관하게 [기본 정보(분류·주소·영업시간·전화·홈페이지·물어보기)] → [길찾기] → [이 장소 주변 4종] → [역 섹션(역 정보·실시간 도착·첫차막차·교통약자 시설)] → [무장애 편의시설]. 역 섹션은 `isStation`(분류에 `지하철|전철|철도|기차` 포함 또는 이름이 `역`으로 끝남)이 켠다.
- 이 장소 주변이 역 섹션보다 앞인 근거는 "교통약자 시설이 전부 펼쳐져 수백 행"이었다(`PlaceDetailView.swift` 주석, spec `2026-08-01-ios-place-nearby-design.md` §2-1). **시설을 접으면 그 근거가 사라진다.** 실측 천호역 72행, 군자역 50행.
- 경유역 Place(`transitStopPlace`, id `transit-stop:`)에는 주소·전화가 없고 분류는 합성값 "지하철역"이다.
- 근처 지하철 행을 역에서도 숨기지 않은 근거(2026-08-02 리뷰 판정)는 "근접 2개 역은 새 정보 · 장소마다 구성이 바뀌면 위치 암기가 무너진다"였다. 판정 ④가 **모든 역 상세**에서 빼므로 역 상세끼리는 구성이 같다.

## 3. 역 장소 상세 레이아웃 (판정 ①④⑤)

### 3.1 무엇이 "역 상세"인가 — 좁은 판정 `stationLayoutKind`
`isStation`은 넓다(리뷰 M2 실호출: 분류 `…도로,철도시공`인 업체, `천호역 5호선 5번출구` 출구 POI, 이름이 `역`으로 끝나는 비역 장소가 모두 참). 레이아웃은 별도의 좁은 Kit 순수 판정으로 켠다:

- `.subway` — id가 `transit-stop:`(경유역) **또는** 카카오 분류 경로에 `지하철,전철` 조각이 있고 마지막 조각이 `지하철출구`·`지하철,전철`이 아님(후자는 네이버 병합 역 POI의 뭉개진 분류).
- `.rail` — 분류 경로에 `기차역` 조각이 있음(`기차,철도 > 기차역 > KTX정차역` 등).
- `nil` — 그 밖. **현행 레이아웃 그대로**(현행 `isStation` 기반 역 섹션 로드·위치도 불변 — 판정 ①의 "역이 아닌 장소는 현행 그대로"가 이 분기다).

### 3.2 순서
`stationLayoutKind != nil`인 장소만. 위에서 아래로:

| 순서 | 섹션(제목) | 행 |
|---|---|---|
| 0 | (비-ko 병기 보조 줄)·도메인 섹션 | 현행 그대로(도메인 섹션은 그 화면에 온 이유라 서열 1위 유지) |
| 1 | **역 정보** | ①**전화 줄**(§5.5) ②역 메타 한 줄(현행 `metaLine`, 조회 null이면 없음) ③분류 줄 — `.rail`만(`KTX정차역` 같은 정보가 여기뿐, 리뷰 M2). `.subway`는 없음(합성값이거나 메타 줄 노선과 중복) ④도로명·지번·영문 주소 + 각 복사 ⑤영업시간 ⑥홈페이지 ⑦물어보기 — ④~⑦은 현행 조건 그대로 |
| 2 | 실시간 도착 | 현행 그대로 |
| 3 | 첫차·막차 | 현행 그대로(3-state 포함) |
| 4 | 교통약자 시설(철도) | 현행 4줄 그대로(한 종류 한 줄이라 접지 않는다) |
| 5 | 교통약자 시설(서울 지하철) | **§4 종류별 접기** |
| 6 | 무장애 편의시설 | 현행 그대로 |
| 7 | 길찾기 | 행·게이트 현행 그대로. 제목에 `.isHeader`를 명시한다(지금 이 섹션만 문자열 헤더라 제목 점프 노출이 미확인 — 화면 아래로 내려가 점프 의존이 커진다, 리뷰 L10) |
| 8 | **이 장소 주변** | 버스 도착 · 따릉이 · 날씨·공기질. **지하철 도착 행 없음** |

- "역 정보" 제목은 역 상세면 **항상** 선다(종전엔 메타 조회가 성공해야 섰다).
- 전화 줄·메타 줄은 비동기로 나타난다(자동 등장 보조 정보 관례, 통지 없음).
- `nil` 장소는 순서·구성 불변(소스 가드 §8).

## 4. 교통약자 시설 종류별 접기 (판정 ②)

- 종류 한 개 = `DisclosureGroup` 한 개, 기본 접힘, 펼침 상태는 뷰 수명 `@State`(영속 안 함).
- 접힘 행 라벨 = 현행 개수 줄 `ios.station.kindCount`("엘리베이터 6곳"). **운행 중지가 1곳 이상이면 그 수를 같은 줄에 붙인다**("엘리베이터 6곳, 운행 중지 1곳", 신규 키 1개 6로케일). 지금은 줄마다 "운행 중지"가 보이는데 접으면 가려진다 — 멈춘 엘리베이터는 동선을 바꾸는 정보다(리뷰 M8).
- 보강 실패 줄(`subway.supplementFailed`)은 **종류 행들 앞**(어느 종류를 펼칠지 고르기 전에 알아야 한다). 음성유도기 기준일 줄(`subway.voiceGuideSource`)은 **음성유도기 묶음의 마지막 자식**.
- 포커스 코드 없음: 펼친 뒤 커서는 접힘 행에 남고 다음 스와이프가 첫 시설이다(경유역 목록 선례).

## 5. 역 전화번호 (판정 ③의 전제 · 레이아웃 1-①)

### 5.1 사실
경로 응답(ODsay)·역 메타·시설 응답 어디에도 전화번호가 없다. 카카오 키워드 검색은 노선별 역 POI(`"{역명}역 {노선}"`, 분류 끝 `수도권5호선` 등)에 번호를 준다. 실호출(2026-09-17, 본 세션 + 리뷰 18회)에서 번호는 세 부류다:

| 부류 | 예 |
|---|---|
| 역무실 직통 | 서울교통공사·9호선(02-6110-xxxx·02-6311-xxxx·02-2656-xxxx), 인천1호선(032-), 대전·대구, 우이신설·김포골드·에버라인·신분당선 |
| **운영사 대표번호** | 코레일 구간 1544-7788(수인분당선·경의중앙선·경강선·수원역 1호선 등), 공항철도 1599-7788, 부산교통공사 1544-5005 |
| 없음 | 서해선·신림선·GTX-A POI, 네이버 병합 역 POI |

### 5.2 조회 대상
- **경유역(`transit-stop:`)만 조회한다.** 검색 탭·채팅·주변 화면에서 연 역은 이미 카카오 POI라 자기 `phone`이 전부다(다시 찾아도 같은 POI가 나온다, 리뷰 L1). 경유역은 이름이 한국어 원문(조인 키)이고 노선을 안다.
- 노선 힌트 = 그 경유역이 속한 leg의 `lineName`(ODsay 표기). **목록 행을 누르는 순간 확정해 상세 항목과 함께 나른다**(시트 클로저에서 `currentLeg`를 읽으면 목적지 상세에도 붙고, 상세가 열린 채 구간이 바뀌면 힌트가 바뀐다 — 리뷰 M4).

### 5.3 호출 (Kit `StationPhoneService`)
- `/api/places?query={역명}역&lat&lng&lang=ko` **장소 트랙만**, 타임아웃 3초(`SearchService.search`는 주소·유료 웹 검색까지 부르므로 쓰지 않는다 — 리뷰 M3, 짧은 상한은 `destinationEntrance` 선례).
- 언어는 항상 `ko`(번호는 언어 무관, 매칭 축이 한국어 이름).

### 5.4 선택 규칙 (Kit 순수 `pickStationPhone`)
1. **이름 키**: POI 이름을 **마지막 공백**에서 가른다 → 앞 조각에서 괄호 부기·끝 `역`·공백·`.`·`·`을 뺀 것이 역 키, 뒤 조각이 노선 표기. 경유역 이름도 같은 정규화(괄호 부기·끝 `역`·공백·`.`·`·`). `동대문역사문화공원역 2호선` → `동대문역사문화공원`(종전 "첫 `역` 앞" 규칙은 `동대문`으로 잘라 옆 역과 섞였다 — 리뷰 H1).
2. **노선 키**: 노선 표기를 기존 노선명 닫힌 표(`src/lib/subway-line-names.ts` `subwayLineKey`→`LINE_EN` — 공백·마침표 제거, `수도권` 접두만 벗김, `(급행)` 분리)의 **영문 값**으로 바꾼 것이 노선 정체성이다. `수도권 수인.분당선`·`수인분당선` → 같은 값, `1호선`(수도권) ↔ `인천1호선` → 다른 값(리뷰 M1 부평 사례). Kit에 표 미러를 두고 웹 표와 항목 동일을 드리프트 테스트로 잠근다(서버 코드는 건드리지 않는다).
3. **후보** = §3.1 `.subway` 분류 ∧ 역 키 일치 ∧ 노선 키 일치 ∧ 역 좌표에서 1,000m 이내(동명이역 차단 — 양평 5호선 ↔ 경의중앙선 53km, 리뷰 실측).
4. 후보 중 최근접 하나. **그 POI에 번호가 없으면 결과는 "없음"이다 — 다른 노선 번호로 떨어지지 않는다**(사용자는 다른 노선 번호임을 알 수 없다, 리뷰 M1). 노선 키를 못 만들면(표 미지) 역시 "없음".
5. **대표번호 판별**(판정 ⑥): 숫자만 남겨 8자리이고 `15`·`16`·`18`로 시작하면 전국 대표번호다(1544-7788·1599-7788·1588-7788·1544-5005 모두 해당). 번호 자체는 그대로 쓰고 표시만 가른다(§5.5). 판별은 번호 모양만 본다 — 운영사 이름 표를 두지 않는다(메타 줄이 이미 운영기관을 말한다).

### 5.5 결과 3상태와 표시 (헌장 §1 3-state, 리뷰 M7)
| 결과 | 역 상세 전화 줄 | 경유역 로터 |
|---|---|---|
| 번호(역 직통) | "전화 걸기, {번호}"(현행 `ios.place.callLine`) | "전화 걸기"(현행 `ios.place.call`) |
| 번호(대표번호) | **"전화 걸기, 대표번호 {번호}"**(신규 키) | **"대표번호로 전화 걸기"**(신규 키) |
| 없음(해당 노선 POI 없음·번호 없음·노선 미지) | 줄 없음(주소 없는 장소와 같은 관례) | 액션 없음 |
| 실패(네트워크·비-2xx·3초 초과) | **"역 전화번호를 불러오지 못했습니다."** 한 줄(신규 키, 시간표 `TimetableState.error` 선례) | 액션 없음 |

지하는 통신이 끊기기 쉽고 이 줄은 "가장 많이 쓸 메뉴"라 실패를 없음으로 뭉개지 않는다.

대표번호 표기는 **역 상세 레이아웃 전체**에 적용한다 — 검색 탭에서 연 코레일 구간 역도 자기 `phone`이 1544-7788이라 같은 줄 모양을 쓴다(어디서 열든 같은 역은 같게 읽힌다, 판정 ①). `nil` 장소(대표번호를 쓰는 일반 업체 등)는 현행 그대로.

신규 문자열 키 4개(6로케일, iOS 전용 `ios/i18n/ios-extra`): 대표번호 전화 줄 · 대표번호 로터 · 조회 실패 줄 · §4 운행 중지 수 줄. 웹 `messages/`는 건드리지 않는다.

### 5.6 저장소 (앱 층 `StationPhoneStore`)
- `@MainActor` 싱글턴, 메모리만. 키 = (역 키, 노선 키, 좌표 소수 4자리). **"번호·없음"은 5분 보관**(서버 `kakao-local` 캐시 300초와 같은 수명 — 앱이 몇 시간 사는 안내 세션에서 카카오 결과를 무기한 들고 있지 않는다, 리뷰 M9), 실패는 보관하지 않는다.
- 같은 키 진행 중 조회는 공유하고, **소비자가 사라져도 공유 조회는 취소하지 않는다**(소비자만 기다리기를 멈춘다, 리뷰 L6).

## 6. 경유역 목록 로터 "전화 걸기" (판정 ③)

- 지하철 leg 경유역 행을 **하위 뷰로 뗀다**. 하위 뷰만 저장소를 관찰하고 시트 본문은 읽지 않는다 — 번호 도착이 시트 전체 재렌더가 되지 않게(리뷰 M5, `rendered` 참조 상자 주석과 같은 계열).
- 행은 종전처럼 행 전체 버튼(E33)이고 `.accessibilityActions`를 번호 상태에서만 단다. 라벨은 역 직통이면 `ios.place.call`(기존 키), 대표번호면 "대표번호로 전화 걸기"(§5.5 신규 키).
- **목록을 펼치는 순간 그 leg의 경유역 전부를 미리 조회한다**(행이 실현될 때 조회하면 VO 커서와 조회가 같이 도착해 액션이 조용히 늦게 생긴다 — 리뷰 M6). 저장소가 중복을 막는다.
- 번호가 늦게 와도 뷰 종류·정체성은 불변(`Button` 그대로).
- 버스 leg·상태 문장 로터는 범위 밖.

## 7. 범위 밖·판정 기록

- **웹 장소 상세** 동조 — 동결 뒤, BACKLOG 등재. **안드로이드 장소 상세** 동조 — BACKLOG 등재, Kit 신규 파일은 미러 등록부 `pending`. 정규식은 `[0-9]`(안드로이드 `:kit` 이식 규칙, 리뷰 L7).
- 안내 시트 "주변 확인" 결과 항목(`SurroundingsSceneSection`의 `NavigationLink`)이 NavigationStack 없는 시트 안에서 동작하는가 — 실기기 확인 항목(§8).
- 2026-09-16 로그의 다른 발견(승차 전 도보가 역 안에서 시작 · boarding 배경 무폴 · `neverSeen` 상한) — BACKLOG §2 A25·E36·A36 표본으로 기록 완료, 별도 판정.
- **개인정보 판정**: 경유역 조회는 사용자가 입력하지 않은 자동 조회지만 보내는 것은 역 이름·역 좌표(사용자 위치 아님)이고 제3자(카카오·네이버)는 기존 신고와 같다. `PrivacyInfo.xcprivacy`·ASC 라벨 변경 없음. 웹 privacy 문구 보강 여부는 동결 뒤 검토(리뷰 L9).
- **약관 판정**: 앱 메모리 5분 보관(§5.6). 검증용 실호출 원본은 세션 임시 폴더에만 두고 판정 표만 남긴 뒤 지운다(리뷰 M9).
