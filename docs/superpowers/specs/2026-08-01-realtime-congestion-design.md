# 실시간 인구 혼잡도 설계 (서울 `citydata_ppltn`)

> 백로그 E1. 종전 판정은 **보류**였다: "핫스팟 영역 경계가 미공개라 이름을 지오코딩하면 근사 2겹이 된다." 이 스펙은 그 전제가 **틀렸음을 실측으로 뒤집고** 착수 조건을 세운다.

## 1. 실측 (2026-08-01, 실호출)

### 1-1. 영역은 코드로 열거된다

`AREA_CD`(`POI001`~)로 조회가 되고, 이름을 몰라도 전수를 훑을 수 있다.

| 확인 | 값 |
|---|---|
| 유효 코드 범위 | `POI001`~`POI131`, 그중 10개 공백(`022·028·057·062·065·069·075·097·113`, `099`) |
| 실재 영역 | **121개** (공백 코드는 `citydata`·`citydata_ppltn` 양쪽에서 부재 확인) |
| 등급어 | `AREA_CONGEST_LVL` 4단계(여유·보통·약간 붐빔·붐빔) |
| 낭독 문장 | `AREA_CONGEST_MSG` 완성 문장 |
| 갱신 표기 | `PPLTN_TIME`(실측 13:40 응답을 14:10에 수신) |
| 예보 | `FCST_PPLTN` 12개, 1시간 간격 |

### 1-2. 전제가 뒤집힌 지점 — 좌표는 있다, 다른 필드에

`citydata_ppltn` 응답에는 좌표 필드가 **0개**다(종전 판정 그대로). 그러나 **전체 `citydata`** 응답의 `SUB_STTS`·`BUS_STN_STTS`가 그 영역을 구성하는 지하철역·버스정류장을 **WGS84 좌표와 함께** 준다.

```
SUB_STTS[0]     = { SUB_STN_NM: "신논현", SUB_STN_X: "127.02506", SUB_STN_Y: "37.504598", ... }
BUS_STN_STTS[0] = { BUS_STN_NM: "신분당선강남역", BUS_STN_X: "127.0285365859", BUS_STN_Y: "37.4958485587" }
```

**이것이 근사 2겹을 없앤다.** 이름을 지오코딩할 필요가 없고(좌표가 API 자체에서 온다), 반경을 가정할 필요도 없다(영역을 구성하는 실제 지점들이 범위를 정의한다). 서울시가 그 영역의 센서로 쓰는 바로 그 점들이다.

전수 수집 결과: **116개 영역 / 구성 지점 1,969개**(나머지 5개는 지점 0개, 아래 1-5).

### 1-3. 영역 크기는 제각각이라 단일 반경 상수는 틀리다

중심(구성 지점 평균)에서 최원점까지 거리:

| 최소 | 1사분 | 중앙 | 3사분 | p90 | 최대 |
|---|---|---|---|---|---|
| 0m | 277m | **475m** | 711m | 941m | 1,872m |

가장 넓은 곳은 잠실 관광특구 1,872m(지점 48개), 좁은 곳은 안양천 0m(지점 1개). **중심-반경 원으로 판정하면 잠실 원이 무관한 주택가를 통째로 삼킨다.**

### 1-4. 판정 규칙: 중심-반경 원이 아니라 구성 지점 근접

> **사용자 좌표에서 가장 가까운 구성 지점까지의 거리가 300m 이내이면 그 영역 안으로 본다.**
> 후보가 여럿이면 **중심까지 거리가 최소**인 영역 하나만 쓴다.

8지점 실측(기대와 전부 일치):

| 지점 | 최근접 구성 지점 | 판정 |
|---|---|---|
| 길동(자택 인근 주택가) | **1,319m** (천호역) | 매칭 없음 ✓ |
| 강동역 | **676m** (천호역) | 매칭 없음 ✓ |
| 일산(서울 밖) | **10,505m** | 매칭 없음 ✓ |
| 잠실역 1번 출구 | 7m | 잠실역 ✓ |
| 성수동 카페거리 | 25m | 성수카페거리 ✓ |
| 강남역 11번 출구 | 29m | 강남역 ✓ |
| 홍대 걷고싶은거리 | 61m | 홍대입구역(2호선) ✓ |
| 여의도 IFC | 120m | 여의도 ✓ |

**매칭 대상은 전부 ≤120m, 비대상은 전부 ≥676m로 완전 분리**된다(음향신호기 재캘리브레이션과 같은 형태). 임계값 150·250·300·400·500m 전 구간에서 오판 0이라 이 결정은 임계값에 민감하지 않다.

**중첩 처리**: 잠실역 1번 출구는 세 영역에 동시 매칭된다(잠실 관광특구·잠실롯데타워·잠실역 전부 7m). 중심 거리로 가르면 잠실역 78m < 롯데타워 527m < 관광특구 893m라 **가장 국소적인 영역**이 뽑힌다. 홍대도 같다(홍대입구역 59m < 홍대 관광특구 406m).

**300m를 고른 근거**(서울 bbox 격자 18,590점, 약 278m 간격):

| 임계값 | 핫스팟 판정 비율 |
|---|---|
| 150m | 4.2% |
| **300m** | **8.9%** |
| 500m | 14.7% |
| 750m | 21.5% |

121개 영역이 서울의 9%를 덮는 것은 타당하다. 750m는 서울의 5분의 1이 핫스팟이 되어 과잉이다.

### 1-5. footprint가 실제 영역보다 좁은 곳 — 미탐이지 오탐이 아니다

| 구성 지점 수 | 영역 수 |
|---|---|
| 0개 | 5 (강서·광나루·여의서로·홍제폭포·서울대공원) |
| 1~2개 | 9 (한강공원류·노들섬·안양천·고척돔·신도림역) |
| 3~5개 | 13 |
| 6~15개 | 43 |
| 16개+ | 51 |

한강공원처럼 넓지만 내부에 정류장이 없는 영역은 footprint가 실제보다 좁게 잡힌다. 그 결과는 **매칭 실패(침묵)**이지 틀린 영역을 말하는 것이 아니다. **침묵은 정직하므로 별도 제외 목록을 두지 않는다** — 3-state의 "정보 없음"에 해당한다. 지점 0개인 5곳은 판정 대상에서 자연 탈락한다.

### 1-6. 봉투는 또 다르다 (공용 파서 스코프 밖)

정상: `{"SeoulRtd.citydata_ppltn": [ {...} ], "RESULT": {"RESULT.CODE": "INFO-000", ...}}`
오류: `{"RESULT.CODE": "ERROR-500", "RESULT.MESSAGE": "..."}` — **점이 들어간 평면 키**(최상위)

**코드가 두 자리에 온다**(2026-08-01 재실측으로 정정): 정상은 `RESULT` **객체 안에** `INFO-000`, 오류는 **최상위 평면 키**. 코드 존재만으로 오류 처리하면 **모든 정상 응답이 502가 된다.** 두 자리를 다 읽고 `INFO-000`만 통과시킨다.

**인증키가 무효하면 `/json/` 경로여도 HTTP 200 + XML 본문**이 온다(`<RESULT><CODE>INFO-100</CODE>…인증키가 유효하지 않습니다`). `res.json()`을 그냥 부르면 `Unexpected token '<'`가 되어 502의 원인이 키라는 사실이 가려지므로, 비-JSON을 감지해 원인을 말하고 죽는다(`readSeoulOpenJson`, data.go.kr의 `fetchDataGoKrJson` 동형).

`datagokr-envelope` 공용 파서(`response` 래퍼)와도, 문화행사(`culturalEventInfo.RESULT.CODE` 중첩)와도 다르다. "봉투가 다르면 파서도 다르다"에 따라 전용 파서를 provider에 둔다.

## 2. 설계

### 2-1. 계층

```
scripts/build-congestion-areas.mjs   (오프라인 1회 — 121개 훑어 seed 생성)
        ↓ src/lib/providers/data/congestion-areas.json  (서버 전용, 116영역·1,969지점)
src/lib/congestion-area.ts           (순수 판정 — 좌표 → 영역 또는 null)
src/lib/providers/seoul-congestion.ts (실시간 호출 — AREA_CD → 등급·문장·예보)
src/lib/congestion.ts                 (진입점 — 판정 + 호출 조립)
        ↓
/api/congestion/nearby · 채팅 get_congestion · CLI/MCP
```

**판정과 호출을 나누는 이유**: 판정은 좌표만 있으면 되는 순수 함수라 심야·오프라인 재현이 되고, 호출은 네트워크다. 섞으면 임계값 회귀를 fixture로 못 잡는다.

### 2-2. seed 형식

```json
{ "generatedAt": "2026-08-01", "areas": [
  { "code": "POI014", "name": "강남역", "c": [37.4988, 127.0276],
    "pts": [[37.504598, 127.02506], [37.4958485587, 127.0285365859]] }
]}
```

지점은 `[lat, lng]` 소수 6자리(약 11cm)로 절단해 파일 크기를 줄인다. 갱신은 연 1회(지하철역 seed 선례) 또는 영역 신설 통보 시.

**빌드 가드**(스크립트가 abort하는 조건): 영역 수 < 100, 총 지점 수 < 1,500, 서울 bbox(37.40~37.72 / 126.73~127.27) 이탈 지점 존재, 강남역 좌표가 golden(37.4988, 127.0276)에서 500m 초과 이탈. 조용한 열화를 막는다.

### 2-3. 캐시·쿼터

`SEOUL_OPEN_DATA_KEY` 일 1,000회를 따릉이·문화행사와 **공유**한다. 방어 2겹:

- `unstable_cache` 키 `["seoul-congestion", areaCode]`, `revalidate: 300`(원본 갱신 주기). 좌표가 아니라 **영역 코드**로 캐시해야 같은 영역 안 여러 좌표가 캐시를 공유한다.
- IP 레이트리밋 60초 10회(`checkCongestionRateLimit`, 기존 라우트 관례).

### 2-4. 3-state

| 상태 | 표현 |
|---|---|
| 영역 안 + 데이터 | `{ area: {...} }` |
| 영역 밖(서울 핫스팟이 아님) | `{ area: null }` — 오류 아님, 섹션 미노출 |
| 조회 실패 | throw → 502 |
| 한국 밖 | 200 `{"outOfCoverage": true}` (좌표 라우트 공통 마커) |

**"혼잡도 정보가 없다"와 "한산하다"를 절대 뭉개지 않는다.**

### 2-5. 노출 위치 — 새 패널이 아니라 `LocalConditions`

혼잡도는 목록이 아니라 **좌표 하나 → 단일 등급어**다. 모양이 날씨·공기질과 같고, `LocalConditions`는 이미 "이 지역 조건"의 그릇이며 **현재 위치와 장소 상세 양쪽에서 렌더된다**(`PlaceDetail`이 소비). 11번째 "내 주변" 패널을 만들면 목록 골격(`NearbyPanelShell`)에 단일 값을 억지로 끼우고 발견 경로를 하나 더 만드는 셈이다.

- heading 키를 `weather.heading`("이 지역 날씨")에서 **"이 지역 상황"**으로 바꾼다. 이미 공기질을 품고 있어 종전 이름도 정확하지 않았다.
- 혼잡도가 없으면 줄 자체가 없다(부재를 설명하지 않는다).

### 2-6. 예보는 UI에 넣지 않는다

12개 시간대를 낭독하면 노이즈다. **UI는 현재 등급 + 완성 문장 + 기준 시각**만. 예보는 **채팅 도구의 `data`에만** 실어 "두 시간 뒤엔 어때?"에 LLM이 답하게 한다(`get_weather`·`get_nearby_events`와 같이 카드 없음, 산문이 정본).

## 3. 접근성

- `LocalConditions` 안의 한 줄이므로 새 region·heading 없음(§2-5). 이미 자동 등장 region 안이다.
- **한 줄 = 한 접근성 객체**: `joinText(등급어, 완성문장)`이 아니라, 등급어는 짧은 요약이고 문장은 부연이라 **`<p>` 두 개**로 둔다(문장이 길어 한 객체로 합치면 요약을 건너뛸 수 없다). 각 `<p>` 내부는 인라인 `<span>` 0개.
- 등급어가 3-state 정본이다. 인구수(`AREA_PPLTN_MIN/MAX`)는 **표기하지 않는다** — "76,000명"은 시각장애 사용자가 행동으로 옮길 수 없는 수치이고 등급어가 이미 답이다(해석 불가 수치는 숨기고 등급 단어를 정본으로).
- 기준 시각(`PPLTN_TIME`)은 표기한다. 실시간 데이터의 신선도는 행동을 바꾼다.

## 4. 범위

웹·iOS·채팅·CLI/MCP를 **같은 마일스톤에** 넣는다(백로그 B축 예방 규칙). CLI를 손대므로 백로그 **D1**(`route walk --accessible` 플래그 미배선)을 편승 처리한다.

## 5. 범위 밖

- **예보 UI 표기** (§2-6)
- **인구수 표기** (§3)
- **서울 밖 혼잡도**: 데이터가 서울 121곳뿐이다. 부산·대구 대체 소스는 조사하지 않았다.
- **영역 경계 폴리곤**: 구성 지점 근접으로 충분하고(§1-4 완전 분리), 폴리곤은 여전히 미공개다.
- **혼잡도 이력·추세**: API가 현재+예보만 준다.

## 6. 테스트 계약

**결정론 게이트(매 커밋)**

1. 판정 순수 함수: 8지점 fixture(§1-4 표) 전부 + 중첩 시 중심 최근접 선택 + 임계값 경계(299m 매칭·301m 미매칭) + 지점 0개 영역 자연 탈락.
2. 봉투: 정상 배열 · `RESULT.CODE` 평면 키 오류 → throw · 배열 아님 → throw · 빈 배열 → null.
3. 서비스: 영역 없음 → `{area:null}`(호출 0회) · 영역 있음 → provider 1회 호출.
4. 라우트: 좌표 누락 400(`coord()` 헬퍼 — D3와 같은 함정 반복 금지) · 한국 밖 200 `outOfCoverage`(키 게이트보다 먼저) · 키 없음 → `{area:null}` · provider throw → 502 · 레이트리밋 429.
5. 빌드 스크립트 가드: 영역 수 미달·bbox 이탈·golden 이탈 주입 시 abort(스크립트를 함수로 분리해 단위 테스트).
6. 웹 컴포넌트: 등급어·문장 렌더 · 인구수 미표기 · 혼잡도 null이면 줄 부재 · `<p>` 안 `<span>` 0개.
7. i18n 키 정합(`i18n-messages.test.ts`), CLI 포매터 커버리지(`formatter-coverage.test.ts` — 등록 누락은 text 모드에서만 보인다).

**실호출 게이트(머지 전)**

강남역(붐빔 계열) · 길동(매칭 없음) · 부산(`outOfCoverage`) · 잠실역(중첩 → 잠실역 선택) · CLI `--output text` · 채팅 "지금 여기 붐벼?" · 프로덕션 배포 후 스모크. **수치 고정 어서션 금지**(살아있는 데이터 — 존재·형태만 검증).

## 7. 되돌아갈 조건

- 실호출에서 등급어가 4단계 밖 값을 내면 → 등급 매핑을 열거형이 아니라 원문 통과로 바꾼다.
- 300m 판정이 실사용에서 오탐을 내면 → 임계값이 아니라 **판정 축**(구성 지점 근접)을 먼저 의심한다. 150~500m 전 구간이 같은 답을 냈으므로 임계값 조정은 증상 치료다.
