# 옴니박스 중심 웹 IA 재편 설계 (2026-07-30)

## 문제

웹 홈이 단일 스크롤 페이지 하나에 검색 UI, "내 주변" 9개 독립 섹션, 날씨·공기질, 최근 검색을 전부 세로로 나열한다. idle 첫 화면의 최상위 인터랙티브 컨트롤이 최소 17개이고, 아코디언을 펼치면 항목별 버튼까지 수십 개로 증식한다. iOS가 4탭(검색·채팅·길찾기·내 주변)으로 "화면 하나 = 목적 하나"를 강제하는 것과 정반대 구조다.

세부 문제:

- **채팅 진입점 5곳 분산**: `PlaceDetail`("이 장소에 관해 물어보기"), `WhereAmI`, 그리고 `NightClinicsNearby`·`KidsPlacesNearby`·`SurroundingsNearby`의 목록 항목마다 채팅 버튼이 반복 노출된다. 메인(범용) 채팅 진입점은 없다(과거 `ModeToggle` 폐기 후 미복원).
- **장소 상세 딥링크 9~10개**: `RouteLinks.tsx`가 네이버 5개(도보·대중교통·자동차·앱 열기·웹 폴백) + 카카오 4~5개(도보·대중교통·자동차·앱 열기·조건부 상세페이지)를 전부 나열한다. 프로바이더 그룹 라벨이 `aria-hidden` 시각 전용이라 SR 사용자에게는 그룹 경계 시맨틱이 없다. iOS는 같은 정보를 3~4개 버튼(모드 선택은 길찾기 탭에 위임)으로 처리한다.
- **구조적 재생산**: 게이트 패턴("키 있으면 노출")이 신규 국내 서비스마다 홈에 섹션을 하나씩 얹는 구조라, 서비스 발굴이 계속될수록 홈이 선형으로 비대해진다.

## 방향 결정

- 미니멀리즘의 실행 수단은 요소 제거가 아니라 **단계별 노출(progressive disclosure)**이다(2026-07-30 트렌드 조사, Linear·ChatGPT·Perplexity IA 패턴).
- 최상위 IA는 **옴니박스 중심 재설계**(위원장 선택 2026-07-30). 입력창 하나가 검색·질문의 공용 진입점이 되고, 나머지 기능은 칩과 2-depth 허브로 노출한다.
- 검색/채팅 분기는 **듀얼 액션**: 사용자의 제출 버튼 선택([검색] / [AI에게 질문])이 곧 분기다. LLM 의도 추측 라우터는 재도입 금지가 정본이다(2026-06-27 폐기 이력).
- 이 구조는 iOS 4탭과 개념적으로 등가다: 검색·채팅(옴니박스 듀얼 액션) + 길찾기·내 주변(칩 2개). 플랫폼 관용구만 다르고 정보 구조는 일치한다.

## 설계

### 1. 홈 화면

- 구성(위에서 아래): Header(로고·언어전환) → 옴니박스(입력창·지우기·마이크) → 제출 버튼 2개 [검색] [AI에게 질문] → 칩 2개 [내 주변] [길찾기] → 최근 검색 → 개인정보처리방침 링크.
- Enter 키 = 검색(기존 관성 유지). [AI에게 질문] = 범용 채팅을 열고 입력창 텍스트를 첫 질문으로 전달한다. 입력이 비어 있으면 빈 채팅으로 연다.
- [AI에게 질문]의 텍스트 전달은 **일회성**이며 `?q=`에 기록하지 않는다(질문이 검색을 유발하거나 URL에 잔존하면 안 됨). 검색 API 호출도 발생하지 않는다.
- `LocalConditions`(날씨·공기질)는 홈에서 제거하고 내 주변 허브 상단으로 이동한다(자동 등장 region 계약 유지).
- 홈 최상위 인터랙티브 컨트롤: 17개 → 약 9개.

### 2. 내 주변 허브 (iOS `NearbyHubView` 동형)

- [내 주변] 칩 → 허브 뷰: 9개 도메인(현재 위치·지하철·버스·따릉이·소아 야간진료·무장애·아이 놀 곳·둘러보기·보행 인프라) 목록 → 항목 선택 시 2-depth로 해당 도메인 뷰.
- 기존 9개 섹션 컴포넌트는 허브 하위 뷰로 **재배치**한다(재작성 아님). 키 게이트는 허브 목록 항목 노출 단위로 그대로 적용한다.
- 허브 상단에 `LocalConditions` 자동 region.
- 상태는 기존 `?q=`·`?dir=` 관례를 확장한 쿼리 동기화(예: `?panel=nearby`, 도메인 선택 포함)로 URL 공유·새로고침 복원을 지원한다.
- **URL이 상태 정본, History 스택은 파생**: 공유 링크·새로고침으로 허브·도메인 URL에 직접 진입하면 스택을 합성하지 않고 뒤로가기 1회 = 홈으로 처리한다(기존 `?q=` 직접 진입과 동일 규율). 화면 전환은 `pushState`, 같은 화면 내 상태 갱신은 `replaceState`.
- History 규율: 홈 → 허브 → 도메인 스택으로 뒤로가기 복귀 + 트리거 포커스 복원(기존 `popstate` 스택 규율 확장). Esc는 뒤로가기와 동등 동작이며, 채팅 오버레이가 열린 동안은 하위 뷰 Esc 비활성(기존 스택 Esc 경합 규칙 유지).
- V1 구현 전략(2026-07-30 계획 수립 시 확정): 도메인 진입은 iOS식 화면 전환이 아니라 **기존 아코디언 섹션을 허브 뷰로 통째 이동**한다. 9개 컴포넌트의 검증된 계약(트리거 버튼·`nearby-panel-store` 단일 점유·Esc·포커스 비대칭)을 그대로 보존하고, 허브 자체의 열림/닫힘만 URL·History가 소유한다(스토어=아코디언 내부, URL=허브 가시성으로 역할 분리). iOS식 완전 2-depth 전환은 후속 검토.
- **게이트 꺼진 상태의 허브 URL 직접 진입**: 허브는 항상 성립하고(보행 인프라는 무게이트) 게이트 꺼진 도메인 섹션은 기존 패턴대로 미노출된다 — V1은 도메인별 URL이 없어 별도 폴백 화면이 불필요하다.
- 신규 국내 서비스는 이후 홈이 아니라 허브 목록에 한 줄 추가된다(홈 비대화의 구조적 차단).

### 3. 채팅 진입점 5곳 → 2곳

- 유지: ① 홈 [AI에게 질문](범용, `placeContext` 없음 — 기존 채팅 계약이 이미 byte-identical 지원) ② 장소 상세 "이 장소에 관해 물어보기"(장소 앵커).
- 제거: `NightClinicsNearby`·`KidsPlacesNearby`·`SurroundingsNearby` 항목별 채팅 버튼, `WhereAmI` 채팅 버튼. 항목에서 질문하려면 항목 → 상세 → 채팅으로 수렴한다(트레이드오프 승인됨 2026-07-30).
- 현재 위치 문맥의 질문은 범용 채팅이 커버한다(`placeContext` 없는 채팅은 주변 도구가 기기 위치 기준으로 동작 — 기존 계약). `WhereAmI` 채팅 버튼 제거로 잃는 기능은 없다.
- 상세 뷰가 없는 항목(정류소·역·따릉이·보행 인프라)은 원래 항목별 채팅 버튼이 없었으므로 이번 축소의 영향 밖이다.
- `ChatOverlay`(role="dialog", History 미사용)를 재사용한다. 범용 채팅도 동일 오버레이.

### 4. 장소 상세 딥링크 압축 (iOS `Deeplink.swift` 동형)

- `RouteLinks` 9~10개 → 3~4개: "여기까지 길찾기"(도착지 프리필로 `DirectionsView` 3수단 비교 진입) + "네이버 지도에서 열기" + "카카오맵에서 열기" + (조건부, `place.link` 있을 때만) "상세페이지".
- 프로바이더×모드 조합 전개(6개 링크)와 별도 웹 폴백 버튼을 폐지한다. 모드 선택은 길찾기 뷰의 책임이다.
- **"열기" 버튼은 환경별 폴백을 내장한 단일 버튼**이다(iOS `openWithFallback` 동형): 모바일에서는 앱 스킴 시도 후 실패 시 웹 지도 URL, 데스크톱에서는 처음부터 웹 지도 URL. 별도 "map.naver.com" 버튼 제거로 기능이 사라지는 게 아니라 폴백이 버튼 내부로 흡수되는 것이다.
- 내부 길찾기가 실패하는 경우(커버리지 밖, provider 장애, 경로 없음)에도 외부 "열기" 버튼 2개가 항상 남아 있어 대체 경로가 보장된다.
- SR 그룹 경계 문제(`aria-hidden` 시각 전용 라벨)는 링크 수 축소로 그룹 자체가 사라져 해소된다.

### 5. 접근성 계약 (헌장 준수)

- 칩·허브 항목은 일반 버튼/링크(과잉 ARIA 금지). 허브·도메인·채팅 진입 시 포커스 이동, 뒤로가기 시 트리거 복원.
- 단일 polite live region, heading 계층(허브 도메인 목록 이름은 기존 h 계층 관례), 터치 타깃 `min-h-11` 유지.
- 옴니박스는 평범한 `<input>` — SR 경로에 신기술 없음.

### 6. 비범위 (후속 마일스톤)

- ⌘K 커맨드 팔레트(ARIA combobox 패턴), View Transitions API 전환 효과.
- iOS·CLI/MCP 변경 없음. 백엔드 라우트·검색 로직·채팅 백엔드 무변경.

## 성과 (측정 가능)

- idle 홈 최상위 인터랙티브 컨트롤 수: 17 → 약 9.
- 장소 상세 딥링크 수: 9~10 → 3~4.
- 채팅 진입점: 5곳 → 2곳(범용 1 + 장소 앵커 1).
- 게이트: `npm run lint`·`npm run test:run` green, a11y-auditor 점검 통과, 프로덕션 실사용 흐름(검색→상세→길찾기→채팅) 수동 확인.
- 접근성 검증 행렬(구현 게이트, codex 설계 검토 반영 2026-07-30): ① 화면 전환마다 포커스 이동(전환 통지의 정본 — 기존 관례와 동일, live region 중복 통지 금지) ② 딥링크 직접 진입·새로고침·뒤로가기 중첩 시나리오 ③ 게이트 꺼진 도메인 URL 진입 폴백 ④ 채팅 오버레이 열림 중 Esc 경합 ⑤ 허브 포커스 복원(직접 닫기/자동 전환 비대칭).
