# 안내 중 대안 경로 미리 보기와 전환 중립화 (M3 후속) 설계

2026-08-14 확정. M3 spec(`2026-08-12-walk-route-alternatives-design.md`) **§5의 안내 시트 전환 버튼 배치를 대체**한다. 서버 계약(§3)·조회 화면(§4)·이탈 제안 상태 머신(§6)은 무변이고, 순수 iOS UI·모델 재배치다.

## 0. 위원장 판정 (2026-08-14, 설계의 전제)

1. **안내 시트의 상시 전환 버튼 제거** — 걷는 내내 떠 있는 "추천 경로로 전환"은 경로를 바꾸라는 부정적 압박으로 읽힌다. 이탈 국면 UI는 경로 축과 무관하게 동일해야 한다(최단 안내 중 이탈도 "경로 다시 조회"만 — UI 일관성).
2. **전환의 자리는 진행 상황 조망이다** — 사용자가 대안을 탐색하거나 의도적으로 경로를 바꾸기에 가장 자연스러운 지점은 전체 경로를 조망하는 지점이라는 판단. "대안 경로 보기"는 도보 최단 전용이 아니라 **진행 상황 화면의 공통 슬롯**이다(대안 축이 성립하는 세션 공통).
3. **미리 보고 전환(A안)** — 프리뷰 없이 조망에서 직행 전환하는 B안은 기각: 보지 않고 갈아타는 구조라 새 경로가 마음에 안 들면 이미 전환된 뒤다. 탐색(듣고 비교) 후 결정이 원안의 의도다.
4. **E10ⓑ(이탈 시 선조회)는 유지 + 문구 교체** — 확인 결과 이탈 자동 조회·수동 재조회 모두 `sessionVariant`를 유지해(같은 축 재조회) 중립성과 충돌하지 않는다. 다만 "준비된 새 경로로 안내"는 다른 종류의 경로로 갈아탄다고 읽히는 혼란이 있어 교체한다.
5. **관점 전환이 이 설계의 목적이다**: 도보 안내에서 추천 경로를 우위로 가정하던 것을 추천·최단 동등 대안으로 중립화하고, 실시간 안내 중 대안 선택 가능성을 일반화한다.

## 1. 안내 시트에서 제거·교체하는 것

- `BeaconTrackingSheet`의 수동 전환 버튼(M3 §5 배치분, `sessionKind == .walk && mode == .detail && shortestVariantAvailable` 노출)을 제거한다. 이로써 이탈 국면의 시트 컨트롤은 "경로 다시 조회"(또는 준비됨 라벨) 하나만 남는다.
- i18n 교체·제거(ko 정본 + 6로케일 관례):
  - `guide.proposalAdopt`: "준비된 새 경로로 안내" → **"현재 위치부터 다시 안내 시작"**.
  - `guide.proposalReady`: "새 경로가 준비되었습니다. 안내 {count}개, 총 {distance}. {first}" → **"현재 위치 기준 경로가 준비되었습니다. 안내 {count}개, 총 {distance}. {first}"** (라벨과 통지가 같은 어휘를 쓴다).
  - `guide.switchToShortest`·`guide.switchToRecommended`(버튼 전용 키) 제거. 전환 **성공 통지** `guide.switchedToShortest`·`guide.switchedToRecommended`는 유지(§4가 재사용).
- 미준비 라벨 `guide.rerouteButton`("경로 다시 조회")은 그대로 둔다 — 두 라벨의 차이(조회부터 vs 바로 안내 시작)가 실제 동작 차이와 일치한다.

## 2. 진행 상황 조망의 "대안 경로 보기" (공통 슬롯)

- `RouteOverviewSheet`에 "대안 경로 보기" 버튼(신규 키 `guide.viewAlternative`)을 둔다. 배치는 **스텝 목록 뒤, 말미 닫기 앞** — 조망의 주 목적(진행 확인)을 매번 한 스와이프씩 밀지 않으면서([[sr-reading-order-position-is-cost]]), "전체를 조망하다가 대안을 탐색한다"는 흐름과 읽기 순서가 일치한다.
- **노출 조건은 "반대 경로 축이 성립하는가"다**(죽은 버튼 사전 차단 — `carGuideStartable` 선례):
  - walk 상세 + 추천 안내 중(`sessionVariant == nil`): `shortestVariantAvailable`일 때만.
  - walk 상세 + 최단 안내 중(`.shortest`): 항상(추천은 기본 축이라 항상 성립).
  - car: 대안 축이 없어 미노출. 간략(brief)·경로 미보유 세션: 조망 모달 자체가 열리지 않아 자연 배제.
- 슬롯 자체는 공통 요소다: 훗날 다른 수단에 대안 축이 생기면 같은 자리에 같은 문법으로 들어온다(이번에 추상화를 미리 만들지는 않는다 — YAGNI, 노출 조건만 분기).

## 3. 대안 경로 미리 보기 시트

- 조망 모달 위의 시트(기존 "시트 위 시트" 문법 그대로, 3층). 열리는 즉시 **최신 세션 fix**를 출발점으로 반대 variant를 `includeGeometry=1`로 조회한다(`fetchDetailData(origin:dest:variant:)` 재사용 — 채택이 성립하려면 기하가 필요하다). 안내 세션은 연속 fix 수신 중이라 싱글턴 TTL 함정과 다른 층이지만, 출발점이 최신 fix임을 명시한다(M3 §6 동형).
- **화면 골격은 조망 모달 재사용**: 헤더(요약·비교) → **"이 경로 안내로 전환" 버튼**(신규 키 `guide.adoptAlternative`) → 스텝 행 "{n}. {문장}"(조망 행 문법) → 말미 닫기. 시스템이 헤더에 착지해 요약·비교부터 낭독한다(조망 선례 — 별도 Announcement 없음, 착지 낭독이 정본). 전환 버튼이 헤더 다음 한 스와이프인 이유: 이 화면의 결정 행동이고, 사용자가 능동적으로 연 화면이라 압박 문제가 없다.
- **헤더 문장**: "{대안 라벨} 경로, 총 {distance}, 도보 약 {duration}분. 지금 경로 잔여 {remaining}." — 잔여와 대안 총거리가 **둘 다 현위치 기준이라 정확한 비교가 성립**한다(이 설계의 판단 재료). 거리·시간은 기존 정본 포맷터(`formatDistance`·낭독은 `distanceText` 경유). ⚠ **이탈 중엔 잔여 절을 생략한다** — 이탈 중 경로 잔여는 거짓이다(안내 시트가 잔여 행을 숨기는 기존 3-state 관례와 동일 근거).
- **상태 3분리(3-state 정직)**: 조회 중(헤더 "대안 경로 조회 중") / 성공 / 실패(실패 문장 + 말미 닫기만 — 재시도 버튼은 두지 않는다: 닫고 다시 열면 재시도다). 실패를 빈 목록으로 위장하지 않는다.
- **닫힘 폐기**: 프리뷰 조회는 latest-wins 토큰을 갖는다. 시트가 닫히면 도착한 응답을 폐기하고(늦은 응답이 닫힌 화면 상태를 되살리지 않음), 세션 종료·도착 전이 시 조망과 함께 연쇄 소거된다(도착 시 `showRouteList = false`가 자식 시트까지 닫는지 구현에서 확인).

## 4. 전환(채택) 의미론

- "이 경로 안내로 전환"은 **방금 본 프리뷰 경로를 즉시 채택**한다. 신선도는 `RerouteProposalGate.isFresh`(30m/120초)를 재사용하고, 낡았으면 **현위치로 조용히 재조회 후 채택**한다(같은 variant 목표, 버튼에 "조회 중" 병기 — `isSwitchingVariant` 진행 표시 재사용). "본 것 = 안내받는 것"이 신선한 경우의 보장이고, 폴백 재조회는 그 보장을 최신 위치로 갱신하는 것뿐이다.
- **채택은 기존 성공 커밋 경로를 그대로 지난다**(`adoptProposal`/`performReroute` 계열 — 경로·기준선·이탈 표결·finalApproach·래치를 한 지점에서 원자 교체. M3 리뷰 #4 통과분 재사용, 별도 채택 전이 신설 금지). `sessionVariant`는 성공 커밋 시점에만 바뀐다(실패 시 불변 — 기존 계약). **실시간 안내는 끊기지 않고 새 경로 위에서 이어진다.**
- **성공**: 프리뷰·조망 시트를 닫고 안내 시트로 복귀, `.high` 통지 `guide.switchedTo*`(버튼 활성화의 결과 통지 계약 — 포커스를 쥔 시트가 사라지는 전이라 기본 우선순위는 잠식된다), 포커스는 중지 버튼 선점(`landStopFocus` 재사용).
- **실패**: 프리뷰에 남고 `.high` 실패 통지(성공·실패 우선순위 비대칭 금지), 세션은 기존 경로 그대로.
- **이탈 중에도 허용**: 전환 커밋이 이탈 상태를 함께 리셋한다(기존 계약). E10ⓑ 제안이 준비된 상태에서 전환하면 제안은 폐기된다(`clearProposal` — 커밋 경로가 이미 지난다).
- **쿼터**: 프리뷰 조회·채택 폴백 재조회는 전부 사용자 행동당 1회다(자동 루프 없음). E10ⓑ 세션 상한(5회)과 독립이며 새 상한을 신설하지 않는다. Tmap 최악 비용은 종전 전환 버튼과 동일(최단 프리뷰 1건).

## 5. 무변 경계

- 서버 계약(`variant`·`alternatives`)·조회 화면(출발 전 두 경로 제시)·이탈 판정 순수 계층·E10ⓑ 상태 머신(문구 제외) 전부 무변. CLI/MCP·채팅 무변.
- 빌드 구성: ⚠ **이 줄은 낡았다**(2026-08-16 정정). 여기 적힌 `AppConfig.realtimeGuidanceEnabled`는 **지금 존재하지 않는다** — 도보 안내가 2026-08-15에 플래그를 졸업하며 그 검사가 삭제됐고(`guidance-gate-drift.test.ts`가 잔존을 금지한다), 대안 프리뷰는 1.7 아카이브에 포함돼 **정식판 기능**이다. 실험판 전용이 아니다.
- 웹: PORTS의 M3 웹 후속 행에 본 spec을 반영한다(웹은 미착수라 처음부터 이 설계로 간다 — 안내 시트 전환 버튼 없이 조망 경유 프리뷰가 정본).

## 6. 검증

- **게이트 검증**: 신선도 수학은 기존 `RerouteProposalGateTests`가 커버한다(재사용 — 신규 수학 없음). 프리뷰 수명(닫힘 폐기·채택 커밋·실패 시 세션 불변)과 노출 조건은 검증된 proposal 토큰·커밋 패턴 재사용 + 코드 리뷰로 확인한다 — `BeaconModel`은 앱 타깃이라 단위 테스트 레인이 없고 E10ⓑ 제안 수명도 같은 방식으로 검증했다(관례 동형). i18n 키·라벨 교체는 xcstrings 재생성 파이프라인 린터가 강제한다.
- **시뮬 스냅샷**: 조망 버튼·프리뷰 골격·상태 3분리(라벨 회귀 신호로만 — "한 줄 = 한 객체" 정본은 실기기).
- **실기기 실보행 판정(F-a 계열 이월)**: 전환 연속성(끊김 없는 이어가기), 비교 문장 낭독, 전환 후 포커스 복귀, 프리뷰 착지 낭독. a11y-auditor 점검 동반.

## 7. 설계 리뷰 게이트 판정

**생략** — 전환 커밋·신선도 게이트·latest-wins 토큰·`.high` 통지 계약 전부 M3 적대적 리뷰(17건)를 통과한 계약의 재조합이고, 신설분은 국소·가역인 프리뷰 화면(읽기 전용 조회 + 기존 커밋 경로 호출)뿐이다. 조건 ①(새 불변식·판정 계층) ②(새 외부 계약) ③(비가역 파급) ④(안전 축 신설) 모두 비해당 — 안전 크리티컬인 채택·이탈 경계는 기존 검증 계층을 그대로 지난다. 잔여 리스크는 구현 단계 리뷰 + 실보행 판정이 커버한다.
