# E82 베르길리우스 첫 판: 설계

2026-11-14 · iOS 실험판 + 서버 · 선행 조사: `docs/research/RESEARCH-2026-11-12-e82-outing-coverage.md`, `RESEARCH-2026-11-12-e82-models-voice.md`, `RESEARCH-2026-11-14-e82-voice-latency.md` · 안내 인계는 `2026-11-14-e83-chat-route-start-design.md`의 시작 함수를 쓴다

## 1. 목표와 성과

목적지 없이 걷는 사람에게 ①지나치는 가게를 빠짐없이 먼저 말해 주고 ②말한 것을 다시 확인할 수 있게 하고 ③말로 물으면 한두 문장으로 답하고 ④답이나 기록에서 버튼 한 번으로 도보 안내로 넘어간다. 나들이(E51)의 따라가는 엔진을 그대로 쓰고 말하는 방식과 묻는 길을 더한다.

**움직일 성과**(실보행으로 확인):
- 가게가 몰린 구간에서 앱이 알고 있던 길가 20m 안 가게 중 말하지 않은 곳 0(10-30 세션 기준 34곳 중 13곳 누락).
- 말한 것을 세션 안에서 다시 확인할 수 있다(지금 0).
- 주변 목록으로 답하는 질문은 질문이 끝난 뒤 답 첫 문장까지 2초 안, 조회가 끼는 질문은 실측해 기록한다.
- 묻는 동안 온 횡단보도 경고가 버려지는 일 0.

**비목표**: 길 안내 중 동작(판정 10), 잠금 중 묻기(판정 11), 실시간 음성 대화, 카메라, 날을 넘기는 기억, 말만으로 안내 시작, 정식판, 웹, 안드로이드.

## 2. 위원장 판정

BACKLOG E82의 2026-11-12 판정 7건과 2026-11-14 설계 판정 15건이 정본이다. 이 문서에서 「판정 N」은 2026-11-14의 번호다.

## 3. 설계 결정

### 3.1 먼저 말해 주기

| # | 결정 | 근거 |
|---|---|---|
| V1 | 지나침 판정(`OutingPassBy`)은 한 위치 갱신에서 **자격 있는 가게 전부**를 좌·우·방향 모름 셋으로 갈라 돌려준다. 「가장 가까운 한 곳만 말하고 나머지 영구 침묵」을 없앤다 | 판정 1. 누락 13곳 중 8곳의 원인 |
| V2 | 문장은 앱이 틀로 만든다: 「왼쪽에 A, B. 오른쪽에 C」, 한쪽만이면 「왼쪽에 A, B」. 한 쪽 안의 순서는 가까운 순 | 판정 1·2. 구분자는 쉼표 |
| V3 | 진행 방향을 모를 때(`validBearing` 거짓) 지나친 가게도 말한다: 「옆에 A, B」. 좌우를 아는 가게와 섞이지 않는다(방향을 모르는 갱신에서는 전부 「옆에」) | 판정 3. 「앞」은 어느 문장에도 쓰지 않는다 |
| V4 | 아직 말하지 못한 묶음이 기다리는 동안 다음 묶음이 생기면 **덮어쓰지 않고 합친다**(같은 쪽끼리 이어 붙이고 가까운 순). 기다림 칸은 한 칸 그대로다 | 지금은 최신이 이겨 앞 문장이 사라진다(`deferredLow`) |
| V5 | 말했다는 표시(`spokenPlaces`)는 **문장이 실제로 발화 창구에 실린 때** 넣는다. 합쳐진 채 기다리는 가게는 아직 말한 것이 아니다 | latch는 발화 성공 시점에(1회성 경고 전달 계약과 같은 원리) |
| V6 | 한 문장에 드는 가게 수에 상한을 두지 않고 시작한다. 실보행에서 문장이 길어 다음 가게를 놓치면 그때 정한다 | 수치를 근거 없이 정하지 않는다. 판정 항목으로 넘긴다 |
| V7 | 낭독 단계(전부·이정표만·끔)와 횡단보도·갈림길·도로명·걸은 거리·자동 종료·백그라운드 유지는 바꾸지 않는다 | 판정 3(2026-11-12): 엔진은 살린다 |
| V8 | 주변 가게를 받아 오는 양은 M0 확인 호출 결과로 정한다: 몰린 구간에서 분류당 15곳 상한 때문에 받지 못한 가게가 길가 20m 안에 있으면 받는 양을 늘리고, 없으면 그대로 둔다 | 판정 15 |

## 4. 서버 계약

`POST /api/vergilius/ask` (NDJSON 스트림, `no-store`)

요청: `{ question, locale, provider, location: {lat,lng}, heading: number|null, places: [{ id, name, category, side: "left"|"right"|"unknown", distance, lat, lng }], nextCrosswalkMeters: number|null, roadName: string|null, log: [{ id, kind, text, agoSeconds, placeId? }] }`

응답 이벤트: `{type:"text", delta}` … `{type:"done", text, renders: RenderPayload[], proposal: { placeId } | null}` / `{type:"error", code}`. 능력 조회 `GET /api/vergilius/providers` → `{ providers: ["openai","google"] }`(키가 있는 것만).

- 한국 밖 좌표·키 없음·한도 초과는 기존 라우트 관례(커버리지 마커, 게이트, IP 레이트 리밋)를 따른다. IP당 분당 20회.
- 도구 실행은 기존 채팅 라우터의 실행부를 그대로 부른다(예산·3-state·커버리지가 한 곳에 있다). 도구 선언을 두 회사 형식으로 바꾸는 얇은 변환층을 둔다. 한 질문의 도구 왕복은 2회까지.
- `proposal.placeId`는 요청의 `places`·`log`에 있는 id만 통과시킨다(없는 id는 버린다).
- 지침 정본은 한 파일이고 두 회사에 같은 지침을 쓴다.
- `OPENAI_API_KEY`는 서버 전용 env, 게이트 `hasOpenAiKey`.

## 6. 불변식과 테스트

- 좌우 오답 0(나들이 기준 그대로): 좌우는 앱의 판정만 쓰고 모델 답의 좌우는 요청 재료의 값과 같아야 한다(서버 테스트는 지침, 실호출 표는 대조).
- 한 갱신에서 자격 있는 가게가 전부 문장이나 기다림 칸에 든다(Kit fixture: 10-30 세션의 몰린 구간 재생).
- 기다림 칸이 합쳐진다(덮어쓰기 변이를 넣으면 빨개진다).
- 말했다는 표시와 기록은 발화 창구에 실린 때만(묻는 중 미뤄진 경고가 표시만 남기고 사라지지 않는다).
- 묻는 동안 온 횡단보도 경고는 받아쓰기가 끝난 뒤 답보다 먼저 나간다. 지나간 횡단보도는 나가지 않는다.
- 답을 읽는 중 경고는 답을 끊고, 가게 문장은 끊지 않는다.
- 서버: 없는 `placeId` 제안은 버린다, 키 없는 회사는 목록에 없다, 도구 왕복 상한, 3-state.
- **실호출 표(M4 머지 조건)**: 일곱 질문을 두 모델에 각 5회 보내 첫 문장 시간·전체 시간·답 문장·재료 밖 이름(날조) 수·좌우 불일치 수를 표로 낸다. 날조나 좌우 불일치가 1건이라도 있으면 그 모델의 그 질문 유형은 열지 않는다.
- 실보행 판정(위원장): 문장 길이(V6), 대기음, 답 목소리, 겹침 순서, 「옆에」 문장의 빈도.

## 7. 설계 리뷰 판정

별도 컨텍스트 리뷰 대상이다: 실보행 안내의 발화 서열과 횡단보도 경고 전달을 바꾼다(안전 축), 새 외부 통합(OpenAI)과 개인정보 경계가 있다. 리뷰 결과는 이 절에 적는다.
