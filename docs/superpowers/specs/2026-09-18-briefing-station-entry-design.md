# 경로 브리핑에서 지하철역 상세·전화 (E45)

> 2026-09-18 판정 세션. 판정 정본은 `docs/BACKLOG.md` §5 E45. **iOS 전용·서버 변경 없음**(심사 동결 정합 — 좌표는 길찾기 탭이 이미 `includeStops: true`로 받고 있다, `DirectionsTabView.swift:572`). 선례는 채팅 산문 계약(`ChatConversationView.blockView`), E33 안내 시트 역 진입(`2026-09-11-transit-station-to-place-and-landing-design.md`), E44 역 전화번호(`2026-09-17-station-detail-reorg-design.md`). 착수는 별도 세션(위원장 규칙: 판정 세션과 착수 세션 분리).
>
> **설계 리뷰 판정**: 필수. 새 불변식(§3.1)과 줄 종류별 판정 계층(§3.2)을 신설하므로 CLAUDE.md 리뷰 게이트 ①에 해당한다. 1회 적대적 리뷰(§9) 뒤 구현.

## 1. 문제

**요청**(위원장 2026-09-18): "길찾기 탭에서 경로를 조회했을 때 대중교통 브리핑에서 바로 지하철역 상세로 들어갈 수 있으면 좋겠어. 그리고 지하철역 항목에서 로터만으로 전화를 걸 수 있으면 좋겠어."

**현행**: 길찾기 탭의 대중교통 브리핑(`TransitRouteRows`)은 전부 순수 `Text`다. 역 이름이 여러 줄에 들리는데 그 역으로 갈 수단이 없다. 같은 기능이 **안내 시트에는 이미 있다** — E33이 상태 문장 로터로, E44가 경유역 목록 행 버튼+로터 전화로 넣었다. 즉 "안내를 시작한 뒤에는 되고, 시작하기 전에는 안 된다".

**제약**: 브리핑은 처음부터 끝까지 순차로 읽는 화면이다. 줄을 늘리거나 한 줄을 여러 접근성 객체로 쪼개면 읽기 비용이 직접 올라간다(헌장 §4).

## 2. 판정 기록 (위원장 2026-09-18, 순차 문답)

| # | 판정 | 비고 |
|---|---|---|
| ① | **역 이름이 나오는 모든 줄**에 진입점 | 세션 초안("승차·하차가 둘 다 나오는 구간 줄 한 자리")을 **기각**. 그 안은 "어느 줄에서 열어야 하는가"를 사용자가 외워야 했다 |
| ② | 역 1개인 줄은 **줄 전체 탭 = 역 상세**, 로터 한 칸 내리면 전화 | 기본값이 역 상세 진입 |
| ③ | 역 2개 이상인 줄은 로터에 **역별로 묶어** 등장 순 | "A역 상세 보기" → "A역에 전화 걸기" → "B역 상세 보기" → "B역에 전화 걸기" |

| ⑥ | 문구는 다른 UI와 일관 | §6 |
| ⑦ | 실기기 판정은 **낭독 정정 생존 하나만** | 버튼 로터 축 오염·로터 훑는 비용은 위원장 경험상 우려 지점이 아니라 제외 |

**정정**(위원장 지적 2026-09-18): 액션 라벨의 역 이름 언어를 앱 언어 기준으로 두려던 세션 판정을 **기각**하고 줄 언어에 묶었다(§6). 근거는 그 절에 남겼다.

**세션이 강한 기본값으로 정한 것**(위원장 확인): 지하철 구간만(버스 정류장 제외, §7) · 역 상세에서 "여기까지 길찾기" 숨김(§7) · VoiceOver 힌트 없음(§7) · 문장 스캔 대신 구조 확정(§3.2) · 노선 힌트는 줄 종류가 정한다(§4).

## 3. 진입점 규칙

### 3.1 불변식

> **역 이름이 들리는 줄에는 그 역으로 가는 수단이 있고, 들리지 않는 줄에는 없다.**

발견 경로가 규칙 하나로 닫힌다. 사용자가 외울 것은 "이름이 들렸다"뿐이다.

역방향도 성립한다 — 진입점이 있는데 이름이 안 들리는 줄은 만들지 않는다. 마지막 도보 줄("목적지까지 도보 3분, 180m")이 그 경우다.

### 3.2 어느 줄에 어느 역이 실리는가 — 구조로 확정 (문장 스캔 금지)

⚠ **E33과 다르게 한다.** E33은 `transitStationMentions`로 **문장을 훑어** 역을 찾는다. 상태 문장은 폴마다 다르게 조립돼 코드가 내용을 모르기 때문이다. 브리핑 줄은 **우리가 조립한다** — 어느 역이 들어갔는지 코드가 이미 안다. 구조로 확정하면 둘을 얻는다.

1. 정규식을 웹·Kit에 미러할 때 문자 클래스가 어긋나 **iOS만 전량을 놓치는** 함정(CLAUDE.md 실사고)을 아예 지나가지 않는다.
2. `신촌`이 `신촌(경의중앙선)` 안에서 잡히는 식의 이름 오탐이 없다.

**전제**(검증 §8에서 잠근다): `TransitRouteLeg.stops`는 양 끝을 포함하므로 승차역 = `stops.first`, 하차역 = `stops.last`. 안내 세션의 `viaStops`가 이 배열 그대로다(`TransitGuide.swift:497`).

Kit 순수 함수 신설 — `ios/GildongmuKit/Sources/GildongmuKit/TransitBriefingStations.swift`:

```swift
/// 브리핑 렌더 순서의 한 줄.
public enum TransitBriefingRow: Sendable, Hashable {
    case walk(legIndex: Int)
    case transit(legIndex: Int)
    case alight(legIndex: Int)
}

/// 그 줄에서 열 수 있는 역 하나. 순서는 줄에 이름이 들리는 순서다.
public struct TransitBriefingStation: Sendable, Hashable {
    public let stop: TransitLegStop
    /// 전화번호 조회 노선 힌트(§4). 표가 모르는 노선이면 nil — 조회하지 않는다(= 번호 없음).
    public let lineName: String?
}

public func transitBriefingStations(
    _ legs: [TransitRouteLeg], row: TransitBriefingRow
) -> [TransitBriefingStation]
```

| 줄 | 게이트 | 대상 역 | 개수 |
|---|---|---|---|
| `.walk(i)` | `legs[i].mode == "walk"` ∧ `legs[i].toName` 비지 않음 ∧ `legs[i+1]` 존재 ∧ `legs[i+1].mode == "subway"` ∧ `stops.first` 존재 | `legs[i+1].stops.first` | 1 |
| `.transit(i)` | `legs[i].mode == "subway"` ∧ `stops` 존재. 승차는 `fromName` 비지 않을 때, 하차는 `toName` 비지 않을 때 | `stops.first`(승차) → `stops.last`(하차) | 0~2 |
| `.alight(i)` | `legs[i].mode == "subway"` ∧ `stops.last` 존재. 줄 존재 자체는 호출부의 `if let text = alightLineText(…)`가 이미 가른다(`station`이 비면 줄이 없다) | `stops.last` | 1 |

**세 가지 경계**:
- 마지막 도보는 `toName`이 nil이다(provider가 목적지를 모른다). `toName` 게이트가 그 줄을 자동으로 뺀다 — 문구의 `{name}`이 `destinationName`(목적지 이름)에서 채워진 줄에는 진입점이 없다.
- 도보 → 버스 → 도보 → 지하철 경로에서 첫 도보는 다음 leg가 버스라 제외되고, 세 번째(도보)만 진입점을 갖는다.
- `.transit`의 승차·하차가 같은 역이면(`stationId` 또는 `name` 일치) 1개로 접는다.

### 3.3 역 개수로 갈리는 활성화 방식

채팅 산문 계약(`ChatConversationView.blockView`)과 같은 갈래에, 전화 한 층을 더한다.

| 역 개수 | 뷰 | 기본 액션 | 로터 커스텀 액션 |
|---|---|---|---|
| 0 | `Text` (현행) | 없음 | 없음 |
| 1 | 줄 전체 `Button`(`.buttonStyle(.plain)`) | 역 상세 | 전화 1개 |
| 2 이상 | `Text` | 없음 | 역별 (상세, 전화) × N, 등장 순 |

⚠ **현재 실제 최대는 2다.** 역이 여럿 실리는 줄은 구간 줄뿐이고 거기엔 승차·하차 둘만 들어간다(요청 원문의 "두 개나 세 개"는 3개 줄을 전제했지만 그런 줄은 없다). 함수는 일반형(N개)으로 두어 줄 구성이 바뀌면 이 전제가 깨진 것이 드러나게 한다 — 상한 2를 코드에 박지 않는다.

⚠ **로터 액션 선언은 역순**이다 — VoiceOver 로터가 빌더 선언의 역순으로 노출된다(`PlaceRow`·채팅·E33 실측). 역별 묶음 안의 (상세 → 전화) 순서도 함께 뒤집어야 등장 순으로 들린다.

역 상세는 `NavigationStack` **push**로 연다(길찾기 탭에 이미 있다, `DirectionsTabView.swift:666`). 검색 탭과 같은 방식이고 복귀는 "뒤로" 하나다 — 안내 시트처럼 시트를 쌓지 않는다.

Place는 `transitStopPlace(stop)`(Kit `PlaceProjection.swift:192`)로 만들고 `PlaceDetailView(place:stationLineHint:)`에 노선 힌트를 함께 넘긴다.

### 3.4 왜 E33은 이 갈래를 쓰지 않았는가 (그 근거가 여기엔 없다)

E33이 상태 문장에서 "1개면 줄 전체 버튼"을 **기각한** 이유는 하나다: 그 문장은 15초마다 다시 조립돼 언급 수가 오가고, 뷰 종류가 `Button` ↔ `Text`로 갈리면 **포커스가 얹힌 줄이 파괴·재생성된다**(헌장 §5).

브리핑 줄은 조회가 끝나면 바뀌지 않는다. 그 기각 근거가 성립하지 않으므로 채팅 갈래를 그대로 쓴다. 뷰 종류는 **경로 조회 결과가 정하고 그 뒤로 불변**이다 — 전화번호가 늦게 도착해도 뷰 종류는 바뀌지 않는다(§5.1).

## 4. 노선 힌트 — 줄 종류가 정한다

E44 전화번호 조회는 노선 힌트(`lineName`)를 요구한다(같은 역·같은 노선·1km 후보만, `2026-09-17` spec §5.2·§5.4).

| 줄 | 노선 힌트 | 근거 |
|---|---|---|
| `.transit(i)` | `legs[i].lineName` | 그 구간의 노선 |
| `.alight(i)` | `legs[i].lineName` | 내린 노선 |
| `.walk(i)` | **`legs[i+1].lineName`** | 그 역은 **다음에 탈** 노선의 역이다 |

`.walk`의 "다음 leg 참조"는 승차 출구를 고르는 기존 배선(`boardExitAfterWalk`, `TransitExitLines.swift:37`)과 같은 패턴이다.

⚠ **환승역은 줄에 따라 다른 번호가 나올 수 있다.** 5호선 → 9호선 환승에서 여의도는 구간 줄·하차 줄에서 5호선으로, 다음 구간 줄에서 9호선으로 조회된다. **이것이 맞다** — 내리는 노선의 역무실이 그 승강장을 아는 곳이다. 저장소 키가 노선을 포함하므로(E44 §5.6) 두 번호가 서로를 덮지 않는다.

`lineName`이 nil이면 조회하지 않고 "번호 없음"이다(E44 §5.4-4). 액션은 그대로 있고 §5.1 통지가 나간다.

## 5. 전화 3상태

### 5.1 상시 노출 + 결과 통지 (판정 ④)

전화 액션은 **저장소 상태와 무관하게 항상 로터에 있다.** 누르면 그 순간의 저장소 상태로 즉답한다(조회를 기다리지 않는다 — 누른 뒤 몇 초 침묵이 더 나쁘다).

| 저장소 상태 | 동작 |
|---|---|
| 번호(역 직통) | `tel:` 연결. 통지 없음(전화 앱이 뜨는 것이 응답이다) |
| 번호(대표번호) | 같음. 액션 라벨이 이미 대표번호임을 말한다(§6) |
| 없음 | `.high` 통지 `ios.station.phoneMissing` + `ResultHaptic.fire(.attention)` |
| 찾는 중 | `.high` 통지 `ios.station.phonePending` + `.attention` |
| 조회 실패 | `.high` 통지 `ios.station.phoneError`(기존 키) + `ResultHaptic.fire(.failure)` |

**통지 우선순위 `.high`의 근거**: 화면 변화가 없는 활성화 응답이라 통지가 유일한 증거다(CLAUDE.md의 "주소 복사 '복사됨'"과 같은 계열). 성공이 기본 우선순위가 아니라 **통지 자체가 없다**는 점에서 비대칭이 아니다 — 성공의 증거는 전화 앱 전환이다.

**진동**은 문장이 나가는 조건과 같다(CLAUDE.md `ResultHaptic` 계약). 3상태를 촉각에도 싣는다 — 부재·대기는 `.attention`, 조회 실패는 `.failure`.

**통지 문구에 역 이름을 넣지 않는다.** 방금 누른 액션 라벨이 "천호역에 전화 걸기"였고 통지가 그 직후에 오므로 역 이름은 새 정보가 아니다(헌장의 "뻔한 꼬리 문장 금지", 판정선 = 뒷문장이 새 정보를 주는가).

**미리 조회**: 브리핑 줄이 렌더되면 그 경로의 지하철 구간 승차·하차역을 `StationPhoneStore.prefetch`로 미리 조회한다(E44 §6이 "목록을 펼치는 순간"으로 정한 근거와 같다 — 행이 실현될 때 조회하면 VO 커서와 조회가 같이 도착해 결과가 조용히 늦는다). 접힌 대안 경로는 `DisclosureGroup` 본문이 렌더되지 않으므로 펼칠 때 조회된다. 고유 조회는 보통 2~4건이고 저장소가 같은 키 중복을 막는다.

⚠ **뷰 종류는 전화번호 도착으로 바뀌지 않는다.** 액션이 상시라 목록 길이도 불변이다 — 이것이 판정 ④가 E44의 조건부 액션보다 나은 두 번째 이유다(로터를 열어 둔 사이 목록이 변하지 않는다).

### 5.2 안내 시트 경유역 목록 통일 (판정 ⑤ — E44 §5.5 개정)

`ViaStopStationRow`(`TransitTrackingSheet.swift:995`)의 `.accessibilityActions`를 상태 `switch`에서 **무조건 1개**로 바꾼다. 라벨은 종전 그대로 이름 없는 `ios.place.call` / `ios.place.callRepresentative`(행 이름이 곧 역명이다), 통지·진동은 §5.1과 같은 한 벌을 쓴다.

E44 §5.5 표의 "경유역 로터" 열에 개정 표기를 남긴다 — 그 spec 안에서도 **역 상세 줄은 실패를 표시하는데 경유역 로터는 액션을 없애 뭉개는** 불일치가 있었다.

**역 상세 전화 줄은 손대지 않는다.** 그 줄은 로터 액션이 아니라 보이는 줄이고, 3상태가 이미 줄 종류로 드러난다(E44 §5.5).

## 6. 문구

**상세 쪽은 신설 없음.** 채팅 `ios.chat.openPlace`와 안내 시트 `transitGuide.openStation`이 이미 둘 다 `{이름} 상세 보기`다. 브리핑은 `transitGuide.openStation`을 재사용한다 — 브리핑이 안내 세션 키를 재사용하는 선례가 이미 있다(E25 `transitGuide.exitBound`).

**신설 4개**:

| 키 | ko | 자리 |
|---|---|---|
| `transitGuide.callStation` | `{station}에 전화 걸기` | `messages/`(6로케일). 이름을 붙이는 선례 `clinicNearby.callAction`을 계승 |
| `transitGuide.callStationRepresentative` | `{station} 대표번호로 전화 걸기` | 같음. E44의 직통·대표번호 구분 유지 |
| `ios.station.phoneMissing` | `전화번호가 없습니다.` | `ios/i18n/ios-extra`(기존 `ios.station.phoneError`와 같은 자리) |
| `ios.station.phonePending` | `전화번호를 찾고 있습니다.` | 같음 |

역이 1개인 줄의 로터 전화도 같은 문구(이름 포함)를 쓴다 — 규칙을 하나로 둔다.

### 액션 라벨의 역 이름은 어느 언어인가

**그 줄이 쓴 이름과 같은 언어다.** `.transit`·`.alight`는 `transitLegUsesEnglish(leg, lang:)`, `.walk`는 그 도보 줄 자신의 판정을 지나 영문 자격이 있으면 `stop.nameEn`, 없으면 `stop.name`(한국어)을 쓴다. E33과 같다(그 spec 설계 리뷰 E1: "영문이 없으면 라벨 전체가 ko").

⚠ **앱 언어 기준(`bilingual(...).primary`)으로 고르지 말 것.** 그러면 줄은 한국어인데 라벨은 로마자가 되어 **같은 역이 한 화면에서 두 언어로** 들린다. 위원장 판정이 이미 이 선을 그었다: "한국어 폴백은 설계지만 **한 줄 안 혼용과 침묵은 결함**"(`docs/BACKLOG.md` §2 E27 실승차 행).

세션 초안은 "라벨 언어가 줄마다 튀는 것이 더 나쁘다"는 근거로 앱 언어 기준을 택했다. **그 근거는 틀렸다** — 라벨을 줄에 묶으면 줄이 갈릴 때 라벨이 함께 갈리므로 **새로운 튐이 생기지 않는다**. 튀는 것은 줄 자체이고 그것은 E27이 이미 정한 기존 동작이다.

검증: 앱 언어 en · 영문 자격 미달 구간에서 줄과 라벨이 **둘 다 한국어**임을 fixture로 단언한다. 자격 충족 구간에서는 둘 다 영문이다. 한쪽만 영문인 조합은 실패로 잡는다.

**실측(2026-09-18, `lang=en&includeStops=1` 실호출 15경로 / 66루트 / 226 leg, 전부 200)**: **영문 자격 미달 0건**. 지하철 22 · 버스 63 · 도보 141 leg 전부 영문이고, `*En` 값에 한글이 남은 것도 0건이다.

- 지하철 노선 12종(수도권 1·2·4·5·7·9급행·수인분당·신분당, 부산 2, 대구 1, 대전 1, 인천 1)이 전부 표에 맞았다 — `subway-line-names-drift.test.ts`의 전수 매핑 게이트가 실효 중이다.
- ⚠ **세션 초안의 위험 추정("버스 한글 번호가 `isDisplayableEnglish`에서 탈락한다")은 틀렸다.** ODsay `lang=1`은 버스 번호도 영문으로 준다(`송암73` → `Songam73`, `좌석02` → `Express City Bus 02`, `202(동진)` → `202(Dongjin)`, `901(서귀포환승정류장…)` → 전문 영역). provider는 en 응답에서 한국어를 `busNoKor`로, 영문을 `busNo`로 받으므로(`odsay.ts:355·363`) 탈락 경로가 아니다. 표본의 고유 버스 57종 중 한국어 번호 19종이 **모두** 영문을 받았다.
- 표본에 실제로 든 것(부재는 미실측으로 적는다): 마을버스류 한글 번호 · 지방 지하철 4개 도시 · 인천1호선 · 급행 · 광역/직행좌석 · 지하철 0개인 버스 전용 경로. 전부 PASS.

**그래서 §6의 한국어 폴백 분기는 실데이터 표본으로 재현되지 않는다** — fixture로만 검증된다. ⚠ 죽은 코드로 보고 지우지 말 것: 새 노선 개통(표 미스)·ODsay 영문 미제공 신규 정류소에서 살아나고, 그때 이 분기가 없으면 영어 세션이 **침묵**한다(빈 문자열 라벨). 표본은 15경로라 전국 전수가 아니다.

스윕 스크립트와 원자료는 세션 스크래치패드에 있고 저장소에 커밋하지 않는다(재현은 같은 좌표 15쌍으로 다시 호출하면 된다).

## 7. 범위 밖·판정 기록

| 항목 | 판정 |
|---|---|
| **버스 정류장** | **제외.** 정류장은 역 섹션(`stationLayoutKind`)도 전화번호도 없어 상세가 빈 화면이 된다. 지하철 구간만. 도보 줄의 행선지가 버스 정류장이면 그 줄은 현행 `Text` 그대로다(없는 것을 만들지 않는다) |
| **역 상세의 "여기까지 길찾기"** | **숨긴다**(`showsDirectionsEntry: false`). 누르면 바로 뒤 길찾기 폼의 목적지가 그 역으로 바뀌어, 돌아왔을 때 보던 경로가 조용히 사라진다. 안내 시트가 같은 이유로 이미 숨긴다(`PlaceDetailView.swift:17-20`) |
| **VoiceOver 힌트** | **넣지 않는다.** 원칙대로면 역 1개 줄 버튼에 "천호역 상세 보기" 힌트를 달 자리다(버튼 이름이 동작을 알리지 않는다). 그러나 힌트를 켠 사용자에게는 그 문장이 버튼 줄마다 덧붙어 브리핑 읽기가 길어져 애초의 제약과 부딪친다. 채팅이 이미 힌트 없이 도는 것과 일관 |
| **버튼 로터 축 오염** | 판정 ⑦ — 위원장 경험상 우려 지점이 아니라 실기기 판정에서 제외. 참고 수치: 환승 1회 경로에서 "양식 컨트롤" 로터에 걸리는 버튼이 1개 → 4개 |
| **자동차·도보 브리핑** | 범위 밖(역이 없다) |
| **웹 브리핑** | 범위 밖. iOS 선행이고 웹은 `docs/BACKLOG.md` §4에 B8(채팅 산문)과 같은 계열로 등록. 심사 동결로 배포도 막혀 있다 |
| **채팅 대중교통 카드** | 범위 밖. 같은 줄 렌더를 쓰지 않는다 |
| **경유역 전체 접근** | 범위 밖(판정 ①의 기각된 3안). 브리핑은 출발 전 화면이라 필요한 역은 승차·하차·환승이고, 중간 경유역은 안내 세션의 맥락이다 |

## 8. 검증

| 층 | 무엇 |
|---|---|
| Kit 단위(Swift Testing) | `transitBriefingStations` 전수: 줄 종류 3 × (다음 leg 없음·도보·버스·지하철) × (`stops` nil·빈 배열·1개·다수) × (`fromName`/`toName` nil) · 마지막 도보 제외 · 승차 = 하차 접기 · 노선 힌트가 `.walk`에서 다음 leg를 가리키는지 · 환승 경로에서 같은 역이 줄마다 다른 노선 힌트를 받는지 |
| Kit 단위 | **§3.2 전제 잠금**: `stops.first.name` ↔ `fromName`, `stops.last.name` ↔ `toName` 조인. 손 fixture(천호–여의도 5호선, 여의도–노량진 9호선, 1정거장, 순환선) |
| 실호출 게이트 | `/api/route/transit?includeStops=1` 실표본 다수로 위 전제를 재확인. ⚠ **선정 단계가 표본을 자른다** — 확인하려는 케이스(환승 2회 이상, 버스↔지하철 혼합, 0m 도보 leg)를 전체 후보 위에서 별도 PASS로 단언하고, 부재는 FAIL로 적는다([[real-call-gate-weak-predicate]]) |
| 앱 소스 가드(Vitest) | 진입점 부착이 `TransitRouteRows` 한 자리인지 · 로터 액션 선언이 `reversed()`를 지나는지 · `showsDirectionsEntry: false`가 브리핑 경로에 붙는지 · `transitStationMentions`를 브리핑에서 **부르지 않는지**(§3.2 판정 고정) |
| 변이 주입 | 커밋 뒤에 돌린다([[mutation-injection-commit-first]]). 축 넷: `.walk` 게이트에서 `mode == "subway"` 제거 → 버스 진입점이 생기는지 · `reversed()` 제거 → 로터 순서 테스트가 빨개지는지 · `stops.last` → `stops.first` → 하차 줄 대상 테스트 · 노선 힌트를 `legs[i]`로 바꿈 → 도보 줄 테스트 |
| a11y 감사 | `a11y-auditor`(또는 general-purpose + 역할 파일) — 줄 전체 버튼이 한 접근성 객체로 남는지, 과잉 ARIA·중복 낭독이 없는지 |
| **실기기 VoiceOver(정본)** | **판정 ⑦로 1건**: 거리 줄을 `Button`으로 감쌌을 때 낭독 정정이 살아 있는지. 현행 도보 줄은 `Text("…320m").accessibilityLabel(Text(spokenUnits("…320m")))`(`distanceText`, `NearbyLoadState.swift:27`)인데, `Button(label:)`로 감싸면 버튼의 접근 가능한 이름이 그 정정본으로 계산되는지 확인이 필요하다. 실패하면 "320 분"으로 들린다 — 그때는 `Button`에 `.accessibilityLabel`을 직접 단다 |

⚠ 뷰 계층은 테스트 레인이 없다. 배선은 소스 가드로 잠근다(E33·A35 선례).
