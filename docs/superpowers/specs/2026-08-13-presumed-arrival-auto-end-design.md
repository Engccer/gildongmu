## 2. 목표·비목표

- **목표**: 도보 안내의 최종 접근 국면에서 실내 진입 신호가 지속되면 도착으로 간주하고 도착 종을 울린 뒤 자동 종료한다.
- **비목표(범위 제외, §7)**: 자동차 세션, 경로 중간 무진행 리마인더, 대중교통 세션의 잊힌 세션 정리, 웹 UI 배선.

## 3. 판정 계층 (새 순수 함수, 웹·Kit 미러)

`presumedArrivalStep` — Kit `FinalApproach.swift` + 웹 `src/lib/final-approach.ts`(기존 최종 접근 미러 자리)에 나란히 둔다.

입력(전부 유한한 0 이상 값만 유효 — 음수·NaN·무한은 `.none`으로 안전 처리):
- `inFinalApproach: Bool` — 최종 접근 국면 여부.
- `secondsSinceUsableFix: Double` — **기준은 `max(최종 접근 진입 시각, 마지막 usable fix 시각)`**. 진입 시각을 하한으로 두지 않으면 진입 전부터 fix가 늙어 있던 세션이 진입 직후 첫 틱에 종료된다(리뷰 C3).
- `secondsSinceProgress: Double` — 마지막 "진행 관측" 이후 경과. **진행 관측은 앵커 기준 누적 변위다**: 앵커 좌표에서 `progressEpsilonMeters` 이상 벗어난 usable fix가 오면 진행으로 기록하고 그 좌표를 새 앵커로 삼는다. 직전 fix와 비교하면 1m/s 연속 보행이 매 fix 10m 미만이라 5분 300m를 걷고도 제자리로 오판된다(리뷰 C2 — 이 정의 차이가 이 설계의 가장 큰 오탐 축이었다). 기준 시각의 하한은 최종 접근 진입 시각(위와 동형).
- `lastKnownDistanceToDestMeters: Double?` — 마지막 usable fix 기준 목적지 직선거리. nil(한 번도 없음)이면 거리 캡을 통과하지 못한다.

출력: `.none` | `.presumedArrived(reason: .noFix | .stationary)`

판정(순서 고정):
1. `inFinalApproach == false` → 항상 `.none`. **경로 중간 자동 종료 금지의 1선 방어는 이 구조다** — 판정 함수가 국면 입력 없이는 도착을 낼 수 없다.
2. `lastKnownDistanceToDestMeters`가 nil이거나 `presumedArrivalMaxDistanceMeters` 초과 → `.none`. 최종 접근 진입 후 목적지를 지나쳐 멀어진 뒤 실내 진입한 경우(다른 볼일)를 "도착"으로 오판하지 않는다(리뷰 C4).
3. `secondsSinceUsableFix >= presumedArrivalNoFixSeconds` → `.presumedArrived(.noFix)` (오늘 실사고 모양: 실내 진입으로 fix 두절).
4. `secondsSinceProgress >= presumedArrivalStationarySeconds` → `.presumedArrived(.stationary)` (fix는 오는데 도착 반경 밖에서 제자리 — 실내 wifi 측위로 오프셋 좌표에 고정되는 모양).
5. 그 외 `.none`.

### 상수 (전부 잠정값 — 실보행 재판정이 정본)

| 상수 | 값 | 근거 |
|---|---|---|
| `presumedArrivalNoFixSeconds` | 180 | 최종 접근 구간은 목적지 ≤ ~100m(오프셋 실측 16~89m). 보행 1.5분 거리에서 3분 무신호면 실내 진입이 유력. 짧으면 GPS 음영 오탐, 길면 도착 종이 무의미하게 늦는다. 참고: `isUsableFix`는 정확도>0 + 신선이면 통과하는 관대한 술어라, 옥외 보행 중 3분 연속 unusable은 드물다(대개 실내·지하 진입 신호). |
| `presumedArrivalStationarySeconds` | 300 | 목적지 코앞 벤치 휴식·긴 신호 대기 오탐을 줄이기 위해 noFix보다 길게. 5분 초과 옥외 정지는 오탐 잔여 위험으로 수용(발동이 종+낭독으로 공표되고 재시작 가능). |
| `progressEpsilonMeters` | 10 | 앵커 기준 누적 변위 하한. GPS 지터가 앵커 주변 왕복으로 진행을 위조하지 않는 선. ⚠ 실내 지터가 상시 10m를 넘는 환경에선 stationary 축이 영영 안 여는 미탐이 남는다 — 현상 유지 대비 악화는 아니며(오늘도 미종료) 실측으로 튜닝한다. |
| `presumedArrivalMaxDistanceMeters` | 150 | 최종 접근 오프셋 실측 상한 89m + GPS 오차 여유. 이 밖에서의 fix 두절은 "도착"이 아니라 "이탈 후 소실"이다. |

## 4. iOS 배선 (`BeaconModel`) — walk 전용

`GuideTuning`에 게이트를 둔다(walk만 활성, car는 null — `imminentAheadM` walk 전용 선례와 동형). 자동차는 지하차도·지하주차장 진입로·정체(5분 정지가 일상)가 보행과 전혀 다른 분포라 도보 근거 상수를 공유할 수 없다(리뷰 C5) — 백로그로 분리.

트리거 지점 2곳(모양별로 도달 경로가 다르다):
- **워치독 틱**(`tickWatchdog`, 기존 2초 주기에 얹는다 — 새 타이머 없음): `.noFix` 모양은 fix가 안 오므로 fix 경로에는 걸 수 없다(기존 "fix 부재는 타이머 워치독" 원칙 동형). 실제 발동 시점은 "임계 도달 이후 첫 틱"이다(순수 함수 경계와 런타임 지연은 별개 계약).
- **`handleFinalApproach`**: `.stationary` 모양(usable fix 수신 중). 진행 앵커 갱신·`lastKnownDistance` 갱신도 여기서.

**상태 초기화 계약**(리뷰 M5): 진행 앵커·기준 시각·`lastKnownDistance` 등 이 판정의 모든 상태는 ①세션 시작 ②경로 재탐색(재조회 수락 포함) ③목적지 변경 ④최종 접근 진입 시점에 전부 리셋한다. 이전 에피소드의 타임스탬프가 새 에피소드로 새면 조기 종료가 된다.

**원자성**: `BeaconModel`은 MainActor 직렬이고 두 트리거 모두 `isTracking` 가드를 지나며 `stop()`이 동기적으로 `isTracking`을 내린다 — 중복 발동 경로가 없다. 자동 종료는 전용 함수 하나(`autoEndPresumedArrival()`)로 봉인해 확정 도착 경로와 나란히 둔다.

발동 시(기존 확정 도착 경로 동형, 문구만 분리):
1. 통지 문장을 먼저 조립(기존 주석 계약: `stop()`이 dest·statusText를 지운다).
2. `playTone(.nearby)` — 도착 종(확정 도착과 같은 종 — "종 = 도착"의 일관성 유지). 배경 가청은 기존 `endSession` 잔여 대기 규칙이 보장.
3. `stop()` 후 `arrivalDest` 대입 — 시트를 도착 종료 화면으로 유지(기존 presentation 바인딩 재사용). 통지를 놓쳐도 화면에 종료 사실이 남는 2차 증거다.
4. `guide.arrivedPresumed` 낭독, **`.high`** — "{목적지} 부근에 도착한 것으로 판단해 안내를 종료했습니다." ⚠ "신호가 약해져"류 원인 서술 금지 — `.stationary` 모양에선 fix가 계속 오고 있어 거짓이 된다(리뷰 M6). "판단해"가 추정임을 전달한다. 백그라운드 음성 억제 시 기존 전경 복귀 상환 메커니즘을 태우되, **상환 큐가 `stop()` 이후에도 생존하는지 구현에서 확인·테스트한다**(리뷰 M7).
5. 도착 시트 헤딩도 추정 전용 문구(`ios.beacon.arrivedPresumedHeading`) — 확정 도착과 뭉개지 않는다(3-state 정직성).

리셋(오탐 방어): usable fix가 오면 `.noFix` 축이 리셋되고, 앵커에서 10m 이상 변위가 확인되면 `.stationary` 축도 리셋된다(아직 걷는 중). 걸어서 멀어지는 경우는 변위 리셋 + 150m 거리 캡의 이중 방어다.

## 5. 불변식

- 자동 종료 경로는 정확히 두 곳: 확정 도착(반경 15m)과 추정 도착(이 설계, `autoEndPresumedArrival()` 단일 함수). 그 외 어디서도 세션을 소리 없이 끝내지 않는다.
- 추정 도착은 **도보 세션의 최종 접근 국면 + 마지막 확인 거리 ≤150m**에서만 가능하다(판정 함수 구조가 강제).
- 추정 도착 발동은 세션당 최대 1회다(`stop()`이 상태를 소거하고 MainActor 직렬성이 경합을 배제).
- 확정·추정 도착의 낭독·헤딩 문구는 다르다. 추정 문구는 원인을 단정하지 않는 중립 서술이다.
- 시간원은 monotonic(기존 `uptimeNow` = systemUptime)이다 — wall clock 역행·보정과 무관.

## 7. 범위 제외 (백로그 등록)

- **자동차 세션**(리뷰 C5로 이번 라운드에서 제외): 정체·지하 구간 분포가 달라 별도 상수·실주행 검증 필요.
- **경로 중간 무진행 리마인더**: 위원장 판정으로 백로그(2026-08-13). 백그라운드 음성 억제 정책 때문에 도달 채널이 로컬 알림(권한 요청 신설)이어야 하는데, 그 권한·UX 판정을 포함해 별도 설계가 필요하다.
- **대중교통 세션**: 지하 구간 fix 부재가 정상이라 이 판정을 재사용할 수 없다. 별도 축(예: 최종 하차 후 무진행) 필요.
- **웹 UI 배선**: 판정 함수 미러+공유 fixture까지만 이번에. 화면 배선은 PORTS 후속(iOS 먼저·웹 후속 관례).
- **최종 접근 진입 전 fix 두절**(목적지 200m 전 GPS 사망 후 도보 귀가), **실내 지터 >10m로 両축이 안 열리는 미탐**, **간헐 fix(3분 미만 간격)가 noFix를 계속 리셋하는 미탐**: 셋 다 자동 종료 없음 — 현상 유지 대비 악화가 아니고(오늘도 미종료), 리마인더 축이 열리면 그쪽이 덮는다. ⚠ 이 케이스들에서 offRoute 경고음은 기대할 수 없다(fix가 없으면 이탈 판정도 없다) — "경고음이 이미 운다"는 근거는 usable fix가 살아 있는 이탈에만 성립한다(리뷰 M8 정정).

## 8. 설계 리뷰 판정 (codex adversarial-review 2026-08-13)

①새 판정 계층 신설(세션 수명을 끝내는 판정) + ④실보행 안내 안전 크리티컬 축 해당 → 구현 착수 전 codex adversarial-review 실행 완료(gpt-5.6-sol, spec 직접 주입).

**수용(설계 반영)**: C2 진행 관측을 직전 fix 비교→앵커 기준 누적 변위로 재정의(느린 연속 보행 오탐 — 최대 결함), C3 noFix 기준 시각에 최종 접근 진입 하한, C4 마지막 확인 거리 캡 150m, C5 자동차 제외(walk 전용 게이트), M5 상태 초기화 계약 명문화, M6 낭독 문구 중립화(원인 단정 제거), M7 상환 큐의 stop() 생존 검증 항목화, M8 offRoute 근거 정정, M9 반례 테스트 우선 추가, MINOR 무효 입력 안전 처리·틱 지연 계약 명시.

**기각(근거 기록)**: ⓐ"noFix 단독 종료 금지, 독립 근거 추가 요구"(C1) — `isUsableFix`가 관대한 술어(정확도>0+신선)라 옥외 3분 연속 unusable 자체가 실내·지하 신호이고, 거리 캡(C4 수용)이 잔여 오탐을 줄이며, 발동은 침묵이 아니라 종+`.high` 낭독+도착 화면으로 공표되고 재시작 가능하다. 요구된 "접근 추세" 축은 방위 관측이 보행 속도에서 신뢰 불가라는 기존 실측(A6)과 충돌한다. ⓑ"pendingTermination 2단계 상태 머신 + 종료음 전달 확인 후 종료"(C7) — 확정 도착 경로에 없는 방어를 추정 경로에만 얹는 비대칭 과잉. 전달 실패 모드는 확정 도착과 동일하게 수용하고 도착 화면 잔존이 2차 증거다. ⓒ원자성 기계장치·terminal latch(M4) — MainActor 직렬성+`isTracking` 가드로 충분(구조가 이미 배제). ⓓ백그라운드 wake 순서 유예 구간(C6) — 시간원이 monotonic이고 판정·fix 처리가 같은 actor 직렬이라 역전 창이 한 틱(2초)뿐, 임계 180초 대비 무시 가능. ⓔ`stop()` 직접 호출 정적 검사(M10) — 자동 종료를 단일 함수로 봉인하는 선까지만 수용, 소스 가드는 과잉.
