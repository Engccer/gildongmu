# 최근 검색 기록 (Recent Searches) 설계

> 2026-07-26 확정. 대상: iOS 앱 + 웹 동시. 검색 탭 검색창과 길찾기 출발지/도착지 검색창에
> 최근 검색 기록을 노출하고, 전체 삭제와 항목별 삭제(iOS는 VoiceOver 로터 커스텀 액션)를 제공한다.

## 1. 목적

- 반복 검색(집·직장·자주 가는 장소)을 재타이핑 없이 한 번의 선택으로 재실행/재확정한다.
- 스크린 리더 사용자에게 특히 유효: 타이핑·받아쓰기 비용이 크므로 기록 재사용의 가치가 높다.

## 2. 데이터 계약 (양 플랫폼 공통)

두 종류의 기록을 **분리 저장**한다.

| 기록 | 대상 화면 | 저장 내용 | 선택 시 동작 |
|---|---|---|---|
| 검색어 기록 | 검색 탭 검색창 | 제출된 검색어 문자열 | 그 검색어로 재검색 실행 |
| 장소 기록 | 길찾기 출발지/도착지 | 확정 endpoint(라벨+좌표) | 재검색 없이 필드 즉시 확정 |

- **길찾기 출발지/도착지는 한 목록을 공유**한다(출발지로 쓴 장소를 도착지로도 쓴다).
- 최대 **20개**, 최신순. 재사용·재기록 시 중복 생성 없이 맨 위로 끌어올림(dedupe).
  - 검색어 dedupe: trim 후 완전 일치.
  - 장소 dedupe: 좌표 소수 4자리 반올림 일치(라벨 무관 — 같은 장소의 라벨 변형은 최신 라벨로 교체).
- **"현재 위치 사용"은 기록하지 않는다**(전용 버튼이 항상 있어 중복).
- 주소 후보 선택은 지오코딩 성공 후 장소 기록에 남긴다(라벨=도로명 주소).
- 기록 시점:
  - 검색어: 검색 제출 시(타이핑 제출·음성 확정 공통 경로). 결과 0건이어도 기록(재시도 가치).
  - 장소: endpoint 확정 시(iOS `setEndpoint` 경로의 `.place`만, 웹 `resolveAndClose`).
    프리필(`DirectionsPrefillStore`) 확정도 동일 경로면 함께 기록된다.

## 3. 저장

- **기기 로컬 전용**. 서버 전송 0.
  - iOS: `UserDefaults` (키 `recentQueries.v1` / `recentEndpoints.v1`, JSON 인코딩).
  - 웹: `localStorage` (키 `gildongmu:recent-queries:v1` / `gildongmu:recent-endpoints:v1`).
- 파싱 실패·스키마 불일치는 빈 목록으로 조용히 복구(throw 금지 — 기록은 부가 기능, 본 기능을 막지 않는다).
- 웹은 SSR 가드 필수(`localStorage`는 클라이언트 전용 접근).
- **개인정보 3자 일치 불변식 영향 없음**: 수집·전송 항목 불변(로컬 저장만) — privacy 카피·xcprivacy·영양 라벨 갱신 불필요.

## 4. 표시 시점·위치

- **검색 탭**: 검색 결과가 없는 초기 상태(제출 전)에만 "최근 검색" 섹션 노출. 결과가 나타나면 숨김.
  - iOS: `SearchView` List에서 마이크 행 다음 섹션(`.searchSuggestions` 대신 List 섹션 —
    검색 필드 활성화 없이 VoiceOver 스와이프 탐색 경로에 들어오고 기존 화면 구조와 동형).
  - 웹: `PlaceSearch` 초기 상태(빈 쿼리·무결과)에 섹션으로.
- **길찾기**: 후보 검색 전 상태에만 노출.
  - iOS: `DirectionsEndpointSearchView` 시트에서 "현재 위치 사용" 행 다음, 후보 목록 자리.
  - 웹: `EndpointField` 입력창 아래 후보 없을 때.
- 섹션 이름은 "최근 검색" 단일 heading(웹 h 계층은 주변 관례를 따름). 목록이 비면 섹션 자체 미노출(빈 섹션 금지).

## 5. 삭제 UX

- **항목별 삭제**:
  - iOS: List `.swipeActions` 삭제 버튼 → VoiceOver **로터 커스텀 액션으로 자동 노출**
    (위/아래 스와이프 삭제)되고 시각 사용자 스와이프 삭제도 같은 코드로 해결.
  - 웹: 각 항목 옆 삭제 버튼(인터랙티브 요소는 별도 접근성 객체가 정상 — 헌장 §4).
    버튼 접근 이름에 대상 포함("○○ 삭제") — 목록 안 동명 버튼 구분.
- **전체 삭제**: 섹션 끝 "최근 검색 모두 지우기" 버튼 1개.
- **삭제 후 포커스 계약**(헌장 §5 — 포커스를 쥔 요소가 사라지는 전이):
  - 삭제된 항목의 **다음 항목**으로, 마지막 항목이었으면 **이전 항목**으로 이동.
  - 목록이 비면(마지막 항목 삭제·전체 삭제) 섹션이 사라지므로 **검색 진입점으로 이동**
    (iOS는 두 화면 모두 항상 존재하는 마이크 행, 웹=검색 input).
  - 삭제 결과는 polite 통지 1건("삭제됨"/"최근 검색을 모두 지웠습니다").
- 항목 행 자체는 "한 줄 = 한 객체": 검색어는 단일 텍스트, 장소는 라벨 단일 텍스트(좌표 비노출).

## 6. 구현 위치

- **iOS**: 저장·dedupe·cap 로직은 `GildongmuKit`에 `RecentSearchStore`(순수 로직, 단위 테스트 동반,
  UserDefaults 주입 가능하게). 뷰 배선은 `SearchView`·`DirectionsEndpointSearchView`.
- **웹**: `src/lib/recent-searches.ts`(React/Next 비의존 — dodo 이식성, localStorage 접근은 가드된 어댑터)
  + 단위 테스트. 배선은 `PlaceSearch`·`DirectionsView`(`EndpointField`).
- **i18n**: 신규 키는 웹 `messages/*`(전 로케일) 정본에 추가 → iOS xcstrings 결정론 변환 파이프라인 경유
  (키 예: `recent.title`, `recent.clearAll`, `recent.delete`, `recent.deleted`, `recent.cleared`).

## 7. 테스트

- 저장 로직(양 플랫폼): 추가·dedupe 끌어올림·20개 cap·삭제·전체 삭제·파싱 실패 복구를 단위 테스트로.
- 웹 i18n 키 일관성은 기존 `i18n-messages.test.ts` 게이트가 커버.
- 컴포넌트 배선·VoiceOver 로터 동작은 실기기/실브라우저 검증(머지 게이트 관례).
