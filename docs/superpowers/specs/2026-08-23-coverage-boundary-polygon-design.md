# 커버리지 사각형 → 국경 폴리곤 승격 (E19)

> 백로그 `docs/BACKLOG.md` §5 E19. 병렬 계획 `2026-08-23-backlog-sweep-parallel-plan.md` 웨이브 2, 세션 e19.
> 선행 판정(코디네이터 확정): **`isInKorea`의 뜻은 "한국 안인가"이지 "이 upstream이 답하는 범위인가"가 아니다.** upstream 범위는 `unavailableHere`(국내 지역별 미제공)와 0건 축이 따로 든다. 그러므로 폴리곤 승격이 맞다.

## 1. 문제

`src/lib/coverage.ts`의 `isInKorea`는 사각형(31.43~44.35 / 122.37~132.0)이다. 그 사각형은 **일본 서부(후쿠오카·기타큐슈·대마도·시모노세키)와 중국 동부, 북한 남부(개성·해주)를 포함**한다. 같은 결함을 2026-08-16 E12 리뷰가 walk seed에서 잡아 그 provider만 폴리곤으로 고쳤고, 나머지 좌표 라우트 20종·웹 클라이언트·iOS Kit은 사각형에 남았다.

지금은 upstream이 실제로 답을 주므로 거짓말의 출처가 우리 판정이 아니다(후쿠오카에서 커버리지를 통과해도 카카오가 0건을 낸다). 그래서 긴급하지 않다. 그러나 **서버 왕복이 없는 소비자에서는 사각형이 최종 판정**이고(`deeplink.ts`가 후쿠오카 좌표에 `nmap://` 링크를 만든다), 정확한 판정에 필요한 데이터는 E12가 이미 seed 안에 넣어 두었다(`osm-walk-nodes.json`의 `boundary`, 링 4개·좌표점 2,580). **새 데이터가 필요 없다.**

## 2. 결정

### D1. 판정 술어는 하나다 — 클라이언트·서버·Kit 전부 폴리곤

`isInKorea(lat, lng)` = 사각형 프리필터 + 링 ray casting. 호출부는 한 줄도 바뀌지 않고 정밀도만 올라간다.

**기각한 대안: 2층(클라 사각형 프리필터 / 서버 폴리곤 판정).** 사각형은 폴리곤의 상위집합이라 거짓 "밖"을 낼 수 없고, 클라이언트의 사각형 통과는 서버 마커가 받아 주므로 화면 문장은 같다 — 여기까지는 성립한다. 기각 이유는 둘이다. ①**서버 왕복이 없는 소비자**(`deeplink.ts`·`deeplink-kakao.ts`)에서는 그 사각형이 최종 판정이라 거짓말이 남는다. ②"느슨한 클라 술어"를 이름 있는 API로 남겨 두면 다음 클라 전용 기능이 그것을 집어 같은 거짓말을 재도입한다 — 리포 메모리 `rectangle-coverage-lies-near-borders`가 기록한 재발 기제가 정확히 그것이다.

**대가(실측)**: 클라이언트 번들 +53,565 bytes raw(gzip 15,089). 현 `.next/static/chunks` 합계 1.3MB 대비 약 4%. 수용한다 — 이 앱의 1급 사용자에게 판정 정확도가 4%의 바이트보다 비싸다.

**하지 않는 것**: 좌표 양자화·폴리곤 단순화로 바이트를 줄이는 것. 임계값에 근거를 붙여야 하고(§4 G11이 8만 노드를 링 안에 요구하므로 단순화는 빌드를 깨뜨릴 수 있다), 4%는 그 복잡도를 살 만한 이득이 아니다.

### D2. 폴리곤은 한 벌이고 walk seed에서 분리한다

`src/lib/data/korea-boundary.json`을 신설하고 `osm-walk-nodes.json`에서 `boundary` 필드를 뺀다.

- **분리가 선택이 아닌 이유**: seed는 2.8MB(노드 79,575)다. `coverage.ts`가 그 파일을 import하면 클라이언트 번들이 통째로 무너진다.
- **두 벌 금지**: `osm-walk-nodes.ts`의 `isInWalkSeedCoverage`와 그 안의 `SEED_BBOX`를 삭제하고 `isInKorea`를 부른다. 링이 두 파일에 있으면 한쪽만 갱신되는 드리프트가 생기고, 그때 "walk만 제공 지역 밖"이라는 조용한 갈림이 된다.
- **생성은 그대로 연 1회 `scripts/build-osm-walk-nodes.mjs`**: 국경 질의(`BOUNDARY_QUERY`)와 가드 G9~G11은 그 스크립트에 남고 출력 파일만 갈린다. 두 산출물(`osm-walk-nodes.json`·`korea-boundary.json`)을 한 실행이 함께 쓴다 — 링과 노드가 **같은 시점의 같은 국경 정의**여야 G11이 뜻을 갖기 때문이다.
- **ODbL**: 분리된 파일도 OSM 파생이라 `NOTICE.md`에 자기 행을 갖는다. 공공데이터 seed와 합치지 않는다는 기존 제약은 그대로다(오히려 분리로 더 명확해진다).

### D3. Kit은 SPM 리소스 사본 + 바이트 동일 드리프트 테스트

`ios/GildongmuKit/Sources/GildongmuKit/Resources/korea-boundary.json`(`.copy`)을 두고 `Coverage.swift`가 `Bundle.module`에서 한 번 파싱해 캐시한다.

- **2,580점 Swift 리터럴을 기각한 이유**: 타입 검사 비용이 크고, 손으로 고칠 수 있는 형태라 정본이 둘이 된다.
- **선례**: `Localizable.xcstrings`가 이미 `.copy` 리소스 + 생성 스크립트 + 키 검사 골격을 쓴다. 같은 자리를 따른다.
- **드리프트 강제**: 웹 파일과 Kit 리소스는 **바이트 동일**이고 vitest 드리프트 테스트가 그것을 단언한다(`endpoint-catalog-shared.ts` 해시 가드 동형). 빌드 스크립트가 두 경로에 같은 바이트를 쓴다.

### D4. 골든은 공유 fixture 한 벌

`src/lib/__tests__/fixtures/korea-boundary-cases.json`. 기존 `BOUNDARY_GOLDEN` 14점에 E19가 지정한 좌표(서귀포)를 더한다. **세 곳이 같은 표를 본다**: 웹 vitest · Kit `CoverageTests.swift`(`#filePath` 상대 경로, `car-action-cases.json` 선례) · 빌드 스크립트 G10.

표는 사각형으로는 통과할 수 없다 — 앞의 여섯(후쿠오카·기타큐슈·대마도·시모노세키·개성·해주)이 현 사각형 **안**이고, 개성은 파주와 위경도가 겹쳐 어떤 사각형 뺄셈으로도 갈리지 않는다.

### D5. 소비자는 바꾸지 않는다

- 좌표 라우트 20종·웹 클라이언트 7곳·채팅 `coverageGate`·Kit `NearbyLoadCore`·`DirectionsTabView`·`Deeplink`는 전부 `isInKorea`를 부르므로 승격이 자동 전파된다.
- CLI(`packages/cli/src/lib/api-client.ts`)·MCP(`packages/mcp/src/index.ts`)의 `isOutOfCoverage`는 **서버 마커만 읽는다**(자체 좌표 판정이 없다). 변경 0 — 확인만 한다.

## 3. 새 실패 모드와 그 방어

사각형에는 없던 실패 모드가 하나 생긴다: **국내 좌표가 폴리곤 밖으로 떨어지면 그 기능이 통째로 죽는다**(거짓 "서비스 지역 밖"). 사각형은 넉넉해서 이 방향으로는 틀릴 수 없었다.

방어 셋:
1. **골든에 국토 사방 극점**(마라도·독도·백령도·강원 고성·가덕도·정선읍·파주 문산·서귀포).
2. **두 구현의 합의를 8만 점으로 확인**: 빌드 스크립트의 `insideRings`와 `coverage.ts`의 ray casting은 서로 다른 코드다. seed 노드 79,575점 전수를 `isInKorea`로 다시 판정해 전부 `true`인지 보는 계약 테스트를 둔다. 링이 잘못 실렸거나 두 구현이 어긋나면 여기서 즉시 드러난다(G11이 빌드 시점에 보는 것과 같은 명제를 런타임 구현으로 다시 본다).
3. **경계는 해안선이 아니라 영해 경계선**이라 연안·항만·앞바다가 넉넉히 안쪽이다(좌표점이 2,580개뿐인 이유이기도 하다).

**변이 주입으로 잰 검출력(2026-08-23)** — "계약 테스트가 있다"와 "그 축이 지켜진다"는 다르므로 실측했다.

| 변이 | golden 15점 | 노드 전수 |
|---|---|---|
| 링 하나만 사용(섬 링 소실) | 3건 실패 | 실패 |
| 링 비움(리소스 로드 실패) | 9건 실패 | 실패 |
| lat/lng 뒤바꿔 파싱 | 9건 실패 | 실패 |
| 폴리곤 판정 제거(구 사각형 동작) | 6건 실패 | 통과 |
| 균일 이동 +0.05°(약 6km) | 통과 | **실패**(경도축) |
| 균일 이동 +0.2°(약 22km) | 실패 | 실패 |
| 균일 이동 ≤0.02°(약 2km) | 통과 | 통과 |

읽는 법 둘. ①**노드 전수 계약이 golden보다 약 4배 민감하다**(6km vs 22km) — 골든만 두었으면 못 잡는 폭이 있다. ②**2km 이하 균일 이동은 어느 축도 못 잡는데, 그것이 문제가 아니다**: 가장 가까운 외국 육지(대마도)가 50km 밖이고 개성은 군사분계선에서 10km 북쪽이라, 그 폭의 오차로는 어떤 실제 판정도 뒤집히지 않는다. 데이터 자체의 해상도(OSM 경계선 근사)보다 작은 오차이기도 하다.

⚠ 검출되지 **않는** 것으로 확인된 무해 변이가 하나 더 있다: `lng < xAt`를 `lng > xAt`로 뒤집어도 판정이 같다(닫힌 링에서 점의 좌·우 교차 수는 패리티가 같다). 결함이 아니라 동치 표현이므로 그대로 둔다.

| 단위(웹) | 공유 fixture 15점 전수 판정 |

| 드리프트(웹) | `src/lib/data/korea-boundary.json` ↔ Kit 리소스 바이트 동일 |

| 라우트 | 좌표 | 응답 |

## 5. 범위 밖 (BACKLOG E19에 기록만)

커버리지를 통과한 뒤 upstream이 국내 전용이라 0건을 내는 라우트별 문장 갈림("그 근처에 없다" vs "그 지역은 제공 안 된다")을 표로 남기고 **수정하지 않는다**. 그 축은 `unavailableHere`(지역별 미제공)와 0건의 층이지 커버리지 마커의 층이 아니다.

## 6. 설계 리뷰 판정

**적대적 설계 리뷰 생략.** 근거: 새 불변식·판정 계층의 신설이 아니라 **기존 술어의 정밀도 교체**이고(호출부·응답 계약 불변), 파급이 국소·가역이며, 새 외부 계약이 없다(데이터는 이미 repo 안에 있다). 잔여 리스크는 §3의 새 실패 모드 하나이고 §4의 전수 계약 테스트가 그것을 덮는다. 구현 단계 서브에이전트 리뷰(spec-compliance + code-quality)는 그대로 돈다.
