# 실시간 도보 안내 하단 2행 재설계 — 현재 행동 실시간 갱신 + 다음 안내 정적 예고

2026-08-11. 실보행 라운드2 피드백(2026-08-10 저녁 왕복, 자택↔주택 A)의 최상위 항목 반영. 위원장 확정 설계(2026-08-11 새벽 논의 4라운드) + 적대적 설계 리뷰 11건 반영(§9).

> **개정 2026-08-12**: 투영 지연 추정 `PROJECTION_LAG_M` 15→10 하향(위원장 실보행 재판정, 자택↔오아시스마켓 왕복 — 15는 실제 지연보다 크게 잡혀 표시·임박이 실위치보다 앞서갔다). 유도식(임박 = 10 + lag)은 유지되어 임박 큐는 25→20m. 본문 §3의 15·25 수치는 초기값 기록이다.

## 1. 문제 (실보행 피드백)

하단 2행(현재 안내 행 + 상태 행)이 서로 다른 두 정보를 동시에 줘 보행 중 파악이 혼란스럽다. 구체적으로:

- **한 문장에 두 정보**: "왼쪽으로 돌아 파리바게뜨까지 명일로를 따라 58m 이동"은 회전 안내와 직진 안내가 결합된 문장이다. 출발 전 조망에서는 한 의미 단위지만 보행 중에는 두 개의 다른 정보다.
- **낡은 정보의 잔류**: 이미 회전을 마쳤는데 회전 지시가 남아 있고, 50m를 걸었는데 여전히 58m라고 표시된다. 현재 안내 행은 구간 경계에서만 갱신되는 정적 문장이라 구간 내내 낡아간다.
- 요구: **1문장 1정보**. 현재 안내는 지금 실행할 행동 하나를 진행에 따라 갱신("파리바게뜨까지 58m 직진하세요", 숫자 실시간 감소)하고, 그 아래에는 다음 행동이 정적으로 예고되며, 현재 안내의 정보 가치가 소멸하는 순간 다음 안내가 위로 올라오며 동적으로 바뀐다(영상 자막 구조).

## 2. 확정 결정 (위원장, 2026-08-11)

1. **역할 고정 2행**: 윗줄 = 현재 행동(동적), 아랫줄 = 다음 예고(정적, 기존 확정 라벨 "다음 안내," 재사용). 종전 상태 행은 폐지하고, 상태(불확실·이탈·재획득)는 활성인 동안 **윗줄을 대체**한다(그 순간 안내는 무효라 두 정보가 공존할 순간이 없다).
2. **직진 카운트다운은 미터 단위**: 5m 뭉개기 기각(위원장 반론 → A6 실측 인접 fix 상대 잡음 중위 0.42m + 상시 잔여 거리 행의 실사용 판정이 근거). 소폭 역행은 직전 값 유지로 흡수.
3. **편향 모델은 하나만, 문턱·표시·구간 선택에 일관 적용**(위원장 반론 수용으로 확정, 리뷰 F1로 적용 범위 확장): 투영이 실제보다 ~15m 늦게 따라오는 편향을 임박 문턱(10→25 상향)에만 적용하고 표시에는 적용하지 않으면 한 화면에 편향 모델이 두 개가 되어 내적 불일치가 노출된다. **일관된 오차는 사용자가 내재 오차로 예측할 수 있지만, 일관성이 깨진 계산은 정체 모를 의구심을 만든다.**
4. **회전 접근 국면은 "{n}m 후 {행동}" + 숫자 실시간 감소**: 표시 잔여 10부터 전환. 편향 통일(§3)로 표시 10 = 원시 계산 25 = 임박 큐 시점이 유도식으로 일치한다.
5. **윗줄에 도로명 생략**: "명일로를 따라"는 40m 음성 전문·출발 전 조망에 남는다(1문장 1정보).
6. **조망·다음 안내·음성 전문의 거리는 지도 값 그대로**: 구간 길이(이정표)와 지금 남은 거리(계기판)는 다른 종류의 숫자다.

## 3. 표시 좌표계 — `PROJECTION_LAG_M` (리뷰 F1·F7·F10 반영)

표시 계층은 **잔여 거리만 보정하는 것이 아니라 좌표계 전체를 보정한다**. 원시 투영 진행거리 `d`에 지연을 더한 유효 진행거리로 구간 선택·국면·잔여를 모두 계산한다:

```
PROJECTION_LAG_M = 15                          // 투영 지연 추정(m), 실보행 2회 일관 실측 기반 초기값
effectiveLag     = min(PROJECTION_LAG_M, 세션·재조회 기준점 이후 원시 진행거리)   // 램프인(F7)
effectiveD       = d + effectiveLag            // 표시 계층 전용 좌표. 음성 계층은 원시 d 유지
displayRemaining = floor(max(0, 표시 유닛 끝 − effectiveD))                       // 정수화는 버림(F8)
IMMINENT_AHEAD_M = 10 + PROJECTION_LAG_M       // = 25, 값 불변 (유도식으로 재정의)
```

- **좌표계 통일이 잡는 것(F1)**: 잔여만 보정하고 구간 승격을 원시 `d`에 맡기면, 회전을 실제로 마친 뒤에도 원시 투영이 경계를 넘기까지 ~15m 동안 "잠시 후 오른쪽으로 도세요"가 잔류한다. `effectiveD`로 구간을 선택하면 표시 구간 전이가 실제 모퉁이 도달 시점과 일치한다.
- **램프인(F7)**: 지연은 이동 중 쌓이는 오차라 출발·재조회 직후(투영이 기준점에 정렬된 상태)에 15를 통째로 빼면 과소 표시가 된다. `effectiveLag`를 "그 기준점 이후 걸은 원시 거리"로 상한 걸어, 걷기 시작하며 자연스럽게 15까지 차오르게 한다. 짧은 첫 구간이 출발 즉시 "잠시 후 회전"으로 붕괴하는 문제도 함께 사라진다.
- **불변식 A — 음성 불변(이번 변경 한정, F10 반영)**: 이 spec은 화면 표시만 바꾼다. 음성·톤·햅틱 파이프라인은 원시 `d`를 계속 쓰고, `IMMINENT_AHEAD_M`은 lag=15에서 값 25로 동일하므로 이번 리팩터의 이벤트 시퀀스는 byte-identical이다(기존 음성 시나리오 fixture 전체 기대값 무수정 통과가 증명). **향후 lag 상수 갱신은 음성 문턱을 함께 움직이는 의도적 행동 변경이며**, 자동 갱신이 아니라 실보행 리플레이 근거 + spec 개정 + 실보행 재판정을 동반해야 한다.
- **불변식 B — 한 곳 정의**: lag 상수와 `effectiveD` 유도는 웹 `route-guide.ts` ↔ Kit `RouteGuide.swift` 한 쌍에만 존재한다. 표시 계층에 15·25를 직접 쓰면 drift다.
- 편향이 반대로 흐르는 날엔 전환이 다소 일러지는데 이는 늦는 것보다 안전한 방향이다(의도적 수용).

## 4. 파생 계층 — `guideLiveRows` (리듀서형 순수 함수, 웹 ↔ Kit 미러)

새 파일 웹 `src/lib/guide-live-rows.ts` ↔ Kit `GuideLiveRows.swift`. **`guideStep`과 같은 리듀서형이다**(F3): `(prevRowState, 입력) → (nextRowState, rows)`. 입력은 리듀서가 이미 계산하는 값만 받는다(경로 + 구조화 조각 §5, 원시 `d`, 활성 상태 플래그, 세션·재조회 기준점). `prevRowState`는 표시 전용 소상태(직전 표시 유닛 index, 직전 표시 잔여)만 담는다 — 판정 계층 상태 신설 금지.

### 4.1 표시 유닛 (F5·F6 반영)

스텝을 그대로 쓰지 않고 **행동 경계 기준으로 병합한 표시 유닛**을 만든다: 행동 없는 경계(지도 분할로 나뉜 동일 직진)는 이전 유닛에 흡수해, 모든 표시 유닛이 "직진 구간 + (있다면) 끝 행동"의 꼴이 되게 한다. target·길이는 병합 후 유닛의 것. 이로써 "행동 없는 경계의 마지막 10m에 적용할 행이 없다"는 공백이 정의상 사라진다. 최종 유닛(다음 행동 없음)은 회전 접근 국면 없이 직진 국면을 0까지 유지한다(F6) — 목적지 접근의 인계는 finalApproach 국면이 우선순위로 가져간다.

### 4.2 국면 전이표 (윗줄) — 우선순위 내림차순 (F9)

동시 활성 시 위가 이긴다. 한 시점에 정확히 한 국면만 성립한다.

| 우선순위 | 국면 | 조건 | 윗줄 표시 |
|---|---|---|---|
| 1 | 도착 | arrived | 기존 도착 문형 유지 |
| 2 | 최종 접근 | finalApproach 활성 | 기존 최종 접근 문형 유지(확신도 3단 래핑 포함, 이 spec 비범위) |
| 3 | 이탈 | offRoute 확정 | 이탈 상태 문장(기존 키). **아랫줄도 비운다**(§4.3, F2) |
| 4 | 재획득 | reacquiring | 상태 문장이 윗줄 대체. 아랫줄 유지 |
| 5 | 불확실 | uncertain | 상태 문장이 윗줄 대체. 아랫줄 유지. 해소 시 그 자리 숫자로 복귀 |
| 6 | 횡단 중 | 현재 표시 유닛이 횡단보도/지하보도 | 유닛 행동 문장(부가 정보 포함: "횡단보도를 건너세요, 음향신호기 있음"), 카운트다운 없음 |
| 7 | 회전 접근 | displayRemaining ≤ 10 이고 유닛 끝 행동 있음 | `{n}m 후 {행동구}` (n 감소), n=0이면 `잠시 후 {행동구}` (음수 표시 금지) |
| 8 | 직진 | 나머지 전부 | `{target}까지 {n}m 직진하세요` / target 없으면 `{n}m 직진하세요` |

- 행동구는 기존 임박 큐 문구 체계(`walkStepAction` 분류 → left/right/crosswalk/underpass) 재사용.
- **클램프와 국면은 같은 값을 본다(F4)**: 단조 클램프(같은 표시 유닛 안에서 displayRemaining이 직전 표시값을 넘으면 직전 값 유지)를 먼저 적용하고, **국면 판정도 클램프된 값으로** 한다 — "숫자는 8인데 국면은 직진"이라는 자기모순이 구조적으로 불가능하다. 표시 유닛 전이·재조회·이탈 복귀는 `prevRowState` 리셋(새 기준). 클램프는 표시 계층에만 있고 판정 계층(음성)에는 없다.
- **짧은 유닛**(길이 ≤ 10 + 램프인 후 lag): 직진 국면 창이 없어 진입 즉시 회전 접근이다. 의도된 동작(실경로 24m·10m 구간이 실례) — 실보행 판정 축.

### 4.3 아랫줄 (다음 안내) — 다음 표시 유닛의 예고 (F2·F11 반영)

- 아랫줄은 **다음 표시 유닛의 종류에 맞는 예고**다(직진 가정 금지): 직진 유닛이면 `{target}까지 {길이}m 직진`(지도 값), 횡단 유닛이면 그 행동 문장("횡단보도를 건너세요" 계열), 연속 회전이면 행동구. 윗줄이 직진 국면일 때는 현재 유닛 **끝 행동**(`{anchor} 앞에서 {행동구}`, anchor 없으면 행동구만)을, 회전 접근 국면일 때는 **그 행동 뒤의 유닛**을 예고한다.
- **이탈 중에는 아랫줄도 비운다(F2)**: 경로가 무효한데 "약국 앞에서 왼쪽으로 도세요"가 남으면 낡은 회전 지시를 따르게 된다 — "두 정보가 공존할 순간이 없다"는 원칙의 이탈 판. 재조회 진입점은 기존 버튼이 담당한다. 불확실·재획득(경로 자체는 유효, 내 위치만 모름)은 아랫줄을 유지한다(맥락 보존).
- 최종 유닛에서는 비운다. 빈 값은 요소 제거로(빈 텍스트 낭독 금지).

## 5. 서버 구조화 조각 — 문장 파싱은 서버 한 곳

윗줄 템플릿에 넣을 `target`(직진 목표 이름)·`anchor`(경계 기준 이름)는 **클라이언트가 한국어 문장을 재파싱해 얻지 않는다**(CLAUDE.md "낭독 문장은 서버가 만든다 — 소비자 재조합 금지"의 연장). `rewriteWalkGuidance`가 재작성 과정에서 이미 정규식으로 분해하는 조각을 briefing 스텝에 **선택 필드로 노출**한다:

```
steps[i] += { live?: { target?: string, anchor?: string } }
```

- 추출 실패는 필드 부재로 정직하게 표현하고(지어내지 않는다), 표시 계층은 이름 없는 폴백 템플릿으로 강등한다.
- 추가는 additive라 기존 소비자(CLI·MCP·구버전 앱)에 무해. 필드는 `includeGeometry=1`(실시간 안내 옵트인) 응답에만 싣는다.
- **V1 ko 전용**(도보 안내 전체가 ko 전용인 기존 게이트를 따른다).

## 6. i18n·접근성 계약

- 새 키(ko): 직진 `guide.liveStraight` "{target}까지 {n}m 직진하세요" / `guide.liveStraightNoName` "{n}m 직진하세요" / 회전 접근 `guide.liveTurnIn` "{n}m 후 {action}" / 아랫줄 예고 `guide.nextStraight` "{target}까지 {n}m 직진" 계열. 행동구·상태·최종 접근·도착은 기존 키 재사용. 아랫줄 라벨은 기존 `guide.progressNext`("다음 안내,") 재사용.
- **VO 낭독**: 시각 표기는 "10m", 접근성 라벨은 기존 `spokenDistanceUnits` 경유("10미터" — m의 minutes 오독 정정, 실기기 확정 기존 계약). **live region 금지** — 두 행은 커서를 올렸을 때 읽는 정적 텍스트 요소이고, 상태 변화의 능동 통지는 기존 음성·통지 채널이 담당한다(이중 낭독 금지).
- 매 fix 라벨 갱신이 VO 커서 위에서 재낭독 소음을 내는지는 실보행 판정 축(기존 잔여 거리 행이 동일 갱신률로 무문제였던 것이 선행 근거).

## 7. 비범위 (불변)

## 8. 테스트·검증
