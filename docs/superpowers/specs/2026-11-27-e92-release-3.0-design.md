# E92 길동무 3.0 설계: 채팅 모델 전환과 나들이 베타

판정 정본은 `docs/BACKLOG.md` E92(2026-11-27 위원장 판정 고·중·저)다. 이 문서는 그 판정을 코드 계약으로 옮긴다. 설계 리뷰 판별: 여러 계층(서버·iOS·웹·CLI)에 걸치지만 새 구조는 없고 기존 E89 세션 층과 플래그 졸업 관례를 재사용하므로 별도 설계 리뷰 없이 구현 리뷰로 갈음한다.

## 1. 범위

| 묶음 | 내용 | 도달면 |
|---|---|---|
| A. 채팅 모델 | 정식판 설정 「채팅 답변 모델」 두 선택지(GPT-6.1 Terra 처음 값, Gemini 3.6 Flash), 실험판 여섯 선택지 처음 값 Terra | 서버 + iOS |
| A-w. 웹·CLI 전환 | 웹 채팅과 CLI 채팅이 Terra를 명시해 보낸다 | 웹·CLI, **3.0 출시 날까지 별도 브랜치에 보관** |
| B. 졸업 | 나들이(베타 표기), 상단 줄 배치, 채팅 답 아래 안내 시작(E83) | iOS |
| C. 채팅 도구 정리 | 도구 전수 점검 보고 뒤 착수 범위 판정 | 서버 |
| D. 어색한 통지 | 여정을 찾았을 때 「1개 수단」 통지 | 웹·iOS 문자열 |

안드로이드는 범위 밖이다(판정 ⓖ).

## 2. 채팅 모델 계약 (A)

- **A1 요청 값**: 3.0 앱은 Terra를 고르면 `chatModel: "openai"`를 보낸다. Gemini를 고르면 필드를 보내지 않는다(서버의 값 없음 = Gemini는 그대로라 2.8 이하 앱 보호, 판정 ⓑ). 서버의 `parseChatModel`과 「값 없음 = Gemini」 기본값은 바꾸지 않는다.
- **A2 처음 값**: Kit `ChatAnswerModel.defaultID`를 `openai`로 바꾼다. 저장값이 없거나 열리지 않은 값이면 처음 값을 쓴다. 실험판에서 `gemini`를 직접 고른 사용자의 저장값은 그대로 Gemini다.
- **A3 정식판 선택지**: Terra·Gemini 둘(서버 `/api/chat/models`가 `openai`를 열 때만 Terra, 안 열리면 줄을 숨기고 Gemini). 실험판은 종전 여섯(판정 ⓔ). 정식판에 둘만 두는 갈래가 `experimentalChatModelEnabled`의 남은 소비자다(줄 자체는 졸업, 선택지 확장만 실험판).
- **A4 설명 한 줄**: 선택지마다 한 줄. 한국어 확정 문안(2026-11-27 위원장 TextEdit): 「GPT-6.1 Terra (기본): 필요한 정보를 정확히 찾고, 핵심만 간결하게 답하는 모델」, 「Gemini 3.6 Flash (레거시): 기존 모델로, 장소와 길을 친절하게 풀어 설명하는 모델」. 다섯 언어는 번역한다. 실험판 추가 선택지에는 설명을 두지 않는다.
- **A5 하루 상한(판정 ⓓ)**: Terra(`openai`)는 `CHAT_MODEL_DAILY_CAP`에서 뺀다. Terra 운영형 질문당 0.76센트로 Gemini 3.6(1.21~1.25센트)보다 싸고, Gemini 경로에는 하루 상한이 없다(IP 상한만). 상한은 실험판 전용 네 모델(Luna·Claude 셋)에만 남는다.
- **A6 추론**: Terra 추론 끔 그대로(`effort: "none"`, 판정 ⓒ). 추천 질문 칩은 Gemini 그대로.
- **A7 동의 재요청(판정 ⓐ)**: 동의 저장 키를 새 판으로 바꿔 3.0 첫 실행에서 바뀐 문구로 한 번 다시 묻는다. 문구는 기본 수신처 OpenAI, 설정에서 Gemini를 고르면 Google로 간다는 것을 말한다.
- **A8 개인정보 3자 일치**: 웹 처리방침 `privacy.chat`은 지금 배포해도 참인 문장으로 고친다(「설정에 따라 OpenAI 또는 Google Gemini」). 수집 항목은 바뀌지 않으므로 `PrivacyInfo.xcprivacy`와 ASC 영양 라벨은 그대로다(데이터 유형 불변, 제3자 이름은 라벨 항목이 아니다).

## 3. 웹·CLI 전환 (A-w)

웹은 push가 곧 배포라 출시 전에 main에 넣으면 그날 웹 질문이 OpenAI로 간다. 웹 채팅 요청에 `chatModel: "openai"`, CLI 채팅 요청에도 같은 값을 넣는 변경은 브랜치 `release/3.0-web`에 두고 3.0 판매 개시 날 main에 병합한다. CLI는 `packages/cli/CHANGELOG.md`에 수신처 변경을 적고 npm 발행은 그날 위원장 승인 뒤다. 웹 채팅 동의 문구도 같은 브랜치에서 OpenAI로 고친다.

## 4. 졸업 (B)

플래그 졸업은 검사를 삭제한다(항상 참인 상수를 남기지 않는다, `AppConfig.swift` 머리 주석).

- **B1 나들이**: `experimentalOutingEnabled` 삭제. 진입점 둘과 설정 「백그라운드 음성 안내」 설명 문장 선택(A59)이 소비자다. 베타 표기는 나들이 시트 제목 한 곳(판정 ⓕ)이고 버튼 이름에는 붙이지 않는다. 「말로 묻기」 답변 모델은 정식판에서 Terra(`openai`) 고정이고 「나들이 답변 모델」 줄은 실험판에만 남는다. 정식판은 저장값을 읽지 않는다(실험판에서 옮겨 온 저장값이 정식판 요청에 닿지 않게).
- **B2 상단 줄**: `experimentalTopBarRefreshEnabled` 삭제(소비자 `TitleMenu.swift`).
- **B3 채팅 안내 시작(E83)**: `experimentalChatGuideEnabled` 삭제. 정식판 채팅이 능력 `route-start`를 신고하고 답 아래 수단별 안내 시작 카드를 그린다.
- 탭 순서(`experimentalTabOrderEnabled`)는 실험판에 남는다.
- 가드 `guidance-gate-drift.test.ts`·`settings-topic-sections.test.ts`·`chat-model-seal.test.ts`를 새 계약으로 고친다.

## 5. 채팅 도구 정리 (C)

판정 문장은 「앱에 붙은 채팅 도구를 다시 전수 정리해 도구 호출을 강화한다」이다. 먼저 도구 선언 전수 점검 보고서(중복·설명 모호·빠진 인자·Terra에서 안 불리는 도구)를 만들고, 바꿀 것과 eval 게이트를 정한 뒤 착수한다. 프롬프트 수정은 삭제와 긍정 조건의 최소판부터 실측한다.

## 6. 어색한 통지 (D)

「여정」 용어 통일은 위원장이 철회했다(2026-11-28). 대신 세 수단이 든 경로를 찾았을 때 「1개 수단의 경로 안내가 준비되었습니다」로 들리던 통지처럼 어색한 자리만 고친다. 여정을 찾으면 웹·iOS 통지와 상태 줄이 수를 말하지 않는 `directions.journeyReady`(「경로 안내가 준비되었습니다.」)를 쓴다.

## 7. 출시

버전 3.0.0, 빌드는 ASC 최근 +1. What's New에는 설정에서 Gemini로 되돌릴 수 있다는 것을 적는다(판정 ⓖ). 제출은 실험판·정식판 실기기 확인 뒤다.
