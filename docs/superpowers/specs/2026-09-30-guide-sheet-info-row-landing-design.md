# 안내 시트가 열리거나 이어질 때 VoiceOver 초점을 첫 정보 행으로 (E57) 설계

- 판정 정본: `docs/BACKLOG.md` E57(위원장 2026-09-30: "안내시트가 열리면 초점을 최상단 헤딩이 아닌 남은 거리 행(실질적 정보가 시작되는 행)으로. 새로 열릴 때도, 도보 → 지하철 → 도보로 이어질 때도").
- 세션: `sheet-focus`(7차 웨이브 3). 도보 시트는 정식판 경로다. 자동차·대중교통·나들이는 실험판 봉인 중이다.
- 리뷰 게이트 판정: **적대적 설계 리뷰 1회**. 착지 계약(상태별 대상·대기·소실 복구)이라는 새 판정 계층을 담는다. 서버·Kit·문자열 변경 없음.

## 0. 로그 판독 (2026-09-30 기기 회수, 원본 `~/gildongmu-private/field-logs/sheet-focus-2026-09-30/`)

회수: 실험판(`space.dodoplanet.gildongmu.dev`) `Documents/transit-guide-diag.log`(09-30 18:40)·`guide-diag.log`(09-30 18:58). 09-30 저녁 경로가 요청 문장의 "도보 → 지하철 → 도보"다: KST 18:27:58 도보(승차 전 도보, 18:32:39 `briefHandoff reason=tooClose`) → 18:35:28 5호선 굽은다리 → 길동 → 18:40:20 `walkHandoffNow` → 도보 → 18:58:54 도착.

**확정**
1. **대중교통 시트의 착지는 설계대로 상태 문장 행에 앉는다.** E38·A35 이후(09-16~) `controlFocus target=status`는 6건이고 `reason=ok` 5, 배경 이월 1(`reason=background deferred=true` → 전경 복귀 `note=deferred`로 ok)이다. 09-30 세션의 시트 열림(18:35:29, `attempts=1 elapsedMs=649`)과 차량 선택 전이·도착 전이 모두 `vo="굽은다리에서 수도권 5호선 탑승…"`처럼 VoiceOver 커서가 실제로 상태 문장 위에 있었다. 대중교통에서 "최상단으로 올라간다"는 착지 실패가 **아니다**. 시트가 뜬 뒤 0.65초는 시스템이 제목에 두므로 제목 첫마디가 들리는 것은 정상 경로다.
2. **도보 시트는 설계가 제목 착지다.** `BeaconTrackingSheet.landTitleFocus`가 열림·재조회 성공·경로 전환 채택·경유지 삭제·목적지/경유지 검색 닫힘의 착지다. 위원장이 들은 "최상단"은 이 설계 그대로다. 요청 문장의 두 도보 구간(18:27·18:40)이 여기에 해당한다.
3. **모든 인계는 시트를 닫고 새로 연다.** 승차 전 도보 → 대중교통(`endPrewalk` → `transit.start`), 대중교통 → 도보(`acceptWalkHandoff`의 600ms), 자동차 도착 → 도보(`clearArrival` 뒤 `startBeacon`), 나들이 → 도보(`endForReturn` 뒤 `startBeacon`) 전부 `GuideSession.screen`이 한 번 nil을 지나 루트 `.sheet(item:)`이 새 시트를 올린다. 그래서 "인계" 경로는 착지 관점에서 "새로 열림"과 같다(§2 표에 한 행으로 둔다).
4. **시트가 뜬 순간 도보 시트엔 남은 거리 행이 아직 없다.** `start()`가 `status = .tracking`(시트 표시)을 세운 뒤 첫 수용 fix가 경로 조회를 트리거하고, 조회가 끝나야 `mode = .detail`·`remainingText`가 선다. 회수한 네 도보 세션의 `routeOrigin`(조회 착수)은 세션 시작 뒤 0~1초였다. 조회 완료 시각은 로그에 없다(아래 미판정 1).

**미판정**
1. **도보 시트 착지는 로그 스키마가 답하지 못한다.** `GuideDiag`에 착지 기록이 없다(대중교통만 `controlFocus`를 남긴다). 0건은 "문제 없음"이 아니라 "안 보인다"다. 이번에 도보·나들이 시트에 착지 계측(§4)을 더한다. 경로 조회 완료 시각도 없어 "시트 표시 → 남은 거리 행 등장" 간격은 실측이 아니라 추정(착수 +0~1초 + 조회 왕복)이다. 착지 계측의 `waitedMs`가 다음 회수에서 그 값을 준다.

## 1. 원칙

위원장 문장 그대로 **"실질적 정보가 시작되는 행"**이 시트의 첫 착지다. 정보 행은 **지금 상태를 말하는 행**이다(버튼·제목·고정 주석이 아니다). 판단이 필요한 예외는 둘뿐이다.

- **자기 질문을 여는 화면**(E38 허용 집합: 차량 선택 라벨·역 선택 헤딩·급행 확인)과 **도착·종료 화면**(도착 문장이 곧 첫 정보 행)은 종전대로다.
- **띠바 복귀**는 종전대로 접기 버튼(떠난 자리, N1 설계 리뷰 m1)이다. 위원장 판정 질문으로 올린다(§6 Q1).

**첫 정보 행의 순서**는 화면의 행 순서를 따르되 직선거리 주석은 뒤로 뺀다: 남은 거리 → 현재 도로(자동차) → 윗줄 → 상태 문장 → 직선거리 주석. 주석은 "직선거리 기준입니다"라는 고정 단서라 상태가 아니다. 간략 모드에서 그 주석은 상태 문장 바로 위라 한 번 위로 쓸면 닿는다. 모든 추적 상태에서 이 목록은 비지 않는다(간략이면 주석이 늘 있고, 상세면 윗줄이 선다). 그래도 비면 제목 행에 앉는다(마지막 안전망).

## 3. 도보 시트 설계

### 3.1 단일 착지 바인딩

종전 Bool 바인딩 넷(`titleFocused`·`minimizeFocused`·`arrivedFocused`·`healthSummaryFocused`)을 **옵셔널 enum 바인딩 하나**(`focusedRow: SheetFocus?`)로 합친다. 대상이 여섯으로 늘면 Bool 다중 부착의 경합(A19 실승차 `landed=false 2/2`)이 그대로 재현되기 때문이다. 부착은 헬퍼 한 자리(`focusTarget(_:_:)`)이고 그 헬퍼가 바인딩·`scrollTo` 키·실현 관측(onAppear/onDisappear 카운트)을 함께 단다(대중교통 `landingTarget` 동형).

대상: `title` · `minimize` · `remaining` · `road` · `liveTop` · `status` · `straightNote` · `arrived` · `healthSummary`. `liveNext`(아랫줄)는 대상이 아니다(첫 정보 행이 될 일이 없다 — 윗줄이 없으면 아랫줄도 없다).

### 3.2 착지 실행기

대중교통 `landControlFocus`의 정본 시퀀스를 따른다: 직전 착지 취소 → [가시화(`scrollTo`, 실현될 때까지 150ms마다) → 실현 대기(≤500ms) → 존재 재검증 → 대입 → 늦은 검증(600·900·1200ms, 100ms마다 조기 확정)] × 최대 3회 → 로그. 대중교통과 달리 **폴백 통지는 없다**. 정보 행의 폴백 문장은 곧 그 행의 값이라, 착지를 못 했을 때 그것을 통지로 읽으면 같은 순간의 시작·이탈 통지와 겹쳐 말만 늘어난다. 실패는 로그로만 판정한다.

- 배경(`scenePhase != .active`)에선 시도하지 않고 표식만 남겨 전경 복귀에 한 번 착지한다(대중교통 L4 동형). 시트 위에 다른 시트(조망·검색·장소 상세·설정)가 떠 있을 때도 같다. 그 시트가 닫히면 시스템이 트리거 버튼으로 커서를 돌려주는 것이 우선이라 이월분은 **버린다**(이월해서 착지시키면 사용자가 연 화면을 닫은 직후 커서가 튄다).

### 3.3 경로 조회 대기

`BeaconModel.awaitingRoute`를 읽기 전용으로 연다(`private` → `private(set)`, 발화 경로 불변). 착지 요청 시점에 조회 중이면 "첫 정보 행 착지 대기"를 세우고 `onChange(of: model.awaitingRoute)`가 false가 되는 순간 그때의 첫 정보 행에 착지한다. 대기는 다음에서 버린다:

- 20초 경과(`noFixTimeout` 15초 + 조회 왕복). 로그 `reason=timeout`. 그 사이 커서는 시스템이 둔 자리(제목)에 있고, 오래 기다린 뒤 끌어내리면 사용자가 이미 옮긴 커서를 빼앗는다.
- 사용자가 시트 안에서 무언가를 열었다(조망·검색·장소 상세·재조회 버튼). 로그 `reason=userAction`.
- 세션이 끝났다(도착·중지로 종료 화면, 또는 시트 소멸).

**시작 통지와의 순서**: 조회가 끝나는 커밋에서 모델이 시작 요약("{목적지}까지 도보 안내 시작. 안내 N개, 총 1.2km. {첫 안내}")을 `.high`로 통지한다. 착지는 그보다 400ms 이상 뒤다. 이 저장소의 실측은 `.high` 통지가 뒤따르는 포커스 이동에 잘리지 않는다는 것이다(`BeaconModel.fetchGuideRoute` 주석, 목적지 전환 착지 경합 사례). 그래서 요약이 먼저 온전히 들리고 커서는 남은 거리 행에 앉는다. 착지 낭독이 요약 뒤에 들릴지 잘릴지는 기기 판정이다(§5 ②). 요약의 "총 1.2km"와 행의 "남은 거리 1.2km"가 연달아 들리는 중복은 E41 원칙("통지는 그 문장에 없는 것만")에 걸리는 자리지만, 요약 문장은 백그라운드·띠바 상태에서도 나가는 시작 통지라 착지 여부로 문장을 가르면 한 문장이 두 벌이 된다. 이번엔 문장을 바꾸지 않고 판정 행으로 남긴다(§5 ②).

### 3.4 소실 복구

커서를 정보 행에 앉히면 그 행이 사라지는 전이가 생긴다: 이탈 확정(남은 거리·현재 도로 행 숨김), 최종 접근 진입(`remainingText = nil`), 간략 강등(상세 행 전부). SwiftUI List는 사라진 요소 대신 시트 맨 위로 커서를 보내기도 한다(대중교통 A47 관찰). 그래서 `onChange(of: focusedRow)`에서 **이전 값이 정보 행이고 새 값이 nil이며 그 행이 더는 없으면** 그 시점의 첫 정보 행으로 착지한다(로그 `note=lost`). 사용자가 스와이프로 떠난 경우는 행이 남아 있으므로 복구하지 않는다. 종료 화면으로 넘어가는 전이는 도착 착지가 맡으므로 복구하지 않는다(`arrivalDest != nil`).

이탈 확정의 복구 착지는 이탈 문장(윗줄)을 읽는다. 같은 순간 모델의 이탈 경고 통지와 내용이 겹칠 수 있다. 복구 착지를 하지 않으면 커서가 맨 위로 튄다(더 나쁘다). §5 ③으로 판정한다.

### 3.5 같은 시트 안에서 새 세션이 서는 경우

모든 인계가 시트를 새로 여는 것이 §0 확정 3이지만, SwiftUI가 nil을 지나는 두 갱신을 한 트랜잭션으로 합치면 같은 콘텐츠 뷰가 종료 화면 → 추적 화면으로 바뀔 수 있다(`.task`가 다시 돌지 않는다). 그 경로를 위해 `onChange(of: model.isTracking)` false → true에서 새로 열림과 같은 착지를 요청한다. 두 경로가 모두 오면 뒤의 요청이 앞을 취소한다(latest-wins).

## 4. 계측

- 도보·자동차: `guideDiagLog("sheetFocus sheet=beacon target=… landed=… actual=… attempts=… elapsedMs=… waitedMs=… rendered=… reason=… vo=\"…\" note=…")`. `waitedMs`는 경로 조회 대기 시간(대기가 없었으면 0). `reason`은 `ok`·`notRendered`·`stolen`·`vanished`·`cancelled`·`timeout`·`userAction`·`background`·`modal`.
- 나들이: 같은 형식, `sheet=outing`(기존 `land` 헬퍼에 로그만).
- `vo=`는 VoiceOver 커서가 실제로 앉은 요소의 라벨(앞 40자)이다. 종전 `transitFocusedLabel()`을 `GuideDiag.swift`의 `voFocusedLabel()`로 옮겨 두 로그가 함께 쓴다(대중교통 착지 로그 형식은 불변).
- 릴리스 빌드는 no-op(기존 게이트 `#if DEBUG || EXPERIMENTAL`). 정식판 도보 착지는 로그가 없으므로 판정은 실험판 로그 + 정식판 청취다.

## 5. 실기기 판정 (BACKLOG §2 E57 행, 대본 FIELD-TEST)

① 상태별로 처음 들리는 행: 도보 시작·대중교통 → 도보 인계·자동차 도착 → 도보 인계·나들이 귀환 → 도보에서 "남은 거리 …"가 들리는가(실험판 로그 `sheetFocus … target=remaining landed=true`). 경로 조회가 느린 실내 시작에서 제목이 먼저 들리고 1~3초 뒤 남은 거리로 옮겨 가는 것이 거슬리지 않는가.
② 시작 요약(`.high`)이 착지에 잘리지 않는가, 요약 뒤 "남은 거리 1.2km"가 이어 들리면 "총 1.2km"와 중복으로 거슬리는가(거슬리면 후속 판정: 요약에서 총거리를 뺄지).
③ 이탈 확정 때 커서가 남은 거리 행에서 이탈 문장 행으로 옮겨 가는가(`note=lost`), 이탈 경고 통지와 겹쳐 두 번 들리는가. 최종 접근 진입 때도 같은가.
④ 값 갱신 재낭독: 커서가 남은 거리 행에 있는 동안 걸을 때마다 값이 다시 읽히는가. 코드 사실: 행은 `distanceText`(단일 `Text` + 낭독 라벨)이고 `updatesFrequently` 같은 trait이 없다. 이 저장소의 선례는 둘이다: 도보 하단 2행이 커서 위에서 갱신되는 것은 2026-08-16 실보행에서 "거슬리지 않음"으로 통과했고(§2 M0), 대중교통 상태 문장 행도 폴마다 바뀌는 착지 행이다(E38). 나들이 걸은 거리 행은 M9로 착지 행에서 뺐다. 남은 거리 행은 위원장 명시 요청이라 착지 행으로 두고 이 축을 실보행으로 판정한다.
⑤ 제목 메뉴(장소 상세·목적지 바꾸기)까지의 거리: 남은 거리 행에서 위로 쓸기 4~6번(주변 확인 → 진행 상황 → 경유지 버튼 한두 개 → 접기 → 제목). 지름길은 **네 손가락으로 화면 위쪽 탭**(첫 요소 = 제목)과 헤딩 로터다. 종료는 네 손가락 아래쪽 탭(종전 그대로).
⑥ 띠바 복귀(§6 Q1 판정 결과대로).
