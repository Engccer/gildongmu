# 거리 추적 실보행 피드백 반영 설계 (2026-08-02)

## 1. 배경

**위원장 실보행에서 거리 추적이 정상 작동했다.** 백로그 F-b가 닫히고 B1이 확정된다. 폐기 분기(`beacon.*` 11키 제거)는 사라졌고, 이 기능은 iOS 1.3(G1)에 그대로 실린다.

실사용 피드백 2건을 반영한다.

1. 추적 시작 시 모달로 띄워 화면을 분리한다.
2. 1,000m 이상은 km 아래 자리를 m으로 표기한다(예: `1km 200m`).

## 2. 거리 표기

### 2.1 지금 무엇이 어긋나 있나

거리 표기의 정본은 `formatDistance`인데 **세 벌이 각자 구현돼 있고 드리프트 가드가 없다**.

| 구현 | 위치 | 1,000m 이상 |
|---|---|---|
| 웹 | `src/lib/format.ts` | `(m/1000).toFixed(1)` |
| iOS | `ios/GildongmuKit/Sources/GildongmuKit/Format.swift` | `String(format: "%.1fkm", ...)` |
| CLI | `packages/cli/src/lib/formatters.ts` `dist()` | `(n/1000).toFixed(1)` |

그런데 **비콘은 이 정본을 쓰지 않는다.** 문구가 `{meters}m` 리터럴이라 언제나 미터로 낭독한다(웹 `DistanceBeacon.tsx`, iOS `BeaconModel.text(for:)`). 실보행에서 들린 것이 `1.2km`가 아니라 `1187m`였던 이유다.

부수로 드러난 선재 결함 둘:

- `formatDistance(1000)`이 **`"1.0km"`**를 낸다. 스크린 리더가 "일 점 영 킬로미터"로 읽는다.
- `formatDistance(999.6)`이 **`"1000m"`**를 낸다. 1,000 미만 판정을 반올림 **전에** 하기 때문이다.

### 2.2 채택 규칙

`meters`를 100m 단위로 **먼저 반올림한 뒤** km과 나머지로 가른다.

```
r = round(meters)
r < 1000                → "{r}m"
그 외:
  snapped = round(meters / 100) * 100
  km      = snapped / 1000 의 몫
  rest    = snapped % 1000
  rest == 0 ? "{km}km" : "{km}km {rest}m"
```

**먼저 반올림하는 것이 이 설계의 전부다.** km과 나머지를 따로 반올림하면 1,999m에서 나머지가 1,000으로 올라가 `1km 1000m`이 된다. 자리올림을 분기로 처리하지 않고 산술이 흡수하게 만든다.

| 입력 | 종전 | 신규 | 비고 |
|---|---|---|---|
| 999.6 | `1000m` | `1km` | 선재 결함 해소 |
| 1000 | `1.0km` | `1km` | 소수 0 제거 |
| 1049 | `1.0km` | `1km` | |
| 1050 | `1.1km` | `1km 100m` | |
| 1187 | `1.2km` | `1km 200m` | 실보행에서 들린 값 |
| 1999 | `2.0km` | `2km` | **자리올림** |
| 3640 | `3.6km` | `3km 600m` | |
| 89700 | `89.7km` | `89km 700m` | |

**정밀도는 바꾸지 않는다.** 종전 소수 1자리가 곧 100m 단위였으므로 표기 방식만 바뀐다. 요청은 정밀도가 아니라 표기였고, 걷는 중 1m 자리는 비콘 데드밴드(15m 이상)보다 작아 어차피 노이즈다.

**적용 범위는 전역이다.** 비콘만 바꾸면 같은 앱에서 `1.2km`와 `1km 200m`가 섞여 낭독된다. `Format.swift`가 "단일 정본, 앱 로컬 사본 금지"라고 선언한 취지이기도 하다. 세 벌 모두 같은 규칙으로 맞추고 **드리프트 가드를 새로 건다**(현재 없다).

### 2.3 비콘 문구를 정본에 태운다

`{meters}m` → `{distance}`로 바꾸고 `formatDistance` 결과를 넣는다. 6로케일 × 3키(`first`·`closer`·`farther`).

⚠ **`nearby`는 태우지 않는다.** 그 값은 거리가 아니라 **오차 반경**이다(`약 ±{meters}m`). `maxUsableAccuracy`가 100이라 결과 문자열은 어차피 같지만, 의미가 다른 값을 거리 포맷에 태우면 다음 사람이 두 축을 같은 것으로 읽는다.

es·fr·it은 종전에 `{meters} m`처럼 단위 앞에 공백을 뒀는데 `{distance}`로 흡수되며 사라진다. 앱의 다른 모든 거리가 이미 공백 없이 표기되므로 오히려 정합이 맞는다.

## 3. iOS 추적 모달

### 3.1 지금 구조와 그 비용

`DirectionsTabView`의 인라인 `Section` 하나에 시작·중지 버튼, 상태 1줄, 힌트가 함께 있다. 추적 중에도 그 아래 수단 섹션(도보는 인라인 전개라 천호역 실측 수백 행)이 같은 스와이프 경로에 남는다. 걸으면서 중지하려면 그 목록 안에서 버튼을 찾아야 한다.

### 3.2 채택 구조

- **인라인에 남는 것**: 목적지 heading, `시작` 버튼, 직선거리 주석.
- **모달로 가는 것**: 상태 1줄, `중지` 버튼, 화면 유지 힌트.
- 시작이 곧 모달 표시, **중지가 곧 모달 닫힘**.

`중지 = 닫힘`을 1:1로 묶는다. 사용자가 외울 개념이 하나가 되고, 리뷰 이력의 C-1(추적 중 중지 버튼이 화면에서 사라지던 결함)이 구조적으로 재발할 수 없다. 모달이 떠 있는 한 중지 버튼은 항상 거기 있다.

**스와이프·VoiceOver escape로 닫아도 중지한다.** `interactiveDismissDisabled`는 쓰지 않는다. 걷는 중 오조작으로 추적이 꺼질 위험보다, 시각장애 사용자가 닫을 수 없는 화면에 갇히는 쪽이 나쁘다. 실수로 닫히면 다시 시작하면 된다.

### 3.3 포커스 계약

- **열릴 때 → 중지 버튼.** 걷는 중 필요한 유일한 행동이고, 모달 수명 내내 존재해 헌장 §5의 "포커스를 쥔 요소가 사라지는 전이"가 발생하지 않는다. 상태 변화는 기존 단일 polite 통지가 이미 전달하므로 포커스가 상태 텍스트에 있을 이유가 없다(받아쓰기 완료 후 전송 버튼으로 보내는 계약과 같은 꼴이다. 다음 행동이 곧 그 버튼이다).
- **닫힐 때 → 시작 버튼.** 시트 dismiss가 VO 커서를 화면 최상단으로 떨어뜨리는 것은 이 저장소에서 실기기로 확인된 사실이라(`landFocusAfterResolve`), 같은 지연·재시도 패턴을 쓴다.

### 3.4 기존 가드는 지운다고 판단하지 않는다

모달 전환으로 아래 둘은 도달 경로가 사라진 것처럼 보인다.

- `outputSuppressed`(검색 시트 중 톤·통지 억제)
- `stopBecauseDestinationChanged`(추적 중 목적지 변경 시 중지)

**그래도 남긴다.** 추적 중에는 모달이 화면을 점유하므로 검색 시트를 여는 경로가 없어 보이지만, SwiftUI에서 그것이 완전히 막힌다고 증명하지 못했다. 비용이 0이고, 이 가드가 지키는 것은 헌장 §6의 "녹음 중 SR 발화 0"이라는 상위 정본이다. 미니멀리즘의 대상은 잉여이지 안전 가드가 아니다. 주석으로 도달 경로 변화만 남긴다.

### 3.5 웹은 바꾸지 않는다

웹 비콘은 disclosure 패널로 두고 모달로 옮기지 않는다. 모달의 동기는 "걸으면서 목록 속에서 중지 버튼을 찾는 비용"인데, **웹앱 주 사용처가 컴퓨터라 실보행 자체가 성립하지 않는다**(B1 게이트 재정의의 근거와 같다). 없는 문제를 위해 구조를 바꾸지 않는다. 거리 표기는 정본 공유라 웹에도 그대로 적용된다.

이 결정으로 웹·iOS의 비콘 UI 구조가 갈리므로 백로그 B 축에 기록한다.

## 4. 테스트 계획

- **웹 `format.test.ts`**: 위 경계표 8행을 그대로 단언한다. 자리올림(1999)과 선재 결함 2건(999.6·1000)을 반드시 포함한다.
- **Kit `FormatTests`**: 같은 경계표(Int 입력).
- **드리프트 가드 신설**: 세 구현이 같은 입력에 같은 문자열을 내는지 못 박는다. 웹↔CLI는 같은 프로세스에서 직접 대조하고, Kit은 경계표를 공유 상수로 둔다.
- **비콘 문구**: 6로케일에 `{distance}` 존재 + `{meters}` 잔존 0을 `i18n-messages.test.ts` 레인에서 확인.
- **모달**: 앱 타깃 테스트 번들이 없어 자동 검증이 불가능하다. 빌드·xcstrings 린터·별도 컨텍스트 리뷰까지가 게이트이고, **포커스 착지 판정은 실기기 VoiceOver뿐**이다(시뮬 AX 트리는 어느 요소가 포커스를 주장하는지 보여주지 않는다). F-a에 확인 항목으로 등록한다.
