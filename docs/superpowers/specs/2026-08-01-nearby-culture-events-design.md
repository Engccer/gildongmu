# 근처 문화행사 — 설계 (2026-08-01)

> 백로그 E1. 서울 열린데이터 `culturalEventInfo`(OA-15486)를 10번째 "내 주변" 도메인으로 추가한다.
> 웹·iOS·채팅·CLI/MCP를 **한 마일스톤에 담는다**(백로그 B축 재발 방지 규칙).

## 1. 데이터 실측 — 설계를 바꾼 두 가지

착수 전 전수 스캔(2026-08-01, `numOfRows` 1,000 × 20페이지):

| 항목 | 실측 |
|---|---|
| 전체 | 19,477건 (2021-08 ~ 2026-12), **시작일 내림차순** |
| 오늘 진행 중 | **244건** |
| 좌표 | **244/244** 유효, 전량 서울 경계 내 |
| `PRO_TIME`·`HMPG_ADDR` | 244/244 존재. 유료인데 `USE_FEE` 빈 값 0건 |
| 무료 | 175건 |
| 분류 | 교육/체험 102 · 전시/미술 90 · 콘서트 12 · 뮤지컬 6 · 연극 6 |

### 1-1. 안전한 페이지 절단선이 없다

진행 중 행사는 **183행부터 18,587행까지** 흩어져 있다. 정렬이 시작일 내림차순이라, 오래전 시작해 아직 하는 장기 전시(최고령 2021-11-17 시작)가 목록 깊숙이 앉는다.

| 상위 N행만 수집 | 잡히는 진행 중 행사 |
|---|---|
| 1,000 | 154/244 (63.1%) |
| 2,000 | 223/244 (91.4%) |
| 3,000 | 235/244 (96.3%) |
| 5,000 | 238/244 (97.5%) |

"몇 페이지만 받으면 되겠지"는 **조용한 누락**이고, 3-state 불변식("0건"과 "못 읽음"을 뭉개지 않는다)을 위반한다. → **전수(20페이지) 수집 후 코드가 판정**한다. 따릉이의 "전체 받아 서버 정렬" 선례와 동형이되, 19,477건은 매 요청 수집이 불가능하므로 캐시가 선택이 아니라 **필수 설계 요소**다.

### 1-2. `DATE` 파라미터는 "그날 열리는 행사"가 아니다

날짜 필터는 `DATE` **문자열 부분일치**다. `DATE=2026-08-01` → 그날 *시작하는* 28건만 나오고, 7월에 시작해 8월에도 하는 행사는 탈락한다(`DATE=2026-08`도 문자열에 "2026-08"이 있는 것만 = 8월에 시작하거나 끝나는 것만, 7월~9월 관통 행사는 누락).

진행 판정은 **`STRTDATE`/`END_DATE`**(`"2026-12-24 00:00:00.0"` 형식)로 코드가 한다. 이 두 필드는 정상적인 날짜라 문자열 접두 10자 비교로 안전하다.

## 2. 설계

### 2-1. 봉투 — `datagokr-envelope` 스코프 밖

`culturalEventInfo.RESULT.CODE` + `.row[]` + `list_total_count`. `response` 래퍼가 없는 **서울 열린데이터형**이라 D1에서 만든 공용 파서를 쓰지 않는다(따릉이와 동형). CLAUDE.md "봉투가 다르면 파서도 다르다" 그대로.

정상 코드는 두 개다(실호출 확정):

| 코드 | 뜻 | 처리 |
|---|---|---|
| `INFO-000` | 정상 | row 반환. 빈 결과도 `INFO-000` + `row:[]`라 안전 |
| `INFO-200` | "해당하는 데이터가 없습니다" | **빈 배열**. 전체 수를 넘어선 페이지의 정상 응답이라 오류가 아니다(21001~22000 요청 실측) |
| 그 외·`RESULT` 부재 | 실패 | throw |

⚠ 착수 초안은 "정상 코드는 `INFO-000` 하나"라고 썼으나 페이지 루프 구현 중 `INFO-200`이 드러났다. 이를 throw로 두면 **마지막 페이지 다음 호출이 조회 실패로 위장**한다.

⚠ 존재하지 않는 서비스/지역 호출은 **빈 결과가 아니라 `ERROR-500`**으로 온다(실측). 즉 "0건"과 "실패"가 코드로 갈리므로 3-state가 성립한다.

⚠ 봉투 정책은 **한 함수에만** 둔다. 첫 페이지용 사본을 따로 두면 테스트가 한 벌만 덮어 나머지가 조용히 썩는다(변이 주입으로 실제 검출).

### 2-2. 계층

```
seoul-culture-events.ts (provider)   전수 수집 + 진행 판정 + 슬림 투영
        │                            ↑ unstable_cache(일자 키, 6h)
        ▼
culture-events.ts (service)          Haversine 거리 + 3km 필터 + 거리순 + 서버 캡 50
        │
        ├─▶ /api/events/nearby       limit 옵트인 · total · 3-state · 커버리지 마커
        ├─▶ 채팅 도구 get_nearby_events (19번째, 앵커 인지)
        └─▶ CLI/MCP 카탈로그
```

**캐시가 provider에 있고 거리 계산이 service에 있는 이유**: 캐시 대상은 좌표와 무관한 "오늘 진행 중인 244건"이다. 거리를 provider가 계산하면 좌표마다 캐시가 갈라져 캐시가 무의미해진다. 좌표 의존 계산은 전부 캐시 **바깥**에 둔다.

**캐시 키에 일자(KST)를 넣는다.** 진행 여부는 날짜 함수라 자정이 지나면 결과가 달라진다. `revalidate`만으로는 경계에서 어제 목록을 최대 6시간 낭독한다.

**슬림 투영을 캐시한다**(원본 아님): 19,477건 원본은 수십 MB라 캐시 한도를 넘겨 조용히 캐시가 꺼진다. 진행 중 244건 × 필요 필드만 = 수십 KB.

### 2-3. 상수와 근거

| 상수 | 값 | 근거 |
|---|---|---|
| 반경 | **3,000m** | 5지점 실측 밀도(1km: 시청 31 vs 길동 0 — 30배 편차). 3km면 길동 5·강남 9·노원 13·홍대 20·시청 84로 전 지점에서 성립. 무장애 관광지(3km)와 같은 "찾아갈 만한 목적지" 축 |
| 서버 캡 | 50 | 장소 목록 4종 공통(`SERVER_CAP`) |
| 기본 limit | 12 | 둘러보기와 동일. `limit` 미지정 소비자(CLI/MCP) 출력 팽창 방지 |
| 옵트인 limit | 1~50 (`NEARBY_LIMIT_MAX`) | "더 보기"를 구현한 웹·iOS만 명시 요청 |
| 캐시 | 6시간 + 일자 키 | 원본이 일 1회 갱신. 콜드 4회/일 × 20페이지 = 80콜/일 |

### 2-4. ID

`HMPG_ADDR`의 `cultcode` 쿼리 파라미터가 **244/244 추출되고 전부 고유**하다(실측). 이것을 `id`로 쓰고, 추출 실패 시 `제목|장소|시작일` 복합키로 폴백한다(복합키도 244/244 고유). 목록 key 안정성이 목적이라 결측이 있어도 렌더가 깨지지 않는다.

### 2-5. 투영 필드 — 행동을 바꾸는 것만

원본 24필드 중 남기는 것:

| 필드 | 원본 | 왜 남기나 |
|---|---|---|
| `title` | `TITLE` | 무엇인가 |
| `category` | `CODENAME` | 전시인가 체험인가 |
| `place` / `district` | `PLACE` / `GUNAME` | 어디로 가나 |
| `dateText` | `DATE` | "언제까지" — 원본이 이미 완성 표기(`2026-08-01~2026-09-20`) |
| `timeText` | `PRO_TIME` | 몇 시 |
| `isFree` / `fee` | `IS_FREE` / `USE_FEE` | 가느냐 마느냐를 가름 |
| `target` | `USE_TRGT` | "24개월이상 관람가능" 류는 가족에게 결정적(최대 53자) |
| `link` | `HMPG_ADDR` | 유일한 후속 행동(상세·예매) |
| `lat`/`lng`/`distanceMeters` | `LAT`/`LOT` | 정렬·거리 표기 |

버리는 것: `ORG_NAME`·`PLAYER`·`PROGRAM`·`ETC_DESC`·`MAIN_IMG`·`THEMECODE`·`TICKET`·`RGSTDATE`·`ORG_LINK`·`INQUIRY`.

⚠ `INQUIRY`를 버리는 이유를 남긴다: `"070-8680-8477 / 02-337-3103"`처럼 **번호가 여러 개인 자유텍스트**라 소아진료의 `tel:` 링크 패턴을 그대로 못 쓴다. 하나를 골라 링크로 만들면 어느 번호인지 모른 채 거는 셈이라 `link`(홈페이지)를 유일한 행동 경로로 둔다.

## 3. 접근성 계약

- 항목 이름은 **`<h4>`**(내 주변 결과 항목 규칙). `joinText(제목, 분류, 거리)` 단일 텍스트.
- 이하 각 줄도 `joinText`로 한 줄 = 한 객체: `장소, 자치구` / `기간, 시간` / `무료` 또는 `유료, 금액` / `대상`.
- 제목·장소·대상은 한국어 전용 데이터라 줄 전체에 `lang="ko"`(소아진료 선례).
- **`link`만 인터랙티브 별도 객체** — `<a>`는 절대 합치지 않는다. 접근 가능한 이름에 행사명을 넣어 "링크"만 반복 낭독되지 않게 한다.
- "더 보기": 라벨은 수치 없는 `actions.showMore`, 누르면 첫 새 항목으로 포커스(웹 `useLayoutEffect`, iOS `scrollTo`+`AccessibilityFocusState`). 별도 통지 금지.
- 3-state: 반경 내 0건(`empty`) ≠ 키 없음(섹션 미노출) ≠ 조회 실패(502 → `error`). 공유 계층 `nearbyLiveMessage`가 단일 polite 통지로 처리.
- 절단 수치(`total`)는 **API 계약에만** 두고 화면에 쓰지 않는다([[honesty-disclosures-belong-to-api-layer]] — "더 보기" 버튼의 존재가 곧 더 있다는 신호).

## 6. 테스트 계약

- provider: `INFO-000` 정상 / `ERROR-500` throw / `RESULT` 부재 throw / `row` 빈 배열 / 페이지 루프 종료조건(받은 row 수 < 요청 크기) / 진행 판정 경계(시작일 == 오늘, 종료일 == 오늘, 종료일 == 어제) / 좌표 결측 제외 / cultcode 추출·폴백
- service: 거리순 정렬 / 3km 필터 / 서버 캡 / `total`은 절단 전
- route: 400(좌표 범위 밖) / `outOfCoverage` 마커가 키 게이트보다 앞 / 키 없음 → 빈 배열 / upstream throw → 502 / `limit` 범위 밖 400
- 컴포넌트: `// @vitest-environment jsdom` + nearby 계약 스위트 적용
- **변이 주입**으로 검출력 실측(계약 테스트 존재 ≠ 그 축이 지켜짐)
