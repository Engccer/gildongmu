# 도보 실시간 안내 정식 출시 + 길찾기 공지 모달 (설계)

> 2026-08-15 · iOS 1.4 대상 · 위원장 지시로 착수

## 1. 무엇을 정하는 문서인가

실시간 길 안내는 지금 빌드 구성 하나(`AppConfig.realtimeGuidanceEnabled`의 `#if EXPERIMENTAL`)로 **도보·자동차·대중교통·간략 안내가 통째로** 봉인돼 있다. 이 문서는 그중 **도보 안내만 정식판에 내보내는** 설계와, 그 출시에 딸리는 **길찾기 탭 1회성 공지 모달**을 정한다.

### 1.1 이것은 전략 전환이다 (판정 기록)

`docs/BACKLOG.md` G3는 봉인 해제의 선행 조건을 이렇게 못 박아 두었다: **"선행 조건은 코드가 아니라 판정이다"**(E4 잔여 · B1 실주행 · B2 실승차 · 백그라운드 톤 10종 · 계단 회피 3종 전부 통과 후 `#if` 삭제).

이번 결정은 그 조건을 **수단 축으로 분할**한다. 도보 축의 판정이 충분히 쌓였고 자동차·대중교통은 아직이라, 셋을 묶어 두면 검증이 끝난 기능이 검증이 안 끝난 기능을 기다린다. 남은 도보 축의 미판정은 **출시 차단이 아니라 사용자 고지로 처리**하며, 그 고지가 §5의 모달이다.

**알고도 내보내는 것**(모달 문안이 반영해야 하는 목록):

| 항목 | 상태 | 사용자에게 어떻게 나타나는가 |
|---|---|---|
| A11 넓은 부지 도착 판정 | 제품 판단 대기 | 학교·아파트단지·병원에서 도착 선언이 수십 m 어긋난다(실측 58.8m, 이틀 연속 재현) |
| A6 이탈 판정 방위 축 상수 | 구현 완료·검증 보행 대기 | 이탈 확정·복귀 판정 시점이 잠정값이다 |
| A12 톤 뒤 발화 | 구현 완료(2026-08-14)·실보행 판정 대기 | 임박 명령이 약 0.88초 늦는다 |
| 최종 접근 상수 7종 | 동결·판정 대기 | 마지막 몇 미터 안내의 시점·표현 |
| M0·M3·M5 | 구현 완료·실보행 판정 대기 | 하단 2행·경로 대안·목적지 메뉴 |

**A5(반복 낭독)는 2026-08-15 위원장 실사용 판정으로 종결**했다(A5-2는 2026-08-12에 문장 계층에서 이미 닫혔고, 잔여 A5-1·A5-3은 실사용에서 문제로 나타나지 않았다). 이 목록에서 뺀다.

**위원장 판정 3건**(2026-08-15, 이 설계의 전제):

1. **간략 거리 안내는 함께 내지 않는다** — 정식판 메시지를 "도보 안내 하나"로 유지한다.
2. **이탈 판정 방위 축은 켠 채로 낸다** — 실험판과 정식판의 안내 동작을 같게 유지해, 앞으로의 실보행 판정이 정식판에 그대로 적용되게 한다. 축을 끄면 갈림길에서 잘못 들어선 뒤 80초 넘게 안 가는 길을 안내받는 원증상(A6)이 남는데, 그쪽이 헛경고보다 위험하다.
3. **웹은 범위 밖이다** — 웹 실시간 안내는 이미 봉인 없이 배포돼 있고, 공지 모달도 iOS 전용이다.

## 2. 범위

**정식판(Release)에 나가는 것**

- 도보 상세 실시간 안내: 경로 추종·결정 지점 안내·임박 큐·최종 접근·이탈 판정(방위 축 포함)·계단 회피 열화 통지·안내 시트 전체.
- 도보 안내가 경로 조회에 실패했을 때의 **간략 안내 강등**(`BeaconModel.fallbackToBrief`). §3.3 참조.
- 백그라운드 위치·오디오(잠금 화면에서 세션 생존 + 톤 재생).
- 길찾기 탭 공지 모달(§5).

**실험판(Experimental)에 남는 것**

- 자동차 안내, 대중교통 안내, 대중교통→도보 인계, 간략 안내 **단독 진입점**.
- 계측 로그(`GuideDiag`·`TransitGuideDiag`) — §3.4의 함의를 볼 것.

**손대지 않는 것**: 웹 전체, `GuideTuning` 상수 일체(판정 전 임의 변경 금지 규율 유지), `GuideTuning.courseAxisEnabled`(walk만 켬 유지).

## 3. 게이트 재설계

### 3.1 플래그를 졸업시킨다

`AppConfig.realtimeGuidanceEnabled`를 **`experimentalGuidanceEnabled`로 대체**하고, 도보 경로에서는 **플래그 검사 자체를 삭제**한다.

```swift
/// 아직 정식 출시하지 않은 안내 수단(자동차·대중교통·간략 단독 진입)의 봉인.
/// 도보는 1.4에서 졸업했으므로 이 플래그를 보지 않는다.
#if EXPERIMENTAL
static let experimentalGuidanceEnabled = true
#else
static let experimentalGuidanceEnabled = false
#endif
```

**왜 `walkGuidanceEnabled = true`를 남기지 않는가.** `AppConfig.swift`가 스스로 적어 둔 규율이 "기능이 검증되면 `#if`를 지운다(플래그 졸업). 플래그가 쌓이지 않게 하는 것이 이 방식의 유일한 관리 포인트다"이다. 항상 참인 상수가 바로 그 쌓임이고, 다음 사람은 그것을 보고 도보에도 봉인이 남아 있다고 읽는다.

**왜 남은 셋을 하나로 묶는가.** 지금 셋의 운명이 같다(실주행·실승차 판정 대기). 수단별 상수 3개는 정보를 늘리지 않고 삭제 지점만 늘린다. 자동차가 먼저 졸업하는 상황이 실제로 오면 그때 쪼갠다.

### 3.2 호출부 6곳의 처리

`DirectionsTabView.swift`의 현행 참조 전부다. 각각 다르게 처리되므로 일괄 치환이 아니다.

| 자리 | 현행 | 변경 후 | 근거 |
|---|---|---|---|
| `walkGuideStartable` | 플래그 ∧ ko ∧ 경로 성공 | **플래그 검사 삭제** (ko ∧ 경로 성공) | 졸업 |
| `carGuideStartable` | 플래그 ∧ … | `experimentalGuidanceEnabled` ∧ … | 봉인 유지 |
| `transitGuideStartable` | 플래그 ∧ … | `experimentalGuidanceEnabled` ∧ … | 봉인 유지 |
| `altTransitGuideStartable` | 플래그 ∧ … | `experimentalGuidanceEnabled` ∧ … | 봉인 유지 |
| `briefFallbackVisible` | 플래그 ∧ settled ∧ 시작 가능 0개 | `experimentalGuidanceEnabled` ∧ … | 단독 진입점은 봉인 유지 |
| `manualOriginNoticeText` | 플래그 ∧ 수동 출발지 | **플래그 검사 삭제** | 도보 진입점이 정식판에 생겼으므로 사전 고지도 함께 살아나야 한다 |

⚠ **`manualOriginNoticeText`를 `experimentalGuidanceEnabled`로 치환하면 조용한 결함이 된다.** 그 문구는 "실시간 안내는 화면에 보이는 수동 출발지가 아니라 실제 위치를 쓴다"는 사전 고지인데, 정식판에서 도보 안내를 시작할 수 있게 된 순간부터 **정식판 사용자에게 필요한 문장**이 된다. 플래그를 그대로 옮기면 그 사용자만 고지 없이 안내를 시작한다.

### 3.3 간략 안내의 두 얼굴 (경계 명시)

"간략 안내를 함께 내지 않는다"의 범위는 **단독 진입점**이다.

- **빼는 것**: 시작 가능한 수단 안내가 0개일 때 나타나는 `beacon.briefGuideStart` 버튼(`briefFallbackVisible` 경로).
- **남기는 것**: 도보 안내를 시작했는데 경로 조회가 실패해 거리 안내로 강등되는 경로(`BeaconModel.fallbackToBrief`). 이걸 빼면 도보 안내가 실패했을 때 아무 말 없이 끝난다.

⚠ **`briefFallbackVisible = false`만으로는 버튼이 사라지지 않는다.** 선두 섹션(`DirectionsTabView.swift:590~615`)은 세 역할을 겸한다: ①간략 폴백 진입 ②시작 실패 상태와 해결 버튼 ③추적 중 중지 이중 방어. 섹션 표시 조건이 `beacon.isTracking || (… && (briefFallbackVisible || !beacon.statusText.isEmpty))`이고, 그 안의 버튼은 `beacon.isTracking ? 중지 : 간략 시작`이다. 따라서 **실패 상태 경로**(`statusText` 비어 있지 않음)로 섹션이 뜨면 정식판에서도 "간략 안내 시작" 버튼이 노출된다.

처방: 그 버튼을 `beacon.isTracking`일 때는 중지로, 비추적일 때는 `experimentalGuidanceEnabled`일 때만 간략 시작으로 낸다. 둘 다 아니면 버튼을 두지 않는다(섹션은 실패 상태 표시와 해결 버튼으로 계속 유효하다).

### 3.4 계측 로그의 함의 (판정 방식이 바뀐다)

`GuideDiag`는 `#if DEBUG || EXPERIMENTAL`이다. 즉 **정식판 도보 안내에는 계측 로그가 없다.** 도보 안내가 정식판에 나가도 실보행 판정(A6 검증 보행, A12 5종, 최종 접근 상수)은 **실험판에서 계속 해야 로그를 회수할 수 있다.**

이건 결함이 아니라 의도된 분리다(정식판에 진단 로그를 남기지 않는다). 다만 "정식판에도 도보 안내가 있으니 이제 아무 앱에서나 판정하면 된다"고 읽으면 로그 없는 세션을 걷게 되므로 명시한다.

## 4. 빌드 구성과 Info.plist

### 4.1 백그라운드 모드 승격

`ios/Support/Info.plist`(정식)에 지금 `UIBackgroundModes`가 **없다.** 잠금 화면에서 톤이 들리는 것은 `Info-Experimental.plist` 덕분이다. 도보 안내를 정식으로 내면서 이걸 옮기지 않으면, **빌드는 성공하고 전경에서는 완전히 정상인데 화면을 끄면 안내가 죽는다.**

정식 plist에 추가한다(실험판 plist는 그대로 둔다 — 두 파일 수동 동기화가 기존 계약이다):

```xml
<key>UIBackgroundModes</key>
<array>
    <string>location</string>
    <string>audio</string>
</array>
```

역할이 갈린다: 앱을 깨어 있게 유지하는 것은 `location`이고 `audio`는 재생만 허용한다. 위치만 올렸을 때 소리도 음성도 들리지 않은 것이 2026-08-07 실측으로 확인돼 있다.

### 4.2 위치 권한 문구 승격

지금 위치 권한 문구는 두 벌이다. 정식 문구(`InfoPlist.xcstrings`)에는 거리 안내 절이 없고, 실험판 문구는 빌드 스크립트 `ios/scripts/experimental-infoplist.sh`가 6로케일로 덮어쓴다.

도보 안내가 정식이 되면 **실험판 문구가 곧 정식 문구**다. 처리:

1. `InfoPlist.xcstrings`의 `NSLocationWhenInUseUsageDescription` 6로케일을 스크립트의 `location_purpose()` 문구로 교체한다.
2. **스크립트에서 권한 문구 처리를 제거하고 표시 이름 접미사만 남긴다.** 남겨 두면 같은 값을 두 곳이 관리하게 되어 다음 개정 때 갈린다.
3. 스크립트의 "대상 파일 0개면 실패" 가드는 유지한다(표시 이름이 곧 스크린 리더 사용자의 유일한 앱 구분 수단이다).

⚠ 한쪽만 하면 **앱에 있는 기능을 설명하지 않는 권한 문구**가 심사에 나간다. 종전 설계가 이 짝을 스크립트로 묶어 둔 이유가 정확히 그것이다.

### 4.3 `NSLocationTemporaryUsageDescriptionDictionary`

두 plist에 이미 동일하게 있고 문구도 "주변 정보 검색과 거리 추적은 정확한 위치가 필요합니다"라 도보 안내를 포함한다. 변경 없음.

## 5. 길찾기 탭 공지 모달

### 5.1 동작

- **트리거**: 길찾기 탭 진입 시(`DirectionsTabView`의 `.task`). 조회를 기다리지 않는다.
- **형태**: `.sheet`. 확인 버튼 하나가 닫으면서 본 것으로 기록한다.
- **저장**: `@AppStorage("walkGuideNoticeV1")` Bool. `AIChatConsent` 동형으로 키 상수를 한 곳(`enum WalkGuideNotice`)에 두고 뷰와 판정이 같은 키를 읽는다.
- **재노출**: 없음. 키에 버전을 넣어 두었으므로 자동차·대중교통을 추가할 때 `V2`로 새 공지를 낼 수 있다.
- **다시 보기 경로**: 두지 않는다. 요청이 1회 노출이고, 설정 항목 추가는 잉여다.

### 5.2 노출 조건

**한국어 사용자에게만 띄운다**(`AppLanguage.dataLocale == "ko"`). 도보 안내 자체가 한국어일 때만 존재하는 기능이라(`walkGuideStartable`의 ko 게이트), 다른 언어 사용자에게 띄우면 **없는 기능을 설명하는 공지**가 된다.

실험판에서도 같은 조건으로 뜬다(가르지 않는다). 실험판에는 자동차·대중교통도 있어 문안이 정확히 들어맞지는 않지만, 1회성이고 경고 내용은 도보 축에서 그대로 유효하다.

조건은 두 항의 논리곱(미확인 ∧ 한국어)이라 별도 판정 계층을 만들지 않는다. Kit으로 내려도 얻는 것이 없고(이 repo가 판정을 Kit으로 내려 온 이유는 앱 타깃 테스트 번들 부재인데, 그 값어치는 판정이 복잡할 때 생긴다), **이 기능의 실제 회귀 표면은 조건식이 아니라 "확인했는데 저장이 안 되어 매번 뜬다"이고 그건 §7.2의 재실행 확인이 잡는다.** 저장 키만 `AIChatConsent` 동형으로 한 곳에 둔다.

### 5.3 접근성

- 제목은 헤딩 trait(`.accessibilityAddTraits(.isHeader)`).
- **본문은 문단마다 별도 `Text`** — 산문 응답을 블록별 접근성 객체로 나누는 헌장 §6 계약이 그대로 적용된다. 한 덩어리 `Text`면 스크린 리더가 통짜로 읽어 중간에 되짚을 수 없다.
- 한 문단 안에서는 시각 강조용 인라인 분절을 만들지 않는다(한 줄 = 한 객체).
- 시트가 뜨면 포커스가 그 안으로 들어가고 닫으면 길찾기 화면으로 돌아온다(시스템 기본 동작). 별도 통지를 게시하지 않는다 — 모달 등장 자체가 이미 발화된다.
- 이모지·em dash를 쓰지 않는다.

## 6. 심사와 개인정보 정합

- **개인정보 3자 일치는 갱신 대상이 아니다.** `PrivacyInfo.xcprivacy`에 `NSPrivacyCollectedDataTypePreciseLocation`이 이미 `AppFunctionality` 목적으로 신고돼 있다. 백그라운드에서 쓰는 것은 새 데이터 유형도 새 제3자도 아니다. 웹 `/{locale}/privacy`와 ASC 영양 라벨도 같은 이유로 변경 없음. **점검만 하고 변경하지 않는다.**
- **심사 노트에 백그라운드 오디오의 용도를 명시한다**: 시각장애 사용자를 위한 보행 내비게이션 오디오 신호(방향·거리·이탈을 소리로 전달하며, 화면을 보지 않고 걷는 것이 이 기능의 전제다). 백그라운드 오디오는 심사가 실제로 들여다보는 항목이고, `Info-Experimental.plist`의 주석이 졸업 시 이 조치를 미리 지시해 두었다.
- **백그라운드 위치는 When In Use로 충분하다**(전경에서 시작하는 세션이라 Always 권한을 요구하지 않는다). 현행 설계 유지.

## 7. 검증 계약

### 7.1 드리프트 가드 (머지 게이트)

이 repo는 웹 Vitest가 Swift 소스를 읽어 대조하는 가드를 이미 쓴다(`src/lib/__tests__/format-drift.test.ts`). 같은 레인에 게이트 가드를 추가한다.

1. **봉인 유지**: `DirectionsTabView.swift`의 `carGuideStartable` · `transitGuideStartable` · `altTransitGuideStartable` · `briefFallbackVisible`이 각각 `experimentalGuidanceEnabled`를 참조한다.
2. **졸업 완료**: `walkGuideStartable`과 `manualOriginNoticeText`에 `experimentalGuidanceEnabled` 참조가 **없다**.
3. **백그라운드 모드**: `ios/Support/Info.plist`의 `UIBackgroundModes`에 `location`과 `audio`가 둘 다 있다.
4. **권한 문구 단일 관리**: `experimental-infoplist.sh`에 `NSLocationWhenInUseUsageDescription`이 더 이상 등장하지 않는다.

3번이 특히 중요하다. **빠뜨려도 빌드가 성공하고 전경 시험을 통과한다** — 화면을 끄고 걸어야만 드러나는 계열이라 사람의 기억에 맡길 수 없다.

### 7.2 실기기 (판정 정본)

- **정식 구성(`Release`) 실기기 설치**로 확인: 도보 안내 시작 가능, 자동차·대중교통 시작 버튼 부재, 간략 안내 단독 버튼 부재, **화면을 끈 채 톤과 음성이 살아 있음**(4.1의 실패가 여기서만 드러난다), 위치 권한 팝업 문구에 거리 안내 절 포함.
- **모달**: 첫 진입에 뜨고, 확인 후 앱을 껐다 켜도 다시 뜨지 않는다. 제목이 헤딩으로 잡히고 본문이 문단 단위로 스와이프된다.
- ⚠ 실험판과 정식판은 번들 ID가 달라 공존하며 **설정·저장값이 분리된다.** 실험판에서 모달을 확인해도 정식판에서는 다시 뜬다(정상).

## 10. 설계 리뷰 판정

**적대적 설계 리뷰 대상이다** — 글로벌 규율의 조건 ③(비가역·고파급: App Review 리스크, 백그라운드 모드·권한 문구 변경)과 ④(안전·정확성 크리티컬 축: 실보행 안내의 출하 범위와 경고 문안)에 해당한다.

따라서 **구현 착수 전에 `codex adversarial-review`를 이 spec에 돌린다.** 리뷰 포커스는 세 가지다: ①게이트 분리가 남긴 우회 진입 경로(§3.2·§3.3에서 놓친 자리가 있는가) ②정식판에만 존재하는 실패 모드(계측 로그 부재·저장값 분리·구성별 plist 갈림) ③모달 문안이 §1.1의 미판정 목록을 실제로 덮는가.
