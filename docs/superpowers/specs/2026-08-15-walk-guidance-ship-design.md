# 도보 실시간 안내 정식 출시 + 길찾기 공지 모달 (설계)

> 2026-08-15 · iOS 1.4 대상 · 위원장 지시로 착수 · codex 적대적 설계 리뷰 반영본(§11)

## 1. 무엇을 정하는 문서인가

실시간 길 안내는 지금 빌드 구성 하나(`AppConfig.realtimeGuidanceEnabled`의 `#if EXPERIMENTAL`)로 **도보·자동차·대중교통·간략 안내가 통째로** 봉인돼 있다. 이 문서는 그중 **도보 안내만 정식판에 내보내는** 설계와, 그 출시에 딸리는 **길찾기 탭 1회성 공지 모달**을 정한다.

### 1.1 이것은 전략 전환이다 (판정 기록)

`docs/BACKLOG.md` G3는 봉인 해제의 선행 조건을 이렇게 못 박아 두었다: **"선행 조건은 코드가 아니라 판정이다"**(E4 잔여 · B1 실주행 · B2 실승차 · 백그라운드 톤 10종 · 계단 회피 3종 전부 통과 후 `#if` 삭제).

이번 결정은 그 조건을 **수단 축으로 분할**한다. 도보 축의 판정이 충분히 쌓였고 자동차·대중교통은 아직이라, 셋을 묶어 두면 검증이 끝난 기능이 검증이 안 끝난 기능을 기다린다. 남은 도보 축의 미판정은 **출시 차단이 아니라 사용자 고지로 처리**하며, 그 고지가 §5의 모달이다.

**표 A: 모달 문안이 반드시 덮어야 하는 것** (사용자 안전에 직접 걸리는 미판정)

| 항목 | 상태 | 사용자가 겪는 형태 |
|---|---|---|
| A11 넓은 부지 도착 판정 | 제품 판단 대기 | 학교·아파트단지·병원에서 도착 선언이 수십 m 어긋난다(실측 58.8m, 이틀 연속 재현) |
| A6 이탈 판정 방위 축 상수 | 구현 완료·검증 보행 대기 | 잘못 들어선 것을 늦게 알리거나, 제자리로 돌아온 것을 늦게 인정한다 |
| A12 톤 뒤 발화 | 구현 완료(2026-08-14)·실보행 판정 대기 | 회전·횡단 명령이 약 0.88초 늦는다 |
| 최종 접근 상수 7종 | 동결·판정 대기 | 마지막 몇 미터의 안내 시점·표현이 실제와 어긋날 수 있다 |

**표 B: 실사용 검증 잔여** (안전 고지 대상이 아니다 — 문안에 넣지 않는다)

| 항목 | 상태 |
|---|---|
| M0 하단 2행 재설계 | 구현 완료·실보행 판정 대기 |
| M3 경로 대안 제시·전환 | 구현 완료·실보행 판정 잔여 |
| M5 안내 시트 목적지 메뉴 | 구현 완료·실기기 판정 대기 |

⚠ **두 표를 가르는 것이 문안 합격 기준이다.** 표 A의 네 항목은 "안내를 믿고 걷다가 다칠 수 있는 방식"이라 문안이 덮어야 하고, 표 B는 "덜 편할 수 있는 방식"이라 문안 대상이 아니다. 종전 판(2026-08-15 초판)은 둘을 한 표에 두어 합격 기준이 스스로 모순됐다(리뷰 #11).

**덮는 방식은 항목별 열거가 아니라 포괄 문장이다**(위원장 판정 2026-08-15, 문안 확정과 함께). 네 항목을 각각 한 문장씩 펴면 경고가 사용법보다 길어져 1회성 모달에서 읽히지 않는다. 지금 문안은 "실제 상황과는 차이가 있을 수 있습니다" + "보조 정보로만 사용"이 넷을 함께 받는다(§5.4). ⚠ **이 포괄은 표 A가 열려 있는 동안의 처리이지 영구 판정이 아니다** — 어느 항목이든 실사용에서 위험 사례로 재현되면 개별 문장으로 승격한다.

**A5(반복 낭독)는 2026-08-15 위원장 실사용 판정으로 종결**했다(A5-2는 2026-08-12에 문장 계층에서 이미 닫혔고, 잔여 A5-1·A5-3은 실사용에서 문제로 나타나지 않았다). 어느 표에도 넣지 않는다.

**위원장 판정 3건**(2026-08-15, 이 설계의 전제):

1. **간략 거리 안내는 함께 내지 않는다** — 정식판 메시지를 "도보 안내 하나"로 유지한다.
2. **이탈 판정 방위 축은 켠 채로 낸다** — 실험판과 정식판의 안내 동작을 같게 유지해, 앞으로의 실보행 판정이 정식판에 그대로 적용되게 한다. 축을 끄면 갈림길에서 잘못 들어선 뒤 80초 넘게 안 가는 길을 안내받는 원증상(A6)이 남는데, 그쪽이 헛경고보다 위험하다.
3. **웹은 범위 밖이다** — 웹 실시간 안내는 이미 봉인 없이 배포돼 있고, 공지 모달도 iOS 전용이다.

## 2. 범위

**정식판(Release)에 나가는 것**

- 도보 상세 실시간 안내: 경로 추종·결정 지점 안내·임박 큐·최종 접근·이탈 판정(방위 축 포함)·계단 회피 열화 통지·안내 시트 전체.
- 추천 경로와 **최단 경로**(M3) 양쪽의 안내 시작(§3.4).
- 도보 안내 세션이 경로를 잃었을 때의 **간략 모드 강등**(§3.3).
- 백그라운드 위치·오디오(잠금 화면에서 세션 생존 + 톤 재생).
- 안내 시트의 화면 힌트 삭제(§4.4 — 백그라운드 승격과 짝이다).
- 길찾기 탭 공지 모달(§5).

**실험판(Experimental)에 남는 것**

- 자동차 안내, 대중교통 안내, 대중교통→도보 인계, 간략 안내 **단독 진입점**.
- 계측 로그(`GuideDiag`·`TransitGuideDiag`) — §3.5의 함의를 볼 것.

**손대지 않는 것**: 웹 전체, `GuideTuning` 상수 일체(판정 전 임의 변경 금지 규율 유지), `GuideTuning.courseAxisEnabled`(walk만 켬 유지).

## 3. 게이트 재설계

### 3.1 플래그를 졸업시킨다

`AppConfig.realtimeGuidanceEnabled`를 **`experimentalGuidanceEnabled`로 대체**하고, 도보 경로에서는 **플래그 검사 자체를 삭제**한다.

```swift
/// 아직 정식 출시하지 않은 안내 수단(자동차·대중교통·간략 단독 진입)의 봉인.
/// 도보는 1.4에서 졸업했으므로 이 플래그를 보지 않는다.
#if EXPERIMENTAL
static let experimentalGuidanceEnabled = true
#else
static let experimentalGuidanceEnabled = false
#endif
```

**왜 `walkGuidanceEnabled = true`를 남기지 않는가.** `AppConfig.swift`가 스스로 적어 둔 규율이 "기능이 검증되면 `#if`를 지운다(플래그 졸업). 플래그가 쌓이지 않게 하는 것이 이 방식의 유일한 관리 포인트다"이다. 항상 참인 상수가 바로 그 쌓임이고, 다음 사람은 그것을 보고 도보에도 봉인이 남아 있다고 읽는다.

**왜 남은 셋을 하나로 묶는가.** 지금 셋의 운명이 같다(실주행·실승차 판정 대기). 수단별 상수 3개는 정보를 늘리지 않고 삭제 지점만 늘린다. 자동차가 먼저 졸업하는 상황이 실제로 오면 그때 쪼갠다.

### 3.2 봉인의 판정 축은 "세션을 시작시키는 호출"이다

⚠ **플래그 참조 목록과 세션 진입점 목록은 같은 집합이 아니다**(리뷰 #3). 종전 판은 `DirectionsTabView`의 플래그 참조 6곳만 열거했는데, 그중 일부는 진입점이 아니고(고지 문구) 반대로 진입점인데 플래그를 안 보는 자리가 있다. **봉인의 정본 축은 `beacon.toggle`·`beacon.restart`·`transitGuide` 세션 시작 호출 전수**다.

**세션을 시작시키는 호출 전수**(2026-08-15 코드 실측, 진입점 6곳 + 대중교통. ⚠ 2026-08-16 A13으로 재시작 자리의 **호출 형태가 바뀌었다** — `toggle`만 세면 그 진입점이 시야에서 사라진다):

| 자리 | 무엇을 시작하는가 | 정식판 도달 | 근거 |
|---|---|---|---|
| `1258` 도보 추천 시작 버튼 | 도보 세션 | **가능** | `walkGuideStartable` 안 |
| `1283` 도보 최단 시작 버튼 | 도보 세션(`variant: .shortest`) | **가능** | 같은 `walkGuideStartable` 안(§3.4) |
| 정밀 위치 허용 후 재시작(`beacon.restart()`) | **직전 세션과 같은 수단·경로**(A13, 2026-08-16) | **가능** | 게이트 밖이지만 도달 조건이 "이미 실패한 세션"이라 정당(§3.3) |
| `611` 간략 단독 시작 버튼 | 도보 세션 | **차단** | `experimentalGuidanceEnabled`(§3.3) |
| `684` 자동차 시작 버튼 | 자동차 세션 | **차단** | `experimentalGuidanceEnabled` |
| `964` 대중교통→도보 인계 | 도보 세션 | **차단** | 대중교통 세션 안에서만 호출되고 그 세션이 봉인된다 |
| `transitGuideStartable`·`altTransitGuideStartable` | 대중교통 세션 | **차단** | `experimentalGuidanceEnabled` |

**외부 진입 경로는 없다**(리뷰 #3의 "확인 필요"에 대한 실측 답): `beacon.toggle`·`beacon.restart` 호출은 `DirectionsTabView` 밖에 없고, `AppShortcuts`·App Intent·딥링크에 안내 시작 경로가 없다. 세션 복원 기능도 없다(앱을 내리면 세션이 끝난다). 따라서 `964`의 안전성이 "대중교통 세션의 유일한 생성 경로가 UI 게이트"라는 가정에 의존한다는 지적은 맞지만, 그 가정은 실측으로 참이다. **신규 진입점을 만들 때 이 표를 갱신하는 것이 계약이다.**

**플래그 참조 6곳의 처리**(위 축의 구현):

| 자리 | 변경 후 | 근거 |
|---|---|---|
| `walkGuideStartable` | **플래그 검사 삭제** | 졸업 |
| `carGuideStartable` | `experimentalGuidanceEnabled` | 봉인 유지 |
| `transitGuideStartable` | `experimentalGuidanceEnabled` | 봉인 유지 |
| `altTransitGuideStartable` | `experimentalGuidanceEnabled` | 봉인 유지 |
| `briefFallbackVisible` | `experimentalGuidanceEnabled` | 단독 진입점은 봉인 유지 |
| `manualOriginNoticeText` | **플래그 검사 삭제** | 진입점이 아니라 고지다 |

⚠ **`manualOriginNoticeText`를 `experimentalGuidanceEnabled`로 치환하면 조용한 결함이 된다.** 그 문구는 "실시간 안내는 화면에 보이는 수동 출발지가 아니라 실제 위치를 쓴다"는 사전 고지인데, 정식판에서 도보 안내를 시작할 수 있게 된 순간부터 **정식판 사용자에게 필요한 문장**이 된다. 플래그를 그대로 옮기면 그 사용자만 고지 없이 안내를 시작한다.

### 3.3 간략 안내는 별도 모드가 아니라 세션 내부 상태다

리뷰 #4가 "정식판의 간략 강등에 출처 불변식이 필요하다"고 지적했는데, **처방은 기각하고 사실을 문서화한다.** 근거는 코드 실측이다.

- `BeaconModel.mode`의 초기값이 `.brief`이고, `start()`가 경로를 얻으면 상세로 올라간다. 경로를 못 얻거나 잃으면 `fallbackToBrief()`로 되돌아온다.
- 그래서 **"간략 안내 시작"과 "도보 안내 시작"은 같은 호출이다**(둘 다 `beacon.toggle(kind: .walk)`). 다른 것은 버튼 라벨과 포커스 키뿐이다.

따라서 모델에 `.releasedWalkRouteFailure` 같은 출처 태그를 새로 만드는 것은 **없는 계층을 만드는 일**이다. 정식판의 불변식은 구조로 이미 성립한다: 진입점이 `walkGuideStartable`(경로 성공 ∧ ko)뿐이므로 **세션은 언제나 성공한 도보 경로에서 시작하고**, 간략 상태는 그 세션이 나중에 경로를 잃었을 때만 나타난다.

⚠ **`briefFallbackVisible = false`만으로는 단독 버튼이 사라지지 않는다.** 선두 섹션(`DirectionsTabView.swift:590~615`)은 세 역할을 겸한다: ①간략 폴백 진입 ②시작 실패 상태와 해결 버튼 ③추적 중 중지 이중 방어. 섹션 표시 조건이 `beacon.isTracking || (… && (briefFallbackVisible || !beacon.statusText.isEmpty))`이고 그 안의 버튼이 `beacon.isTracking ? 중지 : 간략 시작`이라, **실패 상태 경로**로 섹션이 뜨면 정식판에서도 "간략 안내 시작" 버튼이 노출된다.

처방: 그 버튼을 `beacon.isTracking`일 때는 중지로, 비추적일 때는 `experimentalGuidanceEnabled`일 때만 간략 시작으로 낸다. 둘 다 아니면 버튼을 두지 않는다(섹션은 실패 상태 표시와 해결 버튼으로 계속 유효하다).

**`633`(정밀 위치 허용 후 재시작)은 그대로 둔다.** 게이트 밖이지만 그 버튼이 존재하려면 `beacon.statusText`가 차 있어야 하고, 그건 정식판에서 **이미 도보 세션을 시작해 권한 문제로 실패했다는 뜻**이다. 즉 재시작은 정당한 도보 안내 재개다.

⚠ 다만 그 재시작은 `variant`·`shortestAvailable`을 넘기지 않아, **최단 경로로 시작한 세션이 추천 경로로 재개된다.** 이번 변경이 만든 결함이 아니라 기존 결함이고(M3 이후 줄곧), 범위 밖이지만 `docs/BACKLOG.md`에 등재한다.

### 3.4 최단 경로 시작 버튼도 같은 판정을 쓴다 (리뷰 #5 기각 근거)

리뷰가 "`.walkShortest`가 게이트 목록에 없어 추천 경로만 출시될 수 있다"고 지적했으나 **오탐**이다. 실측(`DirectionsTabView.swift:1280`): 최단 행 안의 시작 버튼도 `if walkGuideStartable, let tracked = trackedDestination` 안에 있다. 추천 행(1255)과 **같은 판정**이므로 졸업이 자동으로 둘 다 덮는다.

다만 지적이 나온 이유가 종전 판의 서술 부족이었으므로 여기 명시한다. 최단 행 자체는 `model.walkShortest != nil`일 때만 그려지고(死행 금지), 그 값은 같은 응답에서 온 쌍이다.

### 3.5 계측 로그의 함의 (판정 방식이 바뀐다)

`GuideDiag`는 `#if DEBUG || EXPERIMENTAL`이다. 즉 **정식판 도보 안내에는 계측 로그가 없다.** 도보 안내가 정식판에 나가도 원인 규명형 판정(A6 검증 보행, A12 5종, 최종 접근 상수)은 **실험판에서 계속 해야 로그를 회수할 수 있다.**

⚠ **그러나 최종 판정을 실험판 결과로 갈음하지 않는다**(리뷰 #10). 두 바이너리는 진단 코드 포함 여부·번들 ID·UserDefaults·권한 상태가 다르고, A12는 0.88초짜리 시간 민감 항목이다. **원인 계측은 실험판, 시간·백그라운드 동작의 최종 확인은 정식판**으로 가른다(§7.3).

## 4. 빌드 구성과 Info.plist

### 4.1 백그라운드 모드 승격

`ios/Support/Info.plist`(정식)에 지금 `UIBackgroundModes`가 **없다.** 잠금 화면에서 톤이 들리는 것은 `Info-Experimental.plist` 덕분이다. 도보 안내를 정식으로 내면서 이걸 옮기지 않으면, **빌드는 성공하고 전경에서는 완전히 정상인데 화면을 끄면 안내가 죽는다.**

정식 plist에 추가한다(실험판 plist는 그대로 둔다 — 두 파일 수동 동기화가 기존 계약이다):

```xml
<key>UIBackgroundModes</key>
<array>
    <string>location</string>
    <string>audio</string>
</array>
```

역할이 갈린다: 앱을 깨어 있게 유지하는 것은 `location`이고 `audio`는 재생만 허용한다. 위치만 올렸을 때 소리도 음성도 들리지 않은 것이 2026-08-07 실측으로 확인돼 있다.

### 4.2 위치 권한 문구는 한국어만 바꾼다

지금 위치 권한 문구는 두 벌이다. 정식 문구(`InfoPlist.xcstrings`)에는 거리 안내 절이 없고, 실험판 문구는 빌드 스크립트 `ios/scripts/experimental-infoplist.sh`가 6로케일로 덮어쓴다.

⚠ **6로케일을 전부 바꾸면 없는 기능을 설명하는 권한 문구가 된다**(리뷰 #6). 도보 안내는 `dataLocale == "ko"` 게이트 안에 있어 **정식판의 비한국어 사용자에게는 존재하지 않는다.** 그런데 종전 판은 6로케일 전부를 거리 안내 문구로 올리려 했다. 이건 이 스크립트가 애초에 막으려던 것("공식판은 없는 기능을 설명하면 안 된다")을 로케일 축에서 되풀이하는 일이다.

처리:

1. `InfoPlist.xcstrings`의 `NSLocationWhenInUseUsageDescription` **ko만** 스크립트의 `location_purpose()` ko 문구로 교체한다. en·es·fr·it·ja는 현행 유지.
2. **스크립트에서 권한 문구 처리를 제거하고 표시 이름 접미사만 남긴다.** 실험판은 6로케일 모두에 안내 기능이 있지만(실험판 미선택 폴백이 ko라 사실상 ko), 남겨 두면 같은 값을 두 곳이 관리하게 되어 다음 개정 때 갈린다. 실험판 비한국어 문구가 한 절 부족한 것은 과소 설명이라 심사 위험이 아니다.
3. **스크립트 가드를 결과 검증으로 바꾼다**(리뷰 #9). 현행 `changed`는 파일 존재만 세므로 `CFBundleDisplayName` 추출 실패·`plutil -replace` 실패를 성공으로 계산한다(`set -e`가 없어 중단되지도 않는다). 접미사가 실제로 붙었는지 다시 읽어 확인하고, 하나라도 실패하면 빌드를 멈춘다. 스크린 리더 사용자에게 표시 이름은 두 앱을 구분하는 유일한 수단이다.

⚠ **알려진 경계**: 시스템 권한 대화상자는 **시스템 언어**를 따르고 `dataLocale`은 **앱 안 선택**이다. 시스템이 영어이고 앱 언어를 한국어로 고른 사용자는 도보 안내를 쓰면서 거리 안내 절이 없는 영어 문구를 본다. 과소 설명이라 심사 위험이 아니고, 지금 출시본과 같은 문구다. ko 게이트를 푸는 시점에 함께 해소한다.

### 4.3 `NSLocationTemporaryUsageDescriptionDictionary`

두 plist에 이미 동일하게 있고 문구도 "주변 정보 검색과 거리 추적은 정확한 위치가 필요합니다"라 도보 안내를 포함한다. 변경 없음.

### 4.4 안내 시트의 화면 힌트를 삭제한다 (iOS만)

`BeaconTrackingSheet.swift:158`이 `beacon.screenHint`를 **조건 없이** 띄운다: **"화면을 켜고 손에 든 채 사용하세요. 화면이 꺼지면 안내가 멈춥니다."** 백그라운드 모드가 정식판에 들어가는 순간 이 문장은 거짓이 된다(실험판에서는 이미 거짓이다).

⚠ **이건 문구 하나의 문제가 아니라 계층이 겹친 것이다.** 앱은 백그라운드 가청 여부를 이미 **런타임에 판정**한다 — `BeaconTonePlayer.isBackgroundAudible`(`appliedCategory == .playback`)이 거짓이면 `soundDegraded` 행이 "화면이 꺼지거나 다른 앱을 쓰는 동안에는 안내 소리가 나지 않습니다"를 띄운다. 즉 **정확한 층이 이미 있고 조건까지 맞다.** `screenHint`는 그 위에 얹힌, 언제나 참인 척하는 상시 문장이다.

처리: **iOS 안내 시트에서 `screenHint`와 "다시 보지 않음" 버튼·저장 키(`beaconScreenHintDismissed`)를 함께 제거한다.** 소비자가 사라지므로 문자열 키는 웹 전용으로 남는다.

- **웹은 그대로 둔다.** 브라우저 탭은 실제로 백그라운드에서 안내가 멈추므로 웹에서는 그 문장이 참이다. 문자열을 지우지 않는 이유가 이것이다.
- 모달 첫 문단이 "화면을 꺼도 이어집니다"를 말하므로, 이 삭제를 빠뜨리면 **같은 앱의 두 화면이 정반대를 말한다.** 모달을 읽고 주머니에 넣은 사용자가 안내 시트에서 "화면이 꺼지면 멈춘다"를 만나면, 어느 쪽이 참인지 확인할 방법이 없다.
- 삭제로 잃는 정보가 없다: 진짜 무음 상황은 `soundDegraded` 행이 조건부로, 더 정확한 문구로 알린다.

## 5. 길찾기 탭 공지 모달

### 5.1 동작

- **트리거**: 길찾기 탭 진입 시(`DirectionsTabView`의 `.task`). 조회를 기다리지 않는다.
- **형태**: `.sheet`.
- **저장은 확인 버튼만 한다.** `@AppStorage("walkGuideNoticeV1")` Bool을 확인 버튼이 켠다.
- **시스템 닫기(드래그·VoiceOver 탈출 제스처)는 막지 않는다.** 닫히되 저장하지 않으므로 **다음 탭 진입에 다시 뜬다.**
- **재노출**: 확인을 누른 뒤에는 없다. 키에 버전을 넣어 두었으므로 자동차·대중교통을 추가할 때 `V2`로 새 공지를 낼 수 있다.
- **다시 보기 경로**: 두지 않는다. 요청이 1회 노출이고, 설정 항목 추가는 잉여다.

⚠ **`.interactiveDismissDisabled()`로 가두지 않는 것이 판정이다**(리뷰 #1의 처방 변경). 리뷰는 "확인 없이 닫고 안내에 진입할 수 있다"를 BLOCKER로 지적했고 그 사실은 맞다. 그러나 스크린 리더 사용자에게 **VoiceOver 탈출 제스처는 모달에서 빠져나오는 표준 수단**이라, 그것을 막으면 이 앱의 1급 사용자를 대화상자에 가두게 된다. 대신 **저장을 확인 버튼에만 걸어** 읽지 않고 닫은 사용자에게 다음에 다시 보여준다. 안전 고지의 목적(읽게 하는 것)은 지켜지고 탈출구는 남는다.

즉 계약을 정확히 쓰면 "한 번 뜨면 다시 안 뜬다"가 아니라 **"확인을 누르면 다시 뜨지 않는다"**이다.

### 5.2 노출 조건

**한국어 사용자에게만 띄운다**(`AppLanguage.dataLocale == "ko"`). 도보 안내 자체가 한국어일 때만 존재하는 기능이라(`walkGuideStartable`의 ko 게이트), 다른 언어 사용자에게 띄우면 **없는 기능을 설명하는 공지**가 된다.

실험판에서도 같은 조건으로 뜬다(가르지 않는다). 실험판에는 자동차·대중교통도 있어 문안이 정확히 들어맞지는 않지만, 1회성이고 경고 내용은 도보 축에서 그대로 유효하다.

조건은 두 항의 논리곱(미확인 ∧ 한국어)이라 별도 판정 계층을 만들지 않는다. **이 기능의 실제 회귀 표면은 조건식이 아니라 "확인했는데 저장이 안 되어 매번 뜬다"이고 그건 §7.3의 재실행 확인이 잡는다.** 저장 키만 `AIChatConsent` 동형으로 한 곳에 둔다.

### 5.3 접근성

- 제목과 **소제목 2개**는 헤딩 trait(`.accessibilityAddTraits(.isHeader)`). 레벨 구분(`.accessibilityHeading(_:)`)은 두지 않는다 — 이 repo는 `.isHeader`만 쓰고(`StationSections.swift` 선례), 문단 대여섯 개짜리 모달에서 2단 계층은 정보를 늘리지 않는다.
- ⚠ **소제목을 본문 문자열 안에 마크다운으로 넣지 않는다.** `appLocalized`는 `String`을 반환하고 `Text(String)` 오버로드는 마크다운을 파싱하지 않으므로 `### `가 화면과 낭독에 그대로 나온다(`LocalizedStringKey` 경로였어도 SwiftUI는 블록 헤딩을 렌더하지 않는다). 소제목은 **별도 키 + 별도 `Text`**여야 헤딩이 되고, 그래야 로터로 건너뛸 수 있다.
- **본문은 문단마다 별도 `Text`** — 산문을 블록별 접근성 객체로 나누는 헌장 §6 계약이 그대로 적용된다. 한 덩어리 `Text`면 스크린 리더가 통짜로 읽어 중간에 되짚을 수 없다.
- 한 문단 안에서는 시각 강조용 인라인 분절을 만들지 않는다(한 줄 = 한 객체).
- **최초 착지와 복귀를 검증 항목으로 둔다**(리뷰 #12). 시스템 기본 동작에 기대되, 시트가 열릴 때 커서가 제목에 닿는지와 확인 후 어디로 돌아오는지를 실기기로 확인한다(§7.3). 이 repo는 시트 전환에서 지연·재시도 착지가 필요했던 전례가 여럿이라 "기본 동작이니 된다"고 단정하지 않는다.
- 모달 등장 자체가 발화되므로 별도 통지를 게시하지 않는다.
- 이모지·em dash를 쓰지 않는다.

- **"화면을 잠가도 백그라운드에서 작동한다"는 사용법이자 안전 정보다.** 스크린 리더 사용자는 화면을 켜 둘 이유가 없고, 이 앱의 종전 안내 시트는 정반대를 말해 왔다(§4.4). 이 한 줄이 없으면 사용자는 걷는 내내 화면을 켠 채 손에 들어야 한다고 믿는다.
- **표 A는 항목별 대응이 아니라 포괄 문장으로 덮는다**(위원장 판정 2026-08-15, 리뷰 #2 수용 방식의 변경). "실제 상황과는 차이가 있을 수 있습니다"(본문 2) + "보조 정보로만 사용"(본문 3)이 네 항목을 함께 받는다. 항목별 열거(늦는 이탈 안내·늦는 방향 전환·넓은 부지 수십 미터)를 편 종전 판은 **경고 문단이 사용법보다 길어져** 1회성 모달에서 읽히지 않는다는 판단이다. ⚠ 이 선택은 **표 A가 닫힐 때까지만 유효하다** — A11·A6·최종 접근 상수 중 어느 하나라도 실사용에서 위험 사례로 재현되면 그 항목은 개별 문장으로 승격한다(모달 키에 `V2`를 쓰는 첫 사유가 될 수 있다).
- **본문 3의 횡단 경고는 단문 유지다**(같은 판정). "안내음은 건너도 좋다는 신호가 아니다"라는 구분 문장은 넣지 않는다. 다만 **횡단을 별도 문장으로 남긴 것 자체가 그 층의 흔적**이므로, 이 문장을 다른 한계와 한 문단으로 합치지 않는다.
- **소제목 2개는 별도 접근성 객체다**(§5.3). 마크다운 `###`은 렌더되지 않으므로 문자열에 넣지 않는다 — `appLocalized`가 `String`을 반환하고 `Text(String)` 오버로드는 마크다운을 파싱하지 않아 `### `가 화면과 낭독에 그대로 나온다(SwiftUI는 `LocalizedStringKey` 경로에서도 블록 헤딩을 렌더하지 않는다).
- **횡단 경계를 따로 문단으로 뗐다.** 이 앱은 음향신호기 정보를 다루고 안내음도 낸다. 두 소리를 혼동하면 결과가 차도 진입이라, 다른 한계와 같은 문단에 섞지 않는다.
- **타 앱 사용 권유 문장을 넣지 않는다.** "다른 길찾기 앱을 함께 쓰세요" 계열은 이 repo가 통지 정리(2026-08-02)에서 제거한 패턴이다. 마지막 문단이 가리키는 것은 흰지팡이·안내견·동행 같은 **사용자가 이미 쓰는 보행 방법**이지 경쟁 앱이 아니다.
- **"한 번만 표시됩니다" 같은 안내를 넣지 않는다.** 사용자가 곧 만날 동작을 미리 중복 안내하지 않는다.
- 표 B(M0·M3·M5)는 넣지 않는다. §1.1의 판정선 그대로다.

### 5.5 문자열 배치

iOS 전용 문자열이므로 `ios/i18n/ios-extra/{locale}.json`에 넣는다(웹과 공유하지 않는다). 길찾기 탭 소속이므로 기존 `ios.directions` 아래에 둔다. **9개 키**를 `ios.directions.walkNotice` 아래 화면 순서대로 둔다: `.title` · `.intro` · `.head1` · `.body1` · `.head2` · `.body2` · `.body3` · `.body4` · `.confirm`.

⚠ **키 이름을 화면 순서와 어긋나게 두지 않는다.** 인사 한 줄을 `.body1`로 부르면 뒤 문단이 전부 한 칸씩 밀려 `.head1`이 `.body1`보다 뒤에 오는 목록이 된다. 문단을 더하거나 뺄 때 이 순서를 다시 맞춘다.

⚠ **소제목이 별도 키인 것이 접근성 요구다**(§5.3). 본문에 합치면 헤딩이 성립하지 않는다.

**6로케일 모두 채운다.** 노출은 ko 전용이지만 이 파이프라인은 로케일 간 키 수가 맞춰져 있고(현재 223개 동일), 문안이 준비돼 있어야 나중에 ko 게이트를 풀 때 코드만 고치면 된다. 변환은 `node ios/scripts/messages-to-xcstrings.mjs`, 키 검사는 `node ios/scripts/check-xcstrings-keys.mjs`.

## 6. 심사와 개인정보 정합

- **개인정보 3자 일치는 갱신 대상이 아니다.** `PrivacyInfo.xcprivacy`에 `NSPrivacyCollectedDataTypePreciseLocation`이 이미 `AppFunctionality` 목적으로 신고돼 있다. 백그라운드에서 쓰는 것은 새 데이터 유형도 새 제3자도 아니다. 웹 `/{locale}/privacy`와 ASC 영양 라벨도 같은 이유로 변경 없음. **점검만 하고 변경하지 않는다.**
- **심사 노트에 백그라운드 오디오의 용도를 명시한다**: 시각장애 사용자를 위한 보행 내비게이션 오디오 신호(방향·거리·이탈을 소리로 전달하며, 화면을 보지 않고 걷는 것이 이 기능의 전제다). 백그라운드 오디오는 심사가 실제로 들여다보는 항목이고, `Info-Experimental.plist`의 주석이 졸업 시 이 조치를 미리 지시해 두었다.
- **백그라운드 위치는 When In Use로 충분하다**(전경에서 시작하는 세션이라 Always 권한을 요구하지 않는다). 현행 설계 유지.

## 7. 검증 계약

### 7.1 소스 드리프트 가드 (머지 게이트)

이 repo는 웹 Vitest가 Swift 소스를 읽어 대조하는 가드를 이미 쓴다(`src/lib/__tests__/format-drift.test.ts`). 같은 레인에 게이트 가드를 추가한다. **판정 축은 §3.2의 진입점 표다.**

1. **봉인 유지**: `beacon.toggle` 호출 중 자동차 시작(`684`)·간략 단독 시작(`611`)이 `experimentalGuidanceEnabled` 게이트 안에 있고, `transitGuideStartable`·`altTransitGuideStartable`도 같은 플래그를 참조한다.
2. **졸업 완료**: `walkGuideStartable`과 `manualOriginNoticeText`에 `experimentalGuidanceEnabled` 참조가 **없다**.
3. **진입점 증가 감시**: `ios/Gildongmu` 전체의 `beacon.toggle(`·`beacon.restart(` 호출 수 합이 §3.2 표의 개수와 같다. 늘면 테스트가 실패하고, 그때 표를 갱신하며 정식판 도달 여부를 판정한다. **이것이 "플래그 참조만 세다가 새 진입점을 놓치는" 실패를 막는 유일한 자동 장치다.**
4. **백그라운드 모드**: `ios/Support/Info.plist`의 `UIBackgroundModes`에 `location`과 `audio`가 둘 다 있다.
5. **권한 문구 단일 관리**: `experimental-infoplist.sh`에 `NSLocationWhenInUseUsageDescription`이 더 이상 등장하지 않는다.
6. **화면 힌트 부재**(§4.4): `ios/Gildongmu` 전체에 `beacon.screenHint`·`beaconScreenHintDismissed` 참조가 없다. 웹(`src/`)에는 남아 있어야 하므로 스캔 범위를 iOS로 한정한다. 이 가드가 없으면 삭제가 되돌아와도 조용하다 — 두 문장의 모순은 **잠금 화면에서 걸을 때만** 드러나기 때문이다.

### 7.2 산출물 가드 (소스 검사로는 부족하다)

⚠ **§7.1의 4번은 소스만 본다**(리뷰 #7). 그 검사는 Release 대상이 다른 `INFOPLIST_FILE`을 참조하는 경우, 병합 과정에서 키가 누락되는 경우, Archive가 예상과 다른 구성을 쓰는 경우를 잡지 못한다. 그런데 이 계열은 spec 스스로 "빌드는 성공하고 전경에서는 정상"이라고 규정한 실패다.

따라서 **빌드 산출물의 최종 `Info.plist`를 직접 읽는 검사**를 릴리스 절차에 넣는다: Release 구성으로 빌드한 `.app`에서 `UIBackgroundModes`에 `location`·`audio`가 있고, `ko.lproj/InfoPlist.strings`의 `NSLocationWhenInUseUsageDescription`에 거리 안내 절이 있으며, 비한국어 lproj에는 없음을 확인한다. 자리는 `ios/scripts/asc-submit.mjs`의 사전 점검이 자연스럽다(제출 직전이 마지막 관문이다).

### 7.3 실기기 (판정 정본)

**정식 구성(`Release`) 실기기 설치**로 확인한다.

- **도달**: 도보 추천·최단 **양쪽** 안내 시작 가능, 자동차·대중교통 시작 버튼 부재, 간략 안내 단독 버튼 부재(실패 상태 화면에서도 나오지 않는지 함께).
- **백그라운드**: 화면을 끈 채 톤과 음성이 살아 있음. §4.1의 실패가 여기서만 드러난다. **안내 시트에 화면 힌트가 없고**(§4.4), 소리가 살아 있으므로 `soundDegraded` 행도 뜨지 않음을 함께 본다(그 행이 뜬다면 백그라운드 오디오가 실제로는 붙지 않은 것이고, 모달 문안이 거짓이 된다).
- **권한 문구**: **앱을 지우고 새로 설치해** 권한 팝업을 처음부터 받는다(리뷰 #8 — 이미 허용된 상태면 팝업이 안 떠서 확인 자체가 성립하지 않는다). 한국어 문구에 거리 안내 절이 있고, 시스템 언어를 영어로 바꿔 받은 문구에는 없음을 함께 본다(§4.2 판정대로인지).
- **모달**: 첫 진입에 뜨고, **확인을 누른 뒤** 앱을 껐다 켜도 다시 뜨지 않는다. **드래그·VoiceOver 탈출로 닫으면 다시 뜬다**(§5.1 계약). 제목이 헤딩으로 잡히고 본문이 문단 단위로 스와이프되며, **열릴 때 커서가 제목에 닿고 확인 후 길찾기 화면으로 돌아온다**.
- **타이밍 재확인**(리뷰 #10): A12 계열(임박 명령이 톤 뒤에 오는 체감)과 백그라운드 동작을 **정식판에서도** 한 번 걷는다. 원인 계측은 실험판이 맡되 최종 판정은 사용자와 같은 바이너리에서 한다.

⚠ 실험판과 정식판은 번들 ID가 달라 **설정·저장값·권한이 분리된다.** 실험판에서 모달을 확인해도 정식판에서는 다시 뜬다(정상).
