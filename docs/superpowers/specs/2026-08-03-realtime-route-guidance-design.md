# 실시간 길 안내 설계 (2026-08-03)

> E4(경로 추종형 도보 안내)의 구현 스펙. 조사 정본은 `docs/RESEARCH-2026-08-02-realtime-walk-navigation.md`(이하 "조사")이며 본 문서는 그 §5 설계 골격을 코드 계약으로 확정한다. 조사 본문을 재조사하지 말 것.
>
> 개정 이력: 초판 위원장 승인 후 codex 적대적 리뷰(gpt-5.6-sol·high, 2026-08-03)가 결함 30건을 검출해 전면 반영했다. 다수가 "상태 전이 미정의" 계층이라 §5.0 상태 모델을 신설해 구조적으로 흡수했다. 낭독 타이밍(선행 원칙)·인계 조건도 재설계됐다.

## 1. 배경과 목표

거리 추적(비콘)은 실보행 검증을 통과했으나 직선거리만 알려 준다("경로를 알려주지 않는다"는 한계). 조사는 GPS 단독 자동 턴바이턴을 폐기하고 **경로 추종형 안내**를 채택 가능 설계로 확정했다. 이 스펙은 그 설계를 기존 비콘과 한 기능으로 묶는다.

**측정 가능한 성과**: 도보 이동 중 "다음에 할 일"(회전·횡단보도·계단)을 화면을 보지 않고 들을 수 있다. 최종 판정은 위원장 실보행이다(비콘 B1과 동형 게이트).

## 2. 확정 판단 (위원장, 2026-08-03)

| 사안 | 확정 | 근거·비고 |
|---|---|---|
| 카카오 약관 | **질의 없이 진행** | 안내 세션 동안의 메모리 보유는 실시간 호출 응답의 통상 이용(경로를 화면에 그리는 모든 앱이 하는 일)이지 저장·캐시가 아니라고 판단. 문제된 약관 사례는 전부 서버측 `revalidate` 캐시(임시 DB) 문맥이었다(조사 §8.2). 경계 준수를 코드로 명문화: **세션 종료 시 경로 폐기, 디스크 저장·세션 간 재사용 금지**(§7.3), **기하 포함 응답은 서버 캐시도 우회**(§7.2) |
| 백그라운드 위치 | **전경 전용으로 시작** | 현행 비콘과 같은 계약(화면 켠 채 전경 유지). 실보행 후 승격 재판단. 기각 근거였던 "항상 허용 필요"는 오류로 확인됐으므로(조사 §6.1) 승격 시 이 문서가 아니라 조사 §6.1을 근거로 삼는다 |
| V1 수단 범위 | **상세 안내는 도보 전용** | 간략 안내(비콘)는 목적지 좌표만 쓰므로 전 수단 성립. 자동차 상세는 후속(§10) |
| 컨트롤 배치 | **시트 안 전환 버튼** | 인라인 시작 버튼 하나 + 시트 안 상세⇄간략 전환. 걷는 중 중지 없이 전환 가능 |
| 웹 범위 | **웹도 동시 착수** | B축 갭 예방 규칙 준수. 판정 로직은 웹 정본+Kit 미러 공유, 웹 UI는 disclosure 패널 확장 |

**모드 결정 원칙(리뷰 #27)**: 시작 시 가용성 기반 기본값은 자동으로 정하되(§4.1), **실행 중 행동 추정에 따른 모드 변경은 사용자 확인 필수**(속도 가드·이탈 등 어떤 추정도 자동 전환하지 않는다). 두 원칙은 별개이며 충돌하지 않는다.

## 3. 정보 구조와 명칭

- 기능명 **"실시간 길 안내"**가 "거리 추적"을 대체한다(길찾기 탭 섹션 헤딩·시작 버튼·6로케일 전체 문구).
- 기능 안의 유일한 사용자 축이 **안내 방식 = 거리의 기준**이다:
  - **간략 안내**: 현행 비콘 그대로. **직선거리**+추세 톤. 경로 비의존이라 전 수단·이탈 상태·자유 보행에서 참.
  - **상세 안내**: 경로 추종형. **경로 기반 거리**. 카카오 도보 스텝 문장이 낭독 정본(재조합 금지), 폴리라인 투영으로 진행거리 추적. 도보 전용. 경로 위에서만 참.
- 간략 모드를 경로 기반 거리로 바꾸지 않는다(위원장 판정 2026-08-03). 경로 기반 거리는 투영이 전제라 경로 밖에서 거짓이 되는데, 간략 모드의 존재 이유가 경로 비의존이다.
- 상세는 간략의 합집합이 아니라 거리 기준의 교체다. 추세 톤(가까워짐/멀어짐)은 간략 전용 — 경로가 목적지에서 잠시 멀어지는 구간(횡단보도 우회 등)에서 직선 추세는 올바른 진행에 "멀어지는 중"이라는 거짓 경고가 된다.
- i18n: 기존 `beacon.*` 키는 유지하되 문구를 갱신하고, 상세 안내 신규 문구는 `guide.*` 네임스페이스. 키 상세는 플랜에서.

## 4. 진입과 시트 (iOS)

### 4.1 인라인 섹션과 상세 적격 게이트

- 현행 비콘 섹션 구조 유지: 헤딩("실시간 길 안내" + 목적지), **시작 버튼 하나**, 직선거리 주석.
- 시작 모드 자동 결정: **상세 적격이면 상세, 아니면 간략**.
- **상세 적격 `isDetailedGuideEligible`(리뷰 #20)**: ①이 세션에서 현재 목적지에 대해 조회한 도보 경로가 있고 ②`includeGeometry=1`로 받은 유효 기하(§7.2 검증 통과)를 보유. 하나라도 어긋나면 상세를 시도하지 않고 간략으로 정직 폴백(조용한 강등 아님 — 시작 통지가 모드를 말한다: "간략 안내 시작" vs "상세 안내 시작").

### 4.2 시트 (현행 BeaconTrackingSheet 확장)

시작=시트 표시, 중지=닫힘(1:1), 스와이프·escape 닫기=중지. 전부 현행 계약 그대로.

시트 컨트롤(위→아래):

1. **중지** 버튼 (현행)
2. **현재 안내 반복** 버튼: `lastGuidance`를 재낭독. **반복 대상은 실행 안내뿐이다**(리뷰 #23): 상세=마지막 스텝 문장 또는 통독 묶음 전체(묶음 안에서는 "현재 한 개"가 정의되지 않으므로, 리뷰 #13), 간략=마지막 거리 통지. 상태·오류·속도 통지는 반복 대상이 아니다. "건너뛰기"는 두지 않는다(선례 부재 + 진행 주장 실패 모드, 조사 §5.4).
3. **진행 상황** 버튼: 상태별 응답을 1회 통지(리뷰 #22, 거짓 정밀 금지 — 상태 문구 표는 플랜에서 확정):
   - `following`: "남은 거리 {distance}. 다음: {안내}까지 {distance}"
   - `bundle`: "남은 거리 {distance}. 다음 안내 {N}개" + 묶음 통독
   - `uncertain`·`reacquiring`: 수치를 단정하지 않는 문구("위치 확신이 낮습니다" 등) + 마지막 유효 안내
   - `offRoute`: 이탈 상태 명시 + 목적지 직선거리
   - 간략 모드: 목적지 직선거리
4. **상세⇄간략 전환** 버튼: 추적을 멈추지 않고 방식만 전환(§6). 라벨이 곧 상태 신호. 상세 부적격 세션에서는 **미노출**(죽은 컨트롤 금지).
5. **경로 다시 조회** 버튼: `offRoute`에서만 노출(§5.6).
6. 상태 1줄 + 화면 유지 힌트 (현행)

### 4.3 승계 계약 (변경 금지)

포커스 계약(열릴 때 헤딩 착지 수용·닫힐 때 시작 버튼 복귀), `stopBecauseDestinationChanged`, 워치독(15초 무-fix), 전경 전용 생명주기, 권한·정밀 위치 게이트(`accuracySnapshot`), idle timer.

**`outputSuppressed`(받아쓰기 중 억제)의 상세 모드 계약(리뷰 #9)**: 억제 중에도 **추적·상태 전진은 계속**하되 발화·톤만 막는다. 발화 이력과 상태를 분리해, 억제 해제 시 **미발화 실행 안내가 있으면 현재 상태 기준 최신 것 하나를 복구 발화**한다(밀린 것 전부 재생 금지 — §5.4 병합과 같은 최신 우선). 받아쓰기 몇 초 사이 횡단보도 안내가 조용히 소비되는 구멍을 막는다.

## 5. 상세 안내 판정 설계

아래 상수는 초기값이며 **실보행 튜닝 대상**이다. 상수는 한 곳에 모으고 근거 주석을 단다.

### 5.0 상태 모델 (리뷰 #3·#7·#12·#26 통합)

리듀서의 명시 상태. 산문에 흩어 두지 않고 이 표가 정본이다.

| 상태 | 의미 | 진입 | 이탈 |
|---|---|---|---|
| `following` | 긴 구간 자동 추적 중 | 시작(첫 스텝이 긴 구간)·묶음 통과·재획득 성공 | 묶음 진입, 인계, 이탈, 재획득 필요 |
| `bundle` | 통독 묶음 체류 | 묶음 경계 통과 | 다음 긴 구간 진입 확인, 인계, 이탈 |
| `uncertain` | fix 정확도 > `UNCERTAIN_ACCURACY = 50m` | 정확도 악화 | 정확도 회복 |
| `reacquiring` | 투영 신뢰 상실, 재탐색 중 | fix 공백 > 10초·전경 복귀·구속 창 경계 연속 적중 | 재투영 확정(모호 해소 규칙 §6) |
| `offRoute` | 이탈 확정 | §5.6 판정 | 창 복귀·재조회 성공 |
| `handoff` | 비콘 인계됨(래치) | §5.3 인계 조건 | 수동 상세 복귀(§5.3)뿐 |

- `uncertain`·`reacquiring` 중에는 **자동 낭독·이탈 타이머·속도 판정을 모두 정지**한다(수치 단정 금지, 리뷰 #12·#17·#18). 진입·회복은 각 1회 통지한다 — 이것이 GPS 품질 악화·회복의 상태 채널이며(리뷰 #14), 별도 drip 톤은 후속(§10).
- 상태·이탈·속도의 시간 판정은 **주입된 단조 시각** 기준이고(리듀서 시그니처 `guideStep(state, fix, route, now)`, 리뷰 #19), stale·역순 fix는 폐기한다. `uncertain`·무-fix 구간에서 타이머는 정지·유지된다(리셋 아님).

**이벤트 우선순위(리뷰 #8)**: 한 fix에서 복수 이벤트가 나면 리듀서는 우선순위 최상위 **하나만** 발화로 낸다(상태 전진은 전부 반영): 인계 > 이탈/복귀 > 실행 안내(스텝 낭독·묶음 통독) > 예고 > 주기 통지 > 속도 제안. 통독 묶음은 분리 불가한 원자 발화 단위다.

### 5.1 진행거리 투영 (최근접 매칭 금지)

- 전 경로를 하나의 연속 폴리라인으로 잇는다(스텝 이음매 0.00m 실측, 조사 §1 — 단 응답마다 §7.2 검증을 거친다).
- 현재 위치를 폴리라인에 투영해 누적 진행거리 `d`를 구하되, **탐색 창을 직전 `d` 부근으로 구속**한다: `[d − 20m, d + max(50m, 3×accuracy)]`. 전역 최근접점 매칭은 경로 자기근접 12m 구간에서 엉뚱한 스텝을 고른다(조사 §2).
- `d`는 **단조 전진**한다. 후퇴처럼 보이는 fix는 잡음으로 취급하고 이탈 판정에만 반영한다.
- **창 신뢰 상실 시 `reacquiring`**(리뷰 #7): 투영점이 창 전진 경계에 연속 3회 적중하거나, fix 공백이 10초를 넘거나, 백그라운드를 거쳐 복귀하면 창을 버리고 재탐색한다(모호 해소 규칙은 §6과 동일). 창 끝을 조금씩 따라가는 거짓 전진이 다중 구간 통과·속도 판정을 오염시키는 것을 막는다.
- 세션 시작 시 초기 투영은 `d=0` 앵커(사용자가 경로 조회 직후 그 출발점에서 시작한다) + 전진 창.

### 5.2 구간 분류: 자동은 긴 구간에만

- `LONG_STEP_MIN = 40m`: 이 이상인 스텝만 GPS 자동 발동 대상. 근거: 25m 미만 구간이 21%라 안내 단위가 GPS 오차(도심 7~13m)와 겹치고, 40m는 σ=10m 기준 4σ 여유(조사 §2·§3.2).
- 연속한 짧은 스텝(40m 미만)들은 하나의 **통독 묶음**으로 다룬다. **경로가 묶음으로 시작하면 시작 발화에서 즉시 통독하고, 전 구간이 짧으면 시작 통독 후 인계 조건(§5.3)을 기다린다**(리뷰 #3).

### 5.3 안내 흐름: 낭독은 선행, 전진은 후행 (리뷰 #4 재설계)

**원칙: 실행 안내는 결정 지점 앞에서 들려야 한다.** 초판의 "경계 통과 후 낭독"은 첫 maneuver를 지나친 뒤 낭독하는 안전 결함이었다. 낭독 트리거와 상태 전진 트리거를 분리한다.

- **시작**: "상세 안내 시작. 안내 {N}개, 총 {distance}. {첫 안내}"를 **한 문장(단일 Announcement)으로 원자 발화**(리뷰 #24 — 두 발화의 경합 제거). `lastGuidance`는 첫 안내 부분만.
- **다음 안내 낭독(선행)**: 현재 긴 구간의 잔여가 `ANNOUNCE_AHEAD = 40m` 이하가 되면 예고음(§8)과 함께 **다음 것의 전문을 낭독**한다 — 다음이 긴 스텝이면 그 문장, 묶음이면 묶음 통독("다음 안내 {N}개. 횡단보도 이용. 16m 이동. 좌회전."). 정확도가 나빠도 낭독이 늦어지지 않는다(잔여 거리 기준이라 오히려 조기화된다).
- **상태 전진(후행)**: `d`가 구간 경계 + `max(15m, accuracy)`를 넘으면 내부 포인터만 전진한다(재낭독 없음 — 낭독은 이미 선행했다). 주기 통지의 기준 구간이 이때 바뀐다.
- **주기 통지**: `following`에서 현재 구간 잔여를 "{안내}까지 {distance}" 꼴로 — 잔여 500m 초과 60초 / 150~500m 30초 / 150m 미만 15초(Sendero 표 축약, 조사 §5.3). 기준은 `lastAnnouncedAt`(어떤 발화든 갱신)이고 거리대가 바뀌어도 즉시 발화하지 않고 다음 주기부터 새 간격을 쓴다(리뷰 #25). `bundle`에서는 주기 통지가 **묶음 재통독**이다(리뷰 #5 — 첫 통독을 소음으로 놓쳐도 자동 채널이 침묵하지 않는다). 정본은 구간 잔여이고 목적지 전체 잔여는 진행 상황 버튼 몫(자동 병기는 실보행 튜닝 후보).
- **낭독 병합(최신 우선)**: 한 fix에 구간 경계를 여러 개 지나면(차량 이동·GPS 점프) 건너뛴 중간 안내는 낭독하지 않고 현재 상태의 안내만 낭독한다.
- **도착 인계(리뷰 #2·#3·#11)**: 조건은 **"모든 스텝이 낭독 완료"(마지막 스텝 낭독·마지막 묶음 통독 포함) ∧ 전체 잔여 ≤ `HANDOFF_DIST = 50m`**. 낭독 완료 조건이 마지막 횡단보도·계단 안내가 직선 안내에 삼켜지는 것을 막고, 50m는 그 조건 아래에서 직선 안내가 더 이른 시점부터 유용하다는 판단이다(상용 선례의 15m는 도착 판정 값이지 인계 조건이 아니다). 인계 시 "목적지까지 직선 안내로 전환합니다" 통지 후 검증된 `beaconStep`·`beaconGateStep`·데드밴드·nearby 판정을 그대로 쓴다. **자동 인계는 세션당 래치(단방향)**: 다시 멀어져도 자동으로 상세로 돌아가지 않는다. 수동 상세 복귀는 전환 버튼으로 가능하고, 그 후 자동 재인계는 잔여가 `HANDOFF_DIST + 20m`를 초과한 적이 있어야 재무장한다(전환 루프 차단).
- **낭독 채널**: 모든 통지는 비콘과 동일한 단일 announce 경로를 지나며 그 경로가 `spokenUnits()`를 통과한다(리뷰 #15 — VO가 숫자+m을 minutes로 오독하는 실기기 확정 결함의 방어. 화면 문자열은 원문 유지). VO 미사용자의 채널은 상태 텍스트 갱신+톤(2.1(a) 방어용 가시 텍스트 계약 승계). 비-VO용 별도 TTS는 V1 비도입.
- **상세 모드의 톤**: tick(하트비트)·시작/정지·예고·경고 유지, 추세 톤은 간략 전용(§3).

### 5.4 확신도를 문장에 반영 (Soundscape 3단)

fix 정확도에 따라 거리 표현을 바꾼다: ≤10m 수치 그대로("200m") / ≤20m "약 200m" / >20m "200m쯤". 잔여 200m 이상이면 정확도 무시(상대 오차 작음). 정확도 > 50m는 문장 조절이 아니라 `uncertain` 상태다(§5.0). 거리 문자열은 `formatDistance` 정본을 태우고 확신도 접두·접미만 i18n 문구가 감싼다.

### 5.5 보행 속도 가드 (상세는 도보 전용이라는 전제의 방어)

- 판정(리뷰 #17): 최근 10초 창의 투영 진행 속도 **중앙값**이 `WALK_SPEED_MAX = 3m/s` 초과면 `speedGuardActive` 진입, 2m/s 미만이면 해제(히스테리시스, 리뷰 #16). `uncertain`·`reacquiring` 중에는 판정하지 않는다.
- 진입 시 "이동 속도가 빨라 간략 안내가 적합합니다" **세션당 1회** 통지(`speedWarned` 플래그는 active와 분리). 자동 전환은 하지 않는다(§2 모드 결정 원칙 — 해법은 시트의 전환 버튼).

### 5.6 이탈: 자동 재조회 금지

- 판정: 폴리라인 수직거리 > `max(30m, 2×accuracy)`가 단조 시각 기준 20초 지속(`uncertain`·무-fix 구간은 타이머 정지·유지).
- 동작: 경고음(§8) + "경로에서 벗어난 것 같습니다" 통지 + **"경로 다시 조회" 버튼 노출**. 재조회는 이 버튼으로만(자동 재설정이 도로 중앙 안내로 이어진 실패 기록, 조사 §4.3). 재통지 60초 간격, 창 안 복귀 시 "경로로 복귀했습니다" 1회 + 버튼 숨김.
- `speedGuardActive` 중에는 이탈 재통지를 억제한다(차량 이동 중 필연적 이탈을 두 채널로 반복하는 노이즈 차단). 최종 임계·간격은 차량 이동 실측으로 튜닝(§11).
- **재조회 상태 기계(리뷰 #10·#26)**: 세대 토큰 + in-flight ref 가드(repo 관례). latest-wins — 응답 도착 시 토큰 불일치·시트 닫힘·중지·모드 전환·목적지 변경이면 폐기(채팅 `aliveRef` 이탈 게이트 동형). 성공 시 새 경로로 리듀서 리셋 + 초기 투영은 전역 1회(모호 규칙 §6). 실패 시 기존 경로·상태 유지 + 오류 통지 + 버튼 유지. 요청 중 버튼은 `aria-disabled`/가드(포커스 유지 계약).

## 6. 간략 안내와 모드 전환

- 간략 안내의 판정·톤·통지·데드밴드 전부 현행 유지. 바뀌는 것은 명칭 문구와 사운드 파일(§8)뿐.
- **상세→간략**: 비콘 앵커 리셋 + first-fix 경로(절대거리 1회 발화 후 추세). "간략 안내로 전환했습니다" 1회.
- **간략→상세(리뷰 #6)**: 투영 탐색 창을 전역으로 1회 연다. **정확도 범위 안에 후보가 복수면 전환을 확정하지 않는다** — 잘못 고른 후보도 폴리라인 위라 수직거리 이탈 판정이 잡지 못하므로, "가장 이른 후보" 같은 임의 선택은 금지. 이때 "경로상 위치를 확정하는 중입니다"를 통지하고 간략 안내를 유지한 채 후속 fix들로 재평가한다(이동 방향 course와 후보 구간 방위 일치로 해소). 해소되면 "상세 안내로 전환했습니다" 1회, `RESOLVE_TIMEOUT = 30초` 안에 해소되지 않으면 "경로상 위치를 확정할 수 없어 간략 안내를 유지합니다" 1회.

## 7. 데이터·코드 구조

### 7.1 판정 리듀서 (웹 정본 + Kit 미러)

- 웹 `src/lib/route-guide.ts`에 순수 리듀서 `guideStep(state, fix, route, now)`: §5의 전부를 결정하고 `{state, announce?, tone?}`을 반환(우선순위 최상위 발화 하나, §5.0). 단조 시각 주입, `Date.now()` 직접 호출 금지.
- Kit `RouteGuide.swift` 미러. 드리프트 가드: 경계표 시나리오를 공유 fixture로 두고 웹 `route-guide.test.ts`와 Kit `RouteGuideTests`가 같은 표를 단언한다(`beacon.ts`↔`Beacon.swift` 관례 동형).
- iOS 모델(`BeaconModel` 확장 또는 형제 모델)은 배선만: 권한·타임아웃·I/O·생명주기. 로직 금지(앱 타깃 테스트 번들 부재).

### 7.2 API: 폴리라인 옵트인

- `/api/route/walk`에 `includeGeometry` 추가. **허용값은 누락 또는 정확히 `"1"`**, 그 외 400(리뷰 #29, `accessible` 관례 동형). 지정 시에만 `steps[].pathCoords`를 응답에 보존한다(`annotateAudioSignals` 후 제거 지점을 옵트인 분기로).
- **`includeGeometry=1` 요청은 `no-store`**(리뷰 #1): 세션 전용 실시간 사용 데이터를 서버 `revalidate`에 태우면 §2 약관 판단("세션 한정, 저장 아님")과 모순된다. 비기하 요청의 기존 `revalidate 3600` 계약은 불변(그 회색지대는 별건 백로그 D6). 쿼터 영향은 안내 시작·재조회당 1회라 미미.
- 미지정 응답은 **byte-호환 유지**(CLI/MCP 출력 팽창 방지). CLI/MCP 카탈로그는 이 파라미터를 노출하지 않는다.
- **기하 검증(리뷰 #21)**: 이음매 0m는 실측이지 보증이 아니다. 클라이언트는 수신 시 검증한다 — 스텝별 좌표 존재·유한값·이음매 간격 ≤ `SEAM_TOLERANCE = 5m`. 위반 시 그 경로는 상세 부적격(§4.1)으로 간략 폴백하고 console 경고를 남긴다(fail-closed, 조용한 오작동 금지).
- 레이트리밋(60초 10회) 변경 없음.

### 7.3 경로 데이터 수명 (약관 경계의 코드화)

안내 세션이 쥐는 경로(스텝 문장+폴리라인)는 **메모리에만** 둔다. 디스크 저장·세션 간 재사용·다른 좌표 요청에의 전용을 금지한다. 세션 종료(중지·시트 닫힘·목적지 변경·앱 종료)와 함께 폐기한다. 이 계약이 §2 약관 판단의 성립 조건이다.

## 8. 사운드 교체 (ElevenLabs)

- 현행 합성 톤 6종(시작·정지·가까워짐·멀어짐·도착·틱)을 ElevenLabs 사운드 효과 생성물로 교체하고, 신규 2종(예고음·이탈 경고음)을 추가한다.
- **의미 계약 유지**: 가까워짐=상승감, 멀어짐=하강감, 도착=밝음, 틱=낮은 단음의 방향성 구분을 생성 프롬프트에 명시. 길이는 VO 발화를 가리지 않게 짧게(추세음 300ms 이하, 시작·정지 500ms 이하).
- 종류별 후보 2~3개를 생성해 **위원장 실기기 청취로 선정**. 선정 전까지 기존 톤 유지(교체는 원자적 1커밋).
- 웹·iOS **동일 파일** 번들(웹 `public/sounds/`, iOS 리소스). 현행 톤 데이터 드리프트 가드는 **파일 해시 대조 가드로 대체**.
- iOS `BeaconTonePlayer`는 파일 재생으로 바꾸되 오디오 세션·인터럽션 옵서버·`isSuppressed`·`isSilenced` 계약 유지. 웹도 파일 재생으로 전환.
- 생성은 ElevenLabs MCP가 세션에 없으면 Converters의 ElevenLabs API 스크립트로(구독 보유, 생성 시점에 건수·비용 보고).

## 11. 테스트·검증 게이트

- **Kit·웹 리듀서 단위 테스트**(공유 경계표): 단조 전진, 자기근접 오판 차단(창 구속), 낭독 선행·전진 후행 분리, 통독 묶음 경계(시작 묶음·끝 묶음·전부 짧은 경로), 묶음 재통독, 인계 조건(낭독 완료 ∧ 거리)·래치·재무장, 이탈 판정·복귀·타이머 정지, `uncertain`·`reacquiring` 전이와 낭독 정지, 이벤트 우선순위(동시 발생), 낭독 병합, 억제 해제 복구 발화, 속도 가드 진입·해제·중앙값, 전환 모호 보류·해소·타임아웃, 재조회 latest-wins·실패 유지, 확신도 3단, 주기 기준(`lastAnnouncedAt`·거리대 전환), 기하 검증 실패 폴백(리뷰 #30 시나리오 포함).
- **실호출 게이트**: `includeGeometry=1` 응답에서 기하 검증 통과·이음매 연속성을 실경로(길동역→강동구청)로 확인. 미지정 응답 byte-호환 확인.
- **spokenUnits 드리프트**: 상세 안내의 발화 경로가 `spokenUnits`를 지나는지 테스트로 강제(리뷰 #15).
- **i18n**: 신규 `guide.*` 키 6로케일 + `i18n-messages.test.ts` 레인.
- **접근성**: `a11y-auditor` 점검 + 시트 컨트롤 낭독은 실기기 VoiceOver.
- **차량 이동 실측**: 도보 경로를 쥔 채 차량 이동(실승차 또는 좌표 시뮬레이션)으로 이탈 통지 빈도·속도 가드·억제 동작 확인, 이탈 임계·재통지 간격 튜닝(위원장 지시 2026-08-03).
- **최종 판정은 위원장 실보행**(상세 안내로 실경로 1회 완주 + 전환·반복·이탈 시나리오). 상수 튜닝과 전체 잔여 자동 병기 여부도 이때 판정.
