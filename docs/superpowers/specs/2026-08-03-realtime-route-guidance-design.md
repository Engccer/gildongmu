# 실시간 길 안내 설계 (2026-08-03)

> E4(경로 추종형 도보 안내)의 구현 스펙. 조사 정본은 `docs/RESEARCH-2026-08-02-realtime-walk-navigation.md`(이하 "조사")이며 본 문서는 그 §5 설계 골격을 코드 계약으로 확정한다. 조사 본문을 재조사하지 말 것.

## 1. 배경과 목표

거리 추적(비콘)은 실보행 검증을 통과했으나 직선거리만 알려 준다("경로를 알려주지 않는다"는 한계). 조사는 GPS 단독 자동 턴바이턴을 폐기하고 **경로 추종형 안내**를 채택 가능 설계로 확정했다. 이 스펙은 그 설계를 기존 비콘과 한 기능으로 묶는다.

**측정 가능한 성과**: 도보 이동 중 "다음에 할 일"(회전·횡단보도·계단)을 화면을 보지 않고 들을 수 있다. 최종 판정은 위원장 실보행이다(비콘 B1과 동형 게이트).

## 2. 확정 판단 (위원장, 2026-08-03)

| 사안 | 확정 | 근거·비고 |
|---|---|---|
| 카카오 약관 | **질의 없이 진행** | 안내 세션 동안의 메모리 보유는 실시간 호출 응답의 통상 이용(경로를 화면에 그리는 모든 앱이 하는 일)이지 저장·캐시가 아니라고 판단. 문제된 약관 사례는 전부 서버측 `revalidate` 캐시(임시 DB) 문맥이었다(조사 §8.2). 경계 준수를 코드로 명문화: **세션 종료 시 경로 폐기, 디스크 저장·세션 간 재사용 금지**(§7.3) |
| 백그라운드 위치 | **전경 전용으로 시작** | 현행 비콘과 같은 계약(화면 켠 채 전경 유지). 실보행 후 승격 재판단. 기각 근거였던 "항상 허용 필요"는 오류로 확인됐으므로(조사 §6.1) 승격 시 이 문서가 아니라 조사 §6.1을 근거로 삼는다 |
| V1 수단 범위 | **상세 안내는 도보 전용** | 간략 안내(비콘)는 목적지 좌표만 쓰므로 전 수단 성립. 자동차 상세는 후속(§10) |
| 컨트롤 배치 | **시트 안 전환 버튼** | 인라인 시작 버튼 하나 + 시트 안 상세⇄간략 전환. 걷는 중 중지 없이 전환 가능 |
| 웹 범위 | **웹도 동시 착수** | B축 갭 예방 규칙 준수. 판정 로직은 웹 정본+Kit 미러 공유, 웹 UI는 disclosure 패널 확장 |

## 3. 정보 구조와 명칭

- 기능명 **"실시간 길 안내"**가 "거리 추적"을 대체한다(길찾기 탭 섹션 헤딩·시작 버튼·6로케일 전체 문구).
- 기능 안의 유일한 사용자 축은 **안내 방식**이다:
  - **간략 안내**: 현행 비콘 그대로. 직선거리+추세 톤. 전 수단.
  - **상세 안내**: 경로 추종형. 카카오 도보 스텝 문장이 낭독 정본(재조합 금지, 기존 계약 유지), 폴리라인 투영으로 진행거리 추적. 도보 전용.
- i18n: 기존 `beacon.*` 키는 유지하되 문구를 갱신하고, 상세 안내 신규 문구는 `guide.*` 네임스페이스. 키 상세는 플랜에서.

## 4. 진입과 시트 (iOS)

### 4.1 인라인 섹션 (DirectionsTabView)

- 현행 비콘 섹션 구조 유지: 헤딩("실시간 길 안내" + 목적지), **시작 버튼 하나**, 직선거리 주석.
- 시작 시 모드 자동 결정: **도보 경로가 조회돼 있으면 상세, 없으면 간략**. 선택 UI를 시작 전에 두지 않는다.

### 4.2 시트 (현행 BeaconTrackingSheet 확장)

시작=시트 표시, 중지=닫힘(1:1), 스와이프·escape 닫기=중지. 전부 현행 계약 그대로.

시트 컨트롤(위→아래):

1. **중지** 버튼 (현행)
2. **현재 안내 반복** 버튼: 마지막으로 낭독된 안내를 재낭독. "건너뛰기"는 두지 않는다(선례 부재 + 사용자가 진행을 주장하게 만드는 실패 모드, 조사 §5.4)
3. **진행 상황** 버튼: 남은 거리·현재 안내 요약을 1회 통지(Soundscape "Where Am I?" 대응). 자동 통지보다 관대한 게이트(사용자가 물었을 때는 확신이 덜해도 답한다, 조사 §5.4)
4. **상세⇄간략 전환** 버튼: 추적을 멈추지 않고 방식만 전환. 라벨이 곧 상태 신호("간략 안내로 전환"⇄"상세 안내로 전환"). 도보 경로가 없는 세션(자동차·대중교통 출발)에서는 **미노출**(죽은 컨트롤 금지)
5. 상태 1줄 + 화면 유지 힌트 (현행)

2·3번은 상세 모드 전용이 아니다. 간략 모드에서도 반복(마지막 거리 통지 재낭독)·진행 상황은 유효하다.

### 4.3 승계 계약 (변경 금지)

포커스 계약(열릴 때 헤딩 착지 수용·닫힐 때 시작 버튼 복귀), `outputSuppressed`(받아쓰기 중 톤·통지 전부 억제), `stopBecauseDestinationChanged`, 워치독(15초 무-fix), 전경 전용 생명주기(`.background` 복귀 시 앵커 리셋), 권한·정밀 위치 게이트(`accuracySnapshot`), idle timer. 전부 비콘에서 실보행 검증된 것이다.

## 5. 상세 안내 판정 설계

판정은 전부 순수 리듀서로 구현한다(§7.1). 아래 상수는 초기값이며 **실보행 튜닝 대상**이다. 상수는 한 곳에 모으고 근거 주석을 단다.

### 5.1 진행거리 투영 (최근접 매칭 금지)

- 전 경로를 하나의 연속 폴리라인으로 잇는다(스텝 이음매 0.00m 실측 완료, 조사 §1).
- 현재 위치를 폴리라인에 투영해 누적 진행거리 `d`를 구하되, **탐색 창을 직전 `d` 부근으로 구속**한다: `[d − 20m, d + max(50m, 3×accuracy)]`. 전역 최근접점 매칭은 경로 자기근접 12m 구간에서 엉뚱한 스텝을 고른다(조사 §2).
- `d`는 **단조 전진**한다(후퇴 판정 금지). 후퇴처럼 보이는 fix는 잡음으로 취급하고 이탈 판정(§5.5)에만 반영한다.

### 5.2 구간 분류: 자동은 긴 구간에만

- `LONG_STEP_MIN = 40m`: 이 이상인 스텝만 GPS 자동 발동 대상. 근거: 25m 미만 구간이 21%라 안내 단위가 GPS 오차(도심 7~13m)와 겹치고, 40m는 σ=10m 기준 4σ 여유(조사 §2·§3.2).
- 연속한 짧은 스텝(40m 미만)들은 하나의 **통독 묶음**으로 다룬다. 묶음 앞뒤 경계는 긴 스텝이다.

### 5.3 안내 흐름

- **시작**: "상세 안내 시작. 안내 N개, 총 {distance}." + 첫 안내 즉시 낭독.
- **긴 구간 진행 중**: 잔여 거리를 거리 반비례 주기로 통지 — 500m 초과 60초 / 150~500m 30초 / 150m 미만 15초(Sendero 표 축약, 조사 §5.3). 통지문은 "{안내 문장}까지 {distance}" 꼴. 정본은 **구간 잔여**이고 목적지 전체 잔여는 진행 상황 버튼 몫이다(자동 통지 병기는 문장 길이 트레이드오프라 실보행 튜닝 후보, §11).
- **상세 모드의 톤**: tick(하트비트)·시작/정지·예고·경고는 유지하되 **가까워짐/멀어짐 추세 톤은 간략 전용**이다. 경로가 목적지에서 잠시 멀어지는 구간(횡단보도 우회 등)에서 직선 추세는 올바른 진행에 "멀어지는 중"을 경고하는 거짓 신호가 된다. 목적지 접근감은 경로 잔여 거리의 감소가 전달한다. 즉 상세는 간략의 합집합이 아니라 **거리 기준을 직선→경로로 교체**한 것이다(§6과 같은 축).
- **구간 전환**: `d`가 현재 구간 끝 + `max(15m, accuracy)`를 넘으면 다음 안내 낭독. 다음이 통독 묶음이면 묶음 전체를 순서대로 낭독한다: "다음 안내 3개. 횡단보도 이용. 16m 이동. 좌회전." — **병합이 아니라 통독**이다. 각 문장은 개별 유지되고(Valhalla 시각장애 모드 원칙), 묶음 안에서 "지금 몇 번째인지"를 GPS로 판정하지 않는다. `d`가 묶음 뒤 긴 구간에 진입하면 자동 재개.
- **회전 임박 예고**: 현재 긴 구간의 잔여가 40m 이하로 떨어지면 예고음(§8) + "곧: {다음 안내}". 구간 전환 낭독과 별개(예고는 준비, 전환은 실행).
- **도착 인계**: 전체 잔여 경로 거리 ≤ `HANDOFF_DIST = 50m`에서 "목적지까지 직선 안내로 전환합니다" 통지 후 **간략 안내(비콘)로 자동 전환**. 검증된 `beaconStep`·`beaconGateStep`·데드밴드·nearby 판정을 그대로 쓴다(상용 선례 Getting Warmer 인계, 조사 §5.3).
- **낭독 병합(최신 우선)**: 한 fix에 구간 경계를 여러 개 지나면(차량 이동·GPS 점프) 건너뛴 중간 안내는 낭독하지 않고 **현재 구간 안내만** 낭독한다. 밀린 안내를 순서대로 재생하면 실제 위치와 낭독이 계속 어긋난다.
- **낭독 채널**: 비콘과 동일한 단일 polite Announcement(VoiceOver 음성)다. VO 미사용자의 채널은 상태 텍스트 갱신+톤이고(2.1(a) 방어용 가시 텍스트 계약 승계), 비-VO용 별도 TTS는 V1 비도입(필요 입증 시 TtsPlayer 재사용 후속).

### 5.4 확신도를 문장에 반영 (Soundscape 3단)

fix 정확도에 따라 거리 표현을 바꾼다: ≤10m 수치 그대로("200m") / ≤20m "약 200m" / >20m "200m쯤". 잔여 200m 이상이면 정확도 무시(상대 오차 작음). 거리 문자열 자체는 `formatDistance` 정본을 태우고 확신도 접두·접미만 i18n 문구가 감싼다. 3-state 정신의 연장이다.

### 5.5 이탈: 자동 재조회 금지

- 판정: 폴리라인 수직거리 > `max(30m, 2×accuracy)`가 20초 지속.
- 동작: 경고음(§8) + "경로에서 벗어난 것 같습니다" 통지 1회 + 시트에 **"경로 다시 조회" 버튼 노출**. 재조회는 이 버튼으로만(자동 재설정이 도로 중앙 안내로 이어진 실패 기록, 조사 §4.3·§5.1-6). 재통지는 60초 간격, 창 안으로 복귀하면 "경로로 복귀했습니다" 1회.
- **속도 가드(§5.6) 발동 상태에서는 이탈 재통지를 억제한다.** 차량 이동 중 도보 폴리라인 이탈은 필연이고, 가드 통지가 이미 원인을 설명했으므로 같은 사실을 두 채널로 반복하면 노이즈다. 이탈 임계·재통지 간격의 최종값은 차량 이동 실측으로 튜닝한다(§11).
- 재조회 성공 시 새 경로로 리듀서 리셋. 실패는 기존 3-state 오류 문구.

### 5.6 보행 속도 가드 (상세는 도보 전용이라는 전제의 방어)

시작 모드가 "도보 경로 있으면 상세"로 자동 결정되므로, 도보 경로를 조회해 둔 채 차량으로 이동하면 상세 안내가 차량 속도로 소비된다(낭독 폭주는 §5.3 병합이 막지만 안내 자체가 무의미해진다). 투영 진행 속도가 `WALK_SPEED_MAX = 3m/s`를 10초 지속 초과하면 "이동 속도가 빨라 간략 안내가 적합합니다" **세션당 1회** 통지한다. 자동 전환은 하지 않는다(자동 결정 금지 원칙 — 해법은 시트의 전환 버튼).

### 5.7 GPS 품질 상태

fix 정확도가 15m보다 나쁜 상태로 지속되면 문장 확신도(§5.4)가 1차 채널이고, 무-fix 15초는 기존 워치독 문구를 재사용한다. 별도 drip 톤 채널(Sendero)은 V1 비도입 — 확신도 문장과 역할이 겹치는 동안은 잉여다. 실보행에서 필요가 입증되면 후속.

## 6. 간략 안내 (변경 없음 + 전환)

- 판정·톤·통지·데드밴드 전부 현행 유지. 이 스펙으로 바뀌는 것은 명칭 문구와 사운드 파일(§8)뿐이다.
- **간략 모드를 경로 기반 거리로 바꾸지 않는다**(위원장 질문 2026-08-03 판정). 경로 기반 거리는 폴리라인 투영이 전제라 경로 밖에서는 거짓이 되는데, 간략 모드의 존재 이유가 경로 비의존(전 수단·이탈 상태·자유 보행에서 참)이다. 두 모드의 구분 축이 곧 **거리의 기준**이다: 간략=직선(어디서나 참), 상세=경로(경로 위에서 참). 경로 기반 정밀 잔여는 상세 모드 몫.
- **전환 계약**: 상세→간략 전환 시 비콘 앵커를 리셋하고 first-fix 경로를 태운다(절대거리 1회 발화 후 추세). 간략→상세 전환 시 투영 탐색 창을 전역으로 1회 연 뒤(직전 `d`가 없다) 이후 구속 창으로 복귀한다. 전역 투영에서 복수 후보가 정확도 내 동률이면(자기근접 12m 구간) **가장 이른 지점**을 고른다 — 전방 오류는 단조 전진이 흡수하고 후방 오류는 이탈 판정이 잡으므로, 이른 쪽이 안전한 편향이다. 전환 자체는 "간략 안내로 전환했습니다" 1회 통지.

## 7. 데이터·코드 구조

### 7.1 판정 리듀서 (웹 정본 + Kit 미러)

- 웹 `src/lib/route-guide.ts`에 순수 리듀서 `guideStep(state, fix, route)`: 투영·단조 전진·구간 전환·통독 묶음·예고·인계·이탈을 전부 결정하고 `{state, announce?, tone?}`을 반환. 시각 주입으로 시간 의존 제거(주기 통지 판정 포함).
- Kit `RouteGuide.swift` 미러. 드리프트 가드: 경계표(진행거리·전환·이탈 시나리오 표)를 공유 fixture로 두고 웹 `route-guide.test.ts`와 Kit `RouteGuideTests`가 같은 표를 단언한다(`beacon.ts`↔`Beacon.swift` 관례 동형).
- iOS 모델(`BeaconModel` 확장 또는 형제 모델)은 배선만: 권한·타임아웃·I/O·생명주기. 로직 금지(앱 타깃 테스트 번들 부재).

### 7.2 API: 폴리라인 옵트인

- `/api/route/walk`에 `includeGeometry=1`(불리언, 그 외 값 400은 기존 `accessible` 관례 동형) 추가. 지정 시에만 `steps[].pathCoords`(위경도 쌍 배열)를 응답에 보존한다. `annotateAudioSignals` 후 제거 지점을 옵트인 분기로 바꾼다.
- 미지정 응답은 **byte-호환 유지**(CLI/MCP 출력 팽창 방지, 기존 소비자 무영향). CLI/MCP 카탈로그는 이 파라미터를 노출하지 않는다(V1 소비자는 웹·iOS 클라이언트뿐).
- 레이트리밋(60초 10회)·캐시 계약(`revalidate 3600`) 변경 없음. 재조회(§5.5)는 사용자 확인 후 1회 호출이라 쿼터 압력 미미.

### 7.3 경로 데이터 수명 (약관 경계의 코드화)

안내 세션이 쥐는 경로(스텝 문장+폴리라인)는 **메모리에만** 둔다. 디스크 저장·세션 간 재사용·다른 좌표 요청에의 전용을 금지한다. 세션 종료(중지·시트 닫힘·목적지 변경·앱 종료)와 함께 폐기한다. 이 계약이 §2 약관 판단("통상 이용이지 저장이 아니다")의 성립 조건이다.

## 8. 사운드 교체 (ElevenLabs)

- 현행 합성 톤 6종(시작·정지·가까워짐·멀어짐·도착·틱)을 ElevenLabs 사운드 효과 생성물로 교체하고, 신규 2종(회전 임박 예고음·이탈 경고음)을 추가한다.
- **의미 계약 유지**: 가까워짐=상승감, 멀어짐=하강감, 도착=밝음, 틱=낮은 단음의 방향성 구분을 생성 프롬프트에 명시한다. 길이는 VO 발화를 가리지 않게 짧게(추세음 300ms 이하, 시작·정지 500ms 이하).
- 종류별 후보 2~3개를 생성해 **위원장 실기기 청취로 선정**한다. 선정 전까지 기존 톤 유지(교체는 원자적 1커밋).
- 웹·iOS **동일 파일** 번들(웹 `public/sounds/`, iOS 리소스). 현행 톤 데이터 드리프트 가드(`beacon-tones-drift.test.ts`)는 **파일 해시 대조 가드로 대체**한다.
- iOS `BeaconTonePlayer`는 합성 대신 파일 재생으로 바꾸되 오디오 세션·인터럽션 옵서버·`isSuppressed`·`isSilenced` 계약은 유지한다. 웹도 기존 재생 경로에서 파일 재생으로 전환.
- 생성은 ElevenLabs MCP가 세션에 없으면 Converters의 ElevenLabs API 스크립트로(구독 보유, 건당 비용 미미 — 생성 시점에 건수·비용을 보고).

## 9. 웹 구현 범위

- 기존 `DistanceBeacon.tsx` disclosure 패널을 확장한다(모달 전환 없음 — 웹 비모달 판정은 `2026-08-02-beacon-feedback-design.md` §3.5 유지).
- 패널 안 컨트롤은 iOS 시트와 동일 집합(중지·반복·진행 상황·전환). 통지는 기존 단일 polite live region 재사용.
- 위치는 `useGeolocation`/`awaitGeolocation` 공유 스토어 경유(직접 `getCurrentPosition` 금지). 연속 추적은 기존 비콘 watch 경로 재사용.
- 실보행 검증은 iOS 먼저. 웹은 공유 리듀서 재사용이라 판정 회귀 위험이 낮고, 게이트는 단위 테스트+수동 시뮬레이션(좌표 주입)이다.

## 11. 테스트·검증 게이트

- **Kit·웹 리듀서 단위 테스트**(공유 경계표): 단조 전진, 자기근접 구간 오판 차단(창 구속), 구간 전환 여유, 통독 묶음 경계, 예고·전환 분리, 인계 임계, 이탈 판정·복귀, 확신도 3단, 주기 통지 시각 판정, 낭독 병합(다중 구간 통과 시 최신만), 속도 가드(세션당 1회).
- **실호출 게이트**: `includeGeometry` 응답에서 스텝 이음매 연속성·폴리라인 존재를 실경로(길동역→강동구청)로 확인.
- **i18n**: 신규 `guide.*` 키 6로케일 + `i18n-messages.test.ts` 레인.
- **접근성**: `a11y-auditor` 점검 + 시트 컨트롤 낭독은 실기기 VoiceOver.
- **차량 이동 실측**: 도보 경로를 쥔 채 차량 이동(실승차 또는 좌표 시뮬레이션)으로 이탈 통지 빈도·속도 가드 발동·억제 동작을 확인하고 이탈 임계·재통지 간격을 튜닝한다(위원장 지시 2026-08-03).
- **최종 판정은 위원장 실보행**(상세 안내로 실경로 1회 완주 + 전환·반복·이탈 시나리오). 상수 튜닝은 이 결과로. 전체 잔여 거리의 자동 통지 병기 여부도 이때 판정.
