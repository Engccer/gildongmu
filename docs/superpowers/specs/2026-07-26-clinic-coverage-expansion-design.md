# 소아 진료 커버리지 확장 설계 (달빛 명부 → 일반 소아청소년과)

작성: 2026-07-26 | 상태: **단계 0 구현 완료 / 단계 1 착수 조건 충족(§5 게이트 통과)** | 선행: `2026-06-17-nearby-night-clinic-design.md`

## 1. 문제 (실사용 제보, 2026-07-26 일요일)

일요일에 실제로 진료 중인 **연세도우리소아청소년과의원(서울 강동구, 강동구청 1.6km, 일 0900~1800)** 이 "내 주변 소아 야간·휴일 진료"에 나오지 않는다.

원인은 두 층이고, **게이트 실호출 결과 제보 건의 원인은 (A)로 확정됐다**(§5).

> ⚠ **동명이원 함정** — 같은 이름의 기관이 **강남구 개포동에도 있고 그쪽은 달빛 명부에 있다**(강동구청 6.9km). 게이트 스크립트가 이름만으로 매칭해 이 강남 기관을 제보 대상으로 잡는 바람에 "명부에 있음 → 원인은 (B)"로 잘못 종결될 뻔했다. **기관 동일성 판정은 이름이 아니라 좌표·주소로** 한다. 스크립트는 이 교훈을 반영해 매칭 결과를 거리·주소와 함께 출력하고 판정을 사람에게 넘기도록 고쳤다.

**(A) 데이터셋 범위** — 정본 `getBabyListInfoInqire`는 소아 야간진료를 하는 모든 의원이 아니라 **정부가 달빛어린이병원·소아전문응급센터로 지정한 명부**다. 규모는 **전국 152개(서울 19)**. 지정받지 않은 일반 소아청소년과는 일요일에 문을 열어도 응답에 아예 없다.

**(B) 표시 절단** — 그 작은 명부마저 거리순 **상위 5곳**으로 잘랐다. `docs/SPEC.md`의 실호출 검증 기록이 "강동 길동 **5곳** 거리순"이라 **제보 지역에서 절단이 이미 걸려 있었다**. 게다가 절단은 진료 상태를 계산하기 **전에** 일어나서, 문 닫은 5곳이 앞자리를 차지하면 **지금 진료 중인 곳이 잘려 나갔다** — 의료 안전망에서 가장 나쁜 실패다. 사용자에게는 "근처에 없음"으로 보인다.

(B)도 실재했다: 강동구청 20km 내 명부 기관은 **21곳**이고 위 강남 동명 기관은 그중 **7위**였다 — 옛 상한 5에 정확히 잘려 있었다. 즉 **두 층이 모두 참**이며 단계 0은 (A)와 무관하게 값을 한다.

## 2. 단계 0 — 소스 교체 없이 회수 가능한 것 (구현 완료)

키·활용신청 없이 코드만으로 고칠 수 있는 층. **(B)를 제거하고 (A)의 체감을 줄인다.**

1. **진료중 우선 정렬** — `prioritizeOpen()`이 `open → unknown → closed` 순으로 재배열한 뒤 자른다. `Array.prototype.sort`가 안정 정렬이라 **같은 상태 안에서는 거리순이 보존**된다(입력은 반드시 `rankClinicsByDistance` 결과). `unknown`을 `closed`보다 위에 두는 이유: "정보 없음"은 전화로 확인할 수 있지만 "마감"은 지금 갈 수 없다.
2. **표시 상한 5 → 10, 그리고 절단 사실 노출** — 응답에 `total`(반경 내 전체, 절단 전)·`radiusMeters`를 실어 UI가 "20km 내 N곳 중 M곳"을 밝힌다. **침묵 절단 금지**(no-silent-caps).
3. **공휴일 판정 활성화** — 기존 `fetchIsHoliday`(특일정보 15012690, 지하철 시간표에서 검증된 게이트형 provider)를 재사용해 `dutyTime8`(공휴일 칸)로 판정한다. 판정 불가(키 없음·미신청·실패)면 `null` → **요일 폴백**이고, `basis`(`holiday`|`weekday`)를 UI가 문장으로 밝힌다. **공휴일에 일요일 시간표를 대신 쓰지 않는다** — 추정보다 `unknown`이 정직하다. B1 스펙에서 "V1 비포함"으로 미뤘던 항목의 회수.
4. **채팅 도구 날조 차단** — `get_night_clinics`가 진료시간 배열만 넘기던 것을 고쳐, **서버가 계산한 `openStatus`를 함께** 넘긴다. 현재 KST를 모르는 LLM이 HHMM 배열을 보고 "지금 진료 중"을 추론하면 그건 날조다([[agentic-llm-fabricates-unstated-fields]]). `count`도 표시분이 아니라 반경 내 전체 수로 바꿔 "5곳뿐"이라 답하지 않게 했다.
5. **좌표 누락 행 관측** — 좌표 없는 행은 거리 정렬이 불가해 버리지만, 조용히 사라지면 "명부에 없음"과 구분되지 않는다. 드롭 수를 `console.warn`으로 남긴다(관측만).

진입점은 `findNightClinicsNow()` 하나로 모았고 라우트·채팅이 공유한다. 상태 계산이 한 곳이라 두 경로가 갈라지지 않는다.

## 3. 단계 1 — 소스 확장 (착수 조건 충족, 계약 실호출 확정)

**목표**: 지정 여부와 무관하게 "지금 문 연 소아청소년과"를 찾는다. **같은 `DATA_GO_KR_API_KEY`, 추가 활용신청 없이** 가능함이 확인됐다.

**정본 = `getHsptlMdcncListInfoInqire` + `QD=D002`.** 같은 서비스(B552657)라 `duty*` 스키마를 공유하고, 실호출에서 **`wgs84Lat`/`wgs84Lon` + `dutyTime1s~8c` 8칸을 함께** 준다 → `parseClinics`·`clinicOpenStatus`·`prioritizeOpen`을 **그대로 재사용**하고 provider 하나만 추가하면 된다. envelope·게이트·3-state도 유지된다.

- **`QD=D002`가 소아청소년과다.** 강남구에서 `D001~D016`을 전수 스캔해 역판정했다(`D002`: 232건·이름에 '소아|어린이' 36건·대조 기관 적중 / `D009`: 132건·소아 0건 = 신경외과류). **설계 초안의 "D009=소아청소년과 추정"은 오류였다** — 그 코드로 부른 목록에 정형외과·재활의학과가 섞여 나온 것이 단서였다.
- **⚠ `D002`는 "소아청소년과 전문"이 아니라 "소아청소년과 진료과목 보유"다.** 이비인후과·내과·산부인과가 섞인다(§6-1의 정밀도 대가가 추정이 아니라 실측으로 확인된 것).

**탈락한 후보**
- **`getHsptlMdcncLcinfoInqire`(위치기반)** — 좌표와 `distance`(km)를 주지만 **요일별 진료시간이 없고**(`startTime`/`endTime` 단일 쌍뿐, 기준 요일 불명), `QD`·`QT`·`QN` 어떤 필터를 붙여도 `totalCount=239` 고정으로 **필터가 무시된다**. 단독 사용 불가.
- **`getHsptlBassInfoInqire`(hpid 단건 상세)** — 정상 응답이고 좌표·`dutyTime`을 준다. 위치기반 → 상세 N+1 조인의 길은 열려 있으나, 정본이 이미 둘 다 주므로 **불필요**하다.

**⚠ 남은 설계 과제 — 정본이 반경 검색이 아니다.** `getHsptlMdcncListInfoInqire`는 **시도+시군구** 기반이라 "20km 반경"을 직접 못 받는다. 좌표를 **기존 `coordToAddress`(현위치 주소 라벨용 역지오코딩)로 행정구까지 풀고, 인접 구를 병렬 조회한 뒤 코드가 Haversine으로 자르는** 구조가 필요하다. 인접 구 목록을 어떻게 정하느냐(정적 인접표 vs 반경 후보구 산출)가 이 단계의 핵심 결정이다.

## 4. 단계 2 — 심평원 폴백 (**불필요 — 단계 1이 통과했으므로 착수하지 않는다**)

아래는 단계 1이 무너질 때를 위한 보존 기록이다. 참고로 HIRA `getHospBasisList`는 현재 **403(활용신청 전)**이라 착수하려면 신청부터 해야 한다([[datagokr-api-activation-independent]]).

`docs/RESEARCH-2026-06-domestic-api-expansion.md` §F-5에 조사돼 있다(병원 15001698, 10,000건/일).

- 병원정보서비스로 좌표·진료과목·종별을 얻어 소아청소년과를 거른다.
- **기본 목록에 진료시간이 없다** → 기관별 상세를 `ykiho`로 단건 조회하는 **N+1 조인**이 필요하다. 상위 N곳으로 한정하고 `Promise.allSettled`로 부분 실패를 보존한다(전멸 금지).
- 비용이 크므로 단계 1이 실패할 때만 간다.

**교차 보강(선택)**: HIRA 15001674(소아 야간진료 지정)는 좌표가 없다고 실측 판명됐지만 **주소는 있다** → 기존 juso/카카오 지오코딩을 태워 "야간진료 지정" 배지로 교차 표시할 수 있다.

```bash

```

1. **①이 원인을 가른다.** 대상 기관이 달빛 명부에 **있으면** (B) 절단, **없으면** (A) 확정. ⚠ **이름 일치만으로 "있음"을 판정하지 말 것** — 반드시 주소·좌표로 동일 기관인지 확인한다(§1 동명이원 함정).
2. **②·③ 중 하나가 정상 응답 + `dutyTime` 8칸**을 주면 단계 1 진행(파서 재사용).
3. 둘 다 미신청이거나 진료시간이 없으면 ④ + 상세 조인으로 단계 2.

## 6. 불변식 (확장해도 깨지 않는 것)

1. **커버리지 확대는 정밀도와의 거래이며, UI가 그걸 숨기면 안 된다.** 달빛 명부는 작지만 "소아 야간진료 지정"이라는 품질 보증이 붙어 있다. 일반 소아과를 섞으면 "일요일 오전만 여는 곳"이 같은 목록에 들어와, 밤 11시 사용자가 헛걸음할 수 있다. **지정 여부를 항목 텍스트에 흡수**하고(`joinText`로 한 줄=한 객체 유지) 출처를 구분한다.
2. **3-state 유지** — open/closed/**unknown**. 소스가 늘어도 "정보 없음"을 "마감"으로 뭉개지 않는다.
3. **어떤 소스도 "오늘 실제로 문을 열었는지"는 모른다.** 전부 신고된 시간표이고 임시휴진·명절 변동은 어디에도 없다. 그래서 `tel:` 링크(1탭 통화)가 UI의 1급 행동으로 남아야 하며, 판정 기준(`basis`)을 항상 밝힌다.
4. **mock 폴백 없음, 실패는 502.** "조회 실패"와 "근처에 없음"을 절대 뭉개지 않는다.
5. **절단은 항상 드러낸다.** 상한을 두는 건 좋지만 몇 곳 중 몇 곳인지 말하지 않는 건 안 된다.
