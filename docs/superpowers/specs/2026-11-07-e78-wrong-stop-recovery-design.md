# E78: 정류장·역을 잘못 내렸을 때(일찍 내림·지나침) 고르는 복구 선택지 — 설계

- 판정 정본: `docs/BACKLOG.md` §5 E78(2026-11-02 위원장 요청, "구상부터 별도 세션"). 이 spec은 구현하지 않는다.

## 0. 한 문단 요약

버스·지하철에서 잘못 내렸거나 지나친 사용자가 대중교통 안내 시트에서 **「여기서 다시 길찾기」** 하나를 누르면, 앱은 "지금 어디인가"를 정하고(버스 구간은 새 측위, 지하철 구간은 역을 묻는다) 그 자리에서 **최종 목적지까지** 대중교통을 다시 조회하고 **추천 경로로 바로 바꿔**(Q4 판정) 승차 대기부터 다시 안내한다. 다른 후보는 바뀐 뒤 「진행 상황 → 다른 경로 보기」에서 본다. 같은 노선 다음 차를 다시 타는 길이 가장 나으면 ODsay 추천이 그 경로일 것으로 본다(추정, 실호출로 확인한다). 목적지가 가까워 대중교통 경로가 없으면 「목적지까지 걸어가기」로 도보 안내를 잇는다. **대중교통 상태 머신(리듀서)은 바꾸지 않는다.** 재조회 호출과 세션 교체(`changeRoute`)는 iOS에 이미 있는 「진행 상황 → 다른 경로 보기 → 이 경로로 전환」(E15-1) 기계를 쓰고, 이번 일은 그 입구·출발점·도보 갈래를 정하는 것이다.

## 1. 의도와 목표

**왜**: 시각장애 사용자는 정류장 표지·역명판을 볼 수 없어 하차 지점을 틀리기 쉽다. 지금 앱은 그 순간 할 일을 말해 주지 못한다: 지나침은 「{하차역} 출발.」 한마디나 「내리셨으면 다음 구간 버튼을 눌러 주세요.」뿐이고, 일찍 내림은 앱이 사용자가 아직 탄 줄로 알고 하차역 도착을 계속 센다. 수단은 [탑승 변경] → 하차역 행(하차 선언, A37 ②)으로 구간을 끝내는 것뿐이다.

**목표**
1. 잘못 내린 사용자가 시트에서 한 번 눌러 "지금 여기서 목적지까지"의 길을 다시 얻는다. 일찍 내림·지나침 모두.
2. 앱이 모르는 것을 아는 척하지 않는다: 지금 위치를 앱이 추정해 출발점으로 꾸미지 않는다(E15-1 §5.3, A16 L3와 같은 원칙).
3. 새 판정 계층을 만들지 않는다. A16 위치 기반 폴백 기각(BLOCKER 11건)을 되풀이하지 않는다.

**비목표**: 잘못 내림 자동 판정(Q1 판정 가), 지나친 열차에서 계속 타고 가며 되돌아오는 경로 계산(사용자는 먼저 내린다), 웹·안드로이드(Q5 판정 나 — 뒤로), 여정(E70) 안의 대중교통 단계(§5-3).

**반목표(동작해도 실패인 것)**
- 바르게 타고 가는 사용자에게 "잘못 내리신 것 같습니다"라고 말하는 것.
- 측위가 실패했는데 옛 좌표나 버스 안에서 잡힌 좌표로 조회해 엉뚱한 출발점의 경로를 내는 것(측위는 `force: true`, §3.2).
- 재조회 중·뒤에 기존 하차 안내가 살아 남아 옛 하차역 도착을 계속 말하는 것.

## 2. 사실 (설계를 묶는 코드)

| 상황 | 앱이 아는 것 | 앱이 모르는 것 |
|---|---|---|
| 지하철 정상 하차 | 하차역 도착 코드 1 → 확정 도착, 폴 멈춤 | 확정 뒤의 열차·사용자 이동 |
| 지하철 지나침 | 코드 1을 놓치면 코드 2 → 「{하차역} 출발.」, 이어 안 보이면 추정 도착 「내리셨으면 다음 구간 버튼을 눌러 주세요.」 | 사용자가 아직 탔는지, 열차가 지금 어느 역인지(하차역 뒤 역은 조회도 경유 목록도 없다) |
| 지하철 일찍 내림 | 없음(지하철엔 기기 위치 판정이 없다) | 내렸다는 사실. 피드는 열차를 따라 하차역 도착을 알린다 |
| 서울버스 정상 하차 | 잔여 0 「다음 정류장 {stop}에서 내리세요.」, 기기 위치 50m·정확도 35m·10초 안 2연속이면 「{stop} 도착. 내리세요.」(A69, 한 번만), 차량 소실 → 추정 도착 | 정차 자체(확정 도착 없음) |
| 서울버스 지나침 | 소실 → 추정 도착. 그 뒤 정류장 추적·keep-alive 꺼짐 | 지나친 뒤 사용자 위치, 50m 진입 뒤 멀어짐(코드 없음) |
| 서울버스 일찍 내림 | 기기 위치 표식이 내린 정류장에 머무름(표시 전용) | 차량과 사용자의 괴리(비교 코드 없음). 앱은 아직 탄 줄 안다 |
| 지방버스(TAGO) | 근사 잠금, [다음 구간] 상시 | 내 차량 |

**핵심**: 열차·버스 실시간 정보는 **차량**의 위치이지 **사람**의 위치가 아니다. 사람이 내렸는지는 기기 위치로만 알 수 있고, 지하철은 땅속이라 그것도 어렵다. 그래서 잘못 내림은 사용자가 말해야 시작된다(Q1).

**이미 있는 것(iOS)**
- [탑승 변경](승차 중, 지방버스 제외): 지하철은 「지금 어느 역에 계신가요?」 → 이번 구간 경유역(승차역~하차역) 중 하나. 하차역이면 하차 선언(`declareArrived`), 그 밖이면 그 역 기준 승차 대기(A16 L3). 서울버스는 「지금 어느 정류장에 계신가요?」로 이번 구간 정류장을 묻고 그 정류장 기준으로 노선을 다시 센다(E76 후속 ⓔ, 2026-11-07 `e33bf284`). **하차역 뒤 역은 목록에 없다.**
- 「진행 상황」 조망 → 「다른 경로 보기」(E15-1, `phase != done` ∧ 여정 아님): 출발점은 사용자 선언 승차역(대기·승차 전 국면) → `LocationService.currentCoordinate()` → 신선한 추적 현재역 → 실패 순. 최종 목적지(`dest`)까지 `routeService.transit`로 재조회, 후보를 펼쳐 「이 경로로 전환」 → `changeRoute`가 세션을 새 경로 0번 구간 대기부터 다시 연다(통지 「경로를 바꿨습니다.」 + 시작 문장). 근거 변화·120초 가드 있음.
  - ⚠ 이 경로의 측위는 `force` 없이 부른다(스토어 신선 TTL 60초 재사용). 버스에서 내린 직후면 60초 안의 fix가 버스 안 위치일 수 있다. E78 경로는 `force: true`로 부른다(§3.2).
- 출·도착 700m 안이면 ODsay가 "경로 없음"을 주고 앱은 「여기서 가는 다른 대중교통 경로가 없습니다.」를 낸다. 도보로 잇는 버튼은 없다.
- 도보 인계 기제: 마지막 구간 뒤 `acceptWalkHandoff`(목적지 = 최종 목적지), 환승 도보 `transitTransferWalk`(다음 승차 지점), 승차 전 도보(첫 승차역).
- 「경로 새로고침」·「지금 여기는 어디?」는 대중교통 시트에 없다(E75 판정 7, ODsay가 경유를 받지 않는다).
- 웹에는 대중교통 재조회 경로가 없고, 안드로이드에는 대중교통 안내 세션이 없다.

## 3. 설계 골격 (세션 기본안, §4 판정으로 확정)

### 3.1 입구 (Q2 판정 가)

대중교통 안내 시트의 국면 버튼 자리에 **「여기서 다시 길찾기」** 버튼 하나. 승차 중(`riding`)·도착(`arrived`) 국면, 모든 수단(지방버스 포함). 위치는 그 국면의 기존 버튼([다음 구간]/[남은 도보 안내 시작], [탑승 변경]) 바로 다음. 이름은 상황("잘못 내렸어요")이 아니라 동작을 말한다(컨트롤 라벨은 동작의 범위를 서술한다).

### 3.2 출발점 (Q3 판정 가)

- **버스 구간**: 새 측위 `currentCoordinate(force: true)`. 실패하면 「현재 위치를 확인할 수 없어 다시 길찾기를 하지 못했습니다.」(새 문장 후보) + [다시 시도].
- **지하철 구간**: 먼저 역을 묻는다. 「지금 어느 역에 계신가요?」(기존 키 재사용) + 이번 구간 경유역 + **「목록에 없는 역 찾기」**(역 이름 검색, 하차역을 지나친 경우). 고른 역 좌표가 출발점. GPS를 먼저 쓰지 않는 이유: 땅속 측위는 실패하거나 출입구 쪽 옛 좌표로 붙는다.
- 앱은 출발점을 추정하지 않는다: 하차역 좌표·잠금 열차의 마지막 관측 역으로 자동으로 꾸미지 않는다.

### 3.3 조회와 자동 채택 (Q4 판정 나)

위원장 판정: **추천 경로로 앱이 바로 바꾼다.** 다른 후보는 바뀐 뒤 「진행 상황 → 다른 경로 보기」로 본다. 경로가 없으면 「목적지까지 걸어가기」.

- **조회**: 출발점(§3.2)이 정해지면 `fetchTransitCandidates(origin:, dest:)`(E15-1과 같은 호출, 최종 목적지 `dest`)를 한 번 부른다. 상태는 새 슬롯 `pendingRecovery`(토큰 보유)에 둔다. `pendingAltRoutes`·`pendingDestChange`와 공유하지 않는다(E15-1 §5.2 슬롯 분리 근거: 서로 덮거나 지연 취소가 다른 요청을 지우지 않게).
- **고를 경로**: `transitRouteEntries(result)` 순서(추천 → 대안)에서 **안내 가능 술어(모든 탑승 구간 `trackMode != nil`, §8-2)를 만족하는 첫 경로**. 추천이 안내 불가면 말없이 다음 후보로 넘어간다. 조회 0건과 "경로는 있으나 안내 가능 후보 0"은 다른 상태 문장이다(§8-2).
- **커밋 가드**: 응답 시점에 ① 토큰이 최신(다시 누름·취소·세션 종료로 무효화되지 않음) ② 세션이 추적 중 ③ 누른 시점의 목적지·경로 정체성(`dest`·`route` 식별)이 그대로(그 사이 목적지 바꾸기·다른 경로 전환이 커밋되지 않음)일 때만 `changeRoute(…, announcement: .routeSwitched)`. 셋 중 하나라도 어긋나면 조용히 버린다(그 사이의 사용자 조작이 이긴다). **국면 세대(`phaseGen`)·구간 번호 변화로는 버리지도 재조회하지도 않는다**: 누름 자체가 "옛 세션의 위치 판단이 틀렸다"는 선언이라, 조회 중에 옛 세션이 낸 도착 관측이 그 선언을 뒤집지 않는다(E15-1의 근거 변화 가드와 다른 점). 120초 가드도 없다(조회와 커밋 사이에 사용자 확인 단계가 없다).
- **통지**: 누르는 순간 `.high` 「새 경로를 조회하고 있습니다.」(`ios.transitGuide.destChangeLoading` 재사용). 조회 중 다시 누르면 같은 문장만 다시 말하고 새 요청을 만들지 않는다(E74 규칙). 채택은 `changeRoute`의 `.routeSwitched` = `.high` 「경로를 바꿨습니다.」 + 시작 문장 「{dest}까지 대중교통 안내를 시작합니다. 탑승 구간 {count}개.」(기존 그대로). 진동 `ResultHaptic` 성공·주의·실패(문장이 나가는 조건 = 진동 조건).
- **착지**: 채택 뒤 새 세션은 0번 구간 대기 국면이다. 착지는 기존 전이 착지 규칙(riding·arrived → waiting이면 대기 라벨 `.waitingLabel`, 허용 집합 안)을 따른다. 다음 행동이 차량 선택이기 때문이다(E15-1 §7 전환 성공 행과 같은 규칙).
- **상태 행(3-state)**: 버튼 바로 아래에 복구 상태 한 줄을 두고 실패·없음일 때 거기에 착지한다.
  - 대중교통 경로 없음(0건, 700m 안 포함, 안내 가능한 후보 0) → 「여기서 가는 다른 대중교통 경로가 없습니다.」(`ios.transitGuide.altNone` 재사용) + 버튼 **「목적지까지 걸어가기」**(새 키). 누르면 대중교통 세션을 끝내고 최종 목적지까지 도보 안내(§3.5).
  - 위치 실패(버스) → 「현재 위치를 확인할 수 없어 다시 길찾기를 하지 못했습니다.」(새 키) + 「다시 시도」.
  - 조회 실패(502·네트워크) → 「경로 조회에 실패했습니다.」(`ios.transitGuide.destChangeError` 재사용) + 「다시 시도」.
  - 채택되면 상태 행은 사라진다(착지는 위 규칙).
- 쿼터: 사용자 누름당 ODsay 1회(다시 시도마다 1회). 자동 루프 없음.

### 3.5 「목적지까지 걸어가기」

- 대중교통 세션을 정지음 없이 끝내고 최종 목적지(`dest`)까지 도보 세션을 연다. 연결은 `GuideSession.acceptWalkHandoff` 재사용(§5-4).
- 도보 경로의 출발점은 도보 세션 자신의 측위다(도보 안내의 기존 규칙). 지하철역 안이면 도보 세션의 기존 위치 실패 처리를 따른다.

### 3.4 리듀서·하차 안내와의 관계

- 리듀서 입력·국면·공유 fixture는 바꾸지 않는다. 버튼을 누른 순간은 리듀서 전이를 일으키지 않고, **자동 채택 커밋에서만** 세션이 바뀐다. 복구 진행 중에는 앱 층에서 옛 세션의 폴과 버스 하차 위치 통지를 멈춘다(§5-1).
- 도착 국면(`arrived`)에서도 버튼이 서므로, 지나쳐 추정 도착이 난 뒤에도 복구할 수 있다.

## 5. 판정 뒤 세션이 정한 것 (위원장 판정 아님)

1. **복구 진행 중 옛 세션은 조용히 한다.** `pendingRecovery`가 있는 동안(지하철 역 고르기·검색·조회 중) 옛 세션의 폴 루프를 멈추고(`restartPollLoop`가 `pendingRecovery != nil`이면 예약하지 않음, 즉폴 포함), 버스 하차 위치 통지(A69 `transitBusAlightNoticeStep` 소비)도 그동안 내지 않는다. 리듀서는 바꾸지 않는다(앱 층 게이트, 확정 도착의 "주기 0" 게이트와 같은 자리). 슬롯 종료·재개·옛 통지 장부 무효화는 §8-3·§8-4·§8-5가 정본이다(사용자 경쟁 조작은 토큰 무효화, 자기 토큰만 정리, 재개는 주기 0·유휴 게이트 통과, 옛 문장 재생 없이 즉폴로 재판정). 근거: §1 반목표 셋째(옛 하차역 도착을 계속 말하는 것). 사용자가 이미 "틀렸다"고 선언한 안내를 그 뒤에도 말하면 새 안내와 섞인다.
2. **「목록에 없는 역 찾기」는 길찾기 출발지 검색 화면(`DirectionsEndpointSearchView`)의 「지하철역 검색」 갈래를 재사용한다.** 그 갈래는 지금 여정 실험판 상수(`experimentalJourneyEnabled`) 뒤에서만 열리므로, E78 진입은 그 상수와 무관하게 열리는 별도 모드(같은 뷰·같은 검색, 결과는 역 이름·좌표만 돌려줌)로 부른다. 지원 로케일 모두에서 이 행을 둔다. 검색 원천은 로케일별 실호출로 확인하고, 실패는 실패 문장 + 「다시 시도」다(§8-6).
3. **여정(E70) 단계 안에서는 버튼을 세우지 않는다.** 「다른 경로 보기」가 여정 단계에서 숨는 것과 같다. 여정은 역 A·B 지정 경로라 일반 재조회로 바꾸면 여정 상태 머신과 어긋난다.
4. **「목적지까지 걸어가기」는 `GuideSession.acceptWalkHandoff`를 그대로 부른다**(transit 종료 → 600ms → `self.startBeacon(` 목적지 = 최종 `dest`). 새 진입점이 아니므로 `guidance-gate-drift.test.ts` 계수(`self.startBeacon(` 3)는 불변이고, 그 테스트의 해당 주석에 E78 소비처를 한 줄 더한다. `pendingWalkHandoff` 한 턴 신호를 세우고 같은 턴에 소비하는 E34 꼴을 따른다.
5. **채택한 새 경로의 첫 승차 지점이 걸어가야 하는 곳이면 승차 전 도보(A25)를 연다.** 새로 시작하는 대중교통 안내(`beginTransit`)가 `transitPrewalkTarget`이 설 때 도보를 먼저 여는 것과 같은 판정을 커밋 뒤에 한 번 한다. 서면 대중교통 세션은 새 경로로 바꾼 채 A25 연결(`launchPrewalk` → 도착 `startAfterPrewalk`)로 넘어간다. 버스 위치 출발에서 새 승차 정류장이 길 건너인 경우가 흔하기 때문이다. 기존 「이 경로로 전환」(E15-1)은 바꾸지 않는다(범위 밖, 같은 갭은 BACKLOG 편승 후보로 적는다).

## 9. 구현 메모 (세션 `e78-impl`, 2026-11-07)

- **§8-1 「A25 규칙 그대로」의 정정**: 복구가 연 승차 전 도보는 이미 돌던 대중교통 세션의 연장이라 정지 꼬리는 「대중교통 안내도 종료했습니다」, 위치 상실은 그 구간(새 경로 0번) 대기로 재개, 시작 문장은 `.high`다(E73 환승 도보와 같다). 종전 `PrewalkContext.isTransfer`는 `startLeg > 0`으로 계산돼 0번 구간인 복구를 A25로 오판하므로 입구가 밝히는 저장값으로 바꿨다(`beginTransit` false, `transitTransferWalk` true). 연결 자체는 같은 `transitTransferWalk`이고 진입점 수(12)는 그대로다.
- **「경로를 바꿨습니다.」는 도보 시작 문장과 한 게시다**(`TransitTransferWalkHandoff.lead`) — 둘로 게시하면 latest-wins 창구에서 앞 문장이 진다.
- **새 문장**(초안, `ios.transitGuide.recovery*` 6로케일): 「여기서 다시 길찾기」·「목록에 없는 역 찾기」·「지금 계신 역 검색」(검색 화면 제목·칸)·「현재 위치를 확인할 수 없어 다시 길찾기를 하지 못했습니다.」·「여기서 실시간으로 안내할 수 있는 대중교통 경로가 없습니다.」·「다시 시도」·「목적지까지 걸어가기」. 기존 문장 재사용: 조회 중 `destChangeLoading`, 실패 `destChangeError`, 0건 `altNone`, 역 질문 `reboardStationPrompt`.
- **비한국어(§8-6)**: 앱 데이터 언어가 ko가 아니면 en으로 접히므로 `/api/places?lang=en` 실호출 한 축으로 다섯 로케일을 대표했다 — `Gangnam Station`·`Sindorim` 둘 다 `교통,수송 > 지하철,전철` 분류 장소를 돌려줘 `stationLayoutKind == .subway` 판정이 원문 `category` 축에서 통과한다(corpus는 세션 보고 디렉터리).
- **착지**: 역 질문은 `.reboardPrompt`를 재사용하고(같은 질문 문장), 조회 중·결과 줄은 새 대상 `.recoveryStatus` 하나다. 버스의 첫 누름은 버튼이 그대로라 착지하지 않고 `.high` 통지가 응답이다. 채택 뒤 착지는 국면 전이 착지(대기 라벨)가 맡는다.
- **리뷰 반영(2026-11-07)**: 역 질문을 연 채 잊으면 유휴 상한(`transitIdlePollLimitMs`) 뒤 질문을 거두고 폴을 다시 세워 기존 유휴 정지가 판정된다(슬롯 동안 폴이 없어 안전망이 돌지 않았다). 버스 「다시 시도」는 조회 중 통지를 내지 않는다(착지가 응답). 시트가 최소화돼 있으면 결과 문장을 통지(전경)·복귀 낭독(백그라운드)으로 갚는다. 자동 전이가 지나간 결과 행은 거둔다. 조망이 열린 동안의 착지는 이월해 닫힌 뒤 착지한다. 복구 역 검색의 「지하철역을 골라 주세요.」는 6로케일 새 키(`recoveryNotSubway`, 여정 문장은 ko 전용이라 비한국어에서 키가 낭독됐다).
- **§8-6 「검색 실패는 실패 문장 + 「다시 시도」」의 정정**: 역 검색 화면은 기존 끝점 검색 그대로 실패 줄 + 검색 칸 재제출이다(재제출이 곧 다시 시도라 버튼을 더하지 않았다). Release 구성 빌드는 확인했다(`init(recoveryStation:)`은 실험 플래그를 보지 않는다).
- **범위 밖으로 남긴 것(판정 요청 중)**: 추적 불가 구간(비수도권 지하철·노선 이름 없는 버스)은 리듀서가 대기 국면에 머물러 버튼이 서지 않는다. §3.1 「모든 수단」과 국면 조건(승차 중·도착)이 이 경우 어긋난다 — 기본값은 지금처럼 제외.
- **재검토 반영**: 결과 문장은 복귀 낭독·유휴 재개 문장을 대신하지 않는다(시트가 떠 있을 땐 결과 행 착지, 최소화 중엔 자동 통지 창구 하나로 내고 백그라운드 채널은 E53 술어가 가른다). 역 질문 시한은 마지막 조작 기준이고 검색 시트가 열려 있으면 미루며, 닿으면 곧장 유휴 정지다. 변환 실패로 끝난 커밋은 「안내 불가」로 수렴한다.
- **관측으로 남긴 접근성 메모**: 탑승 변경과 복구의 질문·취소 라벨 공유, 0건 문장의 「다른」은 문안 판정(judgment-202611071042) 왕복에서 함께 본다. 승차 전 도보 채택의 성공 진동이 시작 문장보다 600ms 이상 먼저 나는 것은 FIELD-TEST §5-5c ①에서 간격을 듣는다.
- **재재검토 반영**: 검색 시트 미룸은 전경에서만(백그라운드에서 미루면 안전망이 무기한 꺼진다). 주기 0 국면(확정 도착·비관측 승차)에서 시한이 닿으면 「안내를 멈추었습니다」 없이 질문만 거둔다. 최소화 ∧ 백그라운드에서 버려진 결과는 다음 복귀 낭독 한 번만 결과 문장을 말한다(1회성 표식).
