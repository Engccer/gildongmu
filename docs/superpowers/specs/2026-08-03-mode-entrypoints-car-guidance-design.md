# 수단별 안내 진입점 재편 + 자동차 안내 (묶음 B1) 설계

> 2026-08-03. 위원장 실사용 판정(진입점을 도보·자동차·대중교통 3종으로 분리)의 1차 마일스톤. 조사 정본은 `docs/RESEARCH-2026-08-03-mode-specific-guidance.md`(이하 "조사"), 기반 자산은 E4 스펙 `2026-08-03-realtime-route-guidance-design.md`. 대중교통 안내는 **B2 별도 스펙**이다. codex 적대적 리뷰(gpt-5.6-sol·high) 반영본 — 반영 요지는 §11.

## 1. 배경과 목표

E4(실시간 길 안내)는 "간략(직선거리)/상세(도보 경로 추종)" 2모드 단일 진입이었다. 위원장 실사용 판정: 수단별 경로가 너무 달라 이 구분으로는 대중교통·자동차에서 유의미한 안내가 성립하지 않는다. B1의 목표 둘:

1. **진입점을 수단별로 재편**한다: "도보 안내 시작" / "자동차 안내 시작"(대중교통은 B2에서 추가).
2. **자동차 안내를 신설**한다: 시각장애인 **승객** 관점의 진행 브리핑 — "지금 어느 도로, 다음 분기까지 얼마, 잔여 거리·시간, 도착 임박". 명칭은 위원장 명명대로 "자동차 안내"를 유지하되, 분기 문장은 Tmap 완성 문장 원문을 그대로 낭독한다(재조합 금지 원칙이 승객 프레이밍보다 우선 — 원문이 명령형이어도 경로 이해 정보로 유효).

성과 지표: 위원장 차량 실측에서 ①분기 예고가 통과 전에 들리고 ②"지금 어느 도로쯤" 질문에 진행 상황 버튼이 답하며 ③멀쩡한 주행 중 거짓 재확보·이탈 통지가 없을 것.

## 2. 확정 판단

| 사안 | 확정 | 근거 |
|---|---|---|
| 자동차 데이터 | **Tmap 단독** | 폴리라인 321점·이음매 0.00m·실시간 ETA 실측(조사 §2). 카카오는 기하 열위 + 유턴 스냅 |
| 정체 등급 | **V1 제외** | 카카오 병행 호출만 정당화하는 축 — 백로그(§9) |
| 이탈 의미론 | **경고 완화 + 안내 동결 + 수동 재조회** | 차량은 운전자 재량 경로 변경이 정상. 이탈=정보, 단 이탈 중 낡은 안내는 거짓이므로 전부 동결(§4.4) |
| 간략 안내 지위 | **"모드"에서 "폴백 계층"으로** | 위원장 2번 피드백. §4.5 전이표가 정본. 소리 토글 전환은 보류 |
| ETA 갱신 | **현 위치→목적지 재조회 값 직사용** | 비례 축소는 정체 국소성에 취약(리뷰 6축). §4.6 |
| 로케일 | **자동차 안내 ko 데이터 로케일 전용** | Tmap description이 한국어 완성 문장. 비한국어는 시작 버튼 미노출(§3.1) |
| 걷기 리듀서 재사용 | **상수 주입 한정 프로파일화** | 분기 구조·비교 순서 불변, 상수만 인자화(§4.2 회귀 0 계약) |
| car 상수 변경 규칙 | **최초 실주행 판정까지 §4.3 표 값 고정** | 이후 변경은 실측 근거·fixture 갱신 동반(E4 관례와 단일 규칙) |

E4의 유효 계약은 전부 승계한다: 전경 전용, 세션 메모리 한정·종료 시 경로 폐기(약관 경계), 단일 polite 통지, 완성 문장 낭독 정본(재조합 금지), 조용한 강등 금지(모드 변화는 항상 통지), 실행 중 **행동 추정에 따른** 자동 모드 전환 금지(§4.5의 신호 가용성 전이는 이 금지의 대상이 아니다 — E4 도착 인계와 같은 계열).

## 3. 진입점 재편 (IA)

### 3.1 길찾기 뷰 (iOS 길찾기 탭 · 웹 DirectionsView)

- **수단 섹션마다 시작 버튼**: 각 수단 섹션 헤더 직후 첫 행에 "도보 안내 시작" / "자동차 안내 시작". heading 로터로 수단에 착지하면 다음 스와이프가 시작 버튼이다.
- **자동차 버튼 노출 게이트**: ko 데이터 로케일 ∧ 자동차 경로 조회 성공 ∧ **응답 `provider`가 `"tmap"`**. 키 유무(`hasCarRouteKey`)는 서버가 경로 성공으로 이미 증명하므로 클라 게이트 축이 아니다. 카카오 폴백 응답(`provider:"kakao"`)은 기하 미지원이라 버튼을 내지 않는다(누르자마자 강등되는 버튼 = 죽은 컨트롤). 도보 버튼 게이트는 도보 경로 성공 ∧ ko(현행 상세 적격과 동일 축).
- **대중교통 버튼은 B2 전까지 만들지 않는다**(비활성 버튼 사전 배치 금지).
- **간략 폴백 섹션**: 기존 "실시간 길 안내" 단일 섹션은 제거하고, **시작 가능한 수단 안내가 0개**이면서 목적지가 확정된 경우에만 선두에 "간략 안내 시작" 섹션을 노출한다. "모든 수단 조회 실패"가 아니라 "시작 가능 안내 0개"가 게이트다 — en 로케일에서 자동차만 성공한 경우, 카카오 폴백만 성공한 경우 등 "경로는 있는데 안내는 없는" 조합에서 막다른 화면을 만들지 않는다.
- **판정 시점**: 폴백 섹션 노출은 그 세대의 수단 조회가 전부 settled된 뒤에만 계산한다(로딩 중 잠깐 나타났다 사라지는 컨트롤 금지). 노출된 진입점이 상태 변화로 사라져야 하면 포커스 선점 이동 후 제거(헌장 §5).

### 3.2 장소 상세 (웹 패널 · iOS 장소 sheet)

- 기존 진입점(웹 `DistanceBeacon` 패널, iOS 장소 기반 추적)은 **"도보 안내"로 개명**하고 동작은 현행 유지(도보 상세 적격이면 상세, 아니면 간략 폴백). 장소 상세는 수단 맥락이 없는 곳이라 도보가 자연 기본값이다.
- 자동차 안내를 장소 상세에 두지 않는다(진입점 일원화 — E4 브리핑 진입점 정리와 동일 원칙).

### 3.3 세션 UI (시트·패널)와 세션 단일성

- iOS: `BeaconTrackingSheet`를 수단 라벨("도보 안내"/"자동차 안내" + 목적지)로 확장. 컨트롤 집합 — 공통: 중지·진행 상황·잔여 상시 표시(묶음 A). 도보 전용: 상세⇄간략 전환(현행). 자동차 전용: 경로 다시 조회(이탈 시). 자동차 상세⇄간략 수동 전환 버튼은 V1 비범위.
- 웹: `DistanceBeacon` 패널을 `GuideKind` 주입형으로 일반화해 DirectionsView에서도 마운트(장소 상세=walk 고정, 길찾기 뷰=버튼별 kind).
- **세션 단일성 불변식**: 플랫폼별 안내 세션은 동시에 최대 1개다. 새 시작은 기존 세션을 명시 종료한 뒤에만 진행한다(watch·Wake Lock·통지 채널이 2벌 돌면 안 된다). iOS는 `BeaconModel` 싱글 인스턴스가 이미 이 역할이고, 웹은 패널이 2곳에 생기므로 세션 소유를 모듈 싱글턴 스토어로 올린다(geolocation 스토어 관례 동형). **강제 종료 통지는 의도적 생략**(독립 리뷰 질의 확정): 새 세션의 시작 통지와 정지·시작 톤 연쇄가 전환을 이미 전달하고, 별도 통지는 시작 통지와 발화 경합을 만든다. 단 **세션 채널(패널) 자체가 언마운트되는 전이**(목적지 편집·스왑·재조회)는 다르다 — 시작 통지가 없으므로 활성 세션을 명시 중지하고 뷰의 live region으로 중지를 통지한다(`beacon.stopped`, a11y 감사 HIGH 반영).

## 4. 안내 엔진 일반화

### 4.1 구조: kind별 봉인 구성

- 오케스트레이터(웹 `useRouteGuide`, iOS `BeaconModel`)를 수단 파라미터화한다. **주입은 자유 조합이 아니라 `GuideKind`("walk"|"car")를 키로 하는 봉인 구성표에서 원자 선택**한다: 경로 소스(fetch)·리듀서 프로파일·낭독 조립 3요소가 한 항목으로 묶여, "car인데 walk 프로파일" 같은 의미 불일치 세션이 타입상 성립하지 않는다. 알 수 없는 kind는 시작 실패(간략 폴백 아님).
- 판정 리듀서(`route-guide.ts` ↔ `RouteGuide.swift`)는 **튜닝 상수를 프로파일 인자로 받는 형태로 일반화**하되, **변경은 상수 참조를 인자 참조로 치환하는 것에 한정**한다 — 분기 구조·비교 연산자·평가 순서 불변. 기존 export 상수는 walk 프로파일 값으로 유지.
- **리듀서 출력 계약(현행 명문화)**: `guideStep`은 fix당 이벤트 최대 1개를 반환한다. 복수 조건 동시 성립 시 우선순위는 현행 평가 순서를 정본으로 명문화한다 — 이탈 복귀 > 이탈 > 인계(도착) > 선행 낭독(임박) > 주기 > 속도 제안. car 프로파일도 이 순서를 공유하고, 원거리 예고(§4.3)는 선행 낭독과 같은 슬롯의 하위 우선순위다(같은 fix에 둘 다 성립하면 임박만 낭독하고 원거리는 소비 처리 — 뒤늦은 원거리 예고 금지).

### 4.2 walk 회귀 0 계약

- walk 프로파일은 현행 상수와 동작 동일. 증명 3겹: ①프로파일화가 상수 치환 한정이라는 구조 계약(리뷰로 강제) ②기존 공유 fixture 10건 무수정 통과 ③**경계값 fixture 추가** — 임계 직전·동일·직후(선행 낭독 40m, 이탈 30m·20초, 재획득 10초, 인계 50m)를 고정 시나리오로 박아 fixture 커버리지 밖이던 등호 경계를 잠근다.
- 타이브레이크(§4.3)는 walk에 적용하지 않는다(동결 우선, 도보 모호율 낮음). 실보행에서 문제가 관측되면 그때 walk 프로파일만 갱신.

### 4.3 car 프로파일 (초기값 — 최초 실주행 판정까지 고정)

속도 추정 공통 정의: `v = max(직전 fix 구간 속도, 10초 창 중앙값)` — 중앙값 단독은 정체 후 급가속에 뒤처진다. 표본 2개 미만이면 속도항 0으로 두고 거리 하한만 적용. uncertain·reacquiring에서 표본 리셋(현행).

| 축 | walk(동결) | car 초기값 |
|---|---|---|
| 임박 예고(선행 낭독) | 잔여 40m | 잔여 ≤ **max(120m, v×15초)** |
| 원거리 예고 | 없음 | 다음 분기까지 잔여가 **1,500m 경계선을 하향 통과**할 때 1회(스텝당 래치). 세션 시작 시 이미 1,500m 미만이면 원거리 예고 없이 임박만 |
| 구속 창 전방 | max(50m, 3×acc) | **max(150m, 3×acc, v×5초)** |
| 이탈 임계 | max(30m, 2×acc) | **max(50m, 2×acc)** |
| 이탈 확정 | 임계 초과 20초 지속 | 임계 초과 **10초 지속 ∧ 수직거리 비감소 추세**(창 내 최근 표본 기준) — 시간 단독이면 80km/h에서 222m를 달린 뒤이고, 추세 조건이 일시 GPS 튐의 오확정을 막는다 |
| 이탈 재통지 | 60초·warning 톤 | **180초·무톤**, 문구는 상태 전문("경로에서 벗어나 안내를 일시 중지했습니다. 경로 다시 조회로 재개할 수 있습니다") — 첫 통지를 놓쳐도 반복 통지만으로 상태가 완결되게 |
| 인계(도착) | 경로 잔여 50m | 경로 잔여 **150m**. 기준은 직선거리가 아니라 **경로 진행거리**이고(평행 고가 통과 오인계 차단), 이탈·uncertain·reacquiring 중 인계 금지(현행 리듀서 구조 승계 명문화). 재무장선은 인계선 +50m(=200m) — walk의 +20m을 인계선 스케일에 비례해 키운 값(수동 복귀 직후 재인계 루프 차단 마진, 실주행 튜닝 대상) |
| 재투영 모호 해소 | 후보 복수 시 거부 | **재획득(fix 공백 후) 경로에서만** 타이브레이크: 전역 후보 중 직전 d 기준 전방 `v×공백초×1.5 + 100m` 창 안 후보가 정확히 1개면 채택, 0개·복수면 거부 유지. 연속 추적 중 모호(전환·시작)는 현행대로 거부 — 타이브레이크가 평행도로 이탈을 감추는 경로 차단 |
| 속도 가드 | 3m/s 제안 | 미적용(고속이 정상) |

- 주기 통지 간격(60/30/15초)·묶음 통독은 walk 값 유지로 시작. 자동차 스텝은 사실상 전부 long이라 bundle 기계는 자연 미발동(조사 §2 — 결함 아님).
- **낭독 지연 한계의 인정**: "15초 전"은 이벤트 생성 시각 기준이고 VoiceOver 발화 완료 시각을 보장하지 않는다. 실주행 판정 항목에 "분기 통과 전에 들리는가"를 명시하고, 미달 시 시간 계수(15초)를 키우는 것이 1차 조정 축이다(실기기 튜닝 — 코드 재설계 아님).

### 4.4 이탈 중 동결 (자동차)

이탈 확정 순간부터 복귀·재조회 전까지: 분기 예고(원거리·임박)·주기 통지·도로명 표시·잔여 거리·ETA를 **전부 동결**한다(리듀서 offRoute 국면이 6a~6d를 타지 않는 현행 구조의 명문화 + 표시 계층의 잔여·도로명 숨김은 묶음 A `!offRoute` 조건 재사용). 진행 상황 버튼은 이탈 상태 전문 + 목적지 직선거리(E4 §4.2 동형)로 답한다. 복귀(backOnRoute)·재조회 성공 시 동결 해제와 함께 현재 스텝부터 재개.

### 4.5 모드 전이표 (자동차 세션)

| 전이 | 트리거 | 통지 |
|---|---|---|
| 시작 → carDetail | 시작 시 현 위치 기준 `includeGeometry=1` 재조회 성공 + 기하 검증 통과 | "자동차 안내 시작. 안내 N개, 총 {distance}. {첫 안내}" |
| 시작 → brief | 기하 조회·검증 실패 | "경로 정보를 가져오지 못해 간략 안내로 시작합니다"(E4 동형) |
| carDetail → brief | 인계(경로 잔여 ≤150m) | "목적지까지 직선 안내로 전환합니다"(E4 동형) |
| carDetail → uncertain | 정확도 악화·위치 신뢰 상실 | "위치 확신이 낮습니다" — **비콘 폴백 아님**. 같은 GPS를 쓰는 직선거리도 신뢰 불가이므로 안내 정지 상태로 대기(현행 리듀서 uncertain 승계) |
| uncertain → carDetail | 정확도 회복 | "위치 확신을 회복했습니다" |
| carDetail(offRoute) → carDetail | 수동 재조회 성공(새 경로 원자 교체: 기하·상태·예고 래치·ETA 일괄 재설치) | 새 첫 안내 |
| brief → carDetail | **없음**(V1 — 수동 전환 버튼 비범위, 복귀 경로는 세션 재시작뿐) | — |

이 표의 전이는 전부 "신호 가용성" 전이라 E4 "행동 추정 자동 전환 금지"와 충돌하지 않는다(금지 대상은 속도·이탈 같은 행동 추정발 전환).

### 4.6 ETA·잔여 갱신 의미론

- 잔여 거리는 리듀서 진행거리(d) 기반 실시간(묶음 A 계약).
- **ETA는 "현 위치→목적지 재조회의 totalTime을 그대로 잔여 ETA로 사용"한다**(비례 축소 폐기 — 정체 국소성에서 크게 틀린다). 재조회 주기 10분, **세션 캡 6회는 시작 조회·주기·수동 재조회를 모두 포함**한다. 재호출은 ETA만 갱신하고 **기하·안내 상태는 교체하지 않는다**(안내 연속성 — 새 경로가 현 경로와 다르면 ETA에 오차가 생길 수 있음을 수용). 기하 교체는 수동 재조회 전용(§4.5 원자 교체).
- 재호출 사이에는 직전 ETA에서 경과 시간을 차감한 카운트다운으로 표시한다.
- **ETA 3-state**: 최신(10분 내 갱신) / 오래됨(캡 소진·갱신 실패 지속 — 표시 유지 + 진행 상황 응답에 "예상 시간은 {n}분 전 기준" 병기) / 없음(초기 실패 — 거리만 표시). 갱신 실패는 조용히 직전 값 유지(polite 채널 점유 금지), 상태는 진행 상황 버튼이 답한다.
- **세대 3중 일치**: ETA 재호출 응답은 세션 세대·목적지·경로 세대가 모두 일치할 때만 커밋(중지·재조회·목적지 변경 후 도착한 응답 폐기 — 채팅 이탈 게이트 동형).

### 4.7 자동차 낭독 조립

- **기준점 계약**: 스텝 N = "Point N의 동작 + 그 이후 구간(pathCoords)". 따라서 "스팬 N의 끝 접근 = 분기 N+1 접근"이고, 예고(원거리·임박)는 **스팬 끝(다음 분기) 기준 잔여**로 계산한다 — E4 선행 낭독과 동일 의미론이라 리듀서 6b를 그대로 쓴다. fixture로 "연속 분기에서 현재 위치·다음 분기·잔여가 올바른 Point에 연결"을 검증한다.
- 분기 문장은 Tmap description 원문(재조합 금지). ⚠ description 속 거리는 링크 길이라 분기 간 거리와 다를 수 있다(조사 §2) — "다음 분기까지 얼마"는 항상 기하에서 계산하고, **원문과 문법적으로 결합하지 않는다**: 원거리 예고는 "약 1.5km 뒤 다음 안내가 있습니다. {원문}" 두 독립 문장(거리 기준 혼동 차단).
- **"지금 어느 도로"**: LineString별 도로명을 **누적 거리 범위와 함께 보존**하고, 현재 진행거리 d가 속한 링크의 이름만 채택한다(시퀀스 통짜 조인 금지 — 지난 도로·다음 도로 오낭독 차단). `roadType 6` 등 무명 링크는 "도로명 정보 없음"으로 취급해 도로명 자리를 비운다(가짜 정밀 금지). 이탈·uncertain 중엔 도로명 숨김(§4.4).
- 잔여 거리·ETA 상시 표시는 묶음 A 계약 재사용(live region 밖, 이탈 중 숨김).

## 5. 자동차 데이터 계약

- **`/api/route/car` 확장 둘**(둘 다 additive): ①응답에 `provider: "tmap" | "kakao"` 필드(§3.1 버튼 게이트의 판별자) ②`includeGeometry=1` 옵트인(walk 선례 동형: `1` 외 값 400, 미지정 시 신규 키 자체가 없는 byte-호환 — 스키마 스냅숏 테스트로 고정). 자동차는 이미 no-store라 캐시 우회 자연 충족.
- **Tmap normalize 확장**: guide별 `pathCoords?: Coord[]` — 그 Point에서 다음 Point 직전까지의 LineString 좌표 병합 + 링크별 도로명·누적 범위. **Point 처리(구현 실측 정정 2026-08-03)**: description 있는 Point 중 **종점(`E`, "도착")만 마커**로 분리하고 좌표는 `terminalCoord`로 보존한다(커버리지 검증 축). 출발(`S`)은 실측상 첫 안내 문장("올림픽로를 따라 12m 이동")을 갖는 정상 스텝이다 — 1차 스펙의 "S 마커" 서술은 실데이터로 반증되어 폐기. description 없는 Point도 마커(0-길이 스텝 → `buildGuideRoute` null → 조용한 강등 함정 차단, 조사 §2). guides의 `distanceMeters`/`durationSeconds` 하드코딩 0은 유지(표시 계약 불변 — description에 거리 내장, 수치 병기는 중복 낭독).
- **기하 검증은 fail-closed 전체 부적격**: 좌표 유한성·경위도 순서·스텝당 최소 2점·이음매 연속성(`SEAM_TOLERANCE_M`)·전 구간 커버리지(첫 스텝 시작=경로 시작, **마지막 스텝 끝=`terminalCoord` 5m 이내** — E 좌표를 버리면 이 검증이 불가능해 짧은 조립이 fail-closed를 우회한다, 독립 리뷰 반영) 중 하나라도 실패하면 부분 조립 없이 전체 부적격 → 시작 폴백(§4.5). 부분 상세는 중간부터 틀린 도로에 스냅한다.
- **시작 시 재조회**: 안내 시작 시점에 **현재 위치 기준으로** `includeGeometry=1` 경로를 새로 받는다(E4 도보 동형). 길찾기 뷰가 쥔 기존 브리핑의 기하를 재사용하지 않는다 — 조회 후 차량이 이동해 있으면 낡은 출발점 기하로 즉시 이탈·오투영이 난다.
- **카카오 폴백 경로는 geometry 미지원**: 시작 재조회가 카카오로 폴백되면(Tmap 장애) 기하 없음 → 시작 폴백 + 정직 통지. 버튼 게이트(§3.1)가 대부분 걸러 주지만 조회 사이 장애 창은 이 폴백이 받는다.
- 세션 수명: E4 §7.3 동일(메모리 한정, 중지·숨김 시 폐기, 디스크 저장 금지).
