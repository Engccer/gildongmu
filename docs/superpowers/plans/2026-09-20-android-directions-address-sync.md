# 안드로이드 길찾기 현재 주소 상태 동기화

## 범위와 계약

BACKLOG E43 구현 우선순위 1번만 대상으로 한다. iOS `DirectionsAddressState.swift`의 요청 소유권을 Kotlin Kit으로 이식하고 길찾기 화면에 연결한다. 서버 계약과 배포에는 변경이 없다.

- 측위 전에 요청을 발급하고 주소 응답까지 같은 요청을 전달한다.
- 필드 변경과 언어 변경, 코루틴 취소 뒤 늦은 측위와 응답은 주소를 갱신하지 않는다.
- 이전 요청의 종료는 최신 요청의 로딩을 끄지 않는다.
- 한글·영문 주소는 함께 반영하고 `hasLoaded`는 수용된 커밋에서만 설정한다.
- 위치 취득 실패는 직전 주소를 보존한다. 최신 역지오코딩 오류나 매칭 없음은 주소 쌍을 비운다.
- 정식 기능 `debug` 빌드의 한소네 7 검증까지가 완료 조건이다.

## 구현

같은 ViewModel의 요청 시작·종료·커밋이 결합되어 있어 구현은 단일 작업으로 진행하고 리뷰만 별도 컨텍스트에 맡긴다.

1. 취소에 협조하지 않는 측위·전송을 `suspendCoroutine`으로 지연하는 앱 회귀 테스트를 만든다.
2. `DirectionsAddressState`를 순수 Kotlin으로 이식하고 미러 등록부를 갱신한다. 요청 식별은 UUID 대신 불투명 객체의 동일성을 쓴다.
3. 초기 진입·현재 위치 재선택·경로 조회의 세 경로에 측위 전 요청 발급과 수용 검사를 연결한다. 필드 변경은 작업과 소유권을 함께 취소한다.
4. 화면 언어 변경 시 초기 주소 로드를 다시 실행한다. 새 언어에서는 주소 상태를 초기화하며 옛 요청 객체는 새 상태에서도 수용되지 않는다.
5. Android 전체 게이트, 웹 회귀 게이트, APK 구성 검사와 별도 코드 리뷰 후 로컬 반영한다.

## 검증 기록

- 수정 전 기존 `DirectionsViewModelTest`와 `DirectionsTest` 통과.
- 새 앱 회귀 테스트의 최초 6개가 기존 구현에서 모두 실패하는 것을 확인했다. 테스트 URL 헬퍼 반환형 오류를 먼저 수정한 뒤 확인한 실패다.
- 수정 후 앱 주소 테스트 9개와 Kit 상태 테스트 8개를 포함해 `:kit:test` 780개 통과, `:app:testDebugUnitTest` 463개 중 462개 통과·1개 건너뜀, 실패 0.
- `:app:assembleDebug`, `:app:assembleExperimental`, `:app:compileDebugAndroidTestKotlin` 통과.
- 두 APK의 `check-release-manifest.mjs` 통과.
- 웹 전체 게이트 367개 파일 통과·1개 건너뜀, 테스트 4,413개 통과·3개 건너뜀, 실패 0.
- 별도 코드 리뷰 통과. 리뷰어는 Swift 계약·ViewModel 배선·신규 테스트와 기존 ViewModel 29건의 결과를 확인했으며 구체적 결함을 발견하지 못했다. 테스트 재실행은 구현 세션이 수행했다.

## 남은 실기기 확인

ADB 연결 기기가 없어 설치·실행과 한소네 7 키보드·점자 검증은 아직 수행하지 못했다. 자동 테스트를 실기기 통과로 간주하지 않는다.

1. 정식 기능 `debug` APK를 한소네 7에 설치하고 길찾기에 진입한다.
2. 현재 위치 재선택 중 끝점을 바꾸어 이전 주소가 되살아나지 않는지 확인한다.
3. 주소 로딩 중 언어를 바꾸고 새 언어의 주소와 로딩 종료를 확인한다.
4. 필드 라벨과 키보드·점자 초점이 유지되는지 확인한다. 일반 폰 TalkBack 터치 조작 검증은 별도다.

경로 API를 반복 호출할 필요는 없다. 역지오코딩·측위의 역순 완료는 로컬 자동 테스트가 검증한다.
