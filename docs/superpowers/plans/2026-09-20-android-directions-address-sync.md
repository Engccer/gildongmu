# 안드로이드 길찾기 현재 주소 상태 동기화

## 범위와 계약

BACKLOG E43 구현 우선순위 1번만 대상으로 한다. iOS `DirectionsAddressState.swift`의 요청 소유권을 Kotlin Kit으로 이식하고 길찾기 화면에 연결한다. 서버 계약과 배포에는 변경이 없다.

- 측위 전에 요청을 발급하고 주소 응답까지 같은 요청을 전달한다.
- 필드 변경과 언어 변경, 코루틴 취소 뒤 늦은 측위와 응답은 주소를 갱신하지 않는다.
- 이전 요청의 종료는 최신 요청의 로딩을 끄지 않는다.
- 한글·영문 주소는 함께 반영하고 `hasLoaded`는 수용된 커밋에서만 설정한다.
- 위치 취득 실패는 직전 주소를 보존한다. 최신 역지오코딩 오류나 매칭 없음은 주소 쌍을 비운다.
- 정식 기능 `debug` 빌드의 한소네 7 검증까지가 완료 조건이다.

## 구현

같은 ViewModel의 요청 시작·종료·커밋이 결합되어 있어 구현은 단일 작업으로 진행하고 리뷰만 별도 컨텍스트에 맡긴다.

1. 취소에 협조하지 않는 측위·전송을 `suspendCoroutine`으로 지연하는 앱 회귀 테스트를 만든다.
2. `DirectionsAddressState`를 순수 Kotlin으로 이식하고 미러 등록부를 갱신한다. 요청 식별은 UUID 대신 불투명 객체의 동일성을 쓴다.
3. 초기 진입·현재 위치 재선택·경로 조회의 세 경로에 측위 전 요청 발급과 수용 검사를 연결한다. 필드 변경은 작업과 소유권을 함께 취소한다.
4. 화면 언어 변경 시 초기 주소 로드를 다시 실행한다. 새 언어에서는 주소 상태를 초기화하며 옛 요청 객체는 새 상태에서도 수용되지 않는다.
5. Android 전체 게이트, 웹 회귀 게이트, APK 구성 검사와 별도 코드 리뷰 후 로컬 반영한다.

## 검증 기록

- 수정 전 기존 `DirectionsViewModelTest`와 `DirectionsTest` 통과.
- 새 앱 회귀 테스트의 최초 6개가 기존 구현에서 모두 실패하는 것을 확인했다. 테스트 URL 헬퍼 반환형 오류를 먼저 수정한 뒤 확인한 실패다.
- 수정 후 앱 주소 테스트 9개와 Kit 상태 테스트 8개를 포함해 `:kit:test` 780개 통과, `:app:testDebugUnitTest` 463개 중 462개 통과·1개 건너뜀, 실패 0.
- `:app:assembleDebug`, `:app:assembleExperimental`, `:app:compileDebugAndroidTestKotlin` 통과.
- 두 APK의 `check-release-manifest.mjs` 통과.
- 웹 전체 게이트 367개 파일 통과·1개 건너뜀, 테스트 4,413개 통과·3개 건너뜀, 실패 0.
- 별도 코드 리뷰 통과. 리뷰어는 Swift 계약·ViewModel 배선·신규 테스트와 기존 ViewModel 29건의 결과를 확인했으며 구체적 결함을 발견하지 못했다. 테스트 재실행은 구현 세션이 수행했다.

## 남은 실기기 확인

2026-09-21 한소네 7(H732B, Android 15/API 35)에 정식 기능 `debug` APK를 설치·실행했다. 설치된 APK와 로컬 APK의 SHA-256이 일치한다(`2a8397348dac3d69d37853f45b96ac115faa9bb96a01b749735d311a8cc6de79`). 블루투스 스크린리더 연결을 종료하지 않은 상태에서 아래 계측 테스트가 통과했다. 키보드·점자 사용자 판정을 자동 테스트로 대신하지 않는다.

- `DirectionsScreenA11yTest`: 2개 통과. 폼→검색→경로 결과, 구간 행·대안 펼치기·ATF 검사와 도보 오류 뒤 계단 회피 컨트롤 유지.
- `DirectionsAddressDeviceTest`: 2개 통과. 취소된 측위가 최신 주소·로딩을 덮지 않는지, 주입 언어 변경 뒤 늦은 주소 폐기와 재시도, 최종 필드 접근성 이름을 확인했다. 실제 GPS·서버 호출은 없고 앱 설정의 언어 전환 UI를 검증한 것은 아니다.
- 두 클래스를 각각 `--no-configuration-cache`로 실행해 XML의 실제 클래스·테스트 이름과 통과 수를 확인했다. 쉼표로 class 필터를 주었을 때 첫 클래스만 실행돼 성공 종료만으로 전체 실행을 판정할 수 없었다.
- 별도 코드 리뷰 통과. 테스트 APK에 계약 JSON 31개가 있고 앱 APK에는 없음을 확인했다.
- 원시 증거는 공개 저장소 밖 `~/gildongmu-private/probes/android-address-2026-09-21/`에 보존한다(`address-tests.xml`, `screen-tests.xml`, `install-verification.json`).

실기기 실행에서 기존 테스트 결함도 수정했다. JVM `Fixtures`는 Mac 저장소 경로를 찾으므로 기기에서 실패했다. `androidTest` 전용 assets와 `DeviceFixtures`로 교체했다. 화면 크기에 따른 스크롤과 장소 선택 비동기 완료를 기다리고, 필드 검사는 단일 객체의 `contentDescription`을 사용한다.

화면 조회 도구의 보조 앱은 Play 프로텍트에 차단됐다(길동무 앱 차단이 아님). 경고를 닫고 프로젝트 자체 계측 테스트와 화면 캡처를 사용했으며 보호 설정은 변경하지 않았다. 최초 오프라인 테스트 실행은 UTP 의존성 캐시 부재로 실패했고 온라인으로 의존성을 취득한 뒤 실행했다.

마지막에는 일반 앱을 다시 실행하고 채팅 화면 및 점자 표시 영역을 화면 캡처로 확인했다. 재실행 화면에는 AI 채팅 동의 안내가 표시되었다.

2026-09-21 사용자가 안내받은 테스트를 한국어로 수행하고 정상 작동했다고 확인했다. 한국어 현재 주소 읽기·현재 위치 재확인·키보드와 점자 사용 흐름의 사용자 확인으로 기록한다. 언어 전환 및 특정 응답 순서의 수동 재현까지 확인한 것으로 확대하지 않는다.

남은 사용자 확인은 앱 설정에서 한국어→English→한국어로 전환한 뒤 길찾기 필드와 주소가 올바르게 표시되는지다. 일반 폰 TalkBack 터치 조작 검증은 별도다.

경로 API를 반복 호출할 필요는 없다. 역지오코딩·측위의 역순 완료는 로컬 자동 테스트가 검증한다.
