# iOS 다국어(5개 언어) 구현 플랜

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 이 플랜은 인라인 실행을 전제한다: 44개 파일 416줄의 키 매핑은 단일 컨텍스트 일관성(동일 키 규약 누적 적용)이 핵심이라 서브에이전트 분산보다 인라인이 적합(자율성 헌장 인라인 예외 조항).

**Goal:** iOS 앱을 웹 `messages/` 정본 기반 5개 언어(ko/en/es/fr/it)로 로컬라이즈하고 설정 시트에 언어 픽커를 추가한다.

**Architecture:** dodo-planet의 결정론 변환 스크립트를 이식해 String Catalog 2개(앱 타깃·GildongmuKit)를 생성하고, 전 뷰의 한글 리터럴을 `String(localized:)`로, Kit 표시 문자열은 명시 lang 인자 조회로 교체한다. 언어 선택은 `AppleLanguages` 오버라이드(다음 실행부터 적용).

**Tech Stack:** Node(변환·린터 스크립트), Swift/SwiftUI String Catalog, SPM `Bundle.module`.

## Global Constraints

- **ko 불변식**: 마이그레이션 전후 ko 표시 문자열은 동일해야 한다. 웹 카피가 iOS 실문구와 다르면 extra 파일에서 오버라이드한다(웹 `messages/` 수정 금지).
- **키 규약**: 웹 키는 점 표기 그대로(`search.title`), iOS 전용 키는 `ios.` 접두(`ios.settings.title`). 키는 **항상 문자열 리터럴**(린터 추출 전제, 동적 조립 금지).
- **호출 규약**: 앱 타깃은 `String(localized: "키")`, 포맷 키는 `String(format: String(localized: "키"), 인자…)`. SwiftUI `Text("리터럴")` 자동 키화에 의존하지 않는다(전부 명시 `String(localized:)`).
- **Kit 규약**: Kit 소스는 `kitLocalized("키", lang:)`만 사용(`String(localized:)` 금지, 호스트 로케일 비결정론 차단).
- 커밋은 태스크 단위 pathspec(`git add <파일들> && git commit -- <파일들>`), `git add -A` 금지.
- 각 마이그레이션 태스크의 게이트: extra JSON 갱신 → 생성 스크립트 재실행 → 린터 → `xcodebuild build`(Kit 변경 시 `swift test` 추가).
- xcodebuild 게이트 명령(전 태스크 공통): `cd ios && xcodebuild -project Gildongmu.xcodeproj -scheme Gildongmu -destination 'generic/platform=iOS' build 2>&1 | tail -3` (기대: `BUILD SUCCEEDED`)
- 브랜드명 "길동무"(앱 표시명·제품명)는 전 로케일 동일 유지(번역하지 않음). 단 UI 문안 속 "길동무"는 웹 번역을 따른다.

**Interfaces:**

- Consumes: Task 1의 Kit 카탈로그.

**핵심 코드 (Localization.swift):**
```swift
import Foundation

/// Kit 표시 문자열 조회. 호스트 언어에 의존하지 않는 결정론 조회를 위해
/// 해당 언어 lproj 번들에서 직접 찾는다(테스트가 ko를 명시해 Mac 언어 무관).
/// 폴백: 언어 번들이 없으면 모듈 번들(defaultLocalization ko).
func kitLocalized(_ key: String, lang: String, _ args: CVarArg...) -> String {
    let bundle = Bundle.module.path(forResource: lang, ofType: "lproj")
        .flatMap(Bundle.init(path:)) ?? .module
    let format = bundle.localizedString(forKey: key, value: nil, table: nil)
    return args.isEmpty ? format : String(format: format, arguments: args)
}
```

**Interfaces:**
- Produces (AppLanguage.swift):
```swift
import Foundation

/// 앱이 실제 해석한 UI 언어(카탈로그 5개 중 하나). Bundle 해석 결과를 쓰므로
/// AppleLanguages 오버라이드·시스템 언어·폴백이 모두 반영된 단일 정본.
enum AppLanguage {
    static let supported = ["ko", "en", "es", "fr", "it"]

    /// UI 언어 코드(예: "ko"). 데이터 계약(lang 파라미터·chat locale)에 그대로 쓴다.
    static var current: String {
        let resolved = Bundle.main.preferredLocalizations.first ?? "ko"
        let base = String(resolved.prefix(2))
        return supported.contains(base) ? base : "ko"
    }

    /// 웹 data-locale.ts 동형: 외부 데이터는 ko 외 전부 en.
    static var dataLocale: String { current == "ko" ? "ko" : "en" }

    /// STT SpeechTranscriber locale 매핑(자동 감지 금지 계약 유지).
    static var speechLocaleIdentifier: String {
        switch current {
        case "en": "en-US"
        case "es": "es-ES"
        case "fr": "fr-FR"
        case "it": "it-IT"
        default: "ko-KR"
        }
    }
}
```
- 언어 픽커(SettingsView, dodo 동형): `Picker("ios.settings.language")` inline, 항목은 자국어 표기(한국어/English/Español/Français/Italiano 리터럴, lang 속성 개념은 iOS에 없으므로 텍스트만). 선택 시 `UserDefaults.standard.set([code], forKey: "AppleLanguages")` + 재시작 안내 polite 통지(`AccessibilityNotification.Announcement`). 현재값 초기 표시는 `AppLanguage.current`.
- 배선: `SearchModel.submit`의 `lang: "ko"` → `AppLanguage.dataLocale`(명소 ko 게이트는 기존 `lang == "ko"` 조건이 그대로 수행), 태스크 2~5에서 `"ko"`로 두었던 Kit lang 호출부 전부 → `AppLanguage.current`, `ChatRequestBody`에 `locale` 필드 추가 후 `AppLanguage.current` 전송, `SpeechService`의 `Locale(identifier: "ko-KR")` → `Locale(identifier: AppLanguage.speechLocaleIdentifier)`.
