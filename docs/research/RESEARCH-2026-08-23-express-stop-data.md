# 급행 정차역 데이터원 조사 (E14 / A16 L1)

> 시점 고정 기록물(2026-08-23, 실호출 KST 21:40~22:10). 결론이 뒤집히면 이 머리에 한 줄 표기한다.
> 발단: 백로그 [A16](../BACKLOG.md) L1 · [E14](../BACKLOG.md) — "잠금 열차가 하차역에 서지 않으면 안내가 영원히 침묵한다".
> 판정 대상: **(열차·역) 급행 정차 여부**와 **현재역**을 줄 데이터원이 존재하는가.

## 0. 결론 한 줄

**데이터원은 존재하고, 그중 둘은 이미 계약이 걸려 있는 API다.** 급행 정차역 집합은 **ODsay가 이미 주고 있었고**(경유역 목록이 급행 기준으로 이미 좁혀져 온다), 잠금 열차의 현재역은 **서울 실시간 `realtimePosition`**이 준다. 열차번호가 두 서울 API 사이에서 **같은 식별자**임을 실호출 교차 대조로 확정했다(14/14).

## 1. 판정표

| 후보 | 판정 | 실호출 근거 |

## 2. ① ODsay — 경유역 목록은 이미 급행 기준이다

E14 ①은 "지금은 `passStopList` 그대로라 완행 전 역이 나온다"를 전제로 세워졌는데, **그 전제가 틀렸다.** 같은 OD를 급행·완행 두 경로로 받아 나란히 놓으면 목록 자체가 갈린다(2026-08-23 실호출, `OPT=0&SearchPathType=1`).

김포공항 → 종합운동장:

| lane 이름 | passStopList |
|---|---|
| `수도권 9호선(급행)` | 김포공항·마곡나루·가양·염창·당산·여의도·노량진·동작·고속터미널·신논현·선정릉·봉은사·종합운동장 (13) |
| `수도권 9호선` | 김포공항·공항시장·신방화·마곡나루·양천향교·가양·증미·등촌·염창·신목동·선유도·당산·국회의사당·여의도·샛강·노량진·노들·흑석·동작·구반포·신반포·고속터미널·사평·신논현·언주·선정릉·삼성중앙·봉은사·종합운동장 (29) |

`stationID`도 완행 일련번호를 건너뛴다(김포공항 902 → 마곡나루 905: 903 공항시장·904 신방화 생략). 즉 **급행 여부가 이름 표기뿐 아니라 정차역 목록 자체에 반영돼 있다.**

개화 → 중앙보훈병원(전 구간)을 한 번 부르면 급행 leg의 `passStopList`가 **9호선 급행 정차역 16역 전량**으로 나온다(김포공항~중앙보훈병원). 노선의 급행 정차역 집합을 얻는 데 필요한 호출은 **노선당 1회**다.

**따라서 E14 ①은 데이터 층에서 이미 충족돼 있고, 남은 것은 표시 층뿐이다** — 앱이 `leg.stops`를 그대로 쓰는 한 급행 leg에서는 급행 정차역이 나온다.

## 3. ② TAGO — 급행을 모른다

`GetSubwaySttnAcctoSchdulList` 응답 필드는 아래 9개가 전부다(김포공항 9호선 상행 182행, `dailyTypeCode=03`).

```
subwayStationId, subwayStationNm, subwayRouteId,
endSubwayStationId, endSubwayStationNm, depTime, arrTime,
dailyTypeCode, upDownTypeCode
```

열차번호가 없어 역 사이를 잇는 축이 없고, 급행 구분 필드도 없다. 종착역 분포로도 갈리지 않는다(김포공항 상행 182행 중 178행이 중앙보훈병원 종착 — 급행·완행이 같은 종착을 공유한다).

9호선 커버리지도 성기다: 김포공항 182행·여의도 183행인데 **당산·노들은 0행**이다. 급행 정차역인 당산이 0행이라 "행 수 비교로 급행역을 유도한다"는 우회도 성립하지 않는다.

> ⚠ 프로브 함정: `upDownTypeCode`는 `"1"/"2"`가 아니라 **`"U"/"D"`**다. 숫자를 넣으면 인증 정상(`resultCode 00`)에 0행이 와서 "전국이 전멸"로 오독된다(이 조사에서 실제로 한 번 오독했다). 0행이 상시인 API라 **파라미터 오류와 진짜 부재가 같은 응답으로 보인다** — A19가 다루는 3-state 문제와 같은 자리다.

## 4. ③ KRIC — (열차·역) 단위 정본이지만 문이 잠겨 있다

레일포털 Open API 60종 중 **「열차별 운행시각표(급행)」**이 정확히 이 데이터다.

- End point: `https://openapi.kric.go.kr/openapi/trainUseInfo/subwayTimetableExp`
- 요청: `serviceKey`·`format`·`railOprIsttCd`(철도운영기관)·`lnCd`(선)·`stinCd`(역)·`dayCd`(7=토·8=평일·9=휴일)
- 응답: `trnNo`(**열차번호**)·`exptCd`(**급행구분**)·`stinCd`·`arvTm`·`dptTm`·`dayCd`·`dayNm`·`lnCd`·`railOprIsttCd`

역 단위로 부르면 그 역에 서는 열차번호 전량이 급행 구분과 함께 나오므로, **(열차·역) 정차 여부를 관측이 아니라 계약으로** 얻는다. ④가 주는 실시간 위치와 축이 다르다(④는 지금 어디인지, ③은 어디에 설 것인지).

**키 없음.** 무키·더미키 모두 `{"header":{"resultCode":"30","resultMsg":"등록되지 않은 서비스키입니다."}}` — 엔드포인트는 살아 있다.

**발급 절차**(메모리 `kric-railportal-login` 갱신분): ⓐ `https://data.kric.go.kr/rips/login.do`에서 회원가입 — ⚠ 로그인은 `data.kric.go.kr`, API 목록·상세는 `openapi.kric.go.kr`로 도메인이 갈린다 ⓑ **계정 자체를 사람이 수동 승인**한다(수일). 2026-06-18 확인 시점에 승인 대기였고 그 뒤 재확인하지 않았다 ⓒ 승인 후 로그인 → 해당 API 활용신청(무료·단일키). data.go.kr과 달리 API별 자동 승인이 아니다.

## 5. ④ 서울 `realtimePosition` — 9호선을 커버하고, 열차번호가 도착 API와 같다

`http://swopenapi.seoul.go.kr/api/subway/{KEY}/json/realtimePosition/0/200/{노선명}` (키는 기존 `SEOUL_SUBWAY_REALTIME_KEY`).

응답 항목: `subwayId`·`subwayNm`·`statnId`·`statnNm`(**현재역**)·`trainNo`·`recptnDt`·`updnLine`·`statnTid`·`statnTnm`(행선)·`trainSttus`(0진입·1도착·2출발·3전역출발)·`directAt`(**0일반·1급행**)·`lstcarAt`.

노선별 편성 수와 급행 분포(2026-08-23 21:42):

| 노선 | 편성 | `directAt` 분포 |
|---|---|---|
| 9호선 | 25 | 일반 16 / **급행 9** |
| 1호선 | 75 | 일반 69 / **급행 6** |
| 공항철도 | 14 | 일반 12 / **급행 2** |
| 경춘선 | 8 | 일반 7 / **`9` 1건**(ITX 계열 추정, 미확인) |
| 2·3·4·5호선, 경의중앙, 수인분당, 신분당, 우이신설, 서해, GTX-A | 7~33 | 전부 일반 |

**교차 대조(이 조사의 핵심 관측)**: 9호선 위치 목록 26편성과 5개 역(당산·여의도·노들·고속터미널·가양) 도착 목록의 열차번호를 맞췄더니 **도착 14개가 전부 위치 목록에 있었다(14/14)**. 급행 표기도 일치한다(도착 `btrainSttus:"급행"` ↔ 위치 `directAt:"1"` — 9663·9665·9667·9674·9676·9678).

⚠ **함정 — 위치 피드의 `updnLine`은 규격 문언과 반대로 관측된다.** 서울 열린데이터 규격은 `realtimePosition.updnLine`을 `0:상행/내선, 1:하행/외선`으로 적지만, 실측은 **`0`=하행(개화·김포공항 방면)·`1`=상행(중앙보훈병원 방면)**이다(같은 열차번호를 도착 피드의 `updnLine`(`"상행"`/`"하행"`)과 맞춘 12/12 대조). 도착 피드는 한글 낱말이라 애초에 뒤집힐 수 없고, 위치 피드만 숫자라 뒤집힌 채로도 그럴듯하다. **방향이 뒤집히면 반대편 열차를 추적하고 그 사실을 알 수단이 낭독뿐이라, 이 필드는 쓰지 않는 것이 최선의 방어다** — 진행·지나침 판정은 `viaStops`가 이미 승차→하차 순서라 index 증가만으로 성립한다.

**갱신 입도(추적 축으로 쓸 수 있는가)**: 9호선을 45초 간격으로 4회 떠 135초를 관측했다 — 25편성 중 **23편성이 역·상태를 바꿨고** 1편성만 동일, 1편성 소실. 급행 9665는 `증미/출발 → 가양/출발`, 일반 9184는 `노량진 → 노들`로 실제 전진한다. 다만 `recptnDt`가 45~62초 간격으로만 갱신되므로 **위치 축의 실효 해상도는 약 60초**다(승차 국면 폴 주기 15초보다 성기다 — 같은 값을 반복해서 받는 폴이 정상이라는 뜻이고, 소비자는 그 반복을 새 정보로 오인하면 안 된다).

> 종전 기각 근거였던 "5호선 결측"은 이 시점에 재현되지 않았다(33편성 정상). 다만 그 기각은 *낭독 정본* 자리에 대한 판정이었고(완성 문장 부재·도착 API보다 낡음), **보조 축으로 쓰는 것은 그 판정에 걸리지 않는다.**

## 6. A16 L1의 기제를 실호출로 실증했다

같은 시각 각 역의 9호선 도착 목록:

| 역 | 도착 열차 |
|---|---|
| **노들**(완행 전용) | 9177 일반 · 9179 일반 · 9182 일반 · 9184 일반 — **급행 0** |
| 당산 | 9663 **급행** · 9175 일반 · 9676 **급행** · 9184 일반 |
| 여의도 | 9175 일반 · 9665 **급행** · 9182 일반 · 9676 **급행** |
| 고속터미널 | 9179 일반 · 9667 **급행** · 9674 **급행** · 9180 일반 |
| 가양 | 9173 일반 · 9663 **급행** · 9186 일반 · 9678 **급행** |

**그리고 위치 피드는 그 열차를 노들에서 본다.** 급행 9편성을 40초 간격 5회(약 160초) 추적했더니 **9편성 전부가 자기가 서지 않는 역에서 위치 보고**됐고(9665 양천향교·신방화, 9671 삼성중앙·언주, 9680 증미 …), 그중 **9669·9678은 노들에서 관측**됐다 — 노들 도착 목록에는 정의상 나타날 수 없는 바로 그 열차들이다.

두 피드가 같은 열차를 두고 정반대로 답한다: 도착 피드는 **정차 계획**을 말하고 위치 피드는 **물리적 현재**를 말한다. 그래서 "잠금 열차가 하차역을 지나갔다"는 판정은 위치 축에서만 관측 가능하고, 도착 축에서는 원리적으로 불가능하다.

같은 시각 위치 목록에서 급행 9편성이 실제로 운행 중이다(9661·9663·9665·9667·9669·9670·9672·9674·9676·9678). 즉 **노들에 급행이 안 나오는 것은 데이터 결손이 아니라 그 역에 안 서기 때문**이고, 하차역 도착 목록만 보는 매칭은 그 열차를 **정의상 영원히** 못 본다. ODsay 급행 정차역 16역 목록에도 노들은 없다(§2). 두 축이 같은 사실을 독립적으로 말한다.

## 7. 남는 제약 — 쿼터가 설계를 구속한다

`SEOUL_SUBWAY_REALTIME_KEY`는 **일 1,000회**이고 도착 API와 **공유**한다. 안내 세션 한 번의 폴 상한이 `SESSION_POLL_CAP = 240`이므로, 폴마다 위치 조회를 **더하면** 하루 가용 세션이 절반이 된다. 위치를 **보조로 더하는** 설계와 **승차 국면에서 도착 조회를 대체하는** 설계는 쿼터에서 2배 차이가 나고, 이것이 설계의 1급 입력이다.

ODsay도 일 1,000회이며 길찾기 조회와 공유한다 — 급행 정차역 집합을 노선 전 구간 조회로 얻는다면 **긴 수명 캐시가 전제**다(급행 정차역은 다이어 개정 때만 바뀐다).

## 8. 후속 판정으로 넘기는 것

- **어느 축으로 L1을 고칠 것인가**(예방=정차 여부 사전 판정 / 추적=위치 기반 관측)와 쿼터 대가는 spec이 정한다.
- **KRIC 계정 승인 상태 재확인**은 위원장 액션이다(§4 절차). 승인되면 ③이 ①의 노선 전 구간 조회를 대체할 수 있다.
- **경춘선 `directAt:"9"`**의 의미는 미확인이다. 급행 축을 전국으로 넓힐 때 다시 본다.
- **9호선 이외 급행 노선**(1호선·공항철도)에서 ①의 `passStopList` 축약이 같은 방식으로 성립하는지는 확인하지 않았다.
