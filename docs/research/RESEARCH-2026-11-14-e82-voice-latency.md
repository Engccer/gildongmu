# E82 베르길리우스 설계 전 조사: 음성 지연 실측 (OpenAI·Gemini)

측정일 2026-11-14. `RESEARCH-2026-11-12-e82-models-voice.md` §4의 미확인 1~3번(계정 모델 목록, 지연, 오디오 토큰 환산)을 실호출로 메운다. 시점 고정 기록이다.

## 0. 한 줄 결론

「물으면 2~3초 안에 답이 들리기 시작한다」는 **Gemini 실시간 음성(`gemini-3.8-live`)이 모든 질문에서 지켰고(1.3~1.8초), OpenAI 실시간 음성은 세고 묶는 질문에서 3~4초(최대 7초)로 넘었다.** 글 답변 쪽은 `gpt-6.1-terra`(추론 끔)가 첫 문장 1.2초에 목록 전체를 매번 맞게 세어 가장 안정적이었고, 현행 채팅 모델 `gemini-3.6-flash`는 생각을 줄여도 가끔 10초까지 늘어졌다. 목록 전체의 수를 믿고 맡길 수 있는 실시간 음성 모델은 없었다.

## 1. 무엇을 어떻게 쟀는가

- **자리**: Mac(유선·가정 회선)에서 OpenAI API 직접 호출. 휴대전화 LTE·앱 서버 경유 구간은 포함하지 않는다.
- **재료**: 지시문 + 앱이 계산해 넘기는 주변 목록(앞쪽 24곳, 지나친 8곳, 횡단보도·갈림길). 입력 약 1,010토큰. 장소는 전부 가상이다.
- **질문 셋**: q1 「지금 내 앞에 어떤 식당과 카페가 있어?」(세고 묶기), q2 「얼마나 가면 횡단보도가 나와?」(한 값 찾기), q3 「방금 뭘 지나쳤지?」(짧은 나열).
- **반복**: 모델·질문·입력 방식마다 5회. OpenAI 실시간 음성 60회·글 답변 60회·읽어 주기 16회, Gemini 실시간 음성 30회·글 답변 60회. 오류 0건.
- **실시간 음성**: 호출마다 새 연결(WebSocket), 서버 발화 감지는 끄고 질문을 다 올린 순간부터 첫 소리 조각까지를 쟀다. 질문은 소리(macOS 한국어 음성으로 만든 1.6~3초)와 글 두 가지로 넣었다. 추론 강도는 기본값 그대로다.
- **OpenAI 글 답변**: Responses API 스트리밍. 추론은 끌 수 있으면 끄고(`none`), 못 끄면 최저(`low`).
- **Gemini**: 같은 재료·같은 측정점. 실시간 음성은 자동 발화 감지를 끄고 발화 끝 신호를 보낸 순간부터 쟀다. 글 답변은 `streamGenerateContent`에 thinking 수준을 바꿔 가며 쟀다.
- **자료**: 스크립트·원시 결과·답 음성 표본은 `~/gildongmu-private/field-logs/e82-voice-latency-2026-11-14/`(`probe.mjs`·`gemini-probe.mjs`·`materials.mjs`·`analyze*.py`·`results-*.jsonl`·`samples/*.wav`).

## 2. 결과

### 2.1 실시간 음성: 질문이 끝난 뒤 첫 소리까지(초, 중앙값·최소~최대)

| 모델 | 질문 방식 | q2 한 값 | q3 나열 | q1 세고 묶기 | 전체 |
|---|---|---|---|---|---|
| `gpt-realtime-2.1` | 소리 | 1.5 (1.5~1.6) | 2.4 (1.6~3.1) | 4.5 (2.8~7.0) | 2.4 |
| `gpt-realtime-2.1` | 글 | 1.2 (1.1~1.2) | 2.8 (2.1~3.9) | 3.4 (1.6~5.1) | 2.2 |
| `gpt-realtime-2.1-mini` | 소리 | 1.5 (1.4~1.6) | 1.8 (1.2~2.1) | 3.3 (2.7~5.2) | 1.8 |
| `gpt-realtime-2.1-mini` | 글 | 1.1 (1.0~1.2) | 1.6 (1.2~2.8) | 4.1 (2.2~4.5) | 1.6 |

- **지연을 가른 것은 추론 토큰이다.** 실시간 모델은 기본값에서 질문마다 스스로 추론한다. 추론 150토큰 미만이면 첫 소리 1.5초, 150~399토큰이면 2.5~3.1초, 400토큰 이상이면 4.2~6.1초였다(두 모델 같은 모양).
- **연결 비용이 따로 든다.** 연결 1.0초, 세션 설정까지 1.3초(중앙값). 세션을 미리 열어 두지 않으면 첫 질문에 더해진다.
- **서버 발화 감지를 쓰면 침묵 0.5초(기본값)가 더해진다.** 이번에는 끄고 쟀다.
- **답이 길다.** 「한두 문장」 지시에도 답 소리 길이가 중앙 8~13초, 최대 22초였다.
- mini는 한 번 「…빠르게 정리하고, 가장 가까운 곳부터 말씀드려볼게요.」처럼 생각하는 말을 답 앞에 붙였다.

### 2.2 글 답변 모델(초, 중앙값·최소~최대, 15회)

| 모델 | 추론 | 첫 글자 | 첫 문장 끝 | 전체 |
|---|---|---|---|---|
| `gpt-6-luna` | 끔 | 0.9 | 1.0 (0.8~2.9) | 1.8 |
| `gpt-6.1-terra` | 끔 | 0.9 | 1.2 (1.0~1.9) | 2.3 |
| `gpt-6.1-sol` | low | 1.4 | 1.7 (1.4~3.0) | 2.6 |
| `gpt-6-astra` | low | 1.6 | 2.3 (1.7~3.5) | 2.8 |

- `gpt-6.1-sol`은 추론을 끌 수 없다(`none` 거부, 최저 `low`). 11-12 문서의 미확인 4번이 풀렸다.
- 첫 문장을 기기 음성으로 바로 읽으면 「첫 문장 끝」이 곧 첫 소리 시각이다. 서버 음성(`gpt-4o-mini-tts`)으로 바꾸면 첫 소리까지 0.7~0.8초(최대 1.9초)가 더해진다.

### 2.3 Gemini 실시간 음성과 글 답변(초, 중앙값·최소~최대)

| 모델 | 질문 방식 | q2 한 값 | q3 나열 | q1 세고 묶기 | 전체 |
|---|---|---|---|---|---|
| `gemini-3.8-live` | 소리 | 1.4 (1.3~1.6) | 1.4 (1.3~1.6) | 1.7 (1.7~1.8) | 1.5 |
| `gemini-3.8-live` | 글 | 0.7 (0.6~0.8) | 1.0 (0.9~1.1) | 0.9 (0.8~1.3) | 0.9 |

- **질문 종류에 따라 느려지지 않는다.** thought 토큰이 107~862개 붙지만 첫 소리 시각은 흔들리지 않았다.
- **연결이 빠르다.** 연결 0.17초, 설정까지 0.6초(OpenAI는 1.0초·1.3초).
- 답 소리 길이는 중앙 7초, 최대 19초다. 10초를 넘긴 답은 30회 중 8회(`gpt-realtime-2.1` 17회, mini 12회).

| 글 답변 모델 | thinking | 첫 문장 끝 | 최대 |
|---|---|---|---|
| `gemini-3.5-flash-lite` | MINIMAL | 0.8 | 1.1 |
| `gemini-3.6-flash`(현행 채팅 모델) | MINIMAL | 1.5 | 10.5 |
| `gemini-3.6-flash` | LOW | 1.8 | 11.3 |
| `gemini-3.6-flash` | 기본 | 5.5 | 10.6 |

- `gemini-3.6-flash`는 MINIMAL·LOW에서도 15회 중 몇 번이 4~11초로 늘어졌다. thought 토큰이 0인 호출에서도 그랬으므로 생각 때문이 아니라 응답 대기다.

### 2.4 수 세기와 답의 범위(q1, 목록 전체는 카페 7·음식점 10)

「내 앞에」를 목록 전체로 읽으면 7·10이고, 가까운 몇 곳으로 읽으면 더 작은 수가 맞다. 그래서 답을 넷으로 갈랐다: 전체 정답, 가까운 범위만 셈(목록 앞쪽 몇 곳과 수가 맞음), 수를 말하지 않음, 어느 범위로도 안 맞음.

| 모델 | 전체 정답 | 가까운 범위만 | 수 없음 | 안 맞음 |
|---|---|---|---|---|
| `gpt-6.1-terra`·`gpt-6.1-sol`·`gpt-6-astra` | 5/5 | | | |
| `gemini-3.6-flash` 기본 | 5/5 | | | |
| `gemini-3.6-flash` MINIMAL | | 5/5 | | |
| `gemini-3.6-flash` LOW | 1/5 | 4/5 | | |
| `gemini-3.5-flash-lite` | | 3/5 | 2/5 | |
| `gpt-6-luna` | | 3/5 | 1/5 |
| `gpt-realtime-2.1` | 6/10 | 3/10 | 1/10 | |
| `gpt-realtime-2.1-mini` | | 1/10 | 4/10 | 5/10 |
| `gemini-3.8-live` | 1/10 | 3/10 | 3/10 | 3/10 |

- **확실히 틀린 수를 말한 것은 `gpt-realtime-2.1-mini`(5/10), `gemini-3.8-live`(3/10), `gpt-6-luna`(1/5)다.**
- 같은 모델이 호출마다 범위를 다르게 잡는다. 「앞」이 몇 m까지인지는 앱이 정해 넘겨야 한다.
- q3 「방금 뭘 지나쳤지?」에서 `gemini-3.8-live`는 10회 중 8회 가장 가까운 곳 대신 「말하지 않음」 표시가 붙은 먼 곳을 답했다. 재료의 「말해 줌·말하지 않음」 표시를 질문의 뜻으로 읽은 것으로 보이며, 재료 쪽 모호함이라 오답으로 세지 않는다. 다른 모델은 거의 전부 가장 가까운 곳부터 답했다.
- 이름·좌우·거리는 본 범위에서 목록과 어긋난 것을 찾지 못했다(전수 대조는 하지 않았다). **수와 범위는 앱이 세어 넘겨야 한다**는 E82 제안 ⓒ의 근거가 된다.

### 2.5 오디오 토큰 환산과 실제 비용 (OpenAI)

- **입력 오디오 초당 약 10토큰, 출력 오디오 초당 20토큰.** 11-12 문서 §1.4의 가정이 `usage` 실측과 맞았다.
- **추론 토큰이 출력 단가로 더해진다.** 호출당 84~643토큰이 붙어, 실제 1회 비용은 `gpt-realtime-2.1` 0.025달러, mini 0.0055달러였다(11-12 추정 0.017달러보다 `2.1`이 약 1.5배).
- OpenAI 측정 전체 비용은 약 1.3달러다. Gemini 쪽 비용은 계산하지 않았다.

## 3. 읽는 법

- **실시간 음성 단계는 `gemini-3.8-live`가 시간에서 앞선다.** 첫 소리가 빠르고 질문 종류에 흔들리지 않으며 연결도 빠르다. moment·dodo에서 이미 쓰는 모델이기도 하다. 수는 틀리므로 앱이 세어 넘기는 것이 전제다.
- **첫 판(기기 받아쓰기로 묻고 짧은 답을 읽어 주기)의 글 답변은 판정이 갈린다.** 모델에 세기까지 맡기면 `gpt-6.1-terra`(1.2초, 전체 정답 5/5)다. 앱이 수와 범위를 세어 넘기면 모델은 문장만 다듬으므로 `gemini-3.5-flash-lite`(0.8초, 최대 1.1초)로 충분할 수 있다. 이 가정은 재지 않았다.
- **현행 채팅 모델 `gemini-3.6-flash`는 이 용도에 그대로 쓰기 어렵다.** 기본 설정은 5.5초이고, 생각을 줄이면 수를 가까운 범위로만 세며 가끔 10초까지 늘어진다.
- **답 길이는 세 실시간 모델 모두 지시문만으로 잡히지 않았다.** 걷는 중에는 10초 넘는 답이 다음 안내와 겹친다.

## 4. 재지 않은 것

1. 실시간 모델의 추론 강도를 낮췄을 때의 지연과 정답률.
2. 휴대전화 LTE·실외 회선, 앱 서버를 거치는 구간.
3. 기기 받아쓰기가 문장을 확정하기까지의 시간.
4. 도구 호출이 끼는 질문(「○○역에 몇 번 버스가 서?」)의 왕복 지연.
5. 앱이 수와 범위를 미리 세어 넘겼을 때의 지연과 정답률(작은 모델로 충분한지).
6. 한국어 음성 품질. 표본 음성을 들어 판정할 몫이다.
7. 세션을 열어 둔 채 문답이 쌓일 때의 지연과 재과금.
