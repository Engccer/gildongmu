# ODbL 준수 조건 조사 (E12 선행 ①)

> 조사 시점 2026-08-16. **시점 고정 기록물이라 낡는 것이 정상이다** — OSMF 가이드라인이 개정되면 이 문서가 아니라 1차 출처가 정본이다.
>
> 대상: `/api/walk/nearby`의 OSM 축(횡단보도·점자블록)을 Overpass 실시간 호출에서 정적 seed로 옮길 때(BACKLOG E12) ODbL이 요구하는 것.

## 판정 요약

| 질문 | 답 | 근거 |
|---|---|---|
| seed는 Derivative Database인가 | **그렇다** | ODbL §4.4.b가 "Substantial part의 Extraction으로 만든 새 DB"를 명시 |
| 우리 추출이 Substantial인가 | **다툼의 여지 없이 그렇다** | OSMF Substantial Guideline의 insubstantial 상한이 "100 features 미만·인구 1,000명 이하 지역". 전국 92,398 노드 |
| 지오코딩·라우팅 safe harbour가 구제하는가 | **아니다** | Geocoding Guideline이 "도시 규모 이상 지역의 Primary Feature 전량 수집"을 명시 배제. `highway=crossing`은 key-value pair라 Primary Feature |
| 앱 소스코드가 ODbL에 감염되는가 | **아니다. private repo 유지 가능** | §2.3.a(프로그램 제외) · §4.5.b(Produced Work는 파생 DB를 만들지 않음) · §4.7.c(접근 통제 명시 허용) |
| 위반은 언제 성립하는가 | **사용자 도달 시점** | 모든 조건절이 "Publicly"에 걸리고, 정의가 "You 또는 통제 하에 있지 않은 자에게" |

**파일 생성도 private 커밋도 의무를 발생시키지 않는다**(§4.5.c: 조직 내부 사용은 공중 대상이 아니다). [[public-data-seed-export-restriction]]의 juso 계열과 여기가 다르다 — 그쪽은 파일이 놓이는 물리적 위치 자체가 계약 조건이었다.

## 웹과 iOS의 의무가 갈린다

**이것이 이 조사의 가장 실무적인 발견이다.** ODbL의 "Convey" 정의:

> *"Conveying does not include interaction with a user through a computer network... where no transfer of a copy of the Database or a Derivative Database occurs."*

- **웹·CLI·MCP**: seed가 서버에 남고 API 응답만 나간다 → conveying 아님 → §4.2 미적용.
- **iOS 번들**: seed 파일 자체가 기기로 복사된다 → conveying → **§4.2.b 추가 적용**: 라이선스 사본 또는 URI를 "DB와 함께, 그리고 관련 문서에" 동봉.

즉 **같은 seed라도 배포 경로에 따라 동봉물이 다르다.**

## 확정 의무 체크리스트

1. `© OpenStreetMap contributors` + ODbL 고지 + `openstreetmap.org/copyright`를 **사용자가 찾아 들어가지 않아도 만나는 자리**에 둔다. Attribution Guideline: *"The attribution format should not require individuals to interact with the map or produced work to see the attribution."* 설정 화면에만 묻어 두는 것은 safe harbour 밖이다.
2. 앱 시작 시 1회 제시로 충족된다(*"If attribution is presented to the user upon application startup, it does not need to be presented to the user every time"*, 백그라운드 복귀는 재제시 불요).
3. iOS 번들 seed에 ODbL URI + OpenStreetMap 표시 동봉(위 §4.2 비대칭).
4. seed 옆 README 또는 파일 내 메타 필드에 출처·라이선스 기재(*"in a location... such as a readme file, or within the data or metadata"*).
5. 기계 판독 사본을 **요청 시** 무료 제공하는 경로 명시(§4.6). Legal FAQ가 "무료 다운로드 사이트에 두거나 이메일 요청 옵션"을 실무 형태로 인정한다 — 상시 공개 게시가 강제는 아니다.
6. **안내 문장마다 출처를 낭독할 필요는 없다.** Routing engines 조항: *"Routing instructions generated by such a routing engine need not maintain attribution attached to the instructions, as long as they do not form a Derivative Database."*

## 설계를 구속하는 결론: seed 파일을 섞지 않는다

OSM Legal FAQ:

> *"if you make a database which includes OSM data and any additional information (including using information to decide on OSM features NOT to include in your database), then this would be classed as a 'derivative database'."*

지금 계획한 seed는 OSM 자체 태그로만 거르므로 Trivial Transformations의 허용 예시(bbox 필터 · JSON 저장 · 라우팅용 포맷 · 모바일용 경량화) 안에 있다. 그러나 **서울 열린데이터 음향신호기(OA-15543) 같은 국내 소스와 병합해 한 파일로 만들면** 그 병합본은 논쟁의 여지 없는 Derivative Database가 되어 "OSM 원본을 가리키기"로 §4.6을 못 채우고 **병합본 자체를 제공해야 한다.** 그 지점에서 공공데이터 국외 반출 제한과 정면 충돌한다.

⚠ **그래서 OSM 유래 seed와 국내 공공데이터 seed는 파일을 분리해 유지하고 병합은 런타임에서만 한다.** 두 제약이 서로를 잠그는 구조이므로 이것은 취향이 아니라 설계 조건이다.

## 위원장 판단이 필요한 것 2건

### 1. Trivial Transformations Guideline에 기댈 것인가

이 문서의 **지위가 OSMF 안에서 모순된다**: Community Guidelines 목차는 "board가 승인한 문서" 목록에 넣어 두었는데, 본문에는 *"This is at the proposal stage in our process"*라고 적혀 있고 다른 가이드라인에 있는 `Status: Endorsed by the OSMF board YYYY-MM-DD` 줄이 없다.

§4.6 경감 논거의 상당 부분이 이 문서에 기댄다. **보수적 설계 권고**: 경감에 기대지 말고 seed 자체를 요청 시 제공하도록 만든다. 파일이 1~2MB라 비용이 없고, 얻는 것 대비 잃는 것이 없다.

### 2. 스크린 리더 사용자에게 attribution을 언제 들려줄 것인가

OSMF는 앱 시작 시 1회를 허용하고, 커뮤니티 위키는 *"Merely making it available to users who are actively seeking this information is not enough"*라고 요구한다. 시작 시 강제 낭독은 접근성 헌장의 과잉 통지 금지와 긴장 관계다.

⚠ **OSMF 공식 문서에 "지도를 렌더하지 않는 텍스트 전용" 시나리오는 없다.** 문서 자신이 *"This is not a comprehensive list"*라고 인정한다. 웹 검색 요약이 "Text-Only Applications" 항목을 공식 가이드라인에 있는 것처럼 제시하는데 **거짓이고**, 실제 출처는 커뮤니티 위키의 인쇄 지도 절이다. 커뮤니티 의견으로만 취급한다.

가장 가까운 공식 근거 셋: WCAG 준수 권고 문장 · Databases 시나리오 · Geocoding·Routing engines 시나리오(본질적으로 비시각적이며 지도 표시를 전제하지 않는다).

## 판정이 애매하지만 실무 영향이 없는 것

`tactile_paving`이 Primary Feature인가 property인가. Collective Database Guideline은 primary feature를 *"data from a key value pair... but not inclusive of properties (e.g. colour, brand, operator, or width)"*로 정의한다. `highway=crossing`은 명백히 전자라 결론이 안 바뀌고, 어차피 함께 추출하므로 영향이 없다.

한국 법원이 ODbL·EU Database Directive를 어떻게 볼지는 1차 출처 범위 밖이다. OSMF도 *"A court would make a final decision on the issue"*라고 적어 두었다.
