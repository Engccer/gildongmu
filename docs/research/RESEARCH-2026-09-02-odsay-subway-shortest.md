# ODsay 지하철 최단시간 경로(`subwayPath` Sopt=1) vs 길찾기 pool 조사 (E25)

> 시점 고정 기록물(2026-09-02, 실호출 KST 08:40~08:55). 결론이 뒤집히면 이 머리에 한 줄 표기한다.
> 발단: 백로그 [E25](../BACKLOG.md) — 노원→구로디지털단지에서 ODsay 길찾기 pool(21건)에 더 나은 지하철 경로가 없고 `subwayPath`(역 ID 기반 최단시간)는 있다는 2026-08-25 관측. 위원장 판정(2026-09-02): **10쌍 실호출로 "얼마나 자주 차이가 나는가"를 재고 설계 판정은 그 뒤**. 이 문서는 코드가 없다.
> ⚠ **10쌍 중 5쌍만 실측했다** — 6번째 쌍의 `subwayPath` 호출에서 ODsay 일일 쿼터 429("Daily quota exceeded")가 났고, 재시도하지 않았다(프로덕션과 공유하는 키, 429는 재시도 금지 규율). 나머지 5쌍(김포공항→잠실·수유→사당·천호→신촌·왕십리→신도림·상계→양재)은 미실측이다.

## 0. 결론 한 줄

**5쌍 전부에서 `subwayPath`가 pool 최선 지하철 경로보다 2~9분 짧게 나오지만, 그중 4쌍은 같은 경로다**(소요시간 모델 차이 — `subwayPath`는 대기·도보를 빼고 역간 시간만 더한다). **경로 자체가 다른 것은 노원→구로디지털단지 1쌍뿐**(서울역·신도림 2회 환승 58분 vs pool 최선 사당 환승 67분). 표본이 절반이라 빈도는 "5쌍 중 1쌍"까지만 말할 수 있다.

## 1. 방법

- OD 좌표는 seed `subway-stations.json`의 역 좌표. 길찾기 `searchPubTransPathT`(`OPT=0`, 전 수단 — 앱이 쓰는 그대로) → pool 전량.
- `subwayPath?CID=1000&SID=&EID=&Sopt=1`. SID/EID는 pool 응답의 첫·끝 지하철 leg `startID`/`endID`(OD 역명과 일치할 때만) — `searchStation` 별도 호출 0.
- 비교 축: ①pool 안 지하철 전용(`pathType 1`) 최선 소요시간 vs `subwayPath.globalTravelTime` ②`subwayPath`의 환승역 열이 pool의 어느 지하철 전용 경로와 같은가(같으면 "경로 동일, 시간 모델 차이").
- 쌍당 2콜, 5쌍 10콜 + 실패 2콜.

## 3. 읽기

1. **시간 차이는 대부분 모델 차이다.** 같은 환승열인데 `subwayPath`가 2~8분 짧다 — 길찾기 pool은 대기·환승 도보·출발 도보를 더하고 `subwayPath`는 역간 주행 + 환승 도보만 더한다(서울역 180초·신도림 120초 `exWalkTime`). 그러므로 `subwayPath` 시간을 pool 시간과 나란히 보여 주면 **같은 경로가 두 시간으로** 읽힌다. 보강한다면 `subwayPath`의 경로를 pool 형식으로 재조회(`searchPubTransPathT`는 경유역 지정이 없다 — N4)하거나 시간을 표시하지 않아야 한다.
2. **경로가 다른 1쌍은 08-25 관측과 같은 자리다**(노원→구로디지털단지). 다만 08-25엔 카카오가 동대문역사문화공원 환승 59분을 냈고 `subwayPath`는 그때도 지금도 서울역·신도림 2회 환승 58분이다 — 2회 환승 + 환승 도보 300초라 "더 낫다"는 소요시간 축에서만 참이고 최소환승 축에선 pool 최선(1회)이 낫다. 시각장애 사용자에게 환승 1회 추가는 시간 9분보다 비쌀 수 있다(E15 능력 표의 "대안 확인·전환" 축과 같은 판단).
3. **보강 설계에 드는 것**: 역 ID 확보(`searchStation` 1콜 또는 pool 응답 ID 재사용 — 이번 조사처럼 OD가 역이면 0콜), `subwayPath` 1콜(쿼터 공유), 도보 구간 합성(OD가 역이 아닐 때 출발·도착 도보를 pool의 도보 leg에서 빌려야 한다), 그리고 §3.1의 시간 모델 불일치 처리. 쿼터가 오늘처럼 소진되면 두 호출 다 죽는다.

## 4. 후속 판정으로 넘기는 것

- **빈도 판정은 미완**이다 — 나머지 5쌍(특히 순환선·환승 많은 왕십리→신도림, 외곽 상계→양재)을 쿼터 리셋 뒤 같은 스크립트로 잰다(BACKLOG E25 미실측 행).
- 착수 여부는 위원장 판정: 5쌍 중 1쌍(그것도 환승 +1)이면 **보강보다 "최소환승 축 대안"이 이미 pool에 있는 현행이 사용자에게 낫다**는 쪽이 강한 디폴트다. 10쌍 중 3쌍 이상에서 **환승 수가 같거나 적은** 다른 경로가 나오면 그때 설계한다.
